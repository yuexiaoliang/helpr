## 资料与运行职责

正式资料固定在 `~/Library/Application Support/helpr`，独立于安装包；SQLite、浏览器持久会话及诊断分别存放。业务记录只有独立记录进程写入，使用 Zod 契约、XState 纯转换、Drizzle 和 `better-sqlite3`。关键命令采用请求身份、版本检查和事务；回执不明时保留原命令，取消只读核对，避免制造另一份任务。保存未完成或结果未明时阻止退出。

长期控制进程持有私有调试 pipe；观察及单步操作均限制到所属页面、当前执行和代次。工作者不能选择其它任务的页面或浏览器级能力；模型仅能提出受限的角色定位及单个动作，没有 TCP 调试监听或任意宿主脚本执行入口。启动时拒绝单／双横线的裸调试参数；macOS `proc_pidpath` 核对宿主的原生监督父进程及监督的控制父进程映像，宿主无法仅凭外部 IPC 或参数取得角色。

控制进程建立自有进程组，并先启动独立组的原生监督，再由监督创建独立组的网页宿主。监督核对拥有者真实身份和启动时间，持有同一运行租约；拥有者退出时结束控制组（含记录与工作者）及宿主组，独立核对成员清空后才释放租约。清理不依赖网页 JavaScript 响应。私有 pipe 与继承 IPC 仅交给宿主，监督不会保留这些连接。系统授权迟到时也必须遵循这项退出保证。

控制拥有者使用 macOS `accessory` 角色运行，Dock 入口仅由 `regular` 角色的网页宿主持有。网页宿主收到激活事件时显示并聚焦已有窗口；菜单栏入口仍由控制拥有者管理。

真实网页没有 preload，禁用 Node、webview 和任意宿主接口，启用 sandbox、context isolation 与 web security。宿主对话使用独立受信视图，校验发送方、主 frame 和角色。同一网站的持久登录在任务间共享，任务身份、对话和草稿独立；这不证明后续同一业务目标的写入协调已经实现。Cookie 保护从新资料区启用，不能推定整个浏览器目录都加密。

关闭主窗口收起到菜单栏；退出前提示可能丢失尚未保存的网页编辑，确认退出先阻断自动操作、完成记录后关闭。网站自己的未保存编辑不能由 helpr 代为保存，退出按钮明确表示放弃网页编辑。定时任务尚未实现。

Pino／pino-roll 每个角色独占诊断文件，仅保存限定事件、错误码、标识和耗时；按 2 MB、每日和 4 份轮转，不记录目标、URL、消息或凭据。诊断失败不代替或改变业务事实；任务历史不按日志规则清理。

## 验证入口

日常开发运行定向 Vitest 用例，或用 `pnpm validate:workspace` 运行整套源码检查。升级问题可用 `pnpm validate:upgrade` 单独核对升级逻辑、界面状态和凭据保护错误处理。这两个默认入口都能在没有桌面连接、签名包或系统授权的情况下运行。

需要核对实际 Electron 包时，选用含本次改动的固定候选，运行 `pnpm validate:workspace --fixture --candidate=<名称>`。加 `--preflight` 只核对该包，无需窗口截图。运行时通过受限通道核对两项任务、本机网页收件、正常退出和冷重开。每轮创建隔离资料，网页采用临时会话。结果中的 `storage` 和 `pendingAcceptance` 标明本轮能证明什么。现有 [无人值守测试模式](../docs/testing/unattended-fixtures.md) 说明本机网页、虚构凭据和正式资料的隔离边界。

只有核对真实系统凭据和持久登录时才显式选择 `--system-storage`。需要现场操作再加 `--interactive`。此时按事项固定包、准备测试账号及资料，集中处理系统授权与真人动作。`--fixture --install` 把测试副本放在隔离目录。`--installed` 显式选择用户已有的安装。只有相应安装已获授权时才使用 `--system-storage --install` 写入用户应用目录。历史 [01 验收方案](../docs/testing/workspace-01-plan.md)保留当轮的边界。

`validate-owner-exit.mjs --early` 验证宿主执行 JavaScript 前的退出。`validate-workspace.mjs --fault --blocked-host` 验证宿主响应被暂停后的退出与记录重开。每轮限制故障次数，独立核对实际进程。

`validate-dock.mjs` 在空验证资料区启动实际安装包，以只读 `NSRunningApplication` 元数据核对已知同 UID、同安装路径的控制／宿主角色，再正常退出并检查进程。不读取其它窗口或发送输入，也不抵算 CUA／真人点击 Dock 与焦点验收。

单独的 `pnpm validate:workspace --preflight` 供原生验收预检锁屏和受保护输入。Computer Use 无法读取窗口时，登记候选、失败现象和待核对的条目。交互轮已打开时，在入口打印的路径创建 `defer-ui`，脚本会继续核对网页、冷重开和进程清理。输出中的 `automatedPassed` 标记自动部分，退出码 2 表示现场交互仍待验。

脚本累计记录构建、安装、启动、故障和清理次数。隔离调试沿用[仓库验证规则](../AGENTS.md#测试与验证)直接进行，已结束的批次保留原账本与失败。验证资料放在固定 OS 临时根 `helpr-workspace-validation-<uid>` 下，拒绝指向正式资料的链接。每轮结束用 OS 核对自有进程和进程组。原始资料、包及日志限本机保存。

源码测试与旧实验检查分别保留。真实 macOS 中文输入、网页手动登录、焦点和安装后视觉需要实际包证据，不能由 React 模拟输入或旧实验通过替代。具体依赖来自精确版本与锁文件，升级单独核对受影响能力。

## 模型配置与网页理解（02）

顶部“模型设置”配置 OpenAI 兼容的 Chat Completions 服务地址、模型与密钥；不同提供方以这一协议的实际兼容结果为准。“检查连接”只查询该地址的模型列表入口，不产生文本生成，也不证明模型能力。任务对话提问时读取本任务的主 frame 和可访问性树，排除受保护输入及子节点，标明观察时间、页面依据和截断情况；结束时再核对页面，无法核对也提示旧依据可能变化。

冻结 AI SDK `7.0.141` 与 `@ai-sdk/openai-compatible` `3.0.69`，使用显式直连 provider，关闭请求重试、流式重试与 telemetry；实际发送入口再次核对资格并禁止重定向。凭据由 macOS Keychain 支持的 `safeStorage` 异步接口保护，等待期间可停止模型请求；正式凭据从不返回网页、UI 快照或普通日志。密钥轮换和安装后授权行为仍须实际包验证，测试中的替代保护不充抵这项证据。

记录进程可靠保存配置版本、请求身份、预留、输出、原始用量及结束事实。每项任务最多 20 次派发，同时最多两项；单次最大输出 2048 token。预留按输入 UTF-8 字节、固定指令余量与输出上限计算，本机预留额度每任务 200000；这不构成任意服务分词或收费规则的费用保证。服务原始 usage 字段不完整时保留未知和原预留，不采用 SDK 补零。关闭程序中断的请求重开后标记待重新发送，不自动重复；明确的新问题才创建新请求身份。

本次数据结构升为版本 2；已有工作区升级前在相同受保护目录留下 `workspace-before-model-02-*.sqlite` 本机副本，旧应用不应直接读取新版资料。本轮源码测试只打开临时目录，没有迁移正式用户资料。当前安装与旧候选未替换。

开发检查见 [02 检查记录](../docs/testing/model-02-plan.md)。运行 `pnpm exec vitest run tests/workspace/model.test.ts` 使用可独立计数的本机服务，不调用真实模型；实际服务和安装包试用另行安排，不重复已通过的卡片、Dock、输入法核对。

## 网页执行、停止与继续（03）

按已确认 `execution-v1` 接入所属任务的“开始执行”“停止”“继续”和“查看结果”。目标及本次指令交给既有模型客户端，每次只提出一个动作；通用原语支持按可访问角色定位的点击、填写、勾选和选项选择。没有后台专用步骤、上传、发布流程学习或原生接管实现。对话可用“开始执行”“停止”“继续”“查看结果”及“改为：新的目标”；其它普通问题沿用 02 的只读问答。

独立记录进程在 SQLite 事务中计算 XState 纯转换、领取最多两项合格任务、保存动作并消费一次性派发。控制拥有者收到停止先撤销本任务工作者及新模型请求，再保存；每个等待及实际私有 pipe 派发前复核资格。独立 B 可以继续，第三项合格工作排队。当前对同一 `origin + pathname` 的在途／未核实操作保守排队；共享登录和具体目标记录的完整资源协调由 16 继续，不宣称已经覆盖所有冲突。

收到动作返回不等于任务完成。下一轮读取实际页面，模型用本次页面原文提出核对依据；结果不明暂停，明确继续也先核对，不直接重发。停止后迟到的事实可保存但不会恢复执行；修正目标保留停止，旧执行不复活。界面分别显示当前意图、执行状态和已保存结果证据。模型判断的业务正确性仍须实际试用检验，原文匹配本身不是普适的正确性证明。

每轮最多 20 次下一步判断，每项累计最多 60 条动作预留；沿用 02 每任务模型预算和同时两请求限制。达到上限暂停，不无限重试。数据结构升为版本 3，旧工作区迁移前留下 `workspace-before-execution-03-*.sqlite` 本机副本。03 原行为将重开活动执行暂停、等待明确继续；05 已改为按原意图先核对恢复，详见下节。已派发未核实动作保留未知，不恢复旧异步调用。

检查和证据边界见 [03 开发记录](../docs/testing/execution-03-plan.md)。本轮只完成正式源码与本机夹具验证，未启动或替换实际应用；Playwright、Electron 私有 pipe、模型与双页操作的完整实际包组合仍待下一轮核对。

## 直接接管与页面归属（04）

网页宿主使用 AppKit 局部事件与经过矩形核对的原生视图子树识别输入归属，不监听其它应用、不读取输入字符或剪贴板、不申请全局输入权限。网页鼠标、键盘和粘贴让出对应任务；受信对话、标签及浮层不是网页接管。未知归属暂停窗口内自动工作，保留已有停止；能力恢复、重新绑定和页面加载均不自行恢复。明确继续才核对现场及已有结果。

Node-API 8 原生模块经 node-gyp `13.1.0` 构建，固定 arm64／macOS 14 部署条件，实际 SDK、源码哈希另存构建清单。每次运行创建一个受保护的临时资格文件，由原生事件在交付 AppKit 前撤销资格；控制拥有者在网页管道和规划模型网络发送入口的短临界区复核。临界区不等待数据库、网络或 IPC 回执；异步通知只负责取消、保存暂停原因和界面投影。它不保存业务事实，重开不复用旧门，备份也不应将其当作恢复依据。

页面／frame 导航、视图丢失和控制中断使旧资格失效；所属网站弹窗由同一任务承载，保留原页面，弹窗关闭后回到原页面并仍等待明确继续。明确的宿主归属与当前原生命中分别核对，不按 URL、标题或网页自报身份认领任务。真实 frame、弹窗、焦点及输入因果仍需实际包独立证据。

记录格式升为版本 4；升级前在原受保护目录留下 `workspace-before-takeover-04-*.sqlite`，旧版不能直接打开新版记录。暂停原因与用户明确停止分别保留，迟到结果可以登记，不恢复执行。检查范围及实际包准备上限见 [04 核对方案](../docs/testing/takeover-04-plan.md)。真人中文输入法、⌘V 与系统生命周期核对由 06 集中承接。

## 退出与冷重开核对（05）

按已确认 `recovery-v1` 实现退出先冻结派发、等待必要保存与可写检查点，再结束宿主、工作者和控制进程。退出不写成“用户停止”；保存失败保留窗口与阻断，记录进程独立退出后只尝试一次重新连接，先核对已提交回执，不盲目重做未提交命令。工作区保存重试成功后可退出，故障中保存的执行暂停跨重开保持。

新启动取得资料区独占运行租约后才读取记录。活动任务重建页面并核对原 URL 与目标版本；唯一已有结果可以补记，明确未派发的旧预留作废后才可做新的剩余动作，可能已派发的动作保持未知直至核对。停止、接管、待参与和未知暂停保持；恢复期间的新停止或目标变化撤销旧资格。

记录格式升为版本 5，旧格式升级前保存 `workspace-before-recovery-05-*.sqlite`。独立初始化标记防止已用资料区在数据库丢失或截空后被重建成空库；损坏、未知状态模型及不兼容资料保留并明确拒绝恢复。当前没有上传素材或真实发布流程，其版本核对仍由 12–14 扩展。

源码专项为 `pnpm exec vitest run tests/workspace/recovery.test.ts tests/workspace/runtime-ownership.test.ts`。实际签名包限定验证为 `node scripts/validate-recovery.mjs --build=<固定编号>`。[05 核对方案](../docs/testing/recovery-05-plan.md)保存原候选、批次记录和适用边界。真实凭据与有效登录延续归 09 验收。

## 收起、锁屏与休眠恢复（06）

按已确认 `lifecycle-v1` 接入控制拥有者的系统运行条件。锁屏、休眠和系统会话尚未就绪分别阻断；先同步撤销所有旧任务资格，再由记录进程保存原活动任务的恢复检查点。解锁和唤醒须全部满足，完成可靠保存后才先核对；停止、人工接管、输入未知和原待参与状态保持。唤醒取样不清除已收到的锁屏，明确解锁才解除。新系统事件、停止或人工输入会撤销旧核对，迟到领取／继续准备回执不能重新开放资格。

红色关闭按钮只隐藏已有窗口，菜单栏返回同一网页和对话，沿用既有工作区；遵循系统休眠设置，不阻止休眠。地址栏与任务状态显示系统条件及休眠期间不保证按时执行的说明。此项复用版本 5 的恢复检查点，没有更改资料格式或读取正式用户资料。

源码专项：`pnpm exec vitest run tests/workspace/lifecycle.test.ts`。实际包与真人验证按 [06 方案](../docs/testing/lifecycle-06-plan.md)执行；源码检查不替代实际双任务隐藏推进、输入法、⌘V、锁屏、真正休眠或性能证据，当前不宣称这些已经完成。

## 跨任务文字回复（10）

执行中的任务需要补充信息时，工作区会显示带任务名称的待回复卡片。用户可在当前网页上直接回复，也可从顶栏“待回复”重新打开。回答进入提问任务的会话，该任务核对网页后继续。记录格式 8 保存未答问题与所属目标版本，升级旧资料前生成本机数据库副本。

定向源码入口是 `pnpm exec vitest run tests/workspace/participation.test.tsx`。已构建的候选可用 `pnpm validate:workspace --fixture --candidate=participation-10-final --participation` 在临时资料中核对两个网页、回复归属和一次性接受。该入口通过公开业务命令提交答案，原生窗口的点击和输入法另行验收。

菜单栏的“待办”可在主窗口隐藏时单独打开。待办和任务会话共享同一份待改草稿；确认卡列出网站、栏目和完整文字。改稿产生新版本，旧确认失效。记录格式 9 保存本次发布确认和待核对的登录网站；格式 7、8 升级前保留原库副本。

登录待办只在选择“去所属网页登录”时切到该任务；在会话中选择“已登录，核对后继续”，会先读网页。没有登录证据时继续等待。窄发布案例在提交前核对已确认的去向和完整正文，同一次确认不能再次点击提交。多步骤文章发布和长期可复用约定分别在事项 18、19 扩展。

隔离实包命令：`pnpm validate:workspace --fixture --candidate=participation-10-reviewed --participation-review`。该命令走与菜单相同的打开入口，检查窗口状态，由本机网站独立记录发布次数和正文。系统菜单点击、中文输入法和焦点的实机验收单列在[事项 10](../.scratch/helpr-first-release-implementation/issues/10-participation-and-actionable-notifications.md)。

## 任务组与任务历史（11）

在新建任务中输入“把周报分别发到校刊网站和社团公告”，可查看将要建立的两个目标或选择保留为一项。目标没有明确网址时，仍可从各自的地址栏打开网站。顶栏的活动任务入口也可以查看历史。记录格式 10 保存任务组与历史位置，升级前保留原库。

隔离签名候选验证入口为 `pnpm validate:workspace --fixture --candidate=task-groups-11 --task-groups`。该场景使用本机模型夹具和两个测试网页，检查页面身份、历史和冷重开后的结果。原生菜单、输入法及焦点随事项 10 集中验收。

## 固定素材与上传准备（12）

用户可在委托或所属任务的回答中给出文件／文件夹绝对路径与取材规则。当前支持确切文件、范围内唯一文件，以及用户明确要求的最新修改文件；仅查看指定目录的直接文件，缺失、歧义、拒绝访问或超过 8 MiB 时请求参与。网页内容不能赋予本机文件读取资格。

记录进程先将选定字节写入、同步并核对 SHA-256，再保存来源与选择依据。源文件之后变化不会影响这一版本。上传动作只引用本任务当前目标版本下的素材身份，实际派发读取并校验固定副本，不接受模型提供上传路径；已派发的同一上传不能通过“继续”重传。受控观察补充实际文件控件、链接和可访问 iframe 内容，网页步骤仍由模型提议。

目标、上传和草稿依据取得后立即保存。页面观察与下载字节证明分别记录，不把页面文件名当作字节核验。准备完成保存本次观察来源；冷重开继续须取得新的页面核对，不把旧草稿事实当作新成功。最终发布由 13 承接。

记录格式 11 接续格式 10，升级前保留原库。备份携带所有被引用的固定素材（受既有 64 MiB 备份限制），恢复前校验摘要、字节长度和任务引用，先可靠写入文件再提交记录；恢复仍暂停并逐项核对。草稿准备不能被备份核对误记为最终完成。

源码入口：`pnpm exec vitest run tests/workspace/material.test.ts`。隔离签名包入口：`pnpm validate:workspace --fixture --candidate=material-12-diagnostic --material`。本机网站及替代模型不充抵真实 WordPress 证据；两次 iframe 点击超时的唯一根因仍未确认，后续成功不抹去原失败。实际覆盖、剩余检查和真实批次范围见 [12 检查报告](../docs/testing/evidence/material-12/REPORT.md)、[验证安排](../docs/testing/material-12-plan.md)与[真实批次提案](../docs/testing/material-12-real-batch.md)。

## 首次附件发布与流程候选（13）

附件发布先在所属任务预览完整文字、栏目、固定素材、编辑目标和附件链接。确认只适用于这一版。最终点击前独立下载附件并再次观察网页；动作返回后单独核对公开内容、栏目和附件字节，关键证据不足则保持未知，明确继续也不直接重发。结果卡提供实际结果入口和下载摘要。

核实结果、素材处理、本次进度及学得候选由独立记录进程同事务保存。候选包含参数来源、步骤前后条件、结果／恢复规则、版本、摘要与证据，只验证过原输入；新输入和固定版本重放由 15 继续，流程本身不授予发布权限。当前独立结果读取限同站匿名可读且无重定向的公开 HTML 与附件，私有或动态结果保持待核对。

记录格式 12 接续 11，升级前保留原库，新增结果／素材处理／候选／采用引用进入备份和冷开检查。源码入口为 `pnpm exec vitest run tests/workspace/publication.test.ts`；实际候选入口为 `pnpm validate:workspace --fixture --candidate=publication-13-final --publication`。本机通过不等于真实 WordPress 或模型学习验收，覆盖、失败与待验见[13 检查报告](../docs/testing/evidence/publication-13/REPORT.md)。

## 提交中断后的结果核对（14）

提交预留可保存正常编辑页已经观察到的精确永久链接、规则版本与目标／附件准备事实引用。冷进程先按这些记录只读核对公开页和下载，不调用模型、不创建网页动作工作者；只有 canonical 唯一且匹配、确认全文／栏目／附件和固定字节都满足时补记完成。结果、素材处理和流程候选仍同事务保存。核对中较新的停止、接管或目标修改优先，迟到结果只进入历史观察，不恢复派发资格。

可靠未派发的旧预留取消，新执行先核对本机固定素材，再按当前网页和原有效确认经统一入口续做。已经可能派发、缺少稳定关联、超时、404、内容或素材不符均不批准重送。中断的上传需要保存的目标／上传关联和下载字节，旧草稿需要对应动作的准备事实；不把草稿当成发布完成。

记录格式 13 接续 12，升级前保留原库，冻结规则和历史核对进入备份及引用检查。当前规则只支持同站匿名公开 HTML／附件和精确永久链接；私有、动态或不兼容结果保持未知。定向检查见 `tests/workspace/publication.test.ts`、`material.test.ts`、`recovery.test.ts`；实际候选用 `pnpm validate:workspace --fixture --candidate=publication-recovery-14-checked --publication-recovery=result`，另有 `reserved` 和 `committed` 两个中断位置。范围、失败与真实待验见[14 检查报告](../docs/testing/evidence/publication-14/REPORT.md)和[验证安排](../docs/testing/publication-14-plan.md)。

## 换输入与冷启动流程复用（15）

正常委托可采用已有流程，先核对本次明确网站、目标、正文／标题、栏目和固定素材，再保存所用完整版本。流程只提供做法，不带来源任务的单次确认；本次仍预览和确认，改稿后采用确认的全文。网页步骤按字段引用重放，使用当前实际链接和步骤条件，继续经过原预留、派发、停止和素材／结果检查。缺条件或链接歧义则暂停，不借用旧值或重发。

当前支持从已核对动作形成的同站、同入口路径、明确编辑目标的线性附件流程。缺少链接元数据的旧候选不补造重放依据；复杂动态导航和网页变化留待重新观察与后续修复。模型用途与网页重放步骤分别保存，冷开从记录读取固定版本。记录格式 14 接续 13，迁移前保留原库，新增采用和模型用途进入备份及引用检查，恢复仍先暂停。

源码入口：`pnpm exec vitest run tests/workspace/workflow-reuse.test.ts`。固定包检查：`pnpm validate:workspace --fixture --candidate=workflow-reuse-15 --workflow-reuse`。候选 61 已通过首次形成候选、换输入和冷开新输入；真实模型、WordPress／Excel 和双活动网页组合待验。证据、原失败与边界见[15 检查报告](../docs/testing/evidence/workflow-15/REPORT.md)。
