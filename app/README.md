# helpr 正式应用

当前落实[实现事项 01](../.scratch/helpr-first-release-implementation/issues/01-installable-task-workspace.md)已经确认的 `foundation-v2` 交互与 `foundation-v3` 第 4 款标签栏。真实网页占主要区域；每项任务有独立宿主对话和草稿。新建只输入目标，明确 URL 可以打开；未给网站时可在原任务的地址栏补充。事项 02 已接入模型设置、所属页面的流式问答、逐任务停止回复及服务切换，并取得两项真实问答和切回保留的限定通过。事项 03 已开始接入双任务执行、整项停止与继续；当前安装候选仍为 02，尚未替换。原生接管由 04 实现。

## 开发入口

使用 `.node-version` 中的 Node 24.18.0 和 `packageManager` 中的 pnpm 11.7.0。

```sh
pnpm install --frozen-lockfile
node node_modules/electron/install.js
pnpm compile
pnpm check
pnpm dev
```

pnpm 原生构建许可保存在 `pnpm-workspace.yaml`。Electron 二进制单独准备；没有全局展开依赖。`compile` 先构建 macOS 只读进程映像检查器和原生退出监督，再编译控制、网页宿主、记录、观察／单步执行工作者、独立 CJS preload 与 React 静态界面。当前 Mac 需要已有的 Command Line Tools；用户打开打包应用无需这些开发工具。Linux CI 只编译和测试可运行的记录、契约及 UI，不抵算 macOS 原生和安装验收。

```sh
pnpm build:mac
```

产物位于 `dist/packages/mac-arm64/helpr.app`，仅供当前 Apple Silicon Mac 自用，使用 ad-hoc 签名；对外分发仍按已有规格准备 Developer ID 签名和公证。当前安装候选和验收状态见[核对报告](../docs/testing/evidence/workspace-01/REPORT.md)。应用图标仍为 Electron 默认图标，品牌图标等待对应设计确认。

## 资料与运行职责

正式资料固定在 `~/Library/Application Support/helpr`，独立于安装包；SQLite、浏览器持久会话及诊断分别存放。业务记录只有独立记录进程写入，使用 Zod 契约、XState 纯转换、Drizzle 和 `better-sqlite3`。关键命令采用请求身份、版本检查和事务；回执不明时保留原命令，取消只读核对，避免制造另一份任务。保存未完成或结果未明时阻止退出。

长期控制进程持有私有调试 pipe；观察及单步操作均限制到所属页面、当前执行和代次。工作者不能选择其它任务的页面或浏览器级能力；模型仅能提出受限的角色定位及单个动作，没有 TCP 调试监听或任意宿主脚本执行入口。启动时拒绝单／双横线的裸调试参数；macOS `proc_pidpath` 核对宿主的原生监督父进程及监督的控制父进程映像，宿主无法仅凭外部 IPC 或参数取得角色。

控制进程先启动独立进程组中的原生监督，再由监督创建网页宿主。监督核对控制拥有者的真实身份和启动时间；拥有者退出、通道准备失败或宿主退出时结束自己的整组进程，清理不依赖网页 JavaScript 响应。私有 pipe 与继承 IPC 仅交给宿主，监督不会保留这些连接。系统授权迟到时也必须遵循这项退出保证。

控制拥有者使用 macOS `accessory` 角色运行，Dock 入口仅由 `regular` 角色的网页宿主持有。网页宿主收到激活事件时显示并聚焦已有窗口；菜单栏入口仍由控制拥有者管理。

真实网页没有 preload，禁用 Node、webview 和任意宿主接口，启用 sandbox、context isolation 与 web security。宿主对话使用独立受信视图，校验发送方、主 frame 和角色。同一网站的持久登录在任务间共享，任务身份、对话和草稿独立；这不证明后续同一业务目标的写入协调已经实现。Cookie 保护从新资料区启用，不能推定整个浏览器目录都加密。

关闭主窗口收起到菜单栏；明确退出先阻断自动操作，再提示可能丢失尚未保存的网页编辑。网站自己的未保存编辑不能由 helpr 代为保存，退出按钮明确表示放弃网页编辑。定时任务尚未实现。

Pino／pino-roll 每个角色独占诊断文件，仅保存限定事件、错误码、标识和耗时；按 2 MB、每日和 4 份轮转，不记录目标、URL、消息或凭据。诊断失败不代替或改变业务事实；任务历史不按日志规则清理。

## 验证入口

沿用[本轮验证方案](../docs/testing/workspace-01-plan.md)和累计额度。

```sh
node scripts/validate-startup.mjs
pnpm validate:workspace --preflight
pnpm validate:workspace --install --interactive --fault
```

已在核对中安装过且身份一致时，使用 `--installed` 选择现有安装，不再次消耗安装或覆盖应用。

`validate-owner-exit.mjs --early` 验证宿主执行 JavaScript 前的退出；`validate-workspace.mjs --fault --blocked-host` 验证宿主响应被暂停后的退出与记录重开。两者都在既定启动和故障额度内运行，独立核对实际进程；不能以退出消息代替清理证据。

`validate-dock.mjs` 在空验证资料区启动实际安装包，以只读 `NSRunningApplication` 元数据核对已知同 UID、同安装路径的控制／宿主角色，再正常退出并检查进程。不读取其它窗口或发送输入，也不抵算 CUA／真人点击 Dock 与焦点验收。

可见工作区验收在扣减额度前检查 Mac 锁屏及受保护输入；未就绪时保留现场并停止。`--preflight` 只读系统条件，不启动或安装应用。未发现锁屏不代表界面和中文输入已经验收通过。

这不是可以无限重复的日常检查。脚本先记累计次数，再正常启动最终应用；验证资料必须在固定 OS 临时根 `helpr-workspace-validation-<uid>` 内，拒绝指向正式资料的符号链接。安装脚本拒绝覆盖已存在的应用；替换本轮自己的候选前须结束其自有进程并保留构建身份。网页夹具只在本机提供虚构会话；不使用模型或远程业务写入。最终浏览器和数据库资料、构建包及日志均忽略，只提交脱敏结论。

源码测试与旧实验检查分别保留。真实 macOS 中文输入、网页手动登录、焦点和安装后视觉需要实际包证据，不能由 React 模拟输入或旧实验通过替代。具体依赖来自精确版本与锁文件，升级单独核对受影响能力。

## 模型配置与网页理解（02）

顶部“模型设置”配置 OpenAI 兼容的 Chat Completions 服务地址、模型与密钥；不同提供方以这一协议的实际兼容结果为准。“检查连接”只查询该地址的模型列表入口，不产生文本生成，也不证明模型能力。任务对话提问时读取本任务的主 frame 和可访问性树，排除受保护输入及子节点，标明观察时间、页面依据和截断情况；结束时再核对页面，无法核对也提示旧依据可能变化。

冻结 AI SDK `7.0.141` 与 `@ai-sdk/openai-compatible` `3.0.69`，使用显式直连 provider，关闭请求重试、流式重试与 telemetry；实际发送入口再次核对资格并禁止重定向。凭据由 macOS Keychain 支持的 `safeStorage` 异步接口保护，等待期间可停止模型请求；正式凭据从不返回网页、UI 快照或普通日志。密钥轮换和安装后授权行为仍须实际包验证，测试中的替代保护不充抵这项证据。

记录进程可靠保存配置版本、请求身份、预留、输出、原始用量及结束事实。每项任务最多 20 次派发，同时最多两项；单次最大输出 2048 token。预留按输入 UTF-8 字节、固定指令余量与输出上限计算，本机预留额度每任务 200000；这不构成任意服务分词或收费规则的费用保证。服务原始 usage 字段不完整时保留未知和原预留，不采用 SDK 补零。关闭程序中断的请求重开后标记待重新发送，不自动重复；明确的新问题才创建新请求身份。

本次数据结构升为版本 2；已有工作区升级前在相同受保护目录留下 `workspace-before-model-02-*.sqlite` 本机副本，旧应用不应直接读取新版资料。本轮源码测试只打开临时目录，没有迁移正式用户资料。当前安装与旧候选未替换。

开发检查见 [02 检查记录](../docs/testing/model-02-plan.md)。运行 `pnpm exec vitest run tests/workspace/model.test.ts` 使用可独立计数的本机服务，不调用真实模型；实际服务和安装包试用另行安排，不重复已通过的卡片、Dock、输入法核对。

## 网页执行、停止与继续（03）

按已确认 `execution-v1` 接入所属任务的“开始执行”“停止”“继续”和“查看结果”。目标及本次指令交给既有模型客户端，每次只提出一个动作；通用原语支持按可访问角色定位的点击、填写、勾选和选项选择。没有后台专用步骤、上传、发布流程学习或原生接管实现。对话可用“开始执行”“停止”“继续”“查看结果”及“改为：新的目标”；其它普通问题沿用 02 的只读问答。

独立记录进程在 SQLite 事务中计算 XState 纯转换、领取最多两项合格任务、保存动作并消费一次性派发。控制拥有者收到停止先撤销本任务工作者及新模型请求，再保存；每个等待及实际私有 pipe 派发前复核资格。独立 B 可以继续，第三项合格工作排队。当前对同一 `origin + pathname` 的在途／未核实操作保守排队；共享登录和具体目标记录的完整资源协调由 16 继续，不宣称已经覆盖所有冲突。

收到动作返回不等于任务完成。下一轮读取实际页面，模型用本次页面原文提出核对依据；结果不明暂停，明确继续也先核对，不直接重发。停止后迟到的事实可保存但不会恢复执行；修正目标保留停止，旧执行不复活。界面分别显示当前意图、执行状态和已保存结果证据。模型判断的业务正确性仍须实际试用检验，原文匹配本身不是普适的正确性证明。

每轮最多 20 次下一步判断，每项累计最多 60 条动作预留；沿用 02 每任务模型预算和同时两请求限制。达到上限暂停，不无限重试。数据结构升为版本 3，旧工作区迁移前留下 `workspace-before-execution-03-*.sqlite` 本机副本。重开将活动执行改为暂停、已派发未核实动作保留未知，等待明确继续；不恢复执行中的异步调用。

检查和证据边界见 [03 开发记录](../docs/testing/execution-03-plan.md)。本轮只完成正式源码与本机夹具验证，未启动或替换实际应用；Playwright、Electron 私有 pipe、模型与双页操作的完整实际包组合仍待下一轮核对。
