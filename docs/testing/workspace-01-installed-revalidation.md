## 三次启动的核对顺序

1. **候选启动 38。** 使用 37 留下的原任务快照及测试资料区，不安装。活动窗口中三色按钮可见；在 A 标签稳定后按 Down，完整原生 AX 明确焦点为任务卡片，再放行一次本机 A HTTP 响应。响应后完整 AX 仍为卡片；Esc 关闭并回原 A 标签，下一次 Tab 到 A 收起按钮。任何一项缺证据或失败就结束本批，不安装。由真实退出确认结束，核对正常退出及全部已见进程结束。
2. **安装 9、首次启动 39。** 仅在 38 的原生路径及退出通过后，将相同候选原包替换到当前用户 Applications；保留 build 11，核对安装身份和签名。使用既有 UI 验证入口的新测试资料区，通过 CUA 创建两项任务、打开两个本机页面、点击 A 的虚构登录，分别保存消息和不同草稿。网站独立核对登录及共享同站会话；通过同一门控复验安装后的卡片焦点与 Esc／Tab，再回到原登录页，完整保存当前基线。观察安装窗口按钮，真实确认退出，独立检查全部已见进程结束。
3. **同资料区正常冷重开 40。** 沿用同一仍运行的虚构网站及其原会话预期值，不重置网站或伪造已登录状态。比较原两项任务身份、目标、地址、消息、草稿、标签及 active；网站独立确认原会话有效。由 CUA 核对真实网页和独立对话、内容与活动窗口按钮，再真实确认退出、检查全部已见进程及服务结束。未重新进行的真人中文输入法不算本轮证据，原 28／29 的记录仍属于 build 11。

所有原生输入只使用 CUA。测试夹具的 HTTP 放行只影响自有本机页面；记录通道只沿用既有 snapshot、inspect、resize、restart、finish／abort，不新增网页动作旁路、裸 CDP 或任意脚本执行。诊断脚本和应用包、本机资料继续 ignore，公开仅提交脱敏证据。

## 停止、回退及结果解释

锁屏／受保护输入预检拒绝时不消耗启动。修后焦点失败、工具故障或用户状态变化、保存／身份不符、会话丢失、异常弹窗、退出不明、自有进程残留、各阶段或整体时限到，立即保存现场并停止本批，不重建或增加启动。独立计时器只向既有入口写 abort；若超时先于就绪回执，后续回执一到即补发 abort，不交付新 UI 操作。超时独立判为失败，即使应用同时正常退出也不得算阶段通过；超时的候选不能成为安装前置，超时的安装后阶段仍进入有界回退。必要清理仅针对本轮已见自有进程，系统授权与工具服务不触碰。

若尚未替换则保留当前 build 11；复制失败保留 staging 供诊断。已经移出旧包后安装失败，或已安装但后续本轮失败时，在预留收尾时间中先确保自有应用结束，再用安装 10 恢复完整原 build 11，保留失败候选及测试资料，回退命令也受整体截止时间限制。若无法在时限内安全回退，保留原包与现场并明确报告回退未完成，不覆盖记录或再次启动。回退后不再启动，不把回退或人工清理当作候选通过。

通过后也只报告本轮实际覆盖范围：同一安装包的工作区、焦点和正常冷重开。不能用历史跨包结果补齐本轮未运行项目；记录真实 Dock 冷开、正式旧资料凭据连续性等仍有何限制，重新核对事项 01 验收条目后再判断是否完成，不自动开始 02。
