# 01 macOS 原生窗口按钮可见性

## 范围与已有失败

属于事项 01 已确认的基础工作区，不改标签栏设计或关闭主窗口只收起的约定。用户在 build 11 真人核对中看不到红色关闭按钮；候选 13／启动 35 的自身窗口截图仍看不到三色按钮，但 AX 有关闭、全屏、最小化项。真实可见性反馈入口为 CUA 的 `getScreenshot()`，再根据截图确认左上角三色按钮；AX 存在不足以捕获该缺陷，不能用它作通过断言。35 的焦点门控通过与本问题分开，见[原证据](evidence/workspace-01/focus-green-35.json)。

初步已排除窗口整体越界和全屏：32 的固定只读 inspect 表明 bounds 在工作区内且非全屏，按钮位置为 12／18；35 仍是同一布局的普通窗口。该历史几何不替代新候选的视觉检查。

## 假设与单变量候选

1. 标题栏按钮容器在构建／显示过程中没有保持可见。预测：窗口 show 时显式恢复系统按钮可见性、重绘容器，可恢复三色按钮；不改 CSS、位置或内容视图结构。
2. 自定义按钮位置被 AppKit 重新布局或裁切。预测：仅恢复可见性无效，需要另行比较系统默认位置；本批不改位置。
3. 多个原生内容视图遮住标题栏区域。预测：仅恢复可见性无效，按钮像素依然不可见；下一轮应隔离视图层级，不能在当前候选同时调整布局。
4. 工具截图没有呈现原生控件。历史真人看不到的结果使它不能作为唯一解释，但新截图和真实点击仍须分别记录，不以 API 设值替代可见性。

同版 Electron 44.7.2 的 [NativeWindowMac::SetWindowButtonVisibility](https://github.com/electron/electron/blob/v44.7.2/shell/browser/native_window_mac.mm#L1409)会重新绘制按钮容器、取消其隐藏并设置三个标准按钮 hidden 值；构造时 hiddenInset 已显示各按钮，但不等于后续容器必然保持可见。[官方标题栏说明](https://www.electronjs.org/docs/latest/tutorial/custom-title-bar)亦说明该 API 可强制显示／隐藏原生按钮。这仅是可检验机制依据，不断言本机根因已经定位。

候选只在非全屏窗口 show 时调用 `setWindowButtonVisibility(true)`，覆盖初次展示及已有窗口从收起返回；不调整坐标、尺寸、frame、HTML 或 CSS。全屏时跳过，继续交给系统原有全屏处理。不会添加自画红点或新关闭入口，也不改已有 close 事件的收起和退出规则。

正确回归边界是实际 macOS 原生窗口及真实可见性／点击。单个 jsdom、伪造 Electron setter 或源码字符串检查不能证明按钮可见，不新增这类假回归；现有源码检查和真实原生验证保持各自范围。
