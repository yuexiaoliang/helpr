# 07 本机备份与旧备份恢复

实现依据：[07 事项](../../.scratch/helpr-first-release-implementation/issues/07-local-backup-and-restore.md)及用户于 2026-10-23 明确确认的 `backup-v1`（`9bca802`）。本轮实现基点 `27be3b7`。

## 已确认的检查入口

沿用规格的三组公开入口，不增加新的测试分层：记录拥有者的备份／恢复与意图、应用协调服务、UI 与真实网页执行。源码检查使用临时资料、真实 SQLite 和实际备份文件；进程检查经过编译后的记录进程 RPC。模型替身和文件系统故障仅证明相应边界，不当作实际应用或业务能力通过。

目前业务备份为单个 `.helpr-backup` 文件，格式 1、记录格式 6、执行状态模型 1。事务内取得已有任务、执行、动作、请求身份、会话和模型用量的一致逻辑快照；清单包含内联 `records.json` 的字节数和 SHA-256。当前必要证据均在记录中，没有外部素材引用，新增资料类型须随所属事项扩展清单与恢复检查。上限 64 MiB，超过时说明并保留原资料；不截断或显示成功。

模型密钥、认证头、服务配置、浏览器资料、登录会话和临时执行资格均不导出。模型历史通过不含服务配置的历史记录保留，未知用量预留与原请求身份不能因恢复重置。升级至记录格式 6 前在原资料目录保存内部 SQLite 副本；该内部迁移副本与用户选择的业务备份分别处理。

恢复先检查输入，控制拥有者立即撤权、取消在途工作并保存暂停，再由记录拥有者保留当前业务副本并在短事务中导入。相同任务保留当前较新的完整记录，不用旧消息或目标覆盖当前资料；备份中本机没有的任务恢复进来。恢复回执与导入同事务，重送不重复导入。原停止保持，已派发未知事实保留，所有恢复执行先只读核对再逐项选择。只读核对经过既有观察和模型入口，不建立网页动作工作者；停止、原生撤权及版本变化使旧核对失效。

## 源码结果与待做

首次完整 `pnpm check` 通过 87 项正式检查及 25 项旧回归。随后针对“原生已撤权、异步通知未保存”的窗口补反例，先红后绿；最终检查及两轴审阅仍须在实际候选准备前记录。实际包尚未构建或启动，验收复选保持。

## 首批实际包范围

本次用户“可以，开始实现吧”覆盖 07 已确认范围的必要实现与验证；本批限定为本机虚构任务，不使用真实凭据、真实模型或远程业务。沿用全局账本累计计数，不借用 06 完成结论，不扩大全局上限。

- 固定一个新签名候选，最多使用现有上限内的构建 35（仅因明确修正才用预留 36），不替换正式安装。
- 最多两次顺序启动 89／90，同一个受管入口、同一隔离资料和同一虚构网站服务；先正常退出并独立确认本轮 PID／进程组清空，才冷重开。
- 两项虚构任务；最多 12 次本机受控模型、两次本机备注写入、40 条网页交互收件。真实模型、远程写入、安装和故障注入均为 0。不复做已通过的输入法、粘贴、锁屏或休眠。
- 主轮先创建较早备份，再停止／修正 A，在真实 B 网页产生一次备注结果；通过实际设置界面和原生文件选择器恢复，核对 A 的较新意图、当前副本、B 已有结果不重发及仅 A 继续。正常退出后的第二次启动只核对持久状态，0 新模型／效果。
- 由 Codex Computer Use 操作实际应用的备份与恢复、文件选择器、网页及任务按钮，并保存截图；脚本只准备虚构任务、独立接收计数、检查记录和生命周期。公开命令通过不替代界面证据。
- 单次受管轮次最多 20 分钟，启动 30 秒、公开命令 15 秒、原生工具 20 秒、退出 45 秒；文件选择器的人机等待最多 3 分钟。只有一个入口管理实例与子进程；失败、中断或达到上限即停止，不重置计数或自动开新轮。
- 错误、日志、全部 PID／父 PID／进程组保留。先正常退出，必要兜底只处理本轮确认拥有的进程，最多使用全局既有两次清理预留；独立 OS 检查确认全空，不结束 Codex 共享宿主。最终脚本检查后才构建、启动。

构建前全局为 34／8／88／37／16（构建／安装／启动／故障／清理），上限 36／10／90／37／18。源码编译、Node 记录进程和离线测试不计为 Electron 实际启动。若既有上限内不足，先保留具体失败与可核验的修正，再给出精确增量方案；不借本轮实现授权无限运行。
