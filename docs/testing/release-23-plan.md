### 阶段边界与交接规则

- 总阶段固定为P1–P5，不新增P6、24、P1a等前置阶段，不再以某个浏览器细节或一次构建单独命名开发阶段。实现、修复、迁移、源码检查和实包验证都属于对应阶段内的工作。
- 一个阶段可以有多个本地提交；完成一个小修正或一轮验证不触发新聊天。按阶段完成条件验收并提交后，才按既定流程交接下一阶段。确因上下文或执行环境限制必须换聊天时，仍接续同一阶段、同一未完清单及累计失败／用量，不宣布新增阶段或重新开始预算。
- 新发现的问题必须注明阻塞的现有验收条款、最小复现、所属P阶段和修复后检查。已确认范围内直接修复；只有假设、没有实际样本或既有要求依据的兼容性扩展不进入本轮。不能为减少工作而删掉既有范围或换用更简单样本。
- P1–P3按主线推进；某检查依赖登录、工具或用户操作时保留待验，继续可独立工作。进入P4前必须满足其技术门槛。阶段内遇到失败先停止受影响操作、保存现场并清理；没有具体修正或可验证的新假设不得复跑。
- 每轮开始先记录总时限、单步超时和有限尝试次数；同一失败在一个修正批次中最多初次加两次有依据的复跑，仍失败则登记阻碍并转做独立工作。后续恢复必须写明新证据或具体修正，不能靠新聊天重置失败计数。既有远程批次上限始终优先，不能因此增加授权用量。
- 阻碍记录固定包含：所属阶段／AC、已知事实、缺少的能力或外部条件、已尝试及结果、可继续的独立工作、解除条件。无法独立消除的阻碍集中交给用户决定；不能继续生成“先补一个前置”的聊天链。
- 同工作区仍由一个开发聊天负责实现和应用验证。交接标题使用“事项23 P编号/5：阶段名称”，并携带本计划、已完成项、剩余项、提交、候选、证据及累计用量。交接前重新读本节；历史交接文字不再决定下一步。

### P1：打通完整业务链路

**目标：** 将已经分散实现的能力连成可从委托走到结果、并可换输入和冷开复用的完整链路，不再以单一原语通过作为阶段完成。

固定工作包：

1. 收尾当前一般管理页动态结果核对，覆盖缩略列表、唯一结果入口、歧义与错误公开页；最终内容、目标及附件仍独立核验。
2. 完成空白创建与动态目标关联，包括目前没有预置只读身份时的真实目标核对；完整导航后自动续行，未知创建不得重发。所需身份来自普通网页实际证据，不要求网站为测试新增产品专用标识。
3. 连通跨页附件选择、上传、关联回编辑页和就绪核对；额外点击、多链接、受保护下载若实际业务路径需要则在本包内处理，不各开新阶段。

5. 把首次附件发布、换输入、冷复用、Excel成文预览确认和不同后台五类业务接到同一公开入口；修复无人值守跨页对发布约定和定时工作的实际阻碍。

**完成条件：** 五类业务均有完整本机受管实包正例，输入、目标、确认、内容及附件字节能独立核对；流程由实际执行形成，换输入／冷开不靠维护者补流程或代答继续；对应的错误身份、未知结果、节点变化和停止反例通过。基于已有后台证据核对WordPress／Drupal所需结构，缺现场证据时明确列出，不能凭简化夹具宣称真实后台通过。真实站点成功次数只在P4计数。

**输出：** 一份P1整链报告，列五类业务和剩余限制；旧原语报告只作支持证据。任何仍阻塞五类业务的能力缺口都留在P1，不能把P1标完成后转交“新前置”。

### P3：冻结候选并解决工程与性能缺口

**固定工作：** 补齐四项依赖的准确版本许可证正文与来源；从干净已提交产品源码固定工具链、锁文件、资料／状态格式、模型配置与测试输入；完成干净安装到实际包、ASAR／原生依赖／迁移／双层宿主／签名及完整包摘要的闭环；修复反复出现的启动超标并完成06同方法性能复验。
