# 03 执行、停止与继续：开发检查

依据已确认 `execution-v1`（`c3592fb`）及 2026-10-16 用户 implement“开始实现”。本轮正式代码开发，原型资产仍在独立分支；不启动或替换当前产品候选，不调用真实模型或远程业务网页，不追加真人操作。

沿用已确认的两组公开入口：委托、记录与派发；网页执行与结果。以真实临时 SQLite、外部本机接收端及受控模型响应逐条贯通；只替换模型／网页／系统这些外部条件，不 mock 内部记录或调度。观察保存、并行容量、停止、迟到、继续核对、未知结果和修正目标，不为内部方法或 UI 文案写重复测试。真实 Playwright 与安装包控制组合另取得证据，受控端不计作真实理解能力。

先做一个失败用例贯通意图和可靠记录，再接入动作预留、派发和结果；每个循环只跑受影响文件，类型检查贯穿，收尾一次全量源码检查与编译，再做双轴审阅并提交当前分支。已有通过的人工交互沿用，不把旧实验或本轮源码结果充抵实际安装、原生接管或完整恢复验收。

停止、实际效果与完成分别保存。模型每次只提出一个通用动作；先保存一次性预留，临近实际派发复核当前任务、执行与页面归属。旧模型输出、旧回执、记录失败与重开不能直接发起新动作。已送出而未核实的工作先核对，不因缺少成功记录重发。第三项合格工作排队，受影响范围之外的任务继续；目标修正保留明确停止。

## 实现与可复验入口

- `tests/workspace/execution.test.ts`：真实临时 SQLite＋独立 HTTP 接收端。A／B 请求在接收端同时挂起，C 未收到；停止 A 释放容量，B 保持原委托，随后 C 收到。接收端不去重；A 明确继续先观察已有结果，完成后不多送一次。另覆盖旧派发回执迟到、真实目录不可写、未知结果保持核对及继续已提交但回执丢失后的同身份重试。
- `tests/workspace/execution-protocol.test.ts`：独立 Node 子进程经真实私有管道接收协议，核对跨任务／浏览器能力／外部 context／重复及撤销输入没有送达；B 仍能收到输入。工作者接收通道退出只撤销自己，不破坏 B 的连接。这是协议接收端，未启动 Chromium，不证明 Playwright 实际页面可用。
- `tests/workspace/process.test.ts`：编译后的正式记录入口在独立进程读写临时资料，重开后核对停止、取消旧预留、同身份换内容拒绝与版本冲突。现有保存失败检查保留。
- `tests/workspace/model.test.ts`：原模型检查加入规划输出；真实 AI SDK 读取本机受控服务，类型化提议只保存人可读摘要，不把动作 JSON 当对话发出，不调用真实模型。

选用精确 `playwright-core 1.64.0`，沿用此前私有控制实验的版本；新增正式执行工作者仍须自己的实际包证据。已核对该版本类型和实现中的 `connectOverCDP(ConnectOverCDPTransport, { noDefaults: true })`，避免裸监听端口以及默认浏览器设置修改。依据：[官方 API](https://playwright.dev/docs/api/class-browsertype#browser-type-connect-over-cdp)、[官方 transport 用例](https://github.com/microsoft/playwright/blob/main/tests/library/chromium/connect-over-cdp.spec.ts)。协议转接按当前版本实际需求限制能力，升级须复验。
