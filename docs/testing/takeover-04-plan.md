# 04 原生接管：实现与核对

2026-10-16，用户确认 `takeover-v1`（`b3d6e31`）及事项 04 所列范围，并要求按此实现。沿用已确认的三组公开入口，当前先验证“委托、记录与派发”和“网页工作区与执行”，不为新内部辅助函数建立测试套件。

## 实现次序与范围

1. 接管先在当前执行路径阻断，随后在独立记录进程保存暂停原因；保留用户明确停止，重新识别不自行继续。
2. AppKit 所属线程的本窗口局部事件识别在交付网页前撤销本任务资格；未知归属撤销窗口内资格。独立对话及宿主界面不属于网页输入，不读取键盘字符或剪贴板内容。
3. 网页控制与实际模型发送的最后入口检查同一份临时资格。原生侧与控制拥有者通过本机 `mmap` 和 `flock` 短临界区排定资格撤销与单个发送的次序，不持锁等待数据库或回执。它不是第二个业务记录拥有者，旧门文件不能恢复执行。
4. 页面／frame 导航、弹窗、视图丢失与控制失效撤销旧资格。新页面和重新识别只更新归属，明确继续才保存新执行资格、核对当前现场。

正式原生模块使用 Node-API 8、Objective-C++、node-gyp `13.1.0`，固定 Apple Silicon／macOS 14 部署条件，构建时记录 SDK 与源码哈希。测试工具的辅助功能和屏幕权限不成为产品权限；没有全局事件监听、裸调试端口或任意脚本入口。参考 [Electron 原生窗口句柄](https://www.electronjs.org/docs/latest/api/browser-window#wingetnativewindowhandle)与 [Apple 局部事件监视](https://developer.apple.com/documentation/appkit/nsevent/addlocalmonitorforevents(matching:handler:))，实际组合仍须独立核对。

## 已取得的开发证据

- 通过真实 SQLite 和外部本机 HTTP 接收端，复现尚无接管入口的失败后实现：A 接管立即阻断，暂停保存回执迟到时 B 仍能接收；继续 A 先核对已生效的效果，不重复发送。
- 通过同一公开入口核对归属未知、B 已停止、普通调度刷新、修正目标与明确继续；未知不被记录为两项均已接管。这一检查不含真实页面重新绑定。
- 原生资格模块在另一个真实 Node 进程撤销 A，刻意不送控制通知；私有协议接收端最初仍收到 A 旧输入，补齐实际管道临界检查后只收到 B 输入。使用真实原生模块和私有进程管道，不以最终 UI 状态代替此边界。未启动 Chromium，故不充抵原生 AppKit 或实际安装包因果证据。
