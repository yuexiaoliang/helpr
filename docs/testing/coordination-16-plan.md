# 事项 16 隔离检查安排

2026-11-07 接续事项 15。本项在原统一记录和执行入口增加实际 Session／账号／目标关系、共享登录参与及目标占用。真实模型和 WordPress 前置仍未验收；本安排只使用隔离资料、本机虚构账号、替代模型及临时网站，不消耗真实模型或写入远程业务。

先执行定向状态、持久化、保存失败与迟到回执检查，再执行 `pnpm check`。实际包从新候选 `coordination-16` 开始，固定本机开发签名，不替换正式安装。两次实际失败依次定位到规划旧观察和登录核对版本拒绝；原记录保留，修正后候选为 `coordination-16-login`，实际入口为 `pnpm validate:workspace --fixture --candidate=coordination-16-login --coordination`。

每轮总时限 5 分钟；网站读取 5 秒、观察及会话能力 8 秒、动作原有 16 秒截止，场景等待至多 30 秒；模型装置最多 80 次、本机网站最多 12 次写入。一次轮次最多两次正常启动，用于正常运行和冷开。登录核对仅对明确的 `RECORD_VERSION_CONFLICT` 且原问题仍有效时模拟一次重新点击，并单独记录拒绝与新版本；未知回执不重送。其它脚本失败即退出受影响轮次，保留错误、日志、PID／父进程／进程组；仅在明确修正或新假设后复跑。跨事项用量继续累积，旧次数上限不作为审批门。

实际包案例：

1. 两个相同路径、不同稳定记录的真实页面均收到写入请求后再释放服务器回执，核对实际重叠、独立结果与同一账号归属。
2. 两个任务操作同一记录，第二项等待第一项；前项完成后重新读取，仍要改写时提出取舍，回答前不覆盖；本任务明确回答后再执行。
3. 两项相关工作观察原账号后，让网站会话过期。只显示一个登录入口，停止一项后入口仍可用。切换另一虚构账号时保持原任务不写；切回原账号并明确核对后仅符合条件的任务继续。
4. 正常退出、OS 确认旧自有进程清空后冷开；重新配置仅在进程内有效的虚构模型 key，再处理新的独立记录。原停止保持，原进程和旧会话代次不复活。

网站独立读取结果、请求收件和只读 SQLite 分开记录；脚本不注入任务关系、资源、流程或确认状态。网页模型装置只是确定性替代品，不证明真实模型理解和实际后台权限识别。不同站点不受共享登录影响、同目标未知效果和中断后占用保留另有定向源码检查；未取得对应实包或真实站点组合时保留待验。

Computer Use 清单 10 秒超时，本轮没有原生窗口查看或点击证据。连接失败只影响其依赖条目；真人登录、系统授权、输入法与焦点继续集中待验。
