# 23：POST/303请求链归属和自动续行

接续14b33ac，仍为事项23，整体验收0/15。实现独立CDP主文档POST→303→GET请求链；首跳只接受303，随后同站GET可经301/302/303/307/308，最多8跳。相同requestId、loaderId、frameId和独立session贯穿请求、最终2xx响应、主frame提交和加载完成；额外文档请求、脚本导航、错误提交、跨站、片段、保留POST的首跳均拒绝。只存请求地址、方法和状态，不保存正文、Cookie或响应内容。

宿主每次start/redirect继续即时撤权并通知保存暂停，另保留动作导航ID、target、代次、URL和该次撤权前后epoch。控制侧同样保留与暂停requestId关联的撤权回执。恢复要求网络每跳和宿主事件一一匹配，并且所有宿主/控制回执排序后从原派发epoch连续且每次恰好+1；读取当前epoch不作为基线。其它输入、停止、未知导航、能力变化、回执缺口或重叠均拒绝。新目标和完整字段仍先两次稳定核对并保存，再复核原会话、指纹、同target和恰好下一代，可靠保存检查点之后才allow。旧链接守卫和旧直接POST历史保持。

格式30接续29，迁移先备份workspace-before-form-chain-23-*，旧记录不补造链。源码检查覆盖链/宿主/原生回执、保存竞争、停止、会话、冷开和备份。协议依据：[Chromium Network](https://chromedevtools.github.io/devtools-protocol/tot/Network/#event-requestWillBeSent)及[Electron导航事件](https://www.electronjs.org/docs/latest/api/web-contents#navigation-events)，结合本机锁定协议声明与实包核对。
