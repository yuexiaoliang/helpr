# 事项 17 隔离检查安排

2026-11-07 接续 16。只用本机虚构模型 key、临时网站、隔离资料与固定签名候选，不调用真实模型或写远程业务。14、15、16 的真实模型／实际后台前置继续保留。

先通过公开执行／记录入口检查控件及条件变化、固定输入与确认、越界提议、未知提交、停止与接管、原子回滚、同父竞争、备份及冷开引用。运行 `pnpm check` 后构建固定候选（最终为 `workflow-repair-17-session`），不替换正式安装。

实包入口：`pnpm validate:workspace --fixture --candidate=workflow-repair-17-session --workflow-repair`。每轮总时限 5 分钟，准备观察至多 8 次／15 秒，单场景至多 60 秒，网站独立读取 5 秒，动作沿用 16 秒截止。替代模型至多 80 次、本机网站至多 15 次写入。每轮最多正常启动两次，用于原运行与完整退出后的冷开。失败保存错误、日志、PID／父进程／进程组，先收束，只有具体修正或新假设才复跑。跨聊天同一受管入口持锁，旧用量和失败不清零。

实际页面案例：A 首次学得流程；B、C 的草稿、全文或发布控件改名，由实际可访问观察触发产品修复。网站等两个不同稳定目标的草稿请求均到达后才回执，独立证明重叠。B、C 都从 A 固定版本执行；B 先完成并采用，C 完成后保留完整过期候选及来源，不覆盖 B。完整退出并核对旧自有进程清空后，D 用 B 的修复版处理新素材，只有委托绑定模型，不调用网页修复模型。

脚本仅通过公开业务入口创建、开始和确认任务；不得写入候选、采用引用、关系或执行资格。网站收件、下载字节、实际公开页、只读 SQLite 和 OS 进程核对分别保留。替代模型是确定性装置，不充抵真实模型学习能力。原生窗口由 Codex Computer Use 查看；连接失败只标记所依赖证据，继续独立检查。

真实模型／WordPress 的变化修复、复杂网页结构重排、同名控件层级消歧、多站点及本人输入仍待对应验证。当前修复支持同一线性路径的定位和观察条件变化，不能增删步骤或更改动作效果；需要改变范围时提出参与。冲突分支需在后续任务从当前采用版重新走通共同变化，不自动拼接，也不要求用户选择技术分支。
