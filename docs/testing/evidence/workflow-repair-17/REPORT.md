## 实现与保证范围

- 每次执行固定完整流程、素材版本、本次目标和确认。实际可访问控件、frame 归属与步骤条件失效时，先受控重读，再进入有记录的修复。模型只提议同一线性路径剩余步骤的定位和观察条件；动作种类、顺序、效果、参数及最终成功规则不变。越界内容／栏目／效果触发参与，重复控件或缺少证据不能盲选。
- 修复、重放和首次探索共用预留、派发、素材与结果核对入口。已派发未知动作不重送；新停止、接管、页面或共享会话变化使旧资格失效。共享会话未重新核对前，连修复起点也不能保存。模型用途 `workflow-repair` 与 `intent-and-inputs`／`web-planning` 分开记录。
- 核实结果后，只从本次实际走通并核对的动作形成候选。唯一记录进程在同一 SQLite 事务中保存结果、素材处理、候选和采用判断。父版本取自执行中固定版本；只有仍等于当前采用版本才采用，冲突候选与来源完整保留，不覆盖当前版，不改变另一项正在执行的版本。
- 只向新任务提供当前可采用版本。冲突分支需要在后续任务从当前采用版重新走通共同变化，再形成新的完整候选；不会拼接未经共同验证的分支，也不要求用户选择技术分支。新输入仍须绑定本次委托并取得有效确认。
- 格式 16 接续 15，迁移前保留原库。修复、候选、采用决定及跨任务来源进入备份和冷开校验；归档不删除其引用。重复核对同一提交不新增候选，旧回执不恢复派发。
