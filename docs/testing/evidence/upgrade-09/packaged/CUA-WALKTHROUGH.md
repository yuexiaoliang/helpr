# 98／99／100实际界面走查整理

本文件根据本聊天Codex Computer Use工具的实际AX和截图返回编写，不是原始AX转储，也不是脚本自行点击产品。`RESULT.json` 和 `public-states.json` 另存独立服务及公开状态依据。没有使用agent-browser、网页DOM脚本或其它浏览器操纵Electron。

## 98：旧版基线

1. 从受管入口就绪的真实旧窗口读取工作区。脚本仅通过公开入口配置本批测试密钥一次、建立两项任务和停止意图；未启用 `--workspace-fixture`。
2. CUA选择A，点击网站“登录本批虚构账号”；真实网页返回“原测试登录仍有效”。Cookie设为7200秒，独立服务截止在夹具创建时固定，建立登录后约118.19分钟有效；B重新打开也认证成功。精确签发与到期时间保留，不把名义两小时代替服务端认证。
3. 在实际模型设置保持密钥栏空白、显示“已受保护保存，留空沿用”，点击“检查连接”，界面返回“服务地址可连接”。服务器记录98携带最初测试密钥。
4. A的初次 `typeText` 仅输入“A”，随后AX点击焦点下的快捷键选中了顶部chrome；依据实际截图改用草稿区域坐标点击及原生粘贴，完整中文进入A。B原中文保持。真实业务备份独立确认两项草稿分别为“原任务A的中文草稿”“原任务B的中文草稿”，意图均 `stopped`。
5. 点击“备份与恢复”→“选择本机位置”，用原生文件选择器定位本批 `selected-backups`，点击“创建本机备份”；实际界面返回“本机备份已完成并通过完整性检查”。随后受管入口核对格式6、任务数、清单摘要，并正常退出、记录库摘要。

## 99：真实换装和准备

1. 本批同一安装位置从真实0.1.0替换到0.2.0，启动后两任务、原中文草稿及停止状态保持。真实网页直接显示原登录有效，未重新登录。
2. “关于与新版”显示当前0.2.0及“先检查，再核对恢复”。点击“检查原资料、凭据与网页控制”，完成后明确说明“本次没有升级前会话依据，不宣称原有效登录延续通过”。这与旧36不具备准备功能一致。
3. 在模型设置留空密钥、点击检查连接，独立服务再次匹配原密钥。没有点击“保存并使用”，配置仍版本1。
4. 本机版本服务切到交互用0.3.0，CUA点击“检查新版”。界面说明该版本仅是本机夹具；没有打开外链或下载。
5. 在B实际网页原生粘贴“网页B待保存的中文文字”，切到A再粘贴“网页A待保存的中文文字”。点击“准备升级”后返回“网页有手动操作尚待核对”，A/B两项分别列出；未出现可退出资格。独立服务器的两项内容哈希均与上述各自预期文字匹配。
6. 经“查看任务A”回网页，点击“保存网页A”，网页返回“已保存1次”；返回应用仅确认A，A的待处理行消失，B仍在。公开状态独立确认只剩B脏现场。
7. 经“查看任务B”确认原中文仍在，真实网页保存B并回到应用确认；重新准备、通过原生目录选择器选隔离位置，可靠备份后显示“已准备好，可以退出”。独立服务器A/B各收到一次中文内容哈希。
8. 点击“取消本次准备，核对后返回工作”，完成后再次出现“准备升级”；任务仍停止。重新准备选择同目录，取得新操作UUID及第二份备份，第一份没有覆盖。
9. CUA点击“退出，准备手动安装”。实际应用退出；独立OS确认15PID／3组为空，退出码0，没有强制清理。

## 100：同版冷重开

1. 同一0.2.0包和原资料重开，网页显示“原测试登录仍有效”“已保存1次”，原任务B中文草稿仍在，停止保持。
2. 应用先要求检查。此时旧保留提示仍出现，是已发现的P2；本轮随后实际检查成功。源码 `ea5cb08` 已修正该陈旧提示，候选37未重新打包。
3. CUA点击基础检查，再进入模型设置留空密钥点击检查连接；独立服务第三次匹配原密钥。原任务事实与98基线完全一致；登录总数仍1，保存效果仍A/B各1。
4. 受管入口正常结束应用，独立OS确认15PID／3组为空；全部夹具服务随后关闭。此轮仅为同版重开，不额外计作跨版成功。
