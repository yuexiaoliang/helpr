## 已实现

「关于与新版」提供准备升级、逐任务处理网页现场、原生目录选择及业务备份、可靠退出、取消准备和启动检查。准备期间统一阻止新的自动派发；原停止、人工接管和待确认保留，不能把升级暂停改成用户停止。任务、草稿、模型配置或网页现场变化使原退出资格失效，重复请求沿用已保存的操作身份及备份。

可靠检查点先完成再关闭网页；网页 `beforeunload` 拦截会取消关闭，失败保留可继续处理的现场。退出复用升级暂停时已撤销的输入资格，避免自身重复阻断使原生epoch变化。关闭后不再执行可能失败的保存步骤。

独立记录进程通过冻结迁移增加升级记录，资料格式由6升为7，状态模型仍为1。迁移前留下旧SQLite副本，业务备份继续接受格式6和7。私有密钥／会话／应用身份摘要不进入业务备份、网页或UI投影。模型原配置通过safeStorage读取后形成摘要，不将重填密钥算作延续。

启动先核对实际应用的darwin／arm64、包标识、有效签名及稳定发布者指定要求，再核对原资料、原凭据及会话摘要和原生能力。失效或缺少依据保持暂停；到期后重新登录单独标记，不称为原会话延续。基础核对通过后，原自动任务仍经已有恢复入口检查网站实际结果，未知结果不直接重发。没有升级前摘要时明确记录 `unrecorded`。
