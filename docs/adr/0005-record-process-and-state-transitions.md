# 独立记录进程计算业务转换，控制拥有者保留即时阻断

SQLite 同步查询、迁移和备份可能阻塞同一进程处理停止。首版将 ADR-0004 的唯一持久记录拥有者放入独立受管进程，采用 better-sqlite3 与 Drizzle；长期控制拥有者继续负责内存执行资格、即时阻断和私有网页连接。相比记录与控制共用进程，这增加通信、背压、提交回执丢失及退出恢复的成本，以隔离数据库停顿并保留停止的响应路径。原生输入组件仍属于网页宿主及其 AppKit 线程。

用户要求首版采用成熟状态库，选择 XState 稳定 5.x 表达通用任务生命周期的层级、并行和合法转换。各任务分别建模，在记录拥有者内按预期版本计算无副作用的转换，校验并提交相关事实与允许的业务命令；不持久化原始 actions、函数或 actor 引用。控制拥有者收到提交回执后仍核对当前资格，界面只订阅投影；网站步骤继续采用运行时流程数据。相比由 RTK／Zustand 组织更新并自行维护转换约束，接受状态图和模型演进的维护成本；纯转换中的计时与异步工作仍由统一执行机制管理。

开始动作先可靠保存，停止先阻断再保存，两者不能混为同一顺序。迟到回执或结果不得解除较新的停止；保存失败不能使内存状态冒充已提交事实，记录不可用时暂停依赖它的自动工作。恢复先核对记录与网页效果，不直接启动快照中会重新发布的 invocation。独立进程本身不证明“先让出再交付用户输入”；正式组合仍须验证实际阻断与网页收件的因果。

2026-10-14，用户分别确认独立记录进程、数据工具和 XState，并在 Q18 选择“整体理解一致，按方案推进（推荐）”，本决定成立。选型确认不等于实际组合验收通过。[评审与备选依据](../../.scratch/helpr-first-release-implementation/engineering-stack-review.md)、[集中方案](../../.scratch/helpr-first-release-implementation/engineering-stack-proposal.md)。
