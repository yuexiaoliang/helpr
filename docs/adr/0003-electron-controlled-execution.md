# 首版采用 Electron 工作区与统一受控的 Playwright 执行

首版在 macOS 上使用 Electron 的真实网页视图及独立任务对话视图，以外部 CDP 连接 Playwright，由 helpr 的统一执行 Interface 管理首次探索、流程重放、修复、停止和继续。网站步骤与规则保存为结构化运行时流程，模型提议也须经过同一执行入口；宿主保留用户网页，每项活跃执行的派发进程独立。此路线同时满足已确认的可见工作区、直接接管和两项并行方向，并有相应受控实验与真人输入依据。

普通 Chromium 加扩展也有页面归属、双页重叠和停止证据，但缺少同等直接人工接管证据，网页内浮窗输入还会进入网站事件观察范围；因此首版集中实现 Electron 路线。Stagehand 未参与关键组合的实测，暂不进入首版关键执行路径。相应代价是维护 macOS 原生输入识别、控制连接和升级兼容，不能由 Electron 本身支持多平台推定接管机制跨平台成立。

用户接受两项明确边界：无法确认窗口内手动输入归属时，说明原因并暂停窗口内两项任务，重新核对后由对应任务的明确继续恢复；核对 helpr 自己的动作、素材、目标和实际结果，但不承诺在发送前拦截网站脚本的所有隐含写入。观察到异常或提交结果不明时停止后续自动动作并核对，不盲目重发。完整组合仍须验收，选择路线不表示所有能力已经实现。依据、替代方案及用户答复见[浏览器承载与流程执行组合](../../.scratch/helpr-first-release/issues/07-browser-runtime-decision.md#answer)。
