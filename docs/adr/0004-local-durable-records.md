# 本机关联记录通过单一拥有者和 SQLite 事务保存

首版以单一持久记录拥有者和一个本机 SQLite 数据库保存任务意图、内容授权依据、动作、定时轮次、素材处理及流程采用等关联事实；素材和大型证据另存为不可变文件。调用方通过统一 Interface 提交带预期版本的变化，数据库只承担短事务，两个独立网页任务仍可并行。这样避免为多份独立 JSON 记录自行构建跨文件提交、重复领取和并发覆盖协议；既有单文件同步和原子替换仍可用于导出或实验资产。

先可靠保存文件再提交引用，先提交关键记录再派发网页动作。数据库事务不包含网页副作用：记录与发送之间、网站已完成与本地记账之间仍有空隙，恢复必须核对实际结果，不能仅因没有成功标志而重发。停止意图、已发生的效果和素材是否已处理分别保留；同一素材在不同约定与目标下不被全局去重。

相应代价是管理本机数据、素材副本、同步配置和升级兼容，并验证保存失败、并发恢复和旧执行失效。存储技术不替代这些证据，进程强杀也不代表机器断电已经验收。具体协议、替代方案及用户选择见[确定执行记录、流程更新与定时恢复的约定](../../.scratch/helpr-first-release/issues/10-durable-execution-contract.md#answer)。

[自动恢复依据实验](../../.scratch/helpr-first-release/issues/23-autonomous-recovery-evidence.md#answer)支持取得目标关联、导航和已核对上传事实后及时保存；不能等整个准备阶段成功才记录。冻结后的新进程可据这些普通记录与运行时规则核对结果，缺少稳定身份和最终派发仍不确定时继续保留未知。该证据不改变存储选择，也不代表完整并发、断电或交付协议已经验收。
