# 首版产品共识

状态：已确认，本轮产品访谈结束。用户确认首版支持最多两项独立任务并行，其余产品共识保持不变。本文是本轮访谈的阅读入口，详细要求以 [产品访谈记录](discovery.md)为准。产品能力尚待实现；已准备并验证的是独立测试后台。

## 产品要解决什么

用户用自然语言委托真实网页工作，并逐渐把一次性的委托变成可重复、可定时执行的能力。系统承担理解目标、选择做法、组织执行和核对结果的工作，减少用户的心智负担；用户无需先学习脚本或流程编排。首版由用户本人进行真实验收。

首次执行由 AI 探索网页并完成任务，形成可复用流程。后续已学会的网页步骤优先由程序执行，理解新委托和处理新素材仍可按需使用 AI。网页变化后，在原目标和发布约定内修复，核对成功后自动记住新做法，并简短告知用户。

产品源码提供通用能力；具体网站步骤、字段映射和任务规则来自运行时形成的流程。不能为通过验收而把 WordPress、某个栏目或某项 Excel 业务写成产品专用实现。

## 用户看到什么，如何参与

| 方面 | 已确定的行为 |
| --- | --- |
| 工作区 | 真实网页为主，对话浮窗用于当前任务交流；标签页提供简洁明确的进度 |
| 多平台委托 | 独立平台任务分别拥有标签页、会话、内容预览和结果，可归入一个任务组；分组只负责整理，不设组级会话或集中审批 |
| 需要参与 | 全局提醒可包含输入或操作组件，用户可以直接处理，也可切到任务页；回答归属对应任务 |
| 内容发布 | 生成内容默认先建议、预览和确认；用户可以明确授权以后按某套要求自动发布，也能修改或撤销约定 |
| 约定范围 | 记住素材范围、目标位置和内容规则；改变目标平台、栏目或内容处理规则时重新确认 |
| 人工接管 | 直接点击或输入网页即接管；仅查看、移动鼠标或切换标签页不接管；明确说“继续”后依据当前页面恢复 |
| 停止与修正 | 明确停止直接生效，不二次确认；之后明确说“继续”，先核对再续做剩余工作，已完成不重发；用户可自然语言修正目标，无需选择技术上的停止类别 |
| 登录 | 用户在真实网页完成首次登录，之后复用登录状态；过期时提示重新登录 |
| 关闭标签页 | 已结束任务直接关闭并保留历史；未完成任务提供“收起任务”和“停止任务”，可按 Esc 返回。收起保留原状态，并从固定活动任务入口找到；关闭或停止本次执行保留已有定时计划 |
| 意外中断 | 重启后恢复记录，对原先自动执行的任务先核对实际页面与结果，再尽量继续；等待参与和已停止的任务保持原状态，无法确定进度时提示用户 |

各任务独立处理失败与结果，不因同属一组而重复发布已完成的平台。所有完成结论都应有实际网页或产出可供核对。

人工输入暂时无法归属到具体任务时，可以暂停该窗口中的两项任务并说明原因；重新核对后，由用户在相应任务明确说“继续”。这是一项异常处理约定，正常的接管、停止与内容确认仍按任务独立处理，另一项已明确停止的任务不会被一起恢复。

首版按委托核对 helpr 自己的操作、素材、目标与实际结果，不承诺在发送前阻止网站脚本的所有隐含写入。已观察到异常或已提交结果不明时，停止后续自动动作并核对，不盲目重发。继续保留新网站自主探索与流程复用，不要求用户逐条批准网络请求；结果正确不能单独证明网站没有产生其它改动。

## 定时执行与多个任务

设定计划时，用自然语言确定执行时间、取材规则和错过执行时间的处理方式。系统提出建议、简短复述并记住每项计划的约定，用户以后仍可自然语言修改。缺少素材或无法确定应选哪份时再请求参与。

到点时打开新的任务标签页，但不切换用户当前所在页。前一轮未完成时，AI 根据实际原因和已有约定判断影响：单篇内容待确认通常不影响新一轮；登录失效会阻碍依赖该登录状态的后续执行。出现新的取舍时，与用户约定如何处理。

约定只取“未处理”素材时，完成事实按约定、目标、素材版本和对应日期／期次等工作含义分别记录。文件未变且工作含义未变时，仅改名或移动不再自动发布到已完成目标；其它目标独立处理，明确要求再发仍可执行。正在等待、已停止或结果不明的同一份工作保留原任务，不因下一轮到点另开一份重做；新合格素材仍遵循已有约定。

首版支持最多两项独立任务同时推进，首次 AI 探索和已学流程复用都支持。由系统自动安排执行，超出容量或可能互相影响的任务排队，用户无需配置并发机制。接管、停止、内容确认与结果仍各自独立，不受相关影响的任务继续。具体机制与验证条件见 [执行与调度设计建议](execution-coordination.md)。

## 首版如何算完成

以下五项均纳入首版，分阶段完成；同时验收上述交互、控制、定时、并行和恢复行为。

1. 从文件夹取得 Excel，通过真实网页上传并发布到指定栏目，下载结果与源文件一致。
2. 更换素材和本次输入后，正确复用已学会的网页操作。
3. 重启 helpr 后仍可复用流程，不依赖上次残留的编辑页面或旧素材。
4. 读取 Excel 内容，生成文章建议，在对应任务中预览确认后发布，事实和数字可核对。
5. 换一套不同结构的后台，允许学习新流程，但无需开发者新增专用业务实现。

验证要分别记录网页步骤复用与理解、内容处理等 AI 调用；修复后的再执行也要能使用已更新的流程。详细标准见 [首版验收范围](acceptance-outline.md)。按表格批量新增或更新后台记录仍是扩展样例；具体社交平台的支持情况以实测为准。

并行交付必须通过两个真实页面同时运行的验证，并覆盖接管或停止其中一项而另一项继续、共享登录冲突和并行中断恢复。仅展示多个“进行中”标签页或轮流执行，不能替代并行证据。

## 运行条件与后续工作

首版先交付本人当前 Apple Silicon / macOS 14.8.3 的 Mac，提供可独立打开的本机应用，要求电脑开机、helpr 保持运行。其它 Mac 环境、正式对外分发及 Windows 等平台取得相应条件与证据后再支持。先使用用户已有的模型 API，在设置中配置服务地址、模型和凭据；任务对话无需选择模型，并保留更换服务的能力。具体接口在接入时核对。

关闭主窗口只收起应用，任务和计划继续运行，可从菜单栏返回；明确退出或 ⌘Q 才结束程序，先停止派发并保存，下次打开按原意图和实际结果核对恢复。首版遵循系统休眠设置，休眠中不承诺按时执行，唤醒后依每项计划已有的错过时间规则处理。

任务历史、素材版本和必要证据默认本机保留，由用户主动清理已结束工作；保留未完成工作所需数据，空间不足时提示并暂停依赖保存的自动工作。提供本机备份，排除模型密钥与网站登录状态，不自动上传云端；恢复旧备份先暂停并核对实际结果，再由用户决定继续哪些任务或计划。

自动检测更新并提醒，默认手动安装，可开启“空闲时自动更新”。等待用户参与不算空闲；自动安装必须能安全关闭现场、避开即将到来的定时工作，先保存并备份。检测不提前下载或安排替换，更新后先检查并按原意图核对恢复。使用约定和待验证条件见[确定本机交付、权限与更新约定](../../.scratch/helpr-first-release/issues/20-local-delivery-and-updates.md#answer)。

用户可自行配置模型服务，配置方式参考现有 AI agent。测试阶段先使用用户提供的 DeepSeek `deepseek-flash`；这不限定正式产品只能使用该提供方或模型。

`home` 只提供测试网站。WordPress 与独立 Drupal 实例均已完成环境的真实网页上传、发布和下载一致性核对，见 [WordPress 测试记录](../testing/validation-backend.md)与 [Drupal 测试记录](../testing/second-validation-backend.md)。测试后台就绪不代表产品能力已通过验收。

技术路线已选定为 Electron 真实网页与独立任务对话、Playwright 网页操作，以及 helpr 自有的统一执行和结构化运行时流程机制。首次探索、复用与修复都经过同一检查与停止入口，Stagehand 暂不进入首版关键执行路径；详见 [ADR-0003](../adr/0003-electron-controlled-execution.md)与[选型结论](../../.scratch/helpr-first-release/issues/07-browser-runtime-decision.md#answer)。

持久化方案已选择本机 SQLite 统一关联记录与独立素材版本，恢复先核对实际结果，已接受的有效确认不会因重启丢弃，并发修复保留各自成果；见[确定执行记录、流程更新与定时恢复的约定](../../.scratch/helpr-first-release/issues/10-durable-execution-contract.md#answer)和 [ADR-0004](../adr/0004-local-durable-records.md)。[持久记录的中断与并发验证](../../.scratch/helpr-first-release/issues/22-durable-record-consistency.md#answer)与[私有控制连接验证](../../.scratch/helpr-first-release/issues/24-private-browser-control.md#answer)已取得本机受控证据；恢复依据自动形成也已取得[限定证据](../../.scratch/helpr-first-release/issues/23-autonomous-recovery-evidence.md#answer)；后续验证应用打包更新，再确定组合验收安排。独立技术实验已取得有限证据，完整产品能力仍须实现并验收。

旧版 flowpolit 只用于参考已核实的功能和界面，本轮需求与架构独立确定。后续沿技术决策地图补足影响规格的约定与证据，再形成实现规格和分阶段任务。
