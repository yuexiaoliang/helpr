# 首版验收范围

状态：以下场景均已确认纳入首版，分阶段完成。本文将 [已确认需求](discovery.md)转成可观察的验收目标，尚未实现，也不代表所有条目已经通过。已完成的只是 [独立测试后台的准备与网页路径验证](../testing/validation-backend.md)。

首版交付平台为 macOS；具体支持的系统版本和硬件范围由交付约定确定。验收使用[已选择的完整技术组合](../../.scratch/helpr-first-release/issues/07-browser-runtime-decision.md#answer)，已有各项技术实验仍分别保留其证据范围，不代替完整产品验收。

## 已确认的场景范围

| 场景 | 需要看到的结果 |
| --- | --- |
| 首次上传并发布 Excel 附件 | 用户通过自然语言委托，系统在真实网页完成工作；发布位置正确，附件可下载，下载内容与源素材一致 |
| 更换输入并复用已学做法 | 同一网站更换素材和标题，并在用户明确指定时改变栏目；使用本次输入完成操作，记录能说明哪些网页步骤直接执行、哪些部分使用了 AI |
| 重启后继续复用 | 已形成的流程在产品重启后仍能找到并正确使用，使用旧素材或依赖上次仍打开的编辑页不能算通过 |
| 读取 Excel 并组织文章 | 按素材和用户要求生成内容建议，在所属任务中预览确认，之后完成网页发布；事实与数字可对照源表格核对 |
| 换一套不同结构的后台 | 使用同一套产品代码理解和完成网页工作，允许在运行时形成新流程；无需开发者补写这个网站的业务执行实现 |

前面三项验证附件发布与流程复用，后两项验证内容处理与跨网站能力。它们共同构成首版完成条件，不能只通过第一条路径就视为首版完成。第二套后台已选用并部署 [Drupal](../testing/second-validation-backend.md)，环境路径核对与技术实验不能替代正式产品验收。

## 已确认行为的验证

- **可见与可控：**真实网页、独立任务对话、标签页进度、直接操作接管、明确继续、停止，以及按状态关闭标签页。
- **停止后继续：**重新查看、登录恢复和程序重启不自行续做；用户明确说“继续”后先核对，只做剩余工作，已完成就告知结果，结果不明不重发。旧回复与旧处理结果仍失效，继续不替代内容确认。
- **参与与发布：**内容默认预览确认；发布约定在其适用范围内复用；全局提醒可直接处理输入，回答只回到对应任务。
- **多个任务：**平台任务分别成页，分组仅用于整理，各自保留进度、会话和结果。首版最多两项独立任务同时自动推进，覆盖首次 AI 探索和流程复用；超出容量或可能互相影响的任务由系统安排等待。接管、停止和确认各自独立，不受影响的任务继续。
- **未知输入归属：**无法确认窗口内手动输入属于哪项任务时，可以说明原因并暂停该窗口中的两项任务；重新核对后，仅恢复用户明确继续的相应任务。未知暂停不被记录为两项均被用户停止或接管，另一项明确停止的意图不会被清除。
- **定时：**按自然语言约定的时间、取材和错过时间处理规则执行；新建后台任务标签页；按实际阻碍与约定处理后续触发。
- **异常与恢复：**网页变化后的处理、登录失效对关联任务的影响、程序意外退出后的结果核对和恢复，以及保持用户已停止或待参与的状态。
- **模型接入：**用户在设置中配置已有模型 API，正常任务对话无需选择模型；服务可以更换，任务和流程不绑定某一家提供方。具体接口与模型能力以接入验证为准。
- **可核对的结果：**完成依据来自目标网页与产出，记录保留结果位置及必要证据，能够区分完成、仍需处理与无法确认的状态。
- **网页写入范围：**helpr 自己的操作、素材、目标与结果按委托核对；已观察到异常或已提交结果不明时停止后续自动动作并核对，不盲目重发。没有观察到异常不等于所有网站隐含写入已被隔离；不把首次发布成功当作这项通用保证，也不新增逐请求批准步骤。

每个行为应通过真实执行中的具体场景验收。部分模拟界面可以帮助验证交互，但不能替代浏览器实际操作、流程复用和结果核对的证据。

## 首版并行的验收条件

两项并行已纳入首版完成条件。以下验证尚未执行；具体实验设计见 [执行与调度设计建议](execution-coordination.md)及 [并行可行性调查](../research/parallel-execution-feasibility.md)。

| 场景 | 必须看到的结果 |
| --- | --- |
| 两项独立任务同时执行 | 两个真实页面在同一段时间各自推进，页面与执行记录能说明工作发生交叠；覆盖首次探索、流程复用及二者组合，不用一项等待一项运行代替 |
| 接管、停止或确认其中一项 | 操作只归属对应任务，不受影响的另一项继续；迟到模型回复、重复提醒回复和已排队动作不能擅自恢复已停止任务或操作其它页面 |
| 登录共享与目标冲突 | 核对登录过期、重新登录和切换账号的影响范围；可能互相影响的工作等待，无关任务继续；同一目标的操作不会因并行互相覆盖 |
| 素材、结果及流程更新 | 同名文件、各项上传下载、内容确认与结果不会串用；按意图共用素材不被错误去重；并发修复同一流程时不丢失或错误覆盖已核对的新做法 |
| 前后台查看 | 用户查看或切换标签页不误触发接管，后台执行不擅自切换当前页；用户仍能核对每项任务的实际网页与进度 |
| 并行中断后恢复 | 两项任务按各自记录和实际网页结果恢复，避免重复发布；已停止、待参与或人工接管的状态不被自动覆盖 |

资源表现与模型 API 限制需要在目标环境测量。首版交付包含两项独立任务可实际并行的证据；技术方案尚未通过验证时，不将该项标为完成。

## 通用性与复用的核对办法

验收从没有预置该项业务流程的状态开始，保留首次探索、运行时形成的流程，以及后续执行记录。后台账号、测试栏目、样本文件和预期结果可以作为测试环境准备；产品执行仍须通过通用能力理解和操作实际网页。

网页步骤重放与其它 AI 工作分别记账。在稳定页面、已确定的操作参数下，验证已学动作能够直接执行；理解新委托、处理新内容等已获允许的模型调用单独记录。固定的失败重试次数或一句“运行成功”都不能单独证明任务已完成。

出现变化后，由证据说明哪些步骤被复用、哪些重新探索、如何核对修复结果。在原任务与发布约定范围内，核对修复成功后自动更新对应流程，并简短告知用户；再次执行应能使用已记住的新做法。修复涉及目标或发布约定改变时，仍需用户确认。

同一素材用于不同任务时分别核对结果。“未处理”的含义应来自用户的取材约定和实际完成记录；等待中的素材与已经完成的素材需要可区分，不能仅凭文件名猜测完成情况。

## 建议的推进顺序

先验证调研中已有证据缺口的关键技术组合，包括真实网页的承载与控制、两个页面同时执行时的目标归属、人工输入识别、独立停止和恢复，以及跨进程重放。随后逐项打通附件发布、换输入复用与重启复用，再加入内容处理及另一套后台；已确认的控制、提醒、定时、并行和恢复行为随相关执行路径逐步验收。

技术实验、交互原型与产品功能的完成状态分别记录。最终支持的平台、任务和操作范围，以实际通过的证据为准。
