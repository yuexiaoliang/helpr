# 验证场景与扩展样例

首版已确认覆盖 Excel 附件发布及换素材、重启后的复用，读取 Excel 后生成并发布文章，以及另一套不同结构的后台。多个任务的独立处理、分组与定时行为也在首版范围内，详见 [首版验收范围](acceptance-outline.md)。表中的批量新增或更新记录仍是扩展样例，不因列在这里就成为首版交付承诺。

| 场景 | 用户期望的结果 | 需要检验的能力 |
| --- | --- | --- |
| 上传并发布 Excel 文件（首条验收） | 指定栏目中出现新内容，并提供原始 Excel 文件下载 | 取材、网页操作、文件上传、结果核对，以及同类任务的流程复用 |
| 读取 Excel 内容后发布文章 | 表格中的信息被组织成可阅读、事实准确的内容并发布 | 理解素材结构、按用户意图选择信息、组织内容，再完成网页任务；默认预览确认，也可按用户明确授权的要求自动发布 |
| 同一素材发布到多个网站 | 用户提出一次目标，在各指定网站得到相应结果；独立平台任务各有标签页，并放入同一个任务组 | 任务拆分与分组、各任务独立会话及内容确认、适配不同网页要求、独立处理失败并分别核对结果 |
| 定时从文件夹取材并发布 | 按约定时间和取材规则选择素材并完成发布 | 设定时通过自然语言确认取材规则，之后自动遵循；检验重复执行，以及错过时间、素材缺失或选择不明确时的处理 |
| 按 Excel 内容新增或更新后台记录（扩展样例） | 表格信息进入目标系统的相应字段和记录 | 根据任务确定字段对应关系、处理多条数据、区分新增和更新、核对实际结果 |
| 将已有目标换到另一套后台执行 | 相同业务目标在不同网页结构中也能完成 | 重新理解目标网页与执行方法，无需开发者为该后台新增专用业务实现 |

## 横向变化

检验流程复用时，应逐步改变素材文件、标题、栏目、表格结构和目标网站，观察系统能否正确区分可复用的做法与需要重新理解的信息。变化不意味着所有场景必须共用同一条流程。

复用验收应分别记录理解委托、处理内容、探索网页和修复网页操作时的 AI 调用，核对已经学会的网页步骤是否能够直接执行。用户已允许理解与内容处理按需使用 AI。

登录失效、必填信息缺失、网页变化、执行中接管、停止和目标修正，是需要在上述场景中讨论和验证的条件；具体行为以访谈确认的规则为准。

## 实现约束

这些样例用于提出和验证产品要求。具体业务规则不能因为出现在验收样例中，就被写死为 helpr 产品源码中的专用功能。相关约束与未决项见 [产品访谈记录](discovery.md)。

微信公众号、小红书等是用户表达目标的实际场景，不代表这些平台已经通过验证。首版通过两套测试后台检验通用能力；具体平台的可用范围仍以真实网页执行证据为准。
