# 08 新版检查与可信下载提醒原型

版本：`version-check-v1`，2026-10-23。来源分支：`codex/version-check-prototype`。

直接双击 `version-check-prototype.html`，不需要安装依赖、服务器或模型设置。全部状态只在内存，刷新即重置。右侧场景切换也会重置；指南可收起。

## 本次要回答的问题

沿用已有 helpr 工作区，后台发现新版或检查失败时，用户能否清楚区分结果、继续任务，并在自己选择的时间查看与打开手动下载入口？

## 拟确认范围

- 关于与新版入口、当前版本与设备信息；手动检查、检查中及成功／失败结果。
- 后台检查只显示非模态提醒与入口标记，不主动切换任务、打开设置或改动任务意图；草稿各自保留。
- 适用新版的说明、来源、架构、系统及资料兼容提示；打开手动下载页与升级准备分别处理。
- 稍后处理在当前会话抑制同一版本的重复提醒，结果继续可查看。
- 拟议频率：启动后后台检查，持续运行每24小时再查；失败不立即循环重试，可手动再查。这里不模拟真实时钟，也不宣称已提供跨重启记忆。
- 正确区分最新、来源版本较早、网络失败、超时、来源无法验证、信息损坏、不适用架构、系统过旧、资料不兼容及下载入口异常。
- 新检查失败时保留上次成功记录，但标明历史，不把它当本次成功；当前入口待重新检查成功后可用。
- 提醒显示失败时仍可在关于与新版查看结果；两项任务独立运行与停止。

## 建议体验

先走“后台发现新版”，观察任务 A 没有被切走；再走“稍后再处理”“网络失败与重试”“旧结果与新失败”“提醒显示失败”。其余场景覆盖信息与兼容异常。也可以在任一任务输入草稿，再查看新版和返回，核对文字保留。

## 模拟与未覆盖

所有版本、服务、网络请求结果、兼容判断和网页任务都是虚构内存状态。`example.invalid` 仅作明确不可用的地址占位，不是已选定的版本基础设施。原型不使用 fetch、外部资源、持久化、真实文件、下载API、安装器、模型或产品进程。

“打开手动下载页”只在演示内显示一个说明卡片，模拟未来在浏览器打开可信入口；没有真实导航或下载。升级准备、保存现场、备份、退出与跨版密钥／登录延续属于09，本版只说明边界。版本说明是示例，不承诺实际0.2.0发布内容。

正式08仍需确定可维护的自用HTTPS来源、实际校验与兼容依据，并以独立服务和实际应用验证请求隐私、无下载副作用、提醒与失败。原型走查不算产品验收，不勾选正式验收条件。

## 本轮浏览器走查边界

- 工具：Codex内置浏览器，同一自有标签页；不启动Electron或agent-browser。
- 开始前核对现有会话与进程；当前没有运行中的helpr或网页验证。
- 本轮交互走查总时限30分钟，单步最多15秒，预览服务启动1次，浏览器标签页1个，必要修正后重载最多2次，失败后的本轮清理最多1次；不重置计数。
- 内容：12个引导场景、自由操作的草稿保留、任务／场景键盘切换、桌面及窄窗口布局、指南收起、检查失败状态。
- 无新增应用构建／安装／启动、模型请求、远程网页写入、故障注入。语法检查仅检查内联脚本可解析，不为原型建立测试套件。
- 预览入口若需本机服务，仅监听127.0.0.1，由独立进程在2小时后到期关闭；交付时明确服务与体验标签页保留。超时或失败只关闭自有标签页和服务，不终止共享浏览器宿主。双击HTML入口不依赖服务。
