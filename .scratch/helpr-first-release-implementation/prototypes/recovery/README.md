# 05 退出、意外退出与冷重开恢复原型

版本：`recovery-v1`。状态：待用户体验与确认。来源分支：`codex/recovery-prototype`。正式事项：[05](../../issues/05-quit-crash-and-cold-recovery.md)。

## 本次要回答的问题

退出和意外中断后，用户能否理解原任务与原意图怎样保留，以及为什么有些任务核对后续做，有些保持停止、接管、待参与或结果不明？本机完成回执与网站实际效果不一致时，是否能理解系统不会从头重做，也不会仅凭“没有成功记录”再次发送？

## 体验

直接双击同目录 `recovery-prototype.html`，不需要安装依赖或启动服务。所有 HTML、样式与脚本都在一个文件内，没有外部资源。浏览器刷新会重置演示；页面里的“退出／重开”只模拟应用生命周期，不会真的关闭浏览器。

也可为了在 Codex 浏览器中体验，临时提供静态预览：

```sh
python3 -m http.server 4318 --bind 127.0.0.1 --directory .scratch/helpr-first-release-implementation/prototypes/recovery
```

地址：`http://127.0.0.1:4318/recovery-prototype.html`。

建议先完成“正常退出”，再体验“已做未记”“结果不明”和“停止接管”。每个标签都会重置为已知初始状态；按绿色按钮逐步演示。结束按钮及“自由操作 → 重置当前场景”可重新体验。

任务标签可以切换 A／B；对话中的“继续”和“停止”只属于当前任务。指南可关闭，关闭后可查看网页、编辑人工文字和使用独立对话。方向键可以切换任务／场景标签。

## 覆盖范围

| 场景 | 演示的行为 |
| --- | --- |
| 正常退出 | 先阻止新派发，再保存、结束自有进程；退出不批量更改用户意图。冷重开先隔离、读记录、核对，只做剩余工作。 |
| 已做未记 | 网站已有唯一匹配效果而本机未记完成；只读核实后补记，不重复写入。 |
| 结果不明 | 已送出请求可在应用退出后完成；结果无法可靠关联时保持未知。明确继续不能绕过未知，另一项独立工作可续做。 |
| 停止接管 | 两项不同意图跨重开保留；查看、登录不恢复，明确继续只作用于对应任务。原型保留示例文字。 |
| 等待参与 | 待补信息和输入归属未知分别保留；登录不是参与回复，核对页面归属也不等于明确继续。 |
| 新的停止 | 核对在途时的新停止优先，旧观察只留历史。自由操作支持目标变化使旧核对失效。 |
| 预留边界 | 单纯预留和可信未派发检查点分别处理；没有网站结果不等于证明未派发。 |
| 记录故障 | 记录进程退出阻止依赖保存的派发；停止已提交而回执丢失时仍保留可靠停止，服务恢复不放行旧回执。 |
| 资料异常 | 不兼容时保留原资料；自由操作可切换记录缺失、损坏、素材不符。无法重建网页现场时保留原任务，另一项独立推进。 |
| 退出竞争 | 保存失败不声称安全退出；旧进程未隔离前不恢复写操作；竞争启动只保留一个拥有者。 |

自由操作还可演示：停止先阻断但保存失败时显示未保存；若此时再意外退出，不保证跨重开保留未提交意图，并保持恢复暂停。切换资料条件或“存储恢复”等按钮是原型夹具，不代表真实资料能够一键修好。

## 原型与产品的边界

- 沿用无竖线的任务标签、网页主体、悬停卡片及独立任务对话。指南、状态表、分步恢复按钮、故障条件和网站实际计数都是原型工具，正式产品自动处理保存、清理、隔离和恢复核对，不要求用户逐步执行技术操作。
- 纯状态模块为单一脚本中的 `RecoveryDemo`；界面只发送动作与显示结果。所有资料、意图、网页效果、进程和提交回执都在内存中模拟。模拟“已保存”不证明真实持久化，模拟“已结束”不证明实际进程树清理。
- 通过一次通用的备注写入演示 01–04 已有窄网页操作的恢复语义。没有连接正式产品、真实模型、网站、SQLite、XState、凭据、操作系统输入或进程控制。
- 网站结果、目标身份和检查点均为事先构造的演示数据，不是产品自动形成恢复依据的证据。真实上传、草稿与发布的自主恢复仍由 12–14 扩展。
- 文字跨模拟重开保留只供体验规则；真实网页现场可重建性、实际输入法、退出／强杀／断电、锁屏／休眠及进程清理，均未在本原型中验收。06 和后续事项范围保留。
- 本次没有新增真实运行、构建、安装、故障注入或模型消耗；浏览器只在本机打开这份单文件原型。
