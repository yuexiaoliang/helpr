# helpr 核心工作区原型

状态：当前为 `foundation-v3`，在已确认的 `foundation-v2` 交互与布局（`c9a7a98`）上，采用用户选定的第 4 款标签栏并移除小竖线。继续保留 A 的顶部标签、B 式悬停卡片、单目标创建与独立对话。B／C 留作历史比较，尚未进入正式实现。

问题：保留“网页是主要工作区，每项任务有独立对话浮窗”的方向，哪种任务导航、浮窗布局和进度呈现最容易使用？

依据：[首版规格](../../../helpr-first-release/spec.md)、[01 可安装的双任务真实工作区](../../issues/01-installable-task-workspace.md)，并沿用接管、停止、继续和任务关闭的既有决定。

仓库还没有可供嵌入的正式产品页面，故采用 prototype 技能的独立页面分支。原型位于实现事项旁，保存在 `codex/core-workspace-prototype`；使用模拟内容，不接模型、真实账号或远程写入。

## 打开方式

在本原型工作副本的仓库根目录运行：

```sh
npm run prototype:workspace
```

打开 [基础工作区完整体验](http://127.0.0.1:4317/foundation.html)，或 [A／B／C 布局比较](http://127.0.0.1:4317/?variant=A)。无需安装依赖。服务只监听本机，并且只提供原型所需的 HTML、CSS、JavaScript；端口可通过 `PROTOTYPE_PORT` 指定。

也可直接打开同目录的 `index.html`。所有任务状态只在页面内存中；刷新会重置模拟任务，URL 中的方案选择会保留。

## 已确认交互：只说目标，紧凑工作区

版本：`foundation-v2`，2026-10-14。文件仍是 [foundation.html](foundation.html)，可直接双击或从预览服务打开。v1 来源提交 `c575cdb`，其体验记录保留在下方；当前页面以本节为准。

用户本轮明确要求：创建任务只输入目标，网站地址由 AI 分析，允许目标里没写地址或写错；界面尽量让出网页空间，恢复提示悬浮，标签并入 header。已按这个方向修订，并继续保留每项独立对话及悬停卡片，不加入被移除的下箭头或卡片底部切换按钮。

建议体验：

1. 点击顶部 ＋，面板只有一个“任务目标”输入框。可试“只说网站名称”：根据演示中的曾用网站线索，直接确定网站并打开模拟登录页。
2. 再点 ＋，试“没说发到哪里”：目标已成为一项任务，AI 在该任务的对话里补问。可以点候选网站，或直接输入“团队资料库”等回答；不会另开一张必填网址表单或复制任务。
3. 试“网址有个笔误”：展示原输入、可能的正确网站与依据；确认后才使用候选地址，也可否定或说另一个网站。
4. 右下角“原型场景”可进入退出重开和失败现场。恢复提示约 5.5 秒后自动收起，也可手动关闭；提示不挤动网页、不夺走对话输入焦点。

顶部为 54 像素的标签栏（含新建与任务入口）和 34 像素的网址栏。常态保存情况缩为图标，细节可悬停查看。原型场景及演示记录收到右下角面板，底部仅留一行简短引导。保存失败的悬浮提示保留到重试成功，不按恢复成功提示的时限消失。

AI 分析使用两个预置网站与明确示例，并非真正调用模型、搜索或核对互联网。默认演示 AI 可用；“AI 未配置”场景仅保留目标，明确等待配置，从原型面板“启用模拟 AI”后再继续。模型设置本身不在本轮原型内。网站识别和补问属于委托入口的交互提案，关联 02／03 的后续能力，不代表 01 已交付 AI 或网页执行。

本轮浏览器走查：

- 新建面板只有一个输入控件；不填网址也能用网站名称进入模拟登录。两个任务各自显示网站和对话。
- 未写网站时停在原任务补问，输入“就是团队资料库”后使用该网站，任务身份与数量不变。
- 笔误候选确认前没有打开网站；可以否定候选。回复“是团队资料库，不是北山官网”后采用团队资料库，没有把句首“是”误当成同意旧候选。
- 1440 × 960 下，网页区域从 y=123 开始、高 794 像素；恢复提示出现、自动消失前后均相同。输入草稿及光标保持。
- 800 × 900 下无横向溢出，两个标签、补问候选、对话输入和网页登录按钮可见。桌面与窄窗口截图已查看。
- AI 未配置时未伪造网站分析，启用模拟 AI 后才补问；保存失败时新目标仍在输入框，模拟退出被阻止，恢复保存后原消息仍在。
- 浏览器未报告页面脚本错误。走查中一次等待命令误用了浏览器状态文件参数，导致测试浏览器回到空白页；重新打开独立测试页后完成检查，没有把该次失败计作产品行为通过。

2026-10-14，用户明确“原型确认，是否需要进行 UI 设计？”。`foundation-v2` 在本节覆盖范围内的交互与布局已确认，可作为对应真实实现的设计依据；后续视觉细化的方式继续讨论。该确认不扩展为全部实现事项的原型批准，也不作为真实产品验收证据。以下 v1／布局方案记录用于保留演进依据。

## 历史版本 v1：基础工作区完整体验

版本：`foundation-v1`，2026-10-14。独立文件 [foundation.html](foundation.html) 内含所有样式与状态逻辑，也可以直接双击打开。沿用已讨论的 A 布局，本轮检查“第一次打开、新建任务、手动登录、退出重开及失败处理是否顺手”，不再增加布局方案。

建议从头体验：

1. 点击“创建第一个任务”，填入 WordPress 示例，创建后在网页点击“登录（模拟）”。演示账号已填好，无需输入任何真实密码。
2. 在任务 A 的浮窗记下一条要求。AI 未配置，界面只保存内容，不生成模型回复或启动自动操作。
3. 新建任务 B，使用 Drupal 示例并登录；各自写下不同要求，在标签之间切换。悬停只看准备情况，点击标签才切换；保留键盘 ↓ 查看、Esc 返回和 Enter 切换。
4. 修改任务 A 网页标题并点“保存网站草稿”。对话的未发送草稿也可以保留着，观察它与网站草稿的区别。
5. 点右上角“退出 helpr”，再点“重新打开 helpr”。检查原任务、各自对话与输入草稿、网站登录和网站已保存的内容。网页未保存的编辑会先提示，明确放弃后才退出。
6. 用底部场景按钮直接进入失败现场。故障仍存在时重试不会假装成功；点“恢复模拟条件”后，再回工作区重试。

| 原型场景 | 重点观察 |
| --- | --- |
| 从头体验 | 空工作区、未配置 AI、新建任务、网页登录、独立对话 |
| 退出后重开 | 找回原身份和记录，不重复建任务，不自动执行 |
| 网页打不开 | A 的网页失败、任务对话仍在，B 可继续手动操作 |
| 登录保护失败 | 暂不打开依赖受保护登录信息的网页，对话保留；重试前可恢复模拟条件 |
| 保存失败 | 新消息留在窗口，新任务表单不丢；恢复保存前不完成模拟退出 |
| 登录过期 | 只要求过期的网站重新登录，其它网站及任务记录保留 |

本轮待确认的提案包括：新建任务时先填写目标与网站；同一网站 origin 的任务共用演示登录、不同 origin 分开；退出前提示网页未保存内容；各失败状态的说明、重试与保留路径。原型将浏览器登录、helpr 记录、网站草稿分别建模，以便比较行为。

底部“查看本次演示记录”显示固定任务身份、网站、登录、保存状态及最近变化。切换场景会重置演示数据。所有“保存”和“退出重开”都只发生在页面内存中，刷新会清空；没有真正访问网站、读取凭据、调用模型或进行远程写入。此原型不证明安装、冷启动、SQLite、Cookie 保护、私有控制连接及宿主隔离已经实现或通过验收。

2026-10-14 浏览器走查记录：

- 从空工作区建立 A／B 并登录，写入不同对话，保留 B 的未发送草稿。退出重开后任务身份、对话、草稿和仍有效登录保留；A 的网站标题恢复为“十月经营周报 · 工作区恢复核对”。
- B 未保存的网页标题触发退出提示；返回可继续编辑，明确放弃后重开恢复网站已保存版本，B 的对话草稿仍在。
- A 网页失败时重试仍失败，B 可编辑；恢复条件并重试 A 后回到网站已保存草稿。登录保护失败同样先保留现场，再经重试恢复会话。
- 保存失败时新建任务未创建，目标和地址仍保留；退出被阻止。恢复并重试后，未保存消息随原任务重开；原表单也能再次创建，同一 origin 复用演示登录。
- A 登录过期不影响 B；A 再次登录、收起后重新查看保留原记录。悬停及键盘查看卡片均不切换网页，Enter 才切换；卡片没有下箭头入口或“查看任务”底栏。
- 检查 1440 × 960 及 800 × 900 的工作区、登录和失败页面；无横向溢出，对话输入和登录按钮可见。浏览器无页面脚本错误，脚本语法检查通过。未为一次性原型建立测试套件。

## 三个方案

| 方案 | 导航与进度 | 浮窗布局 | 待用户比较的取舍 |
| --- | --- | --- | --- |
| [A 标签工作台](http://127.0.0.1:4317/?variant=A) | 顶部任务标签，悬停显示 B 式进度卡片 | 当前任务的右下角浮窗 | 保留熟悉的标签切换；可临时查看另一项进度，不常驻占用网页宽度 |
| [B 任务侧栏](http://127.0.0.1:4317/?variant=B) | 左侧同时显示两项状态、进度与步骤 | 当前网页左下角浮窗，靠近任务导航 | 更容易持续观察两项进度；侧栏占用横向空间 |
| [C 双页并排](http://127.0.0.1:4317/?variant=C) | 两个网页各自有标题、状态和进度 | 两个独立浮窗，默认简短，可展开或最小化 | 可以同时观察两页；每页宽度较小，窄窗口改为上下排列 |

底部箭头、A／B／C 按钮或键盘左右方向键可以切换，URL 的 `variant` 参数同步变化。本轮任务、手动文字、对话草稿和各自结果保持不变。输入框内的方向键仍用于编辑。

## 体验一轮

1. 点顶部“开始演示”，在委托面板点“开始两项任务”。
2. 查看两项模拟任务的进度。任务 A 在发布前会留出时间，等你体验接管。
3. 点击任务 A 网页中的标题，修改几个字。A 显示“已让出操作”，B 保持自己的状态并继续推进。
4. 在 A 的对话里输入“继续”并发送，或点“核对并继续”。页面会先核对，再保留修改后的文字接着推进。
5. 等待完成，或点顶部“快进到结果”；分别点各任务的“查看结果”。

随时切换方案即可比较相同现场，无需为每个方案重做。顶部“使用说明”可重新查看步骤，“重置演示”返回起点。

## 其它可操作位置

- A 的标签悬停约 280 毫秒后展开卡片，显示状态、步骤、模拟进度和最近动态；查看不切换网页，也不暂停任务。移入卡片可继续阅读，离开后约 180 毫秒收起。
- 点击标签切换当前网页。卡片只展示信息，不再提供标签下箭头或底部“查看任务”入口。键盘聚焦标签后按 ↓ 可查看进度，Esc 收起并返回原标签，Enter 仍用于切换任务。
- 两项任务的对话、输入草稿、停止与结果分别归属各自任务；聊天和切换不会触发网页接管。
- 浮窗可最小化后展开，C 还可展开完整对话记录。
- 未完成任务的“×”提供收起或停止；Esc 和点击提示外侧返回。已结束任务关闭后，从活动与历史重新查看。
- 收起继续保留原状态；重新查看已停止任务不自动恢复。明确继续才核对后续做。
- 网页“预览”展示当前输入；最终“查看结果”展示模拟完成时保留的内容。
- “快进到结果”只推进正在执行的模拟任务，接管、停止和核对中的任务不会被它恢复。

## 原型范围

这一页演示的是界面和交互。两个后台、文件、进度、回复与结果均为预置模拟，表格没有实际读写或上传，不代表真实网站控制、模型理解、macOS 原生输入、持久化或发布已经通过。

模拟网站是为了比较有内容的工作区；这些网站专用展示不能进入正式产品执行逻辑。正式实现仍遵守统一执行入口与运行时形成流程的规格。

原型不引入保存机制、外部服务或生产构建；图标素材随源码保存在本地。方案切换栏只存在于布局比较页。选定后将设计决定补入相关实现事项，正式界面按产品要求实现，原型代码保留在独立分支作为来源。

## A 与 B 的组合决定

2026-10-13，用户反馈：“方案 A 更符合人们的使用习惯”，建议标签 hover 时显示 B 侧栏式任务卡片。据此以 A 为主要导航方向，保留每项任务独立对话；B 的状态、步骤和最近动态按需展示。悬停时长、尺寸、固定打开方式为本次原型提出的细节，尚不视为用户逐项确认。

这次补充走查：

- 当前网页保持 A 时悬停 B：B 的卡片进度到 16%，A 到 18%，两项都仍在执行；点击卡片“查看任务 B”后才切换到 B。
- 鼠标可移入卡片阅读，移出后收起；小箭头可固定打开，点击外部或 Esc 可关闭。键盘 ↓ 与 Enter 可打开，Esc 返回对应的进度按钮。
- A 在 51% 接管时，卡片同步显示“已让出操作”，B 仍执行。继续后结果保留“十月经营周报 · 悬停核对”；完成卡片四步均显示已完成。
- 切换至 B 布局后没有遗留浮层，手动标题保留。1440 × 960 和 800 × 900 已截图查看，卡片在窗口内、页面无横向溢出；浏览器未报告脚本错误。
