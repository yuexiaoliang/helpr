# helpr 核心工作区原型

状态：用户认为 A 更符合使用习惯，选择以顶部标签为主，并提出悬停标签显示 B 式任务卡片。组合已加入 A，具体交互细节待体验；B／C 保留作为比较。

问题：保留“网页是主要工作区，每项任务有独立对话浮窗”的方向，哪种任务导航、浮窗布局和进度呈现最容易使用？

依据：[首版规格](../../../helpr-first-release/spec.md)、[01 可安装的双任务真实工作区](../../issues/01-installable-task-workspace.md)，并沿用接管、停止、继续和任务关闭的既有决定。

仓库还没有可供嵌入的正式产品页面，故采用 prototype 技能的独立页面分支。原型位于实现事项旁，保存在 `codex/core-workspace-prototype`；使用模拟内容，不接模型、真实账号或远程写入。

## 打开方式

在本原型工作副本的仓库根目录运行：

```sh
npm run prototype:workspace
```

打开 [原型入口](http://127.0.0.1:4317/?variant=A)。无需安装依赖。服务只监听本机，并且只提供这一页所需的 HTML、CSS、JavaScript；端口可通过 `PROTOTYPE_PORT` 指定。

也可直接打开同目录的 `index.html`。所有任务状态只在页面内存中；刷新会重置模拟任务，URL 中的方案选择会保留。

## 三个方案

| 方案 | 导航与进度 | 浮窗布局 | 待用户比较的取舍 |
| --- | --- | --- | --- |
| [A 标签工作台](http://127.0.0.1:4317/?variant=A) | 顶部任务标签，悬停显示 B 式进度卡片 | 当前任务的右下角浮窗 | 保留熟悉的标签切换；可临时查看另一项进度，不常驻占用网页宽度 |
| [B 任务侧栏](http://127.0.0.1:4317/?variant=B) | 左侧同时显示两项状态、进度与步骤 | 当前网页左下角浮窗，靠近任务导航 | 更容易持续观察两项进度；侧栏占用横向空间 |
| [C 双页并排](http://127.0.0.1:4317/?variant=C) | 两个网页各自有标题、状态和进度 | 两个独立浮窗，默认简短，可展开或最小化 | 可以同时观察两页；每页宽度较小，窄窗口改为上下排列 |

底部箭头、A／B／C 按钮或键盘左右方向键可以切换，URL 的 `variant` 参数同步变化。本轮任务、手动文字、对话草稿和各自结果保持不变。输入框内的方向键仍用于编辑。

## 体验一轮

1. 点顶部“开始演示”，在委托面板点“开始两项任务”。
2. 查看两项模拟任务的进度。任务 A 在发布前会留出时间，等你体验接管。
3. 点击任务 A 网页中的标题，修改几个字。A 显示“已让出操作”，B 保持自己的状态并继续推进。
4. 在 A 的对话里输入“继续”并发送，或点“核对并继续”。页面会先核对，再保留修改后的文字接着推进。
5. 等待完成，或点顶部“快进到结果”；分别点各任务的“查看结果”。

随时切换方案即可比较相同现场，无需为每个方案重做。顶部“使用说明”可重新查看步骤，“重置演示”返回起点。

## 其它可操作位置

- A 的标签悬停约 280 毫秒后展开卡片，显示状态、步骤、模拟进度和最近动态；查看不切换网页，也不暂停任务。移入卡片可继续阅读，离开后约 180 毫秒收起。
- 点击标签切换当前网页。卡片只展示信息，不再提供标签下箭头或底部“查看任务”入口。键盘聚焦标签后按 ↓ 可查看进度，Esc 收起并返回原标签，Enter 仍用于切换任务。
- 两项任务的对话、输入草稿、停止与结果分别归属各自任务；聊天和切换不会触发网页接管。
- 浮窗可最小化后展开，C 还可展开完整对话记录。
- 未完成任务的“×”提供收起或停止；Esc 和点击提示外侧返回。已结束任务关闭后，从活动与历史重新查看。
- 收起继续保留原状态；重新查看已停止任务不自动恢复。明确继续才核对后续做。
- 网页“预览”展示当前输入；最终“查看结果”展示模拟完成时保留的内容。
- “快进到结果”只推进正在执行的模拟任务，接管、停止和核对中的任务不会被它恢复。

## 原型范围

这一页演示的是界面和交互。两个后台、文件、进度、回复与结果均为预置模拟，表格没有实际读写或上传，不代表真实网站控制、模型理解、macOS 原生输入、持久化或发布已经通过。

模拟网站是为了比较有内容的工作区；这些网站专用展示不能进入正式产品执行逻辑。正式实现仍遵守统一执行入口与运行时形成流程的规格。

原型不引入保存机制、第三方资源或生产构建；方案切换栏只存在于本原型。选定后将设计决定补入相关实现事项，正式界面按产品要求实现，原型代码保留在独立分支作为来源。

## A 与 B 的组合决定

2026-10-13，用户反馈：“方案 A 更符合人们的使用习惯”，建议标签 hover 时显示 B 侧栏式任务卡片。据此以 A 为主要导航方向，保留每项任务独立对话；B 的状态、步骤和最近动态按需展示。悬停时长、尺寸、固定打开方式为本次原型提出的细节，尚不视为用户逐项确认。

这次补充走查：

- 当前网页保持 A 时悬停 B：B 的卡片进度到 16%，A 到 18%，两项都仍在执行；点击卡片“查看任务 B”后才切换到 B。
- 鼠标可移入卡片阅读，移出后收起；小箭头可固定打开，点击外部或 Esc 可关闭。键盘 ↓ 与 Enter 可打开，Esc 返回对应的进度按钮。
- A 在 51% 接管时，卡片同步显示“已让出操作”，B 仍执行。继续后结果保留“十月经营周报 · 悬停核对”；完成卡片四步均显示已完成。
- 切换至 B 布局后没有遗留浮层，手动标题保留。1440 × 960 和 800 × 900 已截图查看，卡片在窗口内、页面无横向溢出；浏览器未报告脚本错误。
