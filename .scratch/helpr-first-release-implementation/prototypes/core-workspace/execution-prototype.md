# 03 网页执行、停止与继续原型

版本：`execution-v1`。状态：待用户确认。来源分支：`codex/core-workspace-prototype`。

体验问题：两项任务同时推进、第三项排队时，能否理解进度与任务归属；停止一项后，如何呈现已送出的迟到结果；明确继续时，先核对再做剩余部分是否自然且清楚。

## 打开

直接双击同目录 `execution-prototype.html`，无依赖、无外部资源，也可以从仓库根运行：

```sh
node .scratch/helpr-first-release-implementation/prototypes/core-workspace/serve.mjs
```

打开 `http://127.0.0.1:4317/execution-prototype.html`。沿用已确认的第 4 款无分隔线标签栏、真实网页为主的布局与独立任务浮窗；标签悬停显示任务卡片，没有下箭头或“查看任务”重复按钮。这里的网页是内存模拟。

## 覆盖范围

| 演练 | 体验内容 |
| --- | --- |
| 并行与排队 | A、B 同时推进，C 排队；停止 A 后 B 继续，C 获得空出的容量 |
| 停止与迟到 | 停止立即约束新操作；网站先前收到的操作仍可完成，结果如实保留；旧模型建议不能恢复执行 |
| 继续剩余工作 | 明确继续先核对，只处理剩余记录；已完成时再次继续只告知结果，不重发 |
| 提交结果不明 | 结果不明时暂停后续；继续不能变成盲目重发，网站提供明确结果后再核对 |
| 保存失败 | 阻断新操作，停止立即生效并注明尚未保存；恢复保存后保留停止，其他任务先核对 |
| 修正目标 | 将 A 缩为前两条，保留先前效果，核对新范围；旧建议不覆盖新要求 |

点击左下角“体验指南与演练”，按当前绿色步骤逐项体验；切换场景会重置至已知起点。也可在所属对话说“开始”“停止”“继续”“查看结果”，分别保留草稿和对话。指南中的“推进一次”同时推动两项运行任务，没有自动计时器；自由条件可以延迟回执、模拟结果不明和保存失败。指南和完整状态面板仅是原型工具，不进入产品常驻界面。

## 模拟边界

所有站点、目标理解、动作保存、网页效果、调度、迟到和故障均由纯内存转换模拟，不调用真实模型、网页或产品桥接，不使用数据库／Keychain，不持久化。对话仅识别示例意图，目标修正仅演示收窄 A 为前两条，不代表通用自然语言能力。正式实现不能复制这些网站规则或正确结果。

04 的直接网页点击／中文输入／粘贴接管、10 的复杂参与组件、后续发布确认与业务上传不在本版本中。没有浏览器跨进程控制、原生停止次序、崩溃恢复或真实并行证据。本原型不改变已确认产品规则，也不解除 01／02 尚余完整验收条件。

## Spec

初次审阅 2 项：停止后修正目标会自行恢复；“正常”选项错误地恢复保存而未解除回执延迟。均已修正，定向复核遗留 0 项。停止后修改目标仅更新要求，保持停止，明确继续才核对续做；“恢复正常回执”只解除延迟，不改变停止、保存或未知结果。

修后通过页面实际按钮定向复查：停止后改目标再推进两轮，A 仍停止且只送出原先 1 次；明确继续后最终只送出 2 次、完成前两条。延迟回执恢复后可收到原结果，已未知的提交恢复回执速度后仍待核对且没有新增发送。浏览器未报告脚本错误。未追加测试套件或真实运行。
