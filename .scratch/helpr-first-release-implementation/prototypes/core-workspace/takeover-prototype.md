# 04 直接接管与页面归属原型

版本：`takeover-v1`。状态：已确认（2026-10-16，用户同意按本版及所列范围实现）。来源分支：`codex/core-workspace-prototype`，确认的最终源码 `b3d6e31`。

体验问题：用户直接操作 A 的网页时，是否理解 A 已让出而 B 独立继续；页面变化或输入归属未知时，能否明确区分“重新认出页面”与“用户明确继续”，并保留人工文字和已有停止。

先按左下角指南中的绿色按钮完成“点击接管”，再切换其它演练。关闭指南可以直接点击网页按钮、编辑备注、粘贴补充资料、切换任务和输入对话。演示没有自动计时器，“推进一次”使所有符合条件的任务各前进一步；任务等待、停止或归属不明时保持暂停。

## 覆盖范围

| 演练 | 体验规则 |
| --- | --- |
| 点击接管 | A 的网页点击让 A 让出，B 继续；明确继续先核对，再推进，保留人工确认 |
| 查看与对话 | 查看、悬停、切标签、鼠标移动及普通任务对话不接管网页；任务对话分别保留 |
| 输入与粘贴 | 键入或粘贴触发本项让出，明确继续后保留两处文字，不覆盖人工编辑 |
| 页面变化 | 刷新、导航、页面内表单、弹窗、视图重建的旧归属失效；旧建议拒绝，重新识别仍等待明确继续 |
| 归属不明 | 暂停窗口内两项并说明未知，不伪造两项均被用户接管；只继续明确指定的任务，原有停止保持 |
| 能力不可用 | 暂停自动操作并保留现场，原因明确；能力恢复不自行继续，不要求改变系统安全设置 |

界面可查看每项任务的意图、当前状态、页面版本与绑定、自动进度、人工确认、备注、粘贴内容和旧建议拒绝次数。最近事件只展示模拟次序，不能证明真实实现满足“先阻断，再交付输入”。

## 模拟边界

全部网页、点击、输入识别、任务进度、资格撤销、重新绑定、旧建议和模型回复都是纯内存模拟。网页备注可以直接输入，但不构成真人中文输入法或原生粘贴验收；指南中的两种文字明确是填入示例。页面内表单、所属弹窗与重建仅用同一个面板表示状态变化，没有创建真实 frame 或新窗口。

页面变化样例沿用同一条模拟记录，备注由模拟网站保留；不能据此承诺任意网站导航后都能保留 DOM 输入，也不会把“保留人工内容”解释为向不同页面自动填入旧备注。

没有真实模型、Playwright、私有控制连接、AppKit／Node-API 组件、数据库、钥匙串、权限申请、保存失败或崩溃恢复。未证明原生事件与执行阻断的因果、页面／frame／popup 真实映射、IPC 延迟或慢盘竞争、隐藏窗口运行。正式实现不能采用演示中直接指定的任务身份或按固定文字回复。

03 的限定实际试用已通过，但剩余完整交付条件保留。本轮只提前准备 04 原型，没有解除事项依赖，没有进入正式原生接管实现。真正中文输入法、⌘V 与系统生命周期核对仍集中到 06。
