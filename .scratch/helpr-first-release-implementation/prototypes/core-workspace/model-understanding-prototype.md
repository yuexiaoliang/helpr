问题：沿用已确认的网页主工作区及独立任务对话，配置一次模型后，网页问答、更换服务、逐任务停止回复和失败处理是否容易理解？本轮采用行为原型，不再比较或重做已确认的标签栏布局。

## 打开

本工作副本根目录运行 `npm run prototype:workspace`，打开 [模型配置与网页理解](http://127.0.0.1:4317/model-understanding-prototype.html)。也可双击同目录的 `model-understanding-prototype.html`；页面自包含，不依赖安装、构建或外网。

来源分支：`codex/core-workspace-prototype`。一次性原型不进入正式 `app/`；当前实现分支只记录入口与待确认范围。

## 建议体验

先在右上角打开“模型设置”，点“填入演示配置”，再点“模拟连接测试”和“保存并使用”。在右下角任务 A 的对话询问“这页是什么”。模型配置为全局设置，对话和回复归属各自任务；正常提问不重复选择模型。

左下角“体验指南”有五个场景；选择后依次点场景内按钮，也可收起指南自由操作。需要已知初始状态的场景在第一步重置本场景，界面明确标注，全部重置也有顶栏入口。

| 场景 | 可体验的提案 |
| --- | --- |
| 首次使用 | 服务协议、地址、模型及演示密钥；模拟连接与保存；配置前保留问题草稿，配置后使用 |
| 两项任务 | A／B 独立问题、逐段回复、草稿和用量；切换不改变归属，停止 A 的回复时 B 继续 |
| 更换服务 | 新设置只影响之后的请求，正在回复的请求保留原服务和页面依据；不重建任务 |
| 失败与重发 | 凭据、连接、超时、格式、能力、凭据不可用与上限的不同提示；不自动重试，用户修正后重新发送 |
| 网页已变化 | 回复标明页面样本、观察时间、所用模型；网页变化后旧回复保留原依据，重新询问才使用新页面 |

界面中的“停止回复”仅取消本次模型回复，不等同于停止整项任务或人工接管；后续执行控制仍归对应事项。请求发出后的取消或错误显示消耗未知；未发出的保护失败和上限拦截单独说明。观察与理解不产生点击、上传、保存或发布；询问“能帮我发布吗”会说明当前边界。

## 模拟与确认边界

全部网页、回复、连接、凭据保护、消耗和设置保存均为内存演示。API 密钥框只可填固定演示值，不接收真实密钥。页面没有网络请求、数据库、本机存储或产品接口；刷新全部重置。演示发送次数与 token 数不是实际消耗。

本轮已确认的是上述设置、所属任务问答、取消、服务更换、错误及页面依据的交互。真实服务的兼容性、模型质量、Keychain、持久记账与重启预算、受控页面观察和进程隔离仍须后续实现及按受影响范围验证；本原型不证明这些能力通过。事项 01 既有人工卡片结论不重测；尚未完成的整体交付检查不在本轮追加。
