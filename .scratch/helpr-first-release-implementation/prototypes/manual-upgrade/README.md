# 09 手动升级原型

版本：`manual-upgrade-v2`，2026-10-27。来源分支：`codex/manual-upgrade-prototype`。初稿 `manual-upgrade-v1` 仍由 `2747a99` 保留。

本版回答：手动换版前如何保留现场、保存备份，换版后如何检查原资料、原密钥、有效登录与控制能力，并按每项任务的原意图恢复？沿用已有工作区、任务标签和所属对话，重点体验状态变化。

## 打开与体验

直接双击同目录的 [manual-upgrade-prototype.html](manual-upgrade-prototype.html)，不安装依赖、不启动服务。文件自包含，没有外部图片、字体或脚本。浏览器刷新会重置全部内存状态。

建议先走「正常手动升级」，再走「网页文字未保存」「备份失败与重试」「结果不明，不重发」。右侧每个场景都从固定状态重置；点击引导中的下一步，或直接操作左侧拟议产品界面。可展开「自由操作与模拟结果」，尝试不满足条件的操作。右侧状态与事件记录用于核对变化，也可收起指南体验工作区。

左侧的下载说明、退出、替换、系统授权和网页都只发生在演示里；按钮上的「模拟」不会执行对应系统操作。正常路径下 A 原来自动运行，B 已停止并有未发送草稿。升级完成后只有符合条件的 A 可续做，B 保持停止。

## 19 个场景

| 场景 | 观察点 |
| --- | --- |
| 正常手动升级 | 查看08已有入口、模拟用户手动取包、准备、保存、备份、退出、手动换版、检查和逐任务恢复。 |
| 网页文字未保存 | 不能直接报告可退出；回到 B 处理文字，重新保存备份。换版后接管及文字保留。 |
| 网站正在处理 | 阻止新操作仍不代表在途动作没有发生；核对到实际完成后补记，不重发。 |
| 备份失败与重试 | 空间不足时不能准备成功；原资料保留，明确处理后重试。 |
| 保存失败，返回工作 | 取消准备后先核对当前现场，仍使用旧版；原停止不改变。 |
| 准备中又说停止 | 新停止使已有准备记录和备份过时；重新保存，旧回执不能恢复资格。 |
| 仍需内容确认 | 安装意图和「继续」不能代替所属任务的内容确认。 |
| 结果不明，不重发 | 启动检查通过后仍单独核对实际结果；明确继续也不盲目提交。 |
| 取消系统授权 | 这里只模拟取消结果；资料保留，相关工作暂停，可主动重试。 |
| 原密钥或登录缺失 | 不能以重新输入密钥或重新登录，把原延续失败改判通过。 |
| 登录确已到期 | 与丢失仍有效登录分开；用户重新登录后继续核对，不清除原停止或确认条件。 |
| 迁移失败与中断 | 原资料副本保留；失败、中断和更换旧程序均不自动恢复网页操作。 |
| 来源、架构与兼容 | 来源或架构不符时保留原版本；不能进入安装准备。 |
| 暂不安装，重开旧版 | 准备退出后也可不安装；重开原版本无需跨版迁移，但仍需检查及结果核对。 |
| 外部强行换版 | 没有准备记录也须按中断恢复，不能伪造备份已完成或把未知效果视为未发生。 |
| 新版检查未通过 | 原生输入、控制、实际安装版本或包来源不符时不恢复。 |
| 资料格式不兼容 | 不支持当前资料或任务状态格式时保留原资料，不迁移或续跑。 |
| 两项网页都有文字 | A、B 的未保存文字分别核对，处理 A 不能清除 B 的未保存现场；两项接管保持。 |
| 重新检查保留新停止 | 新停止或检查条件变化使旧结果核对失效；重新核对后原停止仍保留。 |

自由操作还可演练新草稿、手动接管与准备竞争。准备后修改草稿或网页文字会使已保存快照与备份失效，必须重新保存；仅查看任务不改变其执行意图。输入时保留原输入节点，避免每个字符重建输入框。

## 覆盖与边界

拟作为09实现依据的范围：升级准备与新操作协调、现场处理、任务与草稿保存、业务资料备份、主动退出、由用户手动换版、启动兼容／迁移检查、原密钥及原有效登录检查、原生输入与控制检查、逐任务结果核对、原停止／接管／确认条件保留，以及上述失败、取消和中断交互。

备份只含业务资料。密钥和网站登录从独立的原存储延续，不从业务备份恢复。所有身份、结果和检查结论均为模拟；没有真实密钥、登录、数据库、文件操作、网络请求、包下载、安装、系统弹窗、进程退出或网页写入。

本版不覆盖20的真实定时竞争、23的最终完整资料矩阵，不包含自动下载安装、自动回退资料或正式对外签名。真实两版安装、原密钥／有效登录延续、真实迁移与中断、原生输入、控制和退出清理，必须在正式实现后取证。

当前确认状态：**待用户体验并明确确认**。用户「那就开始做吧」承接的是制作09原型的建议；随后对是否正式实现的询问明确选择「先继续完善和检查原型」。本轮按该选择修正模拟逻辑，未开始正式实现。

## v2 修正与离线状态演练

在不驱动浏览器的情况下，单次 Node 进程只加载原型的纯状态模块与声明式场景数据，没有加载或执行页面的 DOM 渲染。结果见 [STATE-REHEARSAL.json](STATE-REHEARSAL.json)。没有新增测试套件，也没有把这次运行当作网页或产品验收。

保留 v1 同一组动作的反例和 v2 结果：

| 反例 | v1 的实际模拟结果 | v2 的实际模拟结果 |
| --- | --- | --- |
| A、B 都编辑，仅核对 A 后尝试保存备份 | 错误进入可退出状态 | B 仍待处理，准备被阻止 |
| 已核对网站结果后又停止 A，直接完成启动 | 沿用旧核对完成启动 | 旧核对失效，重新核对前不放行 |
| 登录已到期，再按凭据检查 | 错误改成原有效登录并完成 | 保持到期与暂停，需用户重新登录 |
| 原密钥缺失，再模拟取消授权及重新检查 | 缺失被覆盖后错误完成 | 缺失事实保持，不能放行 |
| 实际安装包不符，再核对资料并尝试恢复 | 包不符被资料检查覆盖后错误完成 | 安装包单独核对，失败保持 |
| 资料已知不兼容，再按资料检查 | 不兼容被覆盖后错误完成 | 不兼容事实保持，不能迁移或恢复 |

19 个引导场景的276个离线动作均到达预期末态；正常、取消及受阻场景的末态分别记录，**受阻场景保持暂停才是预期结果**。这只证明这些给定动作的纯状态输出，不证明点击、输入、事件绑定、视觉布局、任意动作排列或真实升级已通过。

本版在启动核对中单列「实际安装包」状态，后续资料或凭据检查不能覆盖已发现的错误来源／版本／架构。网页文字按任务分别跟踪。保存或检查条件变化后，旧准备副本或旧结果核对不会继续充当当前依据。

## 本轮检查与阻碍

- 两段内联脚本的 `node --check` 通过；静态 HTML 没有重复的固定 `id`，没有外部资源依赖。v2具体哈希和记录见 [CHECKS.json](CHECKS.json)，v1原始记录保留在 [CHECKS-v1.json](CHECKS-v1.json)。语法与结构检查没有执行界面；纯状态运行另由上述离线演练记录。
- 计划以一个内置浏览器标签进行一轮走查，上限25分钟、单步8秒、最多两次修后刷新。预检查未发现 helpr 应用或本项目验证进程在运行，本聊天内置浏览器最初无标签。
- 第一次打开单文件入口即被浏览器 URL 安全策略拒绝：`file:` 不在允许的 `http:`／`https:` 协议中；结果明确禁止 workaround、间接执行、其它浏览器表面或策略绕行。本轮停止页面操作，没有改用本机HTTP、其它浏览器、自动化工具或底层协议绕路。
- 失败创建的自有 `about:blank` 已关闭，最终内置浏览器标签列表为空。没有启动应用或本机预览服务，不新增产品构建、安装、模型或故障额度。
- 用户要求继续后，内置浏览器工具重新可用；本轮只读核对会话及官方故障／本机开发说明，没有重试被拒绝的文件导航。原来的拒绝原因没有解除，未驱动用户自行打开的Chrome标签，也未创建新浏览器验证会话或增加原轮次预算。

原型独立保留；主工作区仅登记来源、范围和待确认状态，不合入模拟代码，不勾选09的任何正式验收条目。
