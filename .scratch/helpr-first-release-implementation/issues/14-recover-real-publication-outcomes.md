# 14: 提交中断后的真实网站结果核对

Status: ready-for-agent
Blocked by: 13
Spec: [首版实现规格](../../helpr-first-release/spec.md)
Index: [实现事项总览](../README.md)
User stories: 25、27、48–51、53

**What to build:** 上传、草稿或发布中断后，产品凭正常执行形成的记录找到实际目标；已完成就返回结果，可信未派发位置才续做，无法确认则保持未知并说明。

## 前置交付与范围

把 05 的保守恢复扩展为 13 实际业务的自主核对。使用冻结后的流程与普通记录在冷进程中恢复，不让维护者事后补网站身份、选择器或正确结论。

前置事项：[13 首次附件发布并保存学到的流程](13-first-publication-and-learned-workflow.md)。

## Acceptance criteria

- [ ] 产品在正常准备和执行中形成目标、已知上传、检查点及结果规则；新进程仅凭这些记录与实际网页恢复，不读取测试代理的内部答案。
- [ ] 明确在派发前、准备完成后、提交与保存结果之间等位置中断，独立记下实际到达和产生效果，不能只以产品自己的成功标志作答案。
- [ ] 唯一关联的实际结果匹配素材和内容时记已完成并返回位置，即使本机缺少回执也不再次提交。
- [ ] 只有可信未派发检查点、旧操作来源失效且当前网页／输入／授权匹配时，才经同一执行入口续做剩余步骤。
- [ ] 可能已派发、稳定身份缺失或关联不唯一时仅做可独立确认的只读核对；同名结果、错误素材、正文替换、超时及暂时未找到均不批准重发。
- [ ] 两项活动任务分别恢复；停止、待参与、人工接管、未知输入暂停及有效确认保留，核对中新的停止优先。
- [ ] 旧工作者迟到结果只更新所属历史观察，不恢复旧资格或覆盖当前事实；独立事实确认已完成也不批准下一步。
- [ ] 缺失／损坏记录、不兼容规则和素材变化保持原证据并暂停，不把素材释放成从未处理；恢复失败和已发生效果同时保留。
- [ ] 真实模型、网页写入、故障注入及恢复次数预先界定，失败及清理均留证；强杀与断电、只读核对与真实写入分别记账。

## 验证方式

通过实际应用重开、恢复和网页执行公开入口，使用与候选分离的站点计数和文件内容核验。至少包含两个活动任务和不同暂停意图的组合，不用意图夹具冒充真人输入。

遵循[总览中的跨事项完成约定](../README.md#跨事项完成约定)，从正式产品公开入口验证并保留独立证据；不把旧实验通过当作本项完成。真实运行沿用具体案例的有效授权与累计消耗上限，本事项的发布本身不启动新实验。
