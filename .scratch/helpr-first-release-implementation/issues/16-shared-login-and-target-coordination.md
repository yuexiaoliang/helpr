# 16: 共享登录与同一目标的执行协调

Status: ready-for-agent
Blocked by: 13
Spec: [首版实现规格](../../helpr-first-release/spec.md)
Index: [实现事项总览](../README.md)
User stories: 3、35–36、45、51

**What to build:** 共享登录失效或账号改变时，相关任务等待并复用处理入口，无关任务继续；可能改同一网站目标的两项工作得到协调，不会互相覆盖。

## 前置交付与范围

将已有资源资格检查接到真实登录和业务目标。按实际会话与运行时取得的目标身份判断影响，不把两个标签页、同组或同名文件当成隔离或共享的证明。

前置事项：[13 首次附件发布并保存学到的流程](13-first-publication-and-learned-workflow.md)。

## Acceptance criteria

- [ ] 记录实际网站、登录上下文、账号和稳定目标的关联，派发前使用当前关系核对；新观察使关系改变时使相应旧资格失效。
- [ ] 同一登录过期只阻塞依赖它的工作，复用相关参与入口，无关任务仍可推进；不为每个任务重复要求处理同一登录障碍。
- [ ] 用户重新登录或切换账号后重新观察受影响任务与目标权限，不把登录成功当成解除停止、接管或内容确认。
- [ ] 可能相互覆盖的同一目标操作协调执行，检查资源取得、释放、竞争和过期拥有者；不同可独立目标仍可实际重叠推进。
- [ ] 资源归属或冲突影响未知时相关工作等待并解释，不猜测独立后继续写，也不长期暂停所有无关任务。
- [ ] 共享阻碍解除后的积压按任务、已有约定和实际结果分别判断，新的取舍才请求参与，不隐含补发全部积压。
- [ ] 停止 A、A 待确认以及 A 接管时 B 按自身条件处理，旧共享资源回调不恢复 A 的资格。
- [ ] 在实际业务路径核对登录过期、恢复、切换账号、同一目标竞争、无关工作继续和中断后重新领取；独立站点证据确认没有覆盖或串账号。

## 验证方式

经过工作区会话观察、委托／资源领取和网页执行入口，使用真实测试账号及站点目标验证影响范围。测试工具提供环境变化，不向产品提供应选择哪个目标的答案。

遵循[总览中的跨事项完成约定](../README.md#跨事项完成约定)，从正式产品公开入口验证并保留独立证据；不把旧实验通过当作本项完成。真实运行沿用具体案例的有效授权与累计消耗上限，本事项的发布本身不启动新实验。
