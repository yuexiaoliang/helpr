# 04: 直接接管网页与页面变化后的归属

Status: ready-for-agent
Blocked by: 03
Spec: [首版实现规格](../../helpr-first-release/spec.md)
Index: [实现事项总览](../README.md)

User stories: 21–25、35、51、65

**What to build:** 用户直接操作某项任务的网页时，系统立即让出该项操作并保留文字，另一项继续；页面变化后重新确认归属，只有明确继续才核对续做。

## 前置交付与范围

把 macOS 本应用窗口的原生输入接到 03 的资格撤销与记录路径。交付实现和自动行为证据；真正中文输入法、⌘V 与组合真人证据集中由 06 取得，不把工具输入算真人样本。

前置事项：[03 两项网页任务执行、停止与继续](03-parallel-execution-stop-and-continue.md)。

原生输入组件采用网页宿主 AppKit 线程中的 Objective-C++／Node-API 路线，由 node-gyp 构建并固定源码、SDK、架构和部署条件。记录保存位于独立进程，不能让同步落盘或异步通知排队成为先阻断输入路径的前提；具体次序须由实际组合取得证据。

## Acceptance criteria

- [ ] 网页点击、键盘和粘贴入口分别触发对应任务让出；先阻止新的自动动作再处理人工输入，已送出效果仍按真实结果记录。
- [ ] 仅查看、切换标签页、移动鼠标和独立对话输入不触发网页接管；自动化输入与真人输入来源可区分。
- [ ] 接管后页面及文字保留，B 的独立任务继续；明确继续 A 时核对当前页与实际结果，仅续做剩余工作，不覆盖人工文字。
- [ ] 宿主管理页面、frame、弹窗和任务映射；刷新、导航、新窗口、视图重建、控制失效及焦点变化后旧绑定失效，重核前不能沿用旧资格。
- [ ] 无法确定窗口内输入归属时，说明原因并暂停两项，记录为未知；不伪造两项均被用户接管或停止，另一项原有停止不被清除。
- [ ] 未知解除后仍只恢复用户明确继续的相应任务；重新绑定、查看或页面加载成功不等于继续指令。
- [ ] 本机能力或权限不可用时有明确反馈，测试工具的全局权限不自动变成产品要求，不要求关闭系统安全设置。
- [ ] 自动检查涵盖原生事件归属、焦点、排队动作与输入竞争、旧绑定拒绝及文字保留，并记录 06 尚需真人核对的具体案例和就绪条件。
- [ ] 独立对照原生识别、真实执行阻断、网页首次收件及每次自动派发／效果，在 IPC 延迟、慢盘、旧动作及页面变化竞争下仍满足先阻断后交付人工输入；最终显示 A 停、B 继续不能单独判为次序通过。

## 验证方式

经实际工作区事件与网页执行入口核对，观察两个真实页面和独立效果记录，关联各阶段因果而非只比较最终状态；采集记录不得自行改变被测阻断顺序。任何合成中文输入只说明协议处理，不能标记真人输入法或粘贴验收通过。原生模块必须在已选工具链生成的实际包中验证，不以宿主 Node 或旧实验通过代替。

遵循[总览中的跨事项完成约定](../README.md#跨事项完成约定)，从正式产品公开入口验证并保留独立证据；不把旧实验通过当作本项完成。真实运行沿用具体案例的有效授权与累计消耗上限，本事项的发布本身不启动新实验。
