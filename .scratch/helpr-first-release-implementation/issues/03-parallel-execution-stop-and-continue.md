# 03: 两项网页任务执行、停止与继续

Status: ready-for-agent
Blocked by: 02
Spec: [首版实现规格](../../helpr-first-release/spec.md)
Index: [实现事项总览](../README.md)
User stories: 4、25–28、33–34、48、52、53、65

**What to build:** 用户委托窄而明确的网页操作，两项独立任务真正重叠推进，第三项合格任务排队；停止 A 后 B 继续，明确继续 A 时先核对，仅处理剩余工作。

## 前置交付与范围

把 02 的提议连接到统一网页执行入口，并贯通本机记录、任务状态和实际效果。用受控真实页面缩小任务，不将夹具步骤或预期答案写入产品。人工原生输入由 04 接入，复杂参与组件由 10 完善。

前置事项：[02 配置模型并在所属任务理解网页](02-model-settings-and-page-understanding.md)。

## Acceptance criteria

- [ ] 自然语言目标和本次输入形成带任务归属的动作提议；通用受控原语执行真实页面操作，不允许任意宿主脚本或多步旁路。
- [ ] 最多两项合格任务获得自动推进容量，实际动作存在交叠；第三项排队，容量释放后仍检查其余条件，等待参与不长期占容量。
- [ ] 派发前统一核对任务、执行、页面、会话、输入、授权、流程与资源版本；可靠保存一次性预留后才派发，同一预留不可被通信重试消费两次。
- [ ] 临近派发再次核对最新停止和资格变化；用户明确停止立即阻断新模型动作与网页派发，无二次确认，另一独立任务继续。
- [ ] 停止、修正目标和再次继续有可靠次序；继续获得新资格并先核对，不复活旧执行、旧回调或旧参与请求。
- [ ] 实际结果与用户意图分别记录；停止后已经送出的效果可被如实登记，但不能解锁后续动作。已完成不重发，无法确认的结果保持未知。
- [ ] 公开修改请求按身份和内容去重，同身份换内容拒绝，过时预期版本返回冲突；唯一拥有者、执行容量和资源领取在同一次事务中保持一致。
- [ ] 关键保存失败时不派发；停止先在当前进程生效，停止记录未落盘须明确说明，不宣称未保存意图跨崩溃必然保留。
- [ ] 在应用显示进度、排队、停止、待核对和结果；独立接收端记录实际收到与完成的动作，不替产品去重，也不读取产品数据库取得答案。

## 验证方式

通过委托、记录与派发，以及网页执行两组公开入口验证。受控服务让两项动作真实交叠，并在停止、预留、返回和保存之间插入明确竞争；核对独立效果计数与另一个进程读取的记录。

遵循[总览中的跨事项完成约定](../README.md#跨事项完成约定)，从正式产品公开入口验证并保留独立证据；不把旧实验通过当作本项完成。真实运行沿用具体案例的有效授权与累计消耗上限，本事项的发布本身不启动新实验。
