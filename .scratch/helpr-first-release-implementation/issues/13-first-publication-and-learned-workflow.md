**What to build:** 从自然语言委托贯通 WordPress 附件发布，用户得到正确栏目下可下载的真实结果；系统从实际执行保存完整、可验证的运行时流程。

## 前置交付与范围

扩展 12 的准备到最终提交、独立结果核对及流程形成。产品自主组织学习，不能把既有实验中维护者校准的流程当作正式首次探索；不同输入复用由 15 验证。

前置事项：[12 固定素材版本并准备真实上传](12-material-version-and-upload-preparation.md)。

XState 管理通用任务生命周期，学得的网站步骤仍保存为运行时流程数据；AI SDK 只提出候选动作，经统一资格与派发入口执行。流程、结果及采用事实由独立记录进程提交，不因采用成熟状态库或 SDK 引入网站专用状态图、预置业务步骤或自主执行旁路。

## Acceptance criteria

- [ ] 从没有预置该业务流程的验收资料区开始，以同一通用产品完成选材、准备、发布和核对；用户能看到所属任务进度与实际结果入口。
- [x] 发布前核对本次素材、附件、目标、内容及有效委托／确认；系统生成的发布文字遵循预览确认，旧确认或另一任务的确认不可使用。
- [x] 统一入口对最终提交可靠预留并临近派发检查新停止和输入，发生目标不符、异常或最终结果不明时停止后续自动动作。
- [ ] 独立核对真实目标和发布状态，下载附件与固定素材逐字节一致；同时记录多余结果、已观察到的越界和实际上传／草稿／发布次数。
- [x] 核实结果、相应素材处理事实和本次进度在同一次提交中保存；动作返回、步骤后条件、业务结果和观察覆盖分别记录。
- [ ] 学习得到的流程包含适用条件、参数与来源绑定、步骤前后条件、结果规则、恢复入口及版本／父版本／证据；仅将真实验证支持的部分标为可复用。
- [ ] 流程候选及采用引用可靠保存，执行固定版本；流程说明做法但不能授予发布权限，也不能使用任意脚本绕过控制。
- [x] 辅助截图失败不覆盖已核实结果或触发重做；关键结果证据缺失保持未知，准备目标和上传事实足以供后续恢复入口使用。
- [x] 新增流程、素材处理及结果引用进入备份、迁移和重开读取检查；保留首条业务的真实失败与修正，不凭一次成功宣称首版完成。

## 验证方式

从正常自然语言任务入口完成真实业务，独立检查网站结果和下载文件。核验工具不可给产品站点步骤、恢复身份或正确答案；保存可供 14、15 直接使用的普通流程和执行记录。

遵循[总览中的跨事项完成约定](../README.md#跨事项完成约定)，从正式产品公开入口验证并保留独立证据；不把旧实验通过当作本项完成。真实运行沿用具体案例的有效授权与累计消耗上限，本事项的发布本身不启动新实验。
