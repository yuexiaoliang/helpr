# 09: 手动换版保留资料、原密钥和有效登录

Status: ready-for-agent
Blocked by: 06, 07, 08
Spec: [首版实现规格](../../helpr-first-release/spec.md)
Index: [实现事项总览](../README.md)
Engineering: [共同工程约定](../README.md#工程实现与验证约定) · [已确认选型](../engineering-stack-proposal.md)
User stories: 2–3、58、63–64

**What to build:** 用户从应用准备升级、处理现场并保存备份，手动下载和安装真实新版；新版保留原任务资料、受保护密钥和未过期登录，核对后恢复仍获准的工作。

## 前置交付与范围

及早验证同一产品的真实两版换装，使用前置任务和会话；20 增补定时与升级竞争，23 用完整资料复验。自动下载安装、无人参与升级、正式对外签名和公证不在本项。

前置事项：[06 收起运行、锁屏与休眠恢复](06-hide-lock-sleep-and-resume.md)；[07 本机备份与旧备份恢复](07-local-backup-and-restore.md)；[08 自动检查新版与可信下载提醒](08-version-check-and-download-notice.md)。

两个版本采用固定的 pnpm 工具链与已选 electron-vite／electron-builder 构建路径。Drizzle 迁移在独立记录进程中运行，经审查后冻结；数据和 XState 状态模型版本一并检查，不能在用户库执行开发期结构同步。新库支持声明或原生组件的绑定方式不能替代跨版实际包验证。

## Acceptance criteria

- [ ] 通过 08 的可信入口手动取得实际新版，在目标 Mac 完成两个版本的真实安装和启动；不是开发目录重启或手改版本号。
- [ ] 升级准备与任务派发共用协调入口：阻止新动作，处理不能安全关闭或重建的现场，保存记录并完成可核验备份后才报告可退出。
- [ ] 不能保存、备份失败或现场未处理时不报告准备成功；安装意图不替代内容确认，不放弃人工文字或批准未知结果重发。
- [ ] 新版检查资料格式、引用文件、受保护凭据、有效登录、原生输入和控制能力，再按原意图核对恢复；停止、接管和待参与条件保留。
- [ ] 使用同一原始测试密钥、明确尚未过期的会话和实际任务验证；重填密钥、重新建立仍有效登录、同版重开不替代跨版延续。
- [ ] 记录真实系统交互；取消授权保留资料并暂停依赖工作，重复要求同一授权、丢失原密钥或有效登录不能算稳定通过，也不降低保护以通过。
- [ ] 错误来源、架构、数据兼容、迁移或新版本能力失败时保留原资料并说明，不盲目恢复或把程序降级当数据安全回退。
- [ ] 外部强行替换应用或终止进程后仍按中断规则恢复；实际进程退出、数据变化和网站效果分别留证。
- [ ] 提交早期换版证据及尚需 20、23 扩充的具体矩阵，不把原实验失败或有限自签名证据改成通过。
- [ ] 以真实旧库和引用资料验证冻结迁移、迁移中断／失败及状态模型兼容；保留旧数据备份，迁移成功后仍先核对再恢复。最终包的原生依赖、资源、受限 preload、fuses 和生产路径均按锁定组合复验。

## 验证方式

经实际 UI 共用的升级准备、备份和启动入口，独立核对两个安装包、进程树、原凭据匹配、登录有效期及网页效果。系统交互需用户在系统界面完成，密码不进入对话或日志。

遵循[总览中的跨事项完成约定](../README.md#跨事项完成约定)，从正式产品公开入口验证并保留独立证据；不把旧实验通过当作本项完成。真实运行沿用具体案例的有效授权与累计消耗上限，本事项的发布本身不启动新实验。
