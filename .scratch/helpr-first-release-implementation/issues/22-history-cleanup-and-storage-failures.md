# 22: 历史清理、引用保留与空间不足处理

Status: ready-for-agent
Blocked by: 07, 20
Spec: [首版实现规格](../../helpr-first-release/spec.md)
Index: [实现事项总览](../README.md)
User stories: 52、54–55、57

**What to build:** 用户查看清理影响后主动清理已结束工作的资料；仍可继续的任务、计划、共享文件和必要处理事实保留。空间不足时明确暂停依赖保存的自动工作。

## 前置交付与范围

使用完整的计划、素材及备份引用关系交付资料管理。默认本机保留，不增加自动到期删除或云端备份，也不能把浏览器登录目录当一般缓存清理。

前置事项：[07 本机备份与旧备份恢复](07-local-backup-and-restore.md)；[20 定时选材、旧工作与错过时间处理](20-scheduled-material-work-and-missed-runs.md)。

## Acceptance criteria

- [ ] 历史、素材版本与必要证据默认保留，应用提供主动选择和清理前影响说明，明确会失去哪部分回看或恢复能力。
- [ ] 保护执行、待参与、接管、停止后可继续、结果不明及被其它任务／计划引用的资料，不因单一历史任务结束就删除共享文件。
- [ ] 最小素材完成事实与可清理的大型证据分别处理，清理不能把已发布素材变回未处理；若用户确实清除判定依据，相关自动判断暂停或重新约定。
- [ ] 清理提交前核对最新引用与执行资格，覆盖新领取、备份和恢复竞争；中断后不出现记录仍指向必要文件却已被删掉的可执行状态。
- [ ] 空间不足及关键记录／文件保存失败时保留既有资料、明确受影响工作并阻断依赖派发，不静默删除其它历史凑空间。
- [ ] 缓存与登录、人工现场、业务记录和证据分别管理，不通过清空整个浏览器资料区释放空间或重置失败。
- [ ] 清理后的有效备份、旧备份恢复、素材去重和计划工作仍按事实核对；被保留的数据和删除范围可独立审阅。
- [ ] 使用受控存储故障和隔离测试数据覆盖引用、失败、中断及恢复，不耗尽用户真实磁盘或删除用户非测试资料；保存实际结果与失败记录。

## 验证方式

通过清理预览／执行、记录和备份恢复入口，独立检查文件存在性、引用清单、任务资格与真实效果计数。测试需要清理的只有明确测试数据，存储故障用受控注入而非破坏用户环境。

遵循[总览中的跨事项完成约定](../README.md#跨事项完成约定)，从正式产品公开入口验证并保留独立证据；不把旧实验通过当作本项完成。真实运行沿用具体案例的有效授权与累计消耗上限，本事项的发布本身不启动新实验。
