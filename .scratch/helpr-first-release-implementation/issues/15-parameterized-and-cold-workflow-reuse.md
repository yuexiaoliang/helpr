# 15: 换输入与冷启动流程复用

**What to build:** 用户换素材、标题或明确要求的新栏目后，产品使用已学做法完成本次任务；完整退出并重开后仍能以新输入复用，并取得可下载核对的结果。

## 前置交付与范围

使用 13 产品实际形成的流程和授权记录，分别覆盖换输入与冷启动业务场景。理解新委托可调用模型，稳定网页步骤直接重放；页面变化修复由 17 扩展。

前置事项：[13 首次附件发布并保存学到的流程](13-first-publication-and-learned-workflow.md)。

## Acceptance criteria

- [ ] 复用前检查目标、网站及流程适用条件，绑定本次素材和内容参数，固定当前执行使用的流程版本。
- [ ] 使用不同文件和标题，用户明确要求时改变栏目；核对本次权限与确认是否适用，不沿用旧文件、旧值或单次确认。
- [ ] 稳定网页动作在确定参数后可由程序直接执行；网页重放与意图理解、素材／内容处理的模型调用分别记账。
- [ ] 完成真实结果核对，下载文件与本次固定素材一致；流程或参数不适用时明确重新观察或请求参与，不硬套旧步骤。
- [ ] 完整退出并确认旧进程结束后重开，用新输入复用；不依赖上次编辑页面、内存、未保存流程或测试工具补回状态。
- [ ] 多项执行分别固定流程、输入和结果，不因共用流程而共享任务授权；同一效果的重复回调不重复更新工作。
- [ ] 重放仍经过逐动作资格、可靠保存、停止和接管入口，不能为了减少模型调用增加绕过检查的快捷通道。
- [ ] 分别保留换输入和冷启动场景的通过证据及失败；仅观察总模型用量降低或程序无报错不能证明复用正确。

## 验证方式

从正常任务入口使用实际学得流程，独立对照网站目标、下载字节、进程结束和分项模型记录。确定性参数与歧义反例走公共网页执行／流程入口，不测试内部辅助函数排列。

遵循[总览中的跨事项完成约定](../README.md#跨事项完成约定)，从正式产品公开入口验证并保留独立证据；不把旧实验通过当作本项完成。真实运行沿用具体案例的有效授权与累计消耗上限，本事项的发布本身不启动新实验。
