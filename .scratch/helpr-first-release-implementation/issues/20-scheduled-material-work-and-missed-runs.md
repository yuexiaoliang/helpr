# 20: 定时选材、旧工作与错过时间处理

Status: ready-for-agent
Blocked by: 11, 14, 16, 19
Spec: [首版实现规格](../../helpr-first-release/spec.md)
Index: [实现事项总览](../README.md)

User stories: 36、40–47、51、57、61、63

**What to build:** 用户自然语言设置时间、时区、取材和错过规则，系统到点后台开任务；旧等待、停止或结果不明的同一工作留在原任务，新合格素材依约继续。

## 前置交付与范围

把成熟任务、结果核对、共享资源与发布约定接入本机定时。补齐任务关闭、唤醒、升级准备和备份恢复与计划的组合，不以新增触发绕过旧工作意图。

前置事项：[11 任务组、收起、关闭与历史返回](11-task-groups-history-and-close.md)；[14 提交中断后的真实网站结果核对](14-recover-real-publication-outcomes.md)；[16 共享登录与同一目标的执行协调](16-shared-login-and-target-coordination.md)；[19 发布约定与素材处理归属](19-publishing-agreements-and-material-work.md)。

本项原型用时间表达、时区及夏令时例子确定成熟时间库与版本，展示“每天某时刻”和“每隔固定时长”等差异及歧义处理。库只产生候选时刻，计划版本、触发领取、素材工作去重和恢复由独立记录进程及统一控制入口管理；XState 内存定时器或库的默认策略不能代替持久约定，不自研通用历法。

## Acceptance criteria

- [x] 创建或修改时用具体时间复述时区、素材规则和生效范围；重复或不存在等歧义时刻需明确处理，机器时区改变不偷偷改约定。
- [x] 时间库及版本依据本项原型确定并锁定，代表性时间表达、跨时区和夏令时边界有公开行为检查；恢复后按计划与实际工作重新核对，不因重新启动定时器而多领或补发。
- [x] 每项计划明确补最近一次、跳过或先询问，未约定时不选择全局隐含策略；设备或应用未运行期间不承诺按时执行。
- [ ] 到点后台新建所属任务页并显示进度，不切换当前查看页或抢焦点；缺素材、多义或访问拒绝时提出正确参与请求。
- [x] 同一预定轮次仅领取一次，领取、选材／等待决定及任务工作关联原子成立；重复通知、重开或计划换版本不绕过已有轮次。
- [x] 素材工作另行去重：运行、等待、停止或未知的旧工作仍指向原任务，新合格素材按授权和容量安排；明确停止必须明确继续，不能通过新轮次重建。
- [ ] 补做针对错过而未开始的轮次，不删除已开始旧任务、不将待确认自动批准；共享登录只影响相关工作，解除后逐项核对。
- [x] 关闭或停止本次任务不取消计划，用户自然语言修改或取消计划才改变未来安排；撤销阻止尚未派发动作，已产生效果不自动撤回。
- [ ] 唤醒、重开、升级准备与到点竞争时统一资格检查，暂停期间不派发；原意图和未知结果优先，升级完成不自动补发所有积压。
- [ ] 计划、轮次、素材选择和新意图进入一致备份与旧备份恢复；恢复后核对实际结果，由用户选择继续哪些计划，不覆盖较新停止或约定变化。
- [ ] 结合真实素材与网页验证旧工作保持、新素材推进、时间策略、容量及共享阻碍；时钟与竞争的确定性检查不代替真实业务效果核验。

## 验证方式

通过计划修改、触发领取、素材工作及正常任务入口，受控时钟验证边界和重复；独立效果记录与真实后台核对任务没有多发。实际睡眠证据沿用完整应用的真人安排，新增超出授权的运行先给具体方案。

遵循[总览中的跨事项完成约定](../README.md#跨事项完成约定)，从正式产品公开入口验证并保留独立证据；不把旧实验通过当作本项完成。真实运行沿用具体案例的有效授权与累计消耗上限，本事项的发布本身不启动新实验。

## 开发结果

2026-11-07，按持续开发流程完成独立实现。锁定 `@js-temporal/polyfill` 0.5.1；计划保存命名时区、一次／星期日历／固定间隔、明确错过与夏令时策略、接受边界及期次。接受、修改、取消、候选读取、统一资格复查、轮次与素材任务原子关联进入正式入口。旧工作直接保留原任务，新素材经既有容量与网页守卫推进。新增日期、最新未完成和全部未完成规则；格式19接续18，备份与冷开校验计划及工作引用，旧备份恢复不覆盖新取消并要求逐项核对后继续。

源码293项应用／9项验证器／25项旧回归通过；定时专项18项复核通过。具体固定候选、实包结果及清理见[20报告](../../../docs/testing/evidence/schedules-20/REPORT.md)，失败见[SOURCE-FAILURES](../../../docs/testing/evidence/schedules-20/SOURCE-FAILURES.md)。日历与固定间隔、纽约两类DST、Lord Howe半小时和Apia整日缺失均由库计算；宿主Node24.18.0、ICU78.3、tz2026b。锁库不等于锁住系统时区数据库，升级组合须复验。

尚未取得真实模型／远程后台、原生焦点／IME、实际计划与睡眠／升级／恢复网页效果的完整组合；19的导航后明确继续边界保留。定时不能代答参与请求，限定网页创建证据不等于无人值守发布完成。保留前置，不把本项写成整体验收通过。下一聊天按同一串行流程推进21，优先核对真实运行授权与可独立推进的通用能力，不增加 Drupal 专用业务分支。
