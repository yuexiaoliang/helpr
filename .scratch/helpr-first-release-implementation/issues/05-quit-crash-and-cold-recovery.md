# 05: 退出、意外退出与冷重开核对

Status: ready-for-agent
Blocked by: 04
Spec: [首版实现规格](../../helpr-first-release/spec.md)
Index: [实现事项总览](../README.md)

User stories: 25、48–51、60

**What to build:** 退出或进程意外结束后重新打开，用户找到原任务与意图；原活动任务核对后续做，停止、接管、等待和未知保持，可能已发生的操作不会直接重发。

## 前置交付与范围

在 01–04 已有窄网页操作中完成可靠保存、拥有者生存期及保守恢复。真实上传、草稿和发布的自主恢复依据继续由 12–14 扩充，本项不靠预填网站身份宣称完整业务恢复。

前置事项：[04 直接接管网页与页面变化后的归属](04-native-takeover-and-page-ownership.md)。

恢复读取独立记录进程保存的事实与 XState 模型版本，再核对网页；不直接启动快照中可能产生外部效果的 invocation。记录进程恢复只表示记录服务可用，不解除任务停止、接管、待参与或未知；控制拥有者继续独占当前执行资格。

- 状态：已确认。
- 原型：[退出与冷重开恢复演示](http://127.0.0.1:4318/recovery-prototype.html?v=5a75723)，版本 `recovery-v1`；来源分支 `codex/recovery-prototype`，固定源码提交 `5a75723b480ec88215e74de00d08c3e57346129f`。[单文件原型](/Users/yuexiaoliang/.codex/worktrees/recovery-prototype/helpr/.scratch/helpr-first-release-implementation/prototypes/recovery/recovery-prototype.html)、[范围与体验说明](/Users/yuexiaoliang/.codex/worktrees/recovery-prototype/helpr/.scratch/helpr-first-release-implementation/prototypes/recovery/README.md)。可直接双击 HTML；临时预览入口依赖本机静态服务。原型独立保留，不合并为正式产品。
- 覆盖范围：有序退出的阻断、保存与清理次序；意外退出后的旧控制隔离、唯一拥有者与竞争启动；按可靠记录恢复任务和不同意图；唯一实际结果补记、可信未派发续做与结果不明不重发；核对中新的停止或目标变化使旧核对失效；记录进程退出、保存失败、提交回执丢失及迟到回执；缺失／损坏／不兼容／素材不符资料与无法重建网页现场的保留和说明。通过两项虚构备注写入及 10 个引导场景体验行为，附自由操作与完整状态。
- 模拟边界：记录、意图、提交、进程、目标身份、网页结果和人工文字均在内存中模拟，不构成实际持久化、进程树清理、真实网页重建或自主恢复依据的证据。分步按钮和状态表是原型工具，正式产品自动处理相应阶段。12–14 的真实上传／草稿／发布恢复及 06 的系统生命周期范围保留，原验收条件未勾选。

## Acceptance criteria

- [x] 明确退出或 ⌘Q 先阻止新派发、保存任务与必要事实，再结束自有视图、工作者和控制进程；退出不把全部任务改成用户停止。
- [x] 控制拥有者意外退出时，其自有网页宿主、页面、工作者及记录进程得到清理，不能留下继续操作网页的孤立进程；判断依据为真实进程树，不只是退出通知。
- [x] 新启动取得唯一拥有者并隔离旧执行，确认旧工作者退出或失去目标控制后才允许恢复写操作，不以超时或 PID 改变单独证明远端动作结束。
- [x] 新进程读取任务、意图、动作和结果；已停止、待参与、接管及未知输入暂停保持，查看、重新登录或重开不会自行解除。
- [x] 原活动任务先核对：唯一实际结果匹配则记完成；可信未派发检查点且条件匹配才续做；可能已送出但效果不明只读核对，不盲目重发。
- [x] 恢复中发生新停止或目标改变使旧恢复资格失效；迟到观察可保留历史事实，不覆盖新资格或推进新执行。
- [x] 记录缺失、损坏、素材不符或不兼容时保留原资料并暂停；不能安全重建的网页现场明确说明，不生成伪造的成功或空白可发布任务。
- [x] 覆盖预留前后、效果发生与记账之间中断、两项不同意图、竞争启动、保存失败和正常／异常退出；保留原失败及清理证据。
- [x] 记录进程独立退出、已提交但回执丢失、状态模型不兼容及恢复中收到旧回执时，保持可靠事实与当前资格一致；没有成功回执不等于未提交，状态快照不能直接重发动作。

## 验证方式

通过应用退出／启动、记录与执行公开入口，启动真实独立进程并用独立效果记录核对。进程中断与真实断电分开，不能用强杀结果宣称硬件断电保证。

在实际包内核对控制、记录、网页宿主及工作者各自的退出与失联影响；XState 转换检查、日志尾部或退出通知不能替代进程树和网页效果证据。

遵循[总览中的跨事项完成约定](../README.md#跨事项完成约定)，从正式产品公开入口验证并保留独立证据；不把旧实验通过当作本项完成。真实运行沿用具体案例的有效授权与累计消耗上限，本事项的发布本身不启动新实验。
