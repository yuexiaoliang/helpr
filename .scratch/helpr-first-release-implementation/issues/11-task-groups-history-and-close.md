# 11: 任务组、收起、关闭与历史返回

Status: ready-for-agent
Blocked by: 04, 10
Spec: [首版实现规格](../../helpr-first-release/spec.md)
Index: [实现事项总览](../README.md)
User stories: 17–18、29–32、47、53

**What to build:** 多目标委托形成各自独立的任务，可归组整理；用户收起活动任务或关闭已结束任务，再从活动入口和历史查看对应会话、页面、进度及结果。

## 前置交付与范围

使用已有接管和参与事实决定关闭行为，任务组只整理。定时计划尚未接入，20 必须补验关闭本次任务不取消计划；本项不能隐含实现组级授权。

前置事项：[04 直接接管网页与页面变化后的归属](04-native-takeover-and-page-ownership.md)；[10 参与请求、确认与全局可操作提醒](10-participation-and-actionable-notifications.md)。

## Acceptance criteria

- [ ] 一句多目标委托可形成独立任务并归入任务组，各自拥有会话、进度、内容／参与与结果，不共享一次内容确认。
- [ ] 已完成、已停止或以失败结果结束的任务点击关闭直接进入历史，保留对话和已产生结果。
- [ ] 执行、排队、待参与或接管的任务点击“×”时在标签页旁给出收起／停止及相应说明，不把关闭默认为停止或继续。
- [ ] 点外侧或 Esc 只收起提示，保留原任务状态；停止不作默认焦点或 Enter 的隐式选择，明确停止直接执行且不二次确认。
- [ ] 提示出现期间状态改变时按最新事实处理，不用旧提示启动、停止或关闭另一项执行。
- [ ] 收起仅改变展示，真实页面和原运行／等待／接管状态保留；固定活动入口与提醒可返回，不能销毁页面来模拟保留现场。
- [ ] 从历史重新打开只查看，明确继续后先核对；已完成不重发，有合格剩余工作才恢复活动入口。
- [ ] 关闭操作及重开后仍保持任务身份、结果和参与归属；以受控实际任务检查各种状态、误点和竞争。

## 验证方式

通过任务关闭、停止、查看和参与的公开入口验证真实 UI、页面保留及记录；不要将主窗口隐藏和任务标签页关闭混为一项。20 再在实际计划任务中检验两种身份的独立性。

遵循[总览中的跨事项完成约定](../README.md#跨事项完成约定)，从正式产品公开入口验证并保留独立证据；不把旧实验通过当作本项完成。真实运行沿用具体案例的有效授权与累计消耗上限，本事项的发布本身不启动新实验。
