## 前置交付与范围

完善 03 的等待与输入接受路径，统一确认与回复的可靠记录。用窄任务取得真实可操作提醒证据；复杂文章内容和可复用发布约定分别在 18、19 接入。

前置事项：[03 两项网页任务执行、停止与继续](03-parallel-execution-stop-and-continue.md)。

参与状态转换沿用记录进程中的 XState，接受事实与失效依据原子提交；React 对话和提醒只读取有版本投影，通过同一受限业务契约提交回复。React Aria 按需承担键盘、焦点和浮层交互，不能由组件本地关闭状态推断回复已可靠接受。

## Acceptance criteria

- [ ] 参与请求包含稳定任务、执行、问题及相关内容版本，在所属会话和全局提醒展示明确问题与可操作输入，并可返回该任务真实页面。
- [ ] 即使当前查看 B，在提醒回答 A 仍只进入 A；任务组不提供集中审批或跨平台共享一次确认。
- [ ] 会话与提醒使用同一公开接受入口，同一回复只处理一次；相同身份换内容拒绝，重开及回执丢失不产生第二次动作。
- [ ] 接受回复、更新有效确认依据以及使受影响旧请求和资格失效，在同一事务中成立；接受后未派发即崩溃，仍保留有效确认。
- [ ] 停止、目标／内容变更或新请求使旧回复失效，明确告诉用户需要处理当前请求；继续不自动提供缺少的内容确认。
- [ ] 等待参与释放自动推进容量但保留页面、待办与影响范围；不受影响的另一项继续，登录回复不清除该任务其它停止或等待条件。
- [ ] 在实际安装包中验证全局提醒可以直接输入或操作，关闭主窗口后仍有清楚的待办入口；不因某个系统通知实现不可用而悄悄删掉此能力。
- [ ] 保存、提醒显示或回复接受失败分别反馈，已接受事实不因展示失败丢失；重复、迟到、跨任务与新停止竞争有确定性反例检查。
- [ ] 两处输入的中文提交、焦点返回、任务切换后的草稿及订阅清理通过用户入口检查；记录进程的迟到回执不把旧问题显示成当前问题，也不批准新的执行。

经过委托／参与回复和工作区公开入口，观察真实任务进度、提醒归属与独立效果计数；用新进程检验确认持久性。不能只检查一个布尔同意字段或 UI 已隐藏。

遵循[总览中的跨事项完成约定](../README.md#跨事项完成约定)，从正式产品公开入口验证并保留独立证据；不把旧实验通过当作本项完成。真实运行沿用具体案例的有效授权与累计消耗上限，本事项的发布本身不启动新实验。
