# 07: 本机备份与旧备份恢复

Status: ready-for-agent
Blocked by: 05
Spec: [首版实现规格](../../helpr-first-release/spec.md)
Index: [实现事项总览](../README.md)
User stories: 2、52、56–57

**What to build:** 用户从应用创建可核验的本机备份，恢复旧备份前保留当前资料；恢复后自动工作保持暂停，核对实际结果后由用户选择继续哪些任务。

## 前置交付与范围

首先覆盖已有任务和记录，建立随资料类型增长的一致备份契约。后续流程、素材和计划必须随各自事项接入，不把尚不存在的资料写成已验证；20 增补计划场景，23 复验全量。

前置事项：[05 退出、意外退出与冷重开核对](05-quit-crash-and-cold-recovery.md)。

## Acceptance criteria

- [ ] 备份通过应用公开入口，由记录拥有者协调一致快照和引用文件，包含格式版本、清单及完整性校验；不盲拷正在写入的单个数据库文件。
- [ ] 备份保留业务任务、记录及当时已支持的数据，排除模型密钥、认证头、浏览器登录和会话目录；只保存到用户选择的本机位置，不自动上传。
- [ ] 备份失败、空间不足或文件缺失时保留原资料并说明失败，不把不完整备份显示成功，也不静默删除其它资料。
- [ ] 恢复前先保存当前资料，核对备份格式和引用完整性；损坏或不兼容时拒绝破坏性覆盖，保留可用数据。
- [ ] 恢复旧资料后先暂停自动任务，比较可获得的新旧意图并核对网页结果；不覆盖备份后的停止、约定变更或已产生效果。
- [ ] 没有较新本机记录也不能默认旧意图仍有效；由用户选择继续的工作，可能需重新补模型设置或登录，但不得据此重发未知结果。
- [ ] 明确应用版本回退与数据恢复不同，不把程序降级等同于安全数据回滚；备份可能含业务敏感内容，不宣称整包自动加密。
- [ ] 用前置真实网页效果与独立记录验证备份竞争、旧备份恢复、保存失败、当前资料保留和凭据排除，并为后续数据类型留下公共契约检查。

## 验证方式

通过与 UI 共用的备份／恢复和派发入口验证，独立检查归档清单与内容、恢复后的任务状态、网页实际效果。检查不能通过手改产品数据库制造已核对成功。

遵循[总览中的跨事项完成约定](../README.md#跨事项完成约定)，从正式产品公开入口验证并保留独立证据；不把旧实验通过当作本项完成。真实运行沿用具体案例的有效授权与累计消耗上限，本事项的发布本身不启动新实验。
