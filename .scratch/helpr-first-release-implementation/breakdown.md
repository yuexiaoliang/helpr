# helpr 首版实现事项拆分

状态：2026-10-13 用户已批准，23 项正式事项已发布，见[实现事项总览](README.md)。

依据：[首版实现规格](../helpr-first-release/spec.md)，已提交于 `d649263`。本拆分不改变规格、已确认产品范围或原技术决策。规划事项 01–26 保留原状；实现事项在本目录下单独从 01 编号，每项各自保存，并引用同一份首版规格。

## 拆分原则

当前仓库主要是产品文档、技术实验和日常检查，没有待整理的完整产品实现，因此不单列大规模重构事项。每项都在同一个正式应用里交付可运行、可观察的行为，把必要的界面、记录、执行和检查一并贯通；不另造长期维护的演示应用。

首批逐步建成真实工作区、模型接入、双任务执行、接管、记录与恢复；实际安装及手动换版也在早期验证。业务从上传准备、首次发布、换输入复用逐步扩大，再加入内容生成、发布约定、定时和另一后台。后面的检查扩大早期契约的覆盖范围，不等于早期可以跳过停止、归属或可靠保存。

以下编号表示依赖顺序，不表示必须把前面所有事项做完才能开始后面一项。只列直接阻塞者；例如 08 在 02 完成后即可开展，07 和 06 可以在 05 后分别推进。并行实施仍需要避开共享代码冲突，不因没有依赖而自动创建代理或新对话。

## 已批准事项

1. **可安装的双任务真实工作区**

   **前置：**无。

   **交付：**用户在当前 Mac 独立打开应用，创建两项任务，分别查看真实网页和独立对话；能手动登录，重开后仍找到同一任务与会话。

   **核对：**固定应用身份和数据位置，真实任务记录保存在本机；工作区与私有控制连接只向有归属的调用方开放已支持的观察能力，远程网页不能调用宿主；Cookie 保护从首次建资料区就确定。此项不声称已有自主网页执行。

2. **配置模型并在所属任务理解网页**

   **前置：**01。

   **交付：**设置服务地址、模型和受保护凭据后，用户在任务对话中询问当前网页，得到基于该页观察的回复；更换服务无需重建任务。

   **核对：**页面和对话不串任务，普通日志不含密钥；能力或授权不足明确反馈。公开请求入口覆盖流式响应、取消、并发及消耗上限；中断后未知用量不记为零。受控模型检查与真实服务检查分别记录。

3. **两项网页任务执行、停止与继续**

   **前置：**02。

   **交付：**在同一应用内用自然语言委托窄而明确的网页操作，两项独立任务实际重叠推进，第三项合格任务排队；停止 A 后 B 继续，明确继续 A 时只做已核对的剩余动作。

   **核对：**受控真实页面提供独立效果计数；所有模型提议走同一逐动作资格检查，关键记录先保存、预留只消费一次。停止和目标修改撤销旧资格，迟到回复只记事实；保存失败阻止派发。通用步骤由模型提议，不能把核验页面的做法写进产品源码。

4. **直接接管网页与页面变化后的归属**

   **前置：**03。

   **交付：**用户操作任务网页时对应任务让出，继续前先核对并保留手动文字；查看、切页和聊天不误接管。页面刷新、导航、弹窗或视图重建后不使用旧归属继续操作。

   **核对：**实现并自动核对本机点击、键盘、粘贴、焦点和未知归属处理；未知时暂停同窗口两项且不清除另一项停止。真正的中文输入法和 ⌘V 证据集中在 06 的首轮真人核对取得，本项自动输入不冒充真人样本。

5. **退出、意外退出与冷重开核对**

   **前置：**04。

   **交付：**退出保存后重开，用户能看到原任务、意图和已保存结果；原活动任务核对后续做，停止、接管、等待及未知保持原意图，可能已发生的动作不直接重发。

   **核对：**在前面窄操作路径中覆盖预留前后、效果发生与记账之间中断、竞争拥有者及旧工作者；实际进程树确认自有页面和执行进程退出。不能重建的现场说明缺口，不假造恢复。网站业务目标和上传／发布的自动恢复依据继续由 12–14 贯通。

6. **收起运行、锁屏与休眠恢复**

   **前置：**05。

   **交付：**关闭主窗口后任务继续，菜单栏可返回；锁屏和休眠时暂停派发，解除条件后先核对，停止任务不被自动恢复。

   **核对：**唤醒但仍锁屏、核对中再次锁屏、重复系统事件及两项不同意图；隐藏窗口两项继续。由 agent 先验证现场，再集中完成首轮真人点击、独立中文／粘贴、文字保留、锁屏和真正休眠。定时补做在 20 接入。

7. **本机备份与旧备份恢复**

   **前置：**05。

   **交付：**用户从应用创建可核验的本机备份；恢复旧备份前保留当前资料，恢复后暂停并核对，由用户选择继续的任务。

   **核对：**一致快照与引用文件、完整性和版本、排除密钥及浏览器会话；备份后的停止和实际结果不能被旧记录覆盖。此时以已有任务验证，后续新增流程、素材和计划时同步扩充备份及恢复用例，最终在 23 复验全量资料。

8. **自动检查新版与可信下载提醒**

   **前置：**02。

   **交付：**应用只读检查可信版本来源，发现适用新版后提醒并提供手动下载入口；服务或兼容信息异常时明确反馈。

   **核对：**实际请求仅含必要版本信息，不上传业务资料、不下载包、不登记自动安装；覆盖来源、平台、架构及版本异常。固定可维护的自用版本来源，不要求公开发布或购买签名服务。

9. **手动换版保留资料、原密钥和有效登录**

   **前置：**06、07、08。

   **交付：**从应用准备升级，处理现场、停止新派发并保存备份；用户下载并安装真实新版后，原任务资料、受保护密钥和未过期登录仍可使用，核对后恢复。

   **核对：**两个实际版本安装包，原生接管与控制能力复验；拒绝、备份／迁移失败及不兼容时保留资料，不盲目降级。系统授权单记，重填密钥、重新建立有效登录或反复同一授权不算通过。计划与升级竞争由 20 增补，最终候选在 23 再验。

10. **参与请求、确认与全局可操作提醒**

   **前置：**03。

   **交付：**遇到目标不清、登录或确认需求时在所属任务提出参与请求；用户可以在会话或全局提醒中回答，另一项合格任务继续。

   **核对：**两处回答只接受一次，切到 B 时答 A 仍归 A；停止、修改内容或新请求使旧回复失效。有效确认已保存但回执丢失后不重复索要；等待释放自动推进容量但保留现场。全局提醒在实际安装包可操作。

11. **任务组、收起、关闭与历史返回**

   **前置：**04、10。

   **交付：**多目标委托形成独立任务并可归组；每项保留对话、进度、预览和结果。用户能收起活动任务、关闭已结束任务，从活动入口或历史返回。

   **核对：**未完成任务的“×”给出收起／停止，Esc 和点外侧不改变任务；停止无二次确认且不作默认选择，提示期间完成按最新状态处理。重新打开只查看，组不提供集中审批；20 验证关闭本次任务仍保留计划。

12. **固定素材版本并准备真实上传**

   **前置：**06、10。

   **交付：**自然语言指定素材范围和目标，产品选定 Excel 固定版本，在真实后台自主完成上传和草稿准备；找不到或无法选定素材时请求参与。

   **核对：**素材字节、来源、参数和任务一致，路径变化不偷偷换版本；及时保存实际目标、已知上传和草稿事实。中断或结果不明不重传；产品从观察形成检查与恢复依据，不读核验答案。本项只承诺上传准备路径，最终发布在 13。

13. **首次附件发布并保存学到的流程**

   **前置：**12。

   **交付：**从自然语言委托贯通 WordPress 附件发布，核对真实目标和下载内容，并从实际执行保存完整、可验证的运行时流程。

   **核对：**提交前检查当前授权、素材和目标，生成的发布文字仍经过相应确认；提交后结果与素材处理事实一致保存。流程包含输入来源、条件、结果及恢复规则，只将已实际验证部分标为可复用；维护者不填写站点选择器或流程。

14. **提交中断后的真实网站结果核对**

   **前置：**13。

   **交付：**上传、草稿、发布中断后，产品凭正常执行形成的记录找到实际目标；已经完成就返回结果，可信未派发位置才续做，无法确认就保持未知。

   **核对：**冷进程使用产品形成的恢复依据，独立核验真实效果；同名、缺身份、错误素材、正文替换和迟到结果不能误判。两项活动任务以及停止／等待／接管意图保持，恢复中的新停止优先，记录损坏不重新创建可发布工作。

15. **换输入与冷启动流程复用**

   **前置：**13。

   **交付：**更换素材、标题或明确要求的新栏目后使用已学做法；完整退出并重开后仍能以新输入复用，结果可下载核对。

   **核对：**本次参数、授权及流程适用性正确，执行固定流程版本；稳定网页动作直接重放，意图理解和内容处理的模型消耗另记。不依赖旧编辑页、旧文件、旧确认或进程内状态。

16. **共享登录与同一目标的执行协调**

   **前置：**13。

   **交付：**共享登录失效或账号变化时，相关任务等待并复用处理入口，无关任务继续；两项可能改同一目标的工作不会互相覆盖。

   **核对：**以实际会话、账号和目标关联判断影响，不以标签页或任务组猜测；登录恢复只解除该阻碍，保留停止和确认条件。资源不能确认时相关工作等待，结合真实发布路径核对竞争及迟到变化。

17. **网页变化修复与并发流程采用**

   **前置：**14、15、16。

   **交付：**网页变化后产品重新观察，在原约定内修复、核对、记住新做法并告知；再次冷启动能够复用修复版。

   **核对：**同一旧流程被两项任务同时修复时保留各自候选和来源，采用检查父版本，正在执行的版本不被改写。未验证分支、未经共同验证的合并不采用；不通过重复发送未知提交来验证修复，不放宽目标或成功条件。

18. **读取 Excel、预览并确认文章**

   **前置：**13。

   **交付：**读取已选表格，生成文章建议，用户在所属任务预览、修改和确认后通过实际网页发布。

   **核对：**数字和事实可追溯源表位置及素材版本；建议、预览、确认与提交绑定同一内容。修改目标／正文使旧确认重新核对，跨任务确认拒绝，确认重开保留；不得用硬编码业务模板代替理解素材。

19. **发布约定与素材处理归属**

   **前置：**18。

   **交付：**用户明确约定以后按某套要求发布，产品复述范围并让符合条件的新内容自动执行；可修改和撤销。按约定、目标、素材版本和期次识别已处理工作。

   **核对：**有效约定内不反复确认，目标或规则超范围须参与，撤销阻止新派发；改名不重发 A，未完成 B 独立处理，明确再发形成新意图。来源变化不自行批准更新或另发，流程复用不能提供发布权限。

20. **定时选材、旧工作与错过时间处理**

   **前置：**11、14、16、19。

   **交付：**自然语言设置时间、时区、取材与错过规则，到点在后台开任务页；旧等待／停止／未知工作留在原任务，新的合格素材依约继续。

   **核对：**触发与素材工作分别去重，计划修改不绕过已有轮次，歧义时刻澄清；补最近一次、跳过、询问分别验证。关本次任务不取消计划，登录共享影响按实际范围处理，重开／唤醒／升级准备期间不越过暂停。将计划与取材记录纳入备份、旧备份恢复及新意图保护。

21. **在 Drupal 学习并完成同样的委托**

   **前置：**15。

   **交付：**同一产品在另一套结构不同的真实后台完成附件任务，并能更换输入使用运行时形成的做法。

   **核对：**从未预置该业务流程的资料区开始，任务、素材、确认和结果分别核对；不新增 Drupal 专用执行分支、维护者选择器或手填流程。新通用能力经过原控制入口，并回归已有 WordPress 路径。

22. **历史清理、引用保留与空间不足处理**

   **前置：**07、20。

   **交付：**用户查看清理影响并主动清理已结束工作的资料；仍需继续的任务、计划、共享文件和必要处理事实得到保留。

   **核对：**空间不足或关键保存失败有明确反馈并暂停依赖工作，不静默淘汰资料；清理不能把完成素材变回未处理。与备份／恢复、活动引用及中断竞争共同验证；用户确实清除判定依据时暂停相关自动判断。

23. **固定交付候选并完成整体验收**

   **前置：**09、17、21、22。

   **交付：**在同一固定版本完成五项业务各两次、全部组合检查、第二轮真人核对和手动升级复验，交付当前 Mac 可独立使用的应用与说明。

   **核对：**三种探索／复用并行组合均有实际重叠；全局提醒、任务组、页面变化、确认、计划、资料、控制隔离与恢复按规格矩阵复验。使用前面各项已经建立的公开入口检查，不到本项才编写验证装置。未通过项阻止交付；真实样本失败与累计消耗保留，发现需单独修复的问题形成具体修正范围。

## 跨事项的完成约定

- 每项正式事项都给出用户可观察的通过标准，并通过与 UI 共用的公开入口验证；需要持久化的事实同步覆盖重复调用、中断、归属和保存失败，不能等最后一项才补基本保护。
- 原生输入、控制资格、凭据、记录和应用退出不是只检查一次。后续引入新动作、流程、素材或计划时，检查它们仍服从这些入口；新增数据同步进入备份、迁移和清理规则。
- 早期使用受控真实网页缩小行为范围，仍运行同一正式应用，不把受控模型回应、预填流程或独立核验答案变成正式的理解与学习能力。
- 06 集中首轮真人接管及系统生命周期核对，23 完成第二轮；安装、登录和手动升级必要的系统交互另记。窗口、输入焦点、进度及采集先由 agent 准备，不反复要求用户盲试。
- 每批真实运行按具体案例固定模型、网页写入、构建安装、故障及时间上限，沿用已有有效授权，不重置已结束实验的预算。这份拆分不启动运行、购买签名服务或改变系统设置。
- 09 的早期换版使用当时已有的任务资料与有效登录，20 扩充定时竞争，23 以完整产品复验；不得将早期局部成功算作全部升级通过。
- 正式签名和公证仍安排在首次对外测试或发布前，自动下载安装仍留到盈利后；本组事项不扩大这两个范围。
