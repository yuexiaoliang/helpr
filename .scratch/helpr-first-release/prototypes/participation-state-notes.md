# 并行与用户参与：状态原型与核对记录

状态：用户已确认停止后明确继续的行为，原型已更新。其余情境沿用已有产品要求；本次核对不等于正式界面或产品能力验收。

打开 [单文件原型](participation-state-prototype.html) 即可使用，不需要安装依赖、构建或启动服务。所有状态只存在于浏览器内存；刷新会重置。

## 要回答的问题

两项任务同时推进时，确认、全局提醒、人工接管、继续、停止、目标修正、收起与重新打开，能否始终保持对应任务和本次执行的归属？状态展示是否符合操作者的直觉？

依据 [已确认产品需求](../../../docs/product/discovery.md)、[执行与调度建议](../../../docs/product/execution-coordination.md)及 [关闭交互](../../../docs/product/task-tab-close.md)。原型假定页面关系、登录依赖与已有发布约定已知，不验证如何自动识别它们。

## 十一个引导演练

| 情境 | 重点观察 |
| --- | --- |
| 全局确认 | 查看 B 时回答 A；重复回复不再次生效；A 等待时释放机会 |
| 查看与接管 | 查看、移动鼠标不接管；网页输入才让出操作；继续不代替变更后内容确认 |
| 停止与迟到 | 直接停止；旧结果失效；已发出的请求仍可能留下网站产出；明确继续时已有完整结果就告知，不重发 |
| 停止后续做 | 重新查看仍停止；明确继续后核对并续做；旧确认、旧处理结果不重新生效，尚未确认的内容仍需当前确认 |
| 继续时结果不明 | 明确继续不抹掉已派发事实；结果无法确认时不重发，核实完成后告知结果 |
| 修正与旧确认 | 发布前变更目标；旧内容确认不批准新目标 |
| 收起与提醒 | Esc 返回、收起保留现场、在提醒处理、重新打开只恢复查看 |
| 共同登录 | 共享登录失效只影响依赖它的执行；登录恢复不抹掉确认和停止状态 |
| 中断恢复 | 原自动任务先核对；等待确认、接管、停止保持；结果不明不重发 |
| 定时与容量 | 新一轮有独立内容和待办；不替换旧问题、不抢当前查看位置；最多两项自动推进 |
| 过时关闭提示 | 提示期间任务完成；旧停止点击不把完成记录改成停止 |

状态面板分别展示用户意图、内容确认、目标、网站产出、登录条件、显示状态和定时计划。界面当前选中项不决定回复、旧处理结果或关闭提示的归属。

## 真人反馈与结论

初版暂把停止后的“继续”视为不能恢复旧执行，并明确标为候选。该情境暴露了已有要求中的缺口：自动恢复机制必须保留停止，但用户随后提出新的明确继续指令应如何处理，尚未确定。

2026-10-11，用户回答：“明确继续后，先核对再续做（推荐）”。问题中明确包含：已有完整结果就告知，不重发，也不要求重新委托。原型据此修改，并新增未完成和结果不明两个引导演练。

接受的行为是：新的明确继续指令允许重新核对并续做剩余工作；查看历史、重新登录与程序重启本身不改变停止意图。实际网站结果单独保留；内容确认与登录条件仍需满足，停止前已经失效的问题及处理结果仍然失效。已经完成的工作只告知结果，无法判断是否完成的工作继续核对，不能直接重发。

这里确定的是用户可见的行为关系。继续后是否沿用原执行身份、如何记录新的内部尝试和指令顺序，留给持久化与恢复约定决定；原型的执行编号与内存字段不是既定产品协议。正式决策与产品文档更新保存在主工作目录的[对应事项](../issues/09-participation-state-model.md)，本分支保留原型及本轮反馈作为资料。

## 浏览器走查与边界

2026-10-11，agent 在本机浏览器逐步点击了初版九个演练。收到反馈并修改后，又走查了停止与迟到、停止后续做、继续时结果不明、查看与接管、修正与旧确认、共同登录、中断恢复七个相关情境，状态变化符合上述预期，浏览器未报告脚本错误。走查覆盖已完成不重发、未完成核对后续做、结果不明不重发，以及旧回复失效和原有确认、停止、接管状态的保留。

这些是 agent 的原型可用性走查，不代表用户亲自点击了所有演练，也没有编写测试套件。真人反馈仅记录上面的明确选择，其余约束来自已有已确认需求。

原型没有连接真实网页、模型、数据库或恢复账本。“模拟重启”只保留内存数据；“模拟完成”由演练按钮提供事实。它不能证明并行、人工输入来源、取消、请求归属或磁盘恢复能力。实际记录与恢复协议仍由对应决策事项确定，不直接采用此文件作为产品实现。

模型放在单独的纯逻辑 `<script>` 中，展示层只调用模型；没有框架、网络资源或持久化。原型及本说明保存于 `codex/participation-state-prototype` 分支，主工作目录只记录事项进度和随后经用户核对的决定。
