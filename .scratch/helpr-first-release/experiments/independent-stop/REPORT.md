# 独立停止实验记录

2026-10-10，Electron 外部 CDP 与普通 Chromium 外部 CDP 各执行 11 个场景，共 22 项检查，全部符合各自预期。受控的待发动作、排队重试与迟到回复被阻止；等待点击与连续输入的 Playwright 调用响应了取消。各场景中 B 均继续完成 3–5 次真实请求，A/B 页面保留可读。

其中包含两类有意复现的反例：只结束外层等待，原点击仍会发生；不接受取消的浏览器内部多步工作，仍会在停止后点击。另有网站已经接收的提交和上传，在取消等待后正常完成。这些都是实验发现的限制，**22 项符合预期不代表 22 次操作均被成功取消**。本项的控制约定与后续处理决定记录在 [对应事项的 Answer](../../issues/02-independent-stop.md#answer)。

## 逐项观察

下表两种候选得到相同的功能结果。括号内名称对应原始结果的 `name`。

| 场景 | 观察结果 | 说明 |
| --- | --- | --- |
| 正对照（`positive-control`） | A 点击产生 1 次请求，完整输入 `abcdef`；B 完成 3 次请求 | 排除按钮或输入原本就不能工作的假阳性 |
| 只结束外层等待（`promise-race-negative`） | `Promise.race` 已返回，启用按钮后原点击仍产生 1 次请求；B 完成 4 次 | 没有取消原始操作的反例 |
| 待派发动作（`queued-before-dispatch`） | 停止后释放回调，凭据校验拒绝动作；A 无计数请求，B 完成 3 次 | 阻止尚未进入浏览器的工作 |
| 等待中的点击（`abort-waiting-click`） | 取消后 API 拒绝；随后按钮变为可用，A 仍无点击请求，B 完成 4 次 | 取消的是正在等待目标可操作的点击 |
| 连续输入（`abort-in-flight-typing`） | 52 个字符只输入 `ABC`；取消结束后 B 完成 5 次请求，A 内容仍是 `ABC` | 剩余字符停止，已输入内容保留 |
| 排队重试（`queued-retry`） | 首次点击超时后进入重试等待；停止再释放等待，仅有首次派发，A 无点击请求，B 完成 3 次 | 重试也必须经过同一检查 |
| 迟到外部回复（`late-provider-response`） | HTTP 模拟回复没有被取消；到达后尝试派发被拒绝，A 无计数请求，B 完成 4 次 | 证明可隔离迟到回复，未证明模型服务端停止计算 |
| 新执行后的旧回调（`stale-response-after-new-execution`） | 新代次完成 1 次计数；旧代次被拒绝；B 完成 3 次 | 单一 active 布尔值不足以区分旧工作；显式启动新代次只是实验探针，不是停止后自动恢复 |
| 网站已接收提交（`submit-already-accepted`） | 等待响应被取消，但网站仍产生 1 次提交结果；后续动作被拒绝，B 完成 4 次 | 取消客户端等待不撤销网站已接收的操作 |
| 网站已接收上传（`upload-already-accepted`） | 网站完整收到 65,536 字节后停止，仍产生 1 次上传结果；后续动作被拒绝，B 完成 4 次 | 仅覆盖传输完成、处理未完成；没有测量传输中取消 |
| 浏览器内部多步工作（`opaque-command-negative`） | `Runtime.evaluate` 内部等待后点击仍然发生；外层只能拒收返回结果；B 完成 4 次 | 原语派发检查不能抢占已经运行且忽略取消的内部工作 |

在实际调用 `stop()` 的场景中，没有发现该已停止代次的新 `dispatch`。最后一个反例仍然产生真实点击，说明核对网页与服务器结果是必要的，不能只数调用日志。正对照和 `Promise.race` 反例只在清理时调用控制器的停止，它们的空 `postStopDispatches` 不作为停止有效性的证据。

## 取消耗时的含义

| 在途原语 | Electron 外部 CDP | Chromium 外部 CDP |
| --- | --- | --- |
| 等待按钮的点击 | 1.273 ms | 1.004 ms |
| 连续输入 | 0.700 ms | 0.562 ms |

这是单次本地观察：从调用 `stop()` 到对应 API Promise 拒绝。它不表示网络请求已取消、业务结果已撤回或真人接管已完成，也不是性能保证。停止前已发生的 `ABC` 没有被清除。

使用取消参数的文档依据来自 Playwright 的 [1.62 发行说明](https://playwright.dev/docs/release-notes#version-162)、[连续输入参数](https://playwright.dev/docs/api/class-locator#locator-press-sequentially)与 [响应等待参数](https://playwright.dev/docs/api/class-page#page-wait-for-response)；本轮在锁定的 1.64.0 版本上取得了以上实际行为。不能把某个等待方法支持 `signal` 推广为所有第三方工具或网站请求都可取消。

## 未覆盖的组合

- 真实模型服务、Stagehand 或其他 AI 执行器；它们能否将取消传递到每一个实际动作，仍需 [AI 双页操作归属实验](../../issues/06-ai-parallel-binding.md)验证。
- 真人直接输入与自动动作交错、按键或鼠标手势中途让出、中文输入法来源识别；由 [人工接管实验](../../issues/12-human-input-takeover.md)验证。此处没有收集真人输入。
- 多进程消息排队、进程崩溃、登录冲突及持久化恢复。控制器的执行凭据只在本次 Node.js 进程中有效，不是产品级持久化协议。
- 真实后台如何核对提交结果和避免重复操作；由 [提交中断后的实际结果判定](../../issues/08-result-recovery-evidence.md)取得证据。实验服务器的内部计数不能当作通用网站核对方案。

本轮保留两种承载候选；停止原语的受控证据没有解决最终浏览器组合选择，也没有完成产品的首版并行能力。
