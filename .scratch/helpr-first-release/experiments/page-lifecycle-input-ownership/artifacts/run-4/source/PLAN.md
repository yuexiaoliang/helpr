# 页面变化后的输入归属与继续：实验计划

服务于“验证页面变化后的输入归属与继续”，是已有人工接管候选的独立生命周期实验，不重跑真人中文、粘贴验收，不构建产品。

## 范围和预算

- 只使用本机临时 HTTP 夹具和 Electron 两个任务视图、独立对话。全部输入标记为原生测试注入或自动化；不生成新增真人结论。
- 最多 8 次 Electron 启动、40 个场景尝试、4 个实测源码版本；首次正式启动起 60 分钟。失败和重试累计记账，不修改旧人工接管实验的 14 次历史额度或记录。
- 模型请求、真实后台写入、文件上传和发布均为 0。不改变系统电源设置，不主动休眠电脑，不修改系统权限或其它应用。
- 每轮先记录额度和源码摘要，再启动。保存失败、未知、原始事件和页面结果；预算耗尽时以已有边界和未完成项作答。

## 顺序

1. 先复用原生输入 Module 与停止 Module，建立一个能直接运行的最小反例：初始 A 输入正确归属并只停 A，页面自行刷新后再次输入 A，检查归属以及 B 是否被误停。至少两次独立观测验证复现率。只有取得具体失败信号后才比较修复假设。
2. 区分页面文档变化、原生视图身份变化、焦点改变和控制连接失效。每次只改变一个条件，保留原生命中 / 焦点和控制对象身份。
3. 对候选机制核对：刷新、同源及另一回环 origin 的导航、视图替换、控制断开重连、隐藏切换、已停止任务、等待点击中的变化。控制连接断开只算故障注入，不能代替真实休眠。
4. 输入 A 只让 A 让出，B 可继续；宿主查看与对话不接管网页。无法确认归属时必须保留未知，不能伪记为 A，也不能复用已失效的页面或执行。
5. 明确继续先读取当前页面和任务停止原因，再使用当前控制对象续做；旧对象、旧执行和迟到结果拒绝。另一个已由用户停止的任务保持停止；页面重载实际丢失的文字要如实记录，不伪称保留。

## 证据要求

用页面实际计数 / 文本、服务器收件和动作记录对照，不能只用内存状态判断 B 继续或旧动作未派发。固定页面结果、工具输入和历史真人样本分开。候选仅取得受控范围的事实，任意网页 / popup / 真正休眠等未测范围明确带入组合选择。
