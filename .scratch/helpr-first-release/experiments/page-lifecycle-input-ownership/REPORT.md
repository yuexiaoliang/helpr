# 页面变化后的输入归属与继续：运行事实

日期：2026-10-12。关联事项：[验证页面变化后的输入归属与继续](../../issues/19-page-lifecycle-input-ownership.md)。

现有 macOS / Electron 接管候选可以进入组合选择，但必须把页面生命周期、控制对象身份和停止原因一起管理。旧机制的刷新失败已经稳定复现并定位；候选在受控刷新、导航、视图替换和控制断开重连中通过检查。未知归属仍会暂停窗口中的两项任务，真实休眠唤醒和任意网站不在本次已取得的保证内。

## 最小反例与原因

[第一次基线](artifacts/run-1/checks.json)和[第二次基线](artifacts/run-2/checks.json)采用相同源码。初始点击 A，归属为 A，只停 A；通过网页自身的 `location.reload()` 刷新后，同一坐标的原生点击被认作 `unknown`，A、B 一起停止，B 的后续浏览器动作被拒绝。两次都以退出码 1 结束，失败原样保留。

[诊断运行](artifacts/run-3/checks.json)将三个假设分开核对：

| 假设 | 观测 | 判断 |
| --- | --- | --- |
| 刷新更换了原生输入接收视图 | 最深层 `RenderWidgetHostViewCocoa` 身份改变，外层 `WebContentsViewCocoa` 和窗口根身份未变；旧登记仍指向最深层 | 支持；见[前后祖先链](artifacts/run-3/native-before-after.json) |
| 只是焦点丢失 | 重新聚焦当前输入框后，原生键仍归属未知；只重新登记 A 后，鼠标与键盘都归属 A | 单独恢复焦点不足 |
| 控制页面对象已失效 | 未重连的原 Playwright 页面仍能读取当前文档并写入文本 | 不是该刷新反例的必要原因 |

这解释了本轮复现的刷新故障。历史真人粘贴尝试中 Command-R 附近的未知输入仍以[原始现场](../human-input-takeover/artifacts/run-1791783257762/human-paste-retry-request.json)为准；不能由本轮反例反推当时每个未知事件的原因，更不能把单纯切出应用定为根因。

## 候选机制与必要限制

原生登记改为宿主管理的独立外层子树，核对其可见性、窗口和矩形，避免登记会随文档变化的最深层渲染视图。实验不按 Chromium 私有类名匹配，但仍依赖已测 Electron 版本的原生视图结构。结构或矩形不符时拒绝登记，不把未知输入补记为 A。

控制页面按宿主已登记的 `webContents.id` 与 CDP target 对应，URL 不承担身份识别。Electron 提供 [`webContents.fromDevToolsTargetId`](https://www.electronjs.org/docs/latest/api/web-contents#webcontentsfromdevtoolstargetidtargetid)；重复 URL 场景验证了未登记的同址页面不会接走 A 的执行。

页面开始变化、视图替换或连接断开会停止相关执行并废止当前页面绑定。继续前等旧调用结束，重新匹配登记视图、读取当前页面，再核对这期间绑定及停止意图是否变化，最后创建新的执行资格。旧资格不能因重新连上而恢复有效。当前页面读取通过夹具注入，实际网站的结果核对能力仍由执行约定决定。

停止原因分别保留：用户停止、人工接管、未知输入和技术变化。单纯重连或重新登记不会激活任务；针对 A 的明确继续也不清除 B 的用户停止原因。核对过程中出现的新停止优先于先前的继续请求。最后一项在最终候选新增，并经两次运行验证，未计入旧版基线。

首个候选还暴露了另一处真实失败：替换视图后，新 A 位于对话视图上方，切换为只看 A 时遮住对话区，矩形核对因此拒绝登记。最终版本在布局时恢复对话区的最上层位置，并保留命中前后对照。[Electron 的 View 文档](https://www.electronjs.org/docs/latest/api/view#viewaddchildviewview-index)说明，重复添加已有子视图会将其移到最上层。

## 已取得的具体证据

以下场景均在最终完整运行通过；原始断言、任务状态、页面文本和收件数见 [cases.json](artifacts/run-5/cases.json)，事件顺序见 [events.jsonl](artifacts/run-5/events.jsonl)。

| 场景 | 实测结果 |
| --- | --- |
| 网页自身刷新后点击 A | 外层归属仍为 A，旧操作资格失效，A 让出而 B 保持执行资格；明确继续前读取当前文本 |
| 刷新后原生键盘输入 | 当前文档的文本实际改变，A 让出；B 在 A 暂停期间重新派发并被服务器接收 |
| 同源导航 | 新文档在控制重新绑定之前收到 A 输入，仍归属 A；旧执行被拒绝 |
| 另一回环 origin 导航 | 不同端口的新文档重新核对后归属 A；鼠标接管期间 B 重新派发并被服务器接收 |
| `WebContentsView` 替换 | 新视图获得新 target，旧页面实际关闭，旧对象调用及旧任务资格均拒绝；新 A 输入不停止 B |
| 同 URL 的未登记页面 | 按真实 target 与宿主登记关联，A 的服务器收件属于登记文档，诱饵文档没有收件 |
| 等待点击时导航 | 旧等待取消，旧排队动作被拒绝；新文档即使启用旧按钮，也没有 `late` 收件 |
| 用户停止后刷新 | 重新读取没有清除用户停止；明确继续 A 后，B 的用户停止仍在，B 收件没有增加 |
| 控制连接断开重连 | 旧页面关闭、旧执行拒绝；重新连接后两项仍停止，明确继续 A 使用新页面对象，当前文本保留，B 不重启 |
| 只看 A / 只看 B / 同时查看及对话 | 对话区恢复在最上层；宿主和对话输入不接管任务，随后 A 网页输入只停 A |
| 人为撤销 A 登记形成未知输入 | 事件保持 `unknown`，两项暂停，自动继续拒绝；明确继续 A 时重新核对，B 保留未知暂停 |
| 读取页面期间再次导航 | 旧文档观察结果被拒绝，取得新观察后才能恢复 |
| 读取页面期间再次停止 | 新的用户停止阻止较早的继续请求；随后新的明确继续可以恢复 A |
| 当前页面不能取得核对结果 | 即使显式请求继续，也返回 `current-page-unverified` 并保持 A 停止 |

B 的独立运行不只依据布尔状态。离线审计确认，在最终完整运行的键盘输入事件 79 / 83 后，B 派发事件 86 对应服务器第 3 次 B 收件；在导航后的鼠标输入事件 146 后，B 派发事件 149 对应第 5 次 B 收件。这些收件发生在 A 再次继续之前。原始重送键事件不算两个独立样本。[服务器原始收件](artifacts/run-5/server.json)、[审计索引](artifacts/evidence-index.json)。

三次候选运行的事件审计均未发现停止代次或已废止绑定上的新派发；每次恢复都先有同一绑定的当前页面核对，`late` 收件为 0。这只覆盖本轮原语与注入位置。已被真实业务服务器接收的副作用不会因本机制被撤回，仍依赖既有结果恢复和请求关联约定。

文本保留的结论限于同一当前页面上的接管与控制重连；网页自己刷新或导航造成的文本重置按新页面事实记录，本候选没有自动恢复刷新前未保存内容。

## 来源、环境与未取得的保证

- 环境为 macOS 14.8.3（23J220）、arm64、Electron 44.7.0、Chromium 152.0.7977.130、Playwright 1.64.0。原生插件以 N-API 8、Apple clang 16 编译。见[宿主记录](artifacts/host.json)、[运行环境](artifacts/run-5/environment.json)及[最终构建元数据](artifacts/run-5/source/candidate-native-build.json)。
- 输入通过只针对实验窗口的 AppKit 探针注入；读取页面和点击采用自动化工具。所有事件均标记 `automatic-native-probe`。键盘探针被原生系统重送时，原始同步栈标记会出现 `testInjection: false`；相同时间戳和键码的先前注入与重送都保留，不能将后者记为真人。历史真人点击、中文及粘贴结论没有改写。
- 两个导航 origin 都是本机 HTTP，仅端口不同；没有验证任意公网 / HTTPS 网站、跨站进程切换、popup、新窗口、原生文件对话框、多窗口、复杂 iframe、渲染进程崩溃或应用重启。监听到崩溃事件的代码存在，不等于取得崩溃恢复证据。
- 主动断开 CDP 是受控连接故障，未强制电脑休眠，也未修改电源、系统权限或其它应用设置；不构成真实休眠唤醒证据。
- 未知归属时能确定的范围是本实验窗口，而非具体任务，所以两项一起暂停。这是已测保守出口，仍影响“始终只让出对应任务”的保证。`state()` 暴露不同停止原因，拒绝继续也有明确错误；最终界面提示及用户能否理解尚未验证，本轮没有产品界面验收。
- 外层原生结构在本次版本和窗口布局下稳定，不是 Electron 对未来版本的公开稳定承诺。升级和其它宿主需要重新取得证据；无法匹配时只能维持未知，不能猜测归属。
- 原生二进制与临时浏览器资料不入 Git；每次源码及二进制摘要保留，最终构建元数据保留。早期诊断版本没有独立保留其二进制构建产物，不能据当前构建声称逐字节重建过它。

离线审计通过，来源与账本一致，实验进程已经结束。仓库检查通过：107 个源码文件语法检查、25 项离线测试，以及既有 AI 并行证据审计；没有因此重新请求模型或执行真实后台流程。

可供[浏览器承载与执行组合选择](../../issues/07-browser-runtime-decision.md)使用的事实已经齐备；是否接受这些范围和未知出口，由该决策确定。本报告不选择架构，也不将本次夹具当作完整流程与真人接管的组合验收。
