# 已学流程可以形成可复用的恢复依据，缺少依据仍须保留未知

2026-10-12，在当前 Mac 的 Electron 44.7.0 / Playwright 1.64.0 私有控制路径上，**取得了由实际学习与执行自动形成恢复依据的限定证据**。新进程只读取普通执行记录和已冻结的运行时规则，就能找回已保存草稿、有限续做、核对丢失回执的发布结果；没有由维护者事后填入文章编号、地址、恢复选择器或成功判断。

这支持既定技术路线，无须改变“记录先保存、恢复先核对、未知不重发”的约定。它不代表完整产品、新网站的所有学习阶段、任意网站恢复或打包版本已经通过。

## 自动形成了什么

既有操作及内容／文件条件来自[分阶段流程的冻结候选](../staged-workflow-checks/artifacts/staged/frozen-candidate.json)，出处与摘要保存在 [flow.json](flow.json)。本轮不使用旧恢复实验中人工编写的 `recovery-contract.json`。

在 L3 的真实网页中，模型分别选择了保存草稿按钮、保存后地址中的稳定记录参数、重新打开编辑记录后的公开结果入口。三份原始提议、输入观察及接口校验全部保留在 [model](artifacts/model)；提议不是最终成功依据，结果入口还必须等于此前已实际核对的公开结果地址。

通用程序保存实际导航，取得可识别的地址后登记其任务归属；文件上传按实际下载字节核对并单独保存。因此后续检查失败，不会抹去先前已经观察到的上传或草稿事实。任务、固定素材、流程版本、执行代次及控制代次来自本机记录，选中文件资格也从该记录登记，未沿用上个控制实验的直接夹具授权。

学习完成后保存 [freeze.json](freeze.json)：冻结候选源码、复用源依赖和 [rules.json](rules.json)。后续 U、H、G2 和反例均使用该候选；只读审计确认没有在保留集过程中修改规则或候选来迎合结果。测试驱动后来补充了只读记录快照；它没有向正常恢复入口提供网站身份或判断结果。

H 与 L3 标题相同，附件字节也相同，但正文和执行身份不同。独立核验同时看到了这两条公开文章，H 仅匹配自己的正文和目标；标题或附件摘要单独不足以证明归属。把另一执行的已登记地址交给 H，记录接口拒绝采用。

另有 [10 项资格及条件反例](artifacts/22-H-guards/result.json)和 [3 项真实页面核对反例](artifacts/23-H-negative/result.json)：旧进程资格、停止后的旧动作、继续后的旧资格、迟到提议、四类关键条件缺失、错误输入绑定、错误素材摘要、44 个匹配的非唯一位置及选错的真实位置均被拒绝。这些错误提议由夹具注入；本轮三次真实模型提议本身没有产生这些错误。未弱化成功条件来提高通过率。

## 独立核验和保留集素材修正

测试代理独立统计实际上传／发布请求，在后台成功返回后扣留回执，且冷恢复代理拒绝非只读 HTTP 请求。候选无法从自己的“完成”状态获得独立预期；[核验装置](oracle.mjs)另行读取实际文章、草稿和附件字节，网页与下载文件保存在 [oracle](artifacts/oracle)。没有把回执丢失解释为请求失败。

最初的素材生成夹具误选了 XML 节点，导致几个不同文件名具有相同字节。原文件和失败假设保留在[修订记录](AMENDMENT-2.md)，H **不算附件字节变化的通过证据**。在尚未执行的最后一个样本上，先生成并登记 G2 的真实新版本，再沿冻结流程上传和核对。其摘要 `7b3f04c…0716` 与旧版 `24975a5…eb0f` 不同，独立下载也相符；字节变化证据只归于 G2。没有修改已派发任务的素材或覆盖旧记录。

## 失败、修订与实际成本

全部 24 次宿主启动保留，不能描述为 24 次都顺利完成。前四次业务准备依次遇到登录过期、未等待跳转完成、首页加载超时、iframe 点击能力缺失；诊断夹具还曾误用只能读取普通输入框的接口，修正后保留原失败。

- 登录状态的服务端有效期已过，通过专用测试作者账号重新登录；口令只在本机进程内使用，cookie 存在被忽略的私有目录。不把此夹具算成产品自动登录。
- 只读对照证明：跳转后直接检查在约 11 秒失败，等待页面加载后同一条件在约 30 秒通过。补回导航等待，并设置有界的 90 秒导航期限；成功条件不变。
- 真实 iframe 点击需要 `DOM.getFrameOwner`。只允许当前 session 已归属的 frame，并只从该类型化返回登记 backend node。实际点击、已归属节点解析及三种越界拒绝通过；[证据](artifacts/09-L-diagnostic/diagnostic.json)和[能力依据](AMENDMENT-1.md)。没有开放全权 CDP。
- L、L2 的失败执行及可能产生的空草稿没有被倒填身份或重置。L3 是计划内另建的学习样本，不代表产品自动重做结果不明的旧任务。

[原计划](PLAN.md)与两份修订保留。准备上限曾由 6 调整为 8，以完成原定四个有效样本；其余额度不变，没有借用或重置旧研究额度。

## 对实现与验收的约束

实现时保留“取得目标关联或副作用证据即保存”的机制，不能等整个阶段成功才记录。恢复规则也须保存来源、适用输入和验证版本；缺少唯一归属、任何关键内容／素材条件不成立或最终派发仍有不确定性时，停止后续自动动作。新的继续只允许重新核对，不能使旧动作或旧模型提议重新有效。

本轮顺序执行单任务恢复，没有复验两项真实网页任务并行、完整原生人工接管、所有网站隐含写入、任意外部修改、私有附件下载、系统断电、备份恢复或打包更新。正文替换反例不证明所有外部编辑均可识别；本轮的规则与协议能力仍有覆盖范围。没有稳定目标的上传现场仍只能保留未知，也没有用人工恢复地址把这个缺口掩盖为通过。

这些范围进入后续组合验收，不新增产品保证、不缩小既有五项业务场景。下一项仍是 [macOS 自用应用的封装、更新与运行恢复](../../issues/25-macos-packaged-lifecycle.md)。
