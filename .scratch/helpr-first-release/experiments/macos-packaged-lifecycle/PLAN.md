# macOS 封装、更新与运行恢复：有界实验

2026-10-12，回答[封装、更新与运行恢复](../../issues/25-macos-packaged-lifecycle.md)。只使用虚构任务、文件、密钥和本机页面，不交付完整 helpr，不调用模型或业务后台。既有实验额度不沿用。

## 固定候选与来源

- 当前 Apple Silicon / macOS 14.8.3；Electron 44.7.0、Playwright 1.64.0 复用现有固定安装。
- 应用名 `helpr Lifecycle Lab`，Bundle ID `local.helpr.lifecycle-lab`，两版 `0.0.1` 和 `0.0.2`；安装在本实验的 `installed/`，独立 `.app` 必须包含依赖，不能引用开发目录或依赖外部 Node 命令。
- 当前 `security find-identity -v -p codesigning` 返回 0 个有效身份。优先试验独立的短期本机测试证书；新建私有钥匙串及本实验密钥，不读取或导出已有私钥，不修改系统信任、Gatekeeper、电源和启动项。若必须信任新根或取得用户证书，先停止这一分支并给出具体要求；未满足时不把临时 ad-hoc 签名当作身份连续性通过。
- 保留同一证书和明确 Bundle 身份，记录两版 designated requirement、完整签名校验和系统评估结果。自签名仅提供实验中的来源连续性，不能冒充 Developer ID、公证或正式 HTTPS 更新源。
- 原生输入扩展复用页面生命周期实验的 Objective-C++ / N-API 8 源码，在新构建目录重新编译，并保存源码、编译参数及二进制摘要；构建文件不提交。
- 控制拥有者在独立应用内启动，私有 pipe 和受限转接沿用已验证路径，工作者使用随应用携带的运行环境。原生窗口、凭据、Cookie 与 SQLite 必须在实际打包版本重新观察。
- 按 codebase-design 以小 Interface 统一进入更新资格、备份和恢复；场景夹具调用相同入口，不能修改状态绕过检查后宣称通过。

## 顺序与成功判据

1. 构建／签名与首次启动：核对完整包、原生扩展、SQLite、私有连接和实际双页操作；记录默认系统安装评估，不能关闭安全机制。
2. 关闭／退出／重开：收起保留现场与双页进度，菜单可返回；退出先撤销派发与保存，再清理自有进程；冷启动核对停止、待参与、未知等意图，不把全部任务改成停止。
3. 更新／备份：单独读取版本资料的检测不下载；手动安装或已开启的闲时模式才进入统一资格检查。活动、等待、接管、未知和临近计划均阻止安装；更新准备与新计划争用同一资格。备份排除凭据和浏览器资料，恢复旧备份保持自动工作暂停。两版真实签名更新至少一次；错误身份、架构、数据兼容、备份失败及中断均保留原结果并明确停止，不允许缓存包在下次启动绕过资格。
4. 真人核对：自动探针与真人输入分列。先完成自动检查，再逐步请用户做最少的点击／中文／粘贴和真实锁屏、休眠动作；没有用户回复及相应原生事件就不标通过。等待人不计为可更新空闲。

## 预算和停止

构建尝试最多 6 次，安装／升级动作最多 4 次（含首次及失败），应用启动最多 16 次（含重开与失败），本机 HTTP 请求最多 1,000 次，主动故障注入最多 12 次，真人核对最多 2 轮。模型请求、远程业务上传、发布为 0；不创建公开发布、不上传资料。

首次实际应用启动起，自动实验运行累计不超过 90 分钟；等待用户的期间须另记开始／结束，不伪造测试时长。源码修订和失败逐轮保留，不覆写已运行源码。每次启动前记账和冻结源码；达到上限或需要新增权限时保存现场，先形成具体修订。构建、包、profile、签名私钥及临时钥匙串忽略提交；归档原始判断、日志、哈希与来源。

## 官方机制依据

- [独立应用封装](https://www.electronjs.org/docs/latest/tutorial/application-distribution)：应用内容和原生依赖需随 Bundle 提供。
- [Apple Code Signing Tasks](https://developer.apple.com/library/archive/documentation/Security/Conceptual/CodeSigningGuide/Procedures/Procedures.html)：自签名适用于内部测试；只证明指定要求和版本来源连续性，不取得公开分发信任。
- [safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)：macOS 使用 Keychain；跨版本身份不一致可能再次请求授权。
- [autoUpdater](https://www.electronjs.org/docs/latest/api/auto-updater)：macOS 使用 Squirrel，发现更新即自动下载，且缓存更新可能在下一次启动安装。因此检测必须单独进行，不能在“仅检测”时登记待安装包。
- [Electron 44.7.0 fuses](https://github.com/electron/electron/blob/v44.7.0/docs/tutorial/fuses.md)：显式开启 Cookie 加密；签名前修改 fuse，不能将整个 profile 宣称为加密。

以上是机制依据和待验证假设，不代替本次运行证据。正式更新地址及发布维护条件另记为交付前提，不把本机测试服务器当作正式发布链。
