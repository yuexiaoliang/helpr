# 真实 AI 双页归属实验

对应 [验证可见工作区中的 AI 双页操作归属](../../issues/06-ai-parallel-binding.md)。这是取得选型证据的一次性实验，不是产品执行器。

候选组合：`deepseek-flash` 的封闭动作提议 + 独立 Node.js 执行进程 + Playwright 1.64.0 外部 CDP，分别接入 Electron 44.7.0 的双 `WebContentsView` 和 Chromium 双标签页。Chromium 同时加载只读身份扩展，核对 `tabId` 与 CDP target；Electron 核对 `webContents.id` 与 target。模型、浏览器请求和服务器操作均真实运行，网页业务是本机合成夹具。停止、切换查看、错误和队列延迟由实验程序注入，不冒充真人接管。Stagehand 不在本轮组合内。

## 预先固定的范围

- 两个相同 URL 页面同时探索，模型分别看自己的页面；后续才出现弹窗表单，两页提交在服务器真实重叠，最后核对文字、弹窗和回复归属。
- 切换查看不改变任务路由；导航后保持 target 身份。
- 取消正在等待按钮的动作及连续输入；在执行子进程排队、重试等待、真实模型回复迟到时停止；旧执行回复不能借用新执行。
- 真实模型请求取消、单任务页面错误、故意篡改成另一个任务的页面目标。独立 B 的真实模型循环继续完成。
- 每个浏览器原语都在实际派发进程检查执行身份并接收独立取消信号；页面、服务器和消息日志共同核对。

**预算在首个模型请求前固定：40 分钟、96 次调用、150,000 tokens，最多 6 次程序修订。** 时间从首次运行开始计；修订及失败保留原始证据，不重置总调用或用量。两种宿主共 18 个场景；每个自动探索循环最多 8 次提议，不无限重试。模型客户端沿用已有配置，凭据不复制到证据中。

实际首轮因维护者误判进度并重复运行，耗尽 96 次调用。随后对尚缺的五个 Chromium 场景单独登记了 [补测计划](artifacts/chromium-missing-cases/PLAN.json)，上限为 10 分钟、18 次调用、30,000 tokens、零协议修订，实际使用 17 次调用。两轮合计 113 次调用；不声称全部验证在原先 96 次上限内完成。完整过程见 [实验报告](REPORT.md)。

## 状态、计划与离线检查

本实验的固定身份和历史用量由 `registration.mjs` 登记，运行账本固定在 `private/experiment-state.json`，与输出目录分开。历史 113 次调用一起计入原来的 96 次上限，三个没有 usage 的请求保留估算 token 占用。因此本实验目前额度已耗尽；指定全新输出目录也不会获得新预算。

```sh
node run.mjs --status
node run.mjs artifacts/chromium-missing-cases --plan
node verify.mjs --check
```

`--status` 显示阶段、最近进展、进程存活、在途请求、未知用量和剩余额度。`--plan` 显示待验证场景、失效结果及缺失截图；二者均不改写文件，不读取模型凭据，也不加载浏览器依赖。读取损坏记录会报错。额度或时间已耗尽时，执行入口在启动浏览器前退出，列出未执行项。

账本使用单写入者锁、原子替换和同步落盘；请求在发出前取得持久化预留。进程退出后，已预留但没有 usage 的请求继续占用额度，确认旧进程不存在后可取得锁。锁的所有者无法确认、锁获取过程中留下不完整现场、账本或登记标记丢失时保留文件并报错，需检查现场后处理。保存的账本上限优先于再次传入的登记值；预算变更应另行明确登记，输出目录不是预算变更入口。

功能断言完成即写入账本；截图显示、截图保存和清理各自记录结果。截图失败不使已通过场景重新执行；同一次运行可通过 `collectEvidence` 补采仍留存的页面，新的场景开始后或进程重启后，旧页面被标为不可用，补采不会调用模型或重放动作。连续修改同一实验程序计入修订预算，单独修改采集实现也计程序修订，但不使功能结果失效。

执行指纹包括驱动、场景断言、宿主、扩展、共享控制和模型客户端、依赖锁文件、运行平台与 Node 版本，以及模型配置的哈希。配置值和凭据不写入指纹。截图代码单独记录。旧的 18 项证据缺少完整指纹，因此当前计划不会把它们当成新驱动的通过结果；历史结论继续由各次保存的源码快照和日志支持。

`verify.mjs --check` 只校验历史证据，保留索引原样；省略 `--check` 才更新 [证据索引](evidence-index.json)。复查按固定的历史协议哈希核对快照，不要求经过改进的当前驱动与旧源码相同，也不把离线回归说成新的真实模型实测。

仓库根目录 `npm run check` 已接入源码语法、客户端夹具、运行防线测试及历史证据复查；`npm run test:browser` 运行既有的本机浏览器回归。[CI](../../../../.github/workflows/check.yml)运行这两组检查。新测试通过已确认的模型请求、运行／状态及只读计划入口，使用回环 HTTP 假模型、真实文件和子进程故障注入。实现验收见 [运行防线规格](CONTROL-SPEC.md)，原因与历史经过见 [复盘](RETRO.md)。

将来有已登记额度的实验运行仍使用相邻 `independent-stop` 中锁定的 Electron、Playwright，以及 `model-api` 的本机模型配置。`node run.mjs [输出目录]` 保留 `PLAN.json` 的宿主／场景限制，也支持 `HOST_FILTER` 与 `CASE_FILTER`；过滤条件错误会报错。输出目录保存源码快照、模型输入输出、控制与服务器事件、截图和结果；本机浏览器配置和运行账本忽略提交。

结论仍限于受控网页和本轮单原语集合，不证明共享登录冲突、业务后台并行、任意第三方代理内部动作或生产恢复能力。
