# 真实 AI 双页归属实验记录

2026-10-10，America/New_York。**Electron 外部 CDP 和 Chromium 外部 CDP 各取得 9 项场景的符合预期证据。** 真实模型在两个同地址页面中分别填写文字、打开各自弹窗并保存；模型请求和网页提交均有实际重叠。任务 A 的停止、页面错误和越界目标被隔离，独立 B 继续完成。

这是 `deepseek-flash` + 小型封闭动作执行器 + 独立 Node.js 派发进程的受控网页证据。它支持继续比较两种宿主，不代表 Stagehand、任意代理 SDK、真实业务后台并行或完整 helpr 已经通过。事项结论位于 [验证可见工作区中的 AI 双页操作归属](../../issues/06-ai-parallel-binding.md#answer)。

## 实验组合与真正并行的依据

| 项目 | 本次实际使用 |
| --- | --- |
| 本机环境 | macOS arm64，Node.js 24.18.0 |
| 页面原语 | Playwright 1.64.0；外部 `connectOverCDP`，`noDefaults: true` |
| Electron | 44.7.0，内嵌 Chromium 152.0.7977.130，两个 `WebContentsView` |
| 普通 Chromium | 156.0.8078.4，两个标签页与只读身份扩展 |
| 模型 | 用户已有配置的 `deepseek-flash`，真实 Chat Completions 工具提议；非思考模式 |
| 网站 | 仅监听回环地址的合成网页；表单向真实 HTTP 服务器提交并产生记录 |

主进程为每个任务独立构造模型输入；模型只从实际页面的可访问树提出一个 `click`、`fill`、`type` 或 `finish`，不能提交脚本。具体按钮名称和填写位置由模型从当前观察中选择，输入值通过本任务引用绑定。表单与故障注入属于测量夹具，不作为产品网站知识。

动作通过 IPC 交给独立执行进程。该进程维护 `task + execution + generation` 与明确的 CDP target 归属，调用单个 Playwright 原语之前立即检查有效身份，并传入该执行的独立 `AbortSignal`。观察、弹窗登记、结果、重试和排队动作分别检查归属与有效性。没有把一个不可取消的多步浏览器脚本包成“已可停止”的动作。

两页初始 URL 完全相同、target 不同。Electron 将 target 对应到 `webContents.id`；Chromium 通过扩展的 `chrome.debugger.getTargets()` 对应到 `tabId`，并核对弹窗。扩展只提供身份信息，没有在本轮作为动作执行通道，也没有测试扩展 debugger attach 与其它调试客户端争用。

每次观察只包含本任务的根页面及按 opener 归属登记的弹窗。详情表单在打开弹窗后才可观察，模型需要再次判断；模型不是提前得到整个动作序列。两边最终文字、任务标识与模型回复分别匹配，没有串到另一项任务。

并行依据来自两个层面：

- 每种宿主均存在 A/B 真实模型请求时间区间重叠。选用证据中单对重叠最长分别为 Electron 981 ms、Chromium 1,063 ms；这不是延迟或吞吐保证。
- 网站等待两份真实表单都到达再返回；事件中同时有 A/B 两个在途提交，然后分别生成两条记录。相应关键事件是 Electron 第二次运行的 `seq 83`、Chromium 第一次运行的 `seq 607`。这是请求实际重叠，不是从 `Promise.all` 写法推断并行。

期间自动切换根页面的查看状态 8 次，路由仍按明确 target；弹窗导航到结果页后 target 与 opener 关系保留。切换由实验程序执行，未收集真人查看或输入样本；截图在执行完成后单独显示对应视图采集，不能用截图证明用户当时看到的窗口安排。

## 九项场景的结果

下表每项在两种宿主中均取得符合预期的结果。页面错误、越界目标和取消用例的“通过”表示预期拒绝及隔离发生，并非动作成功。

| 场景 | 实际观察 |
| --- | --- |
| 同地址双页探索、弹窗与导航 | 两组不同文字分别保存；模型和服务器请求重叠；原生身份、弹窗 opener、结果与回复归属正确 |
| 等待点击时停止 | A 的真实模型提议已进入等待禁用按钮的原语；取消后启用按钮，A 没有提交，B 完成 |
| 连续输入时停止 | 两种宿主均只留下 `ABC`；B 完成后仍为 `ABC`，没有继续输入剩余字符 |
| 执行进程排队后停止 | 真实提议已跨 IPC 到达、尚未派发；停止确认后释放队列，执行进程拒绝旧工作，A 无提交 |
| 重试等待中停止 | 首次等待按钮超时后进入受控重试队列；停止并启用按钮后释放队列，旧重试被拒绝，A 无提交 |
| 迟到回复遇到新执行 | 使用真实模型已返回的提议，故意延迟交付；停止旧执行、显式开始新代次后，旧回复被父进程拒收，另行故障注入到执行进程仍被身份检查拒绝；只有新执行产生一条 A 记录 |
| 真实模型请求取消 | 通过独立信号取消 A 的真实请求，客户端记录 `client-aborted`；B 的请求与网页循环完成。没有证明模型服务端停止计算 |
| A 页面出错 | 真实模型提议返回后移除 A 的目标，A 超时；错误归属 A，B 完成，A 无提交 |
| 篡改为 B 的页面目标 | 将 A 的真实提议故意改成 B target，实际派发进程返回 `foreign-page`；B 自己的循环完成，篡改动作未派发 |

各停止场景均在服务器层核对 A 的结果数量，而不只检查派发日志；连续输入还核对取消结束与 B 完成后的实际字段值。正常调用不会转发迟到回复，额外送往执行进程的旧提议是检验第二道检查的故障注入，报告不将它伪装成模型自主行为。

选用证据中，从父进程发起停止到执行进程确认在途浏览器调用结束，观察值为约 0.216–3.095 ms。这是短小本机实验的单次时间，不是用户响应上限，也不表示已有服务端结果被撤销。旧执行恢复为新代次是测试安排，不是产品收到“停止”后自动重启。

## 资源、失败与复查

以 1.5 秒间隔抽样本实验进程树 RSS，记录峰值约 **1,508 MiB**。它包含驱动、宿主、执行进程与 renderer，RSS 求和可能重复计算共享内存；两种宿主依次运行，样本不是稳定态、压力测试或整机最低内存要求。没有观测到 HTTP 限流；当前调用规模不能推导提供方并发配额。

隐藏的 Electron 视图使首次结果截图等待绘制并超时，已有模型、网页和服务器结果仍保留。仅调整证据采集：在任务结束后显示要截图的视图，设置 4 秒超时，将截图结果与功能判断分开记录。没有改变模型提示、实际动作、取消协议或网站表单。补测与之前的 `worker.mjs`、`model.mjs`、`lab.mjs`、`electron.cjs` 哈希完全相同；每次运行均有源码快照。

实测结束后，驱动补上了按兼容执行协议跳过已通过场景的续跑方式，以及浏览器启动和场景开始前的预算检查，避免预算耗尽仍进入后续场景。两份 `--plan` 的离线检查证明原实验剩余五项且调用余量为零，限定补测余项为空；检查前后模型记录文件字节不变。这些驱动改动没有被冒充成本轮运行时已存在的能力。

离线复查覆盖保存的全部尝试：258 次逐原语派发、166 份观察、113 份模型输入，页面归属与已停止代次均通过；另核对 18 项选用证据的实际服务器记录和停止／错误后 B 的完成顺序。保存 56 张截图，并查看两种宿主的结果页图像。失败行、中断现场和重复调用均保留在证据中。

## 供后续选型使用的范围

两种宿主都可进入后续选择，当前事实支持“显式页面身份 + 每执行独立控制 + 实际派发端逐原语检查”的小型 AI 执行器。Playwright 的 [ariaSnapshot 取消参数](https://playwright.dev/docs/api/class-locator#locator-aria-snapshot)、[click](https://playwright.dev/docs/api/class-locator#locator-click) 与 [连续输入](https://playwright.dev/docs/api/class-locator#locator-press-sequentially) 文档提供接口依据，取消和隔离结论来自本次锁定版本的实际运行；[Electron target 映射](https://www.electronjs.org/docs/latest/api/web-contents#webcontentsfromdevtoolstargetidtargetid)用于原生身份核对。

尚不能推广的范围明确保留：

- **真人接管**：自动停止与自动切换不代替真实鼠标、中文输入法和粘贴来源识别；交给 [人工接管验证](../../issues/12-human-input-takeover.md)。
- **真实完整流程组合**：既有完整发布流程与本次逐原语控制尚未合成一个执行器；本次没有验证双任务上传、下载、已学流程重放、流程修复或更新竞争。
- **共享资源与恢复**：同一登录状态、同一业务对象、系统剪贴板、进程崩溃、浏览器重连与持久化恢复未覆盖；不能把两个独立页面当作服务端事务隔离。
- **写请求范围**：没有解决上一轮发现的未知写请求与上传字节关联问题；继续由 [请求关联验证](../../issues/18-action-request-association.md)处理。
- **其它工具与网页结构**：Stagehand、其它代理 SDK、嵌套弹窗、任意跨域页面、原生文件窗口和不接受取消的浏览器内部工作未验证。SDK 如需替换本执行器，应先证明等效的逐原语控制，不能只看是否接受 `page` 参数。

这些范围进入已有承载选型、接管、状态、请求关联与恢复事项及后续实现验收；本项不确定最终宿主，不增加用户的停止确认步骤，也不宣称产品首版两项并行已实现。
