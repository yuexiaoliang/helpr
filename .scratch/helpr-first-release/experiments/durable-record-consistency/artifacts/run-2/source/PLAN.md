# 持久记录与执行资格：有界实验

2026-10-12，依据[待验证事项](../../issues/22-durable-record-consistency.md)和[已确认协议](../../issues/10-durable-execution-contract.md#answer)。这是协议实验，不是产品实现或真实网站验收。

## 范围与预算

本轮最多 6 次实验运行，每次最多 60 个场景、120 次本机效果请求、180 秒；每次启动先保存候选与检查程序的完整源码及摘要，独立目录保留失败、实际消耗、事件、结果和数据库。只使用本机虚构素材，模型调用、远程上传和发布均为 0。最多保留 300 MiB 实验资料，达到上限停止；不填满磁盘、不改变系统设置、不终止非实验进程。环境读取与语法检查不计为效果实验。

Interface 为记录拥有者的命令入口及事实读取入口；所有场景和执行者通过相同入口。独立接收端对每次请求分别记收到与完成，不去重、不读取候选数据库；检查以其日志及已知输入核对，不能只相信候选的返回值。故障注入是实验控制，不属于产品 Interface。

## 固定环境与候选

- 当前 Node v24.18.0 的 `node:sqlite`，实际 SQLite 3.53.1，source ID 在每次环境记录中保存；不安装或替换用户运行时。
- 权威业务记录使用一个 SQLite 数据库，`journal_mode=DELETE`、`synchronous=EXTRA`、`fullfsync=ON`、`foreign_keys=ON`，启动读取实际值，不只发出设置命令。短事务与网络等待分开。
- 另一个专用 SQLite 锁文件仅持有进程级排他锁，不存任务或资格；它用来验证重复拥有者竞争，不把锁的释放当成外部效果已终止。旧资格通过持久代次、任务版本与动作的一次性派发阶段失效。
- 素材先经文件同步、重命名和目录同步，再登记摘要与长度；读取时复核。Node 文件 `fsync` 不等同于 macOS `F_FULLFSYNC`，真实断电的素材落盘不在本轮保证内。
- 接收端只有本机虚构效果。浏览器控制连接、身份认证和真实旧浏览器命令的隔离另由控制连接事项验证；本轮不将 IPC 实验当成它们已经通过。

## 场景与判定

1. 接受确认、预留动作、领取轮次、结果与处理事实共同登记、采用流程候选，在提交前与提交后分别强杀拥有者；重开核对原子变化和响应丢失后的重试。
2. 预留已落盘但尚未派发、派发资格已消费但尚未发送、效果已发生但本地未完成：分别保持未知；独立观察可以确认完成时只记账，不重发。
3. 两个独立调用进程竞争同一恢复资格，重复主程序竞争拥有者，旧资格与旧回调迟到，恢复核对期间新的停止；最多一份有效操作资格，新停止优先。
4. 同一回复重复送达、请求身份换输入、旧内容确认、停止前待答请求、已经接受的确认跨重启保留；两项任务的确认与效果独立。
5. 重复轮次及后续轮次遇到等待、停止、未知、完成的相同素材工作；改名／移动不新建，目标／期次／素材版本／明确再发分别处理。
6. 两个执行固定旧流程，各自留下修复候选，竞争采用不互相覆盖；中断前后当前引用与候选关系一致。
7. 文件写好未登记、已登记但文件缺失或变更、真正的 SQLite 只读和页数上限故障；拒绝缺失输入，关键保存失败后禁止派发。停止保存失败且进程死亡不能伪称停止意图已落盘。
8. 辅助截图无法保存不抹掉完成事实；关键核对依据缺失保持未知。两项本机效果在同一时段实际待完成，证明数据库短事务未跨网络等待持锁。

先跑最小贯通场景，再按同一 Interface 增加场景。固定完整候选后至少再跑一次全场景；竞争场景交换或同时发送顺序。不自动耗尽预算；出现同类阻碍或需要扩大范围时先记录具体差异。

## 官方机制与已知问题核查

- [Node v24.18.0 SQLite 文档](https://nodejs.org/download/release/v24.18.0/docs/api/sqlite.html)：使用同步连接和参数绑定；正式产品的 Electron 运行时绑定仍需另外核对。
- [SQLite 同步配置](https://www.sqlite.org/pragma.html#pragma_synchronous)及 [fullfsync](https://www.sqlite.org/pragma.html#pragma_fullfsync)：DELETE / EXTRA 包含提交时删除日志后的目录同步；配置返回正确不等于真实断电已验收。
- [SQLite 文件锁](https://www.sqlite.org/lockingv3.html)与[损坏风险](https://www.sqlite.org/howtocorrupt.html)：只在本机文件系统运行，不边运行边复制或直接改写数据库，不删仍被使用的锁文件。
- [版本记录](https://www.sqlite.org/changes.html)显示 3.53.1 后仍有修复，[3.53 分支修复记录](https://sqlite.org/src/timeline?from=version-3.53.0&to=version-3.53.4&to2=branch-3.53&y=ci)须核对。本轮版本只是固定实验条件，不据此锁定产品依赖或宣称没有其它缺陷。已知 [WAL-reset 问题](https://www.sqlite.org/wal.html)在 3.53.0 修复，本实验也不启用 WAL。
