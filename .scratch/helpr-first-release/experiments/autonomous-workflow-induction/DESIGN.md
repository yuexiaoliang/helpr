# 无人工修订的归纳实验设计

这是技术决策实验，不是产品实现。依据是“验证无需人工修订的流程归纳与条件校准”。

## 固定实验边界

- 使用已准备的隔离后台和虚构素材，授权来自测试委托。模型只能操作新建的测试记录，不得修改既有记录或站点设置。
- 自然语言委托解析成带原文引用的输入和目标描述。文件元数据由实际文件计算；模型不能修改原文、文件摘要或实验授权。目标描述的语义正确性仍须由独立测试评价，不能仅凭原文引用证明理解正确。
- 第一次探索只接收当前真实页面、委托和先前动作，不能读取旧实验的路径、选择器或候选。每次只提出一个动作；首次探索和复用使用同一个执行 Interface。
- 记录动作、阶段、前后观察以及网络写入。不向模型提供凭据、Cookie、请求正文或服务端秘密。
- 从真实探索记录分别尝试整体归纳和按阶段分项归纳。组合器只按记录顺序连接完整提议，不替换网站定位、参数或条件。无效提议经程序诊断后交回模型修订，绝不人工补写候选。
- 上传校准截住真实上传请求。候选条件必须在未完成时失败、释放请求完成后通过；仅 JSON 正确或模型自述检查过不算证据。重复发布不用于校准；遇到提交不确定即停止该执行。
- 学习阶段独立记录动作效果；复用核对封存动作及效果，不能通过把提交改为读取绕过检查。这个机制仅保护已有判断，不能证明能识别未知网站副作用。
- 相近委托先经模型匹配，再校验原文引用、输入和任务约束。固定输入绑定、规则来源和独立结果断言分别记录。
- 实验初始预算为最多 64 次模型请求、累计 220,000 tokens、单次请求 120 秒、总运行 35 分钟；完整候选最多两次自动校准修订。首轮在重复填写同一已满足输入时由维护者中止，用量 164,918 tokens（16 次调用，其中 1 次取消）。修正通用进度检查及冗余观察后，在第二轮开始前一次性调整总上限为 **64 次调用、400,000 tokens，包含首轮失败**；第二轮可用 48 次调用、235,082 tokens，不再增加预算。各轮元数据单独保留。

## 实验驱动修正记录

第一轮把字段值和可访问名称同时发给模型，模型仍把未变化的空输入标签解释为内容丢失，重复填写标题；程序的即时字段值检查事实上一直通过。原驱动没有拦截无进展填写，失败上下文还重复携带过时页面。第二轮增加当前输入满足情况、重复填写拦截、紧凑失败反馈和阶段差量；这些是跨网站通用修正，不改任何候选选择器或网站条件。首轮停止时还发现关闭页面期间无名称 frame 的诊断错误，第二轮跳过这种 frame，原错误证据保留。

后续仍在同一剩余预算内，依次验证按步后实际页面校准、一次有限格式修复和原生工具调用。尝试重用的前缀全部来自本实验模型的实际执行记录；页面状态不同导致前缀失败时重新观察，没有手动替换网站步骤。每轮的停点、协议变化和未完成阶段分别保留，不能混为固定方案的重复试验。

最后的局部探针进一步收紧模型输出为单个字段观察位置。程序依据通用 `fill` 动作固定相等比较及原动作的输入引用；模型不再同时选择比较语义和期望内容。该探针只检验正文条件，完整流程比较、上传和发布没有运行。最终用量和实际结果以报告及证据索引为准。

## 评价

成功条件是通用程序使用未经维护者修订的候选，在另一组未用于修订的素材上执行并核对实际结果。报告同时记录正确完成、正确拒绝或需要参与、错误宣告成功、执行失败和未运行。独立断言及页面故障注入仅在测试驱动中使用，不进入运行时选择或成功判断。

这次实验不评价第二后台、用户预览版本绑定、实际 AI 双页并行、人工接管或提交中断恢复；它们有各自事项。
