# 免费开发签名验证方案

状态：已搁置，未执行。2026-10-13，用户将自动下载安装推迟到产品盈利后，本方案不再是首版前置工作，也不继续等待安装选择；尚未下载、登录、签发或执行。以下保留原候选方案供未来另行规划时参考，不构成继续执行授权。

2026-10-13，用户先追问签名影响哪些功能，以及首版未正式签名对外提供是否可用，随后选择延后自动安装。免费 Personal Team 仅是原先为当前 Mac 准备的诊断候选，不作为面向其他用户分发的已选路线。当前自用交付约定保持，更新范围见[最新决定](../../issues/26-unattended-update-credential-continuity.md#answer)。

目标：以最低新增条件判断免费 Apple 开发签名能否解决当前自签名换版后的凭据拒绝。此轮只决定是否值得继续真正的自动更新实验，不交付产品，也不承诺免费路线一定满足全部门槛。

## 为什么值得先试

用户没有 Apple Developer Program 会员或证书。Apple 允许未付费账户通过 Xcode 的 Personal Team 管理开发证书；Security 源码也为符合 Apple 开发证书链规则的调用者提供团队分区，而实验自签名落在代码指纹分区。这是待检验的机制依据，不是运行保证。[账户说明](https://developer.apple.com/help/account/basics/about-your-developer-account/)、[调用者分类](https://github.com/apple-oss-distributions/Security/blob/b4bd4fda62af1ebf469ee97f0112fb49363fb482/securityd/src/clientid.cpp)

Apple 对 Personal Team 的 App ID、设备登记和 provisioning profile 规定了七天限制；但无受限 entitlement 的普通 Mac 应用不必带 provisioning profile，不能据此断言所有本机 Mac 应用七天后必定停用。实际证书到期日、签发类型、团队归属与续期路径仍须核对。[TN3125](https://developer.apple.com/documentation/technotes/tn3125-inside-code-signing-provisioning-profiles#Entitlements-on-macOS)

免费开发签名不提供 Developer ID 分发和公证能力。即使钥匙串对照通过，真实更新下载后的系统检查、维护和证书更换仍未通过；不会要求关闭 Gatekeeper 或清除隔离属性来把失败变成成功。

## 准备条件与分工

当前 Mac 为 Apple Silicon、macOS 14.8.3，只装有 Command Line Tools；未发现 `/Applications/Xcode.app`。检查时剩余空间约 100 GiB，安装前再次确认。

选择 **Xcode 16.2**：Apple 列出的支持范围含 macOS Sonoma 14.5，因此适配当前系统，不需要先升级 macOS。经 Apple 官方下载页选择该版本；不从第三方下载，不默认安装当前 App Store 最新版。[系统要求](https://developer.apple.com/xcode/system-requirements)、[Apple 下载入口](https://developer.apple.com/download/all/)

用户确认此路线后，agent 负责可自动完成的下载准备、包校验、安装检查和后续对照。登录 Apple 账户、双重验证、开发者协议和系统安装授权由用户在 Apple／macOS 自己的界面完成；密码、验证码、私钥不进入对话或日志。页面就绪后只给当前所需的一步说明，不要求用户自行排查签名。

首次设置包括：

1. 在 Apple 官方页面下载 Xcode 16.2，完成官方包校验后安装到 `/Applications/Xcode.app`。下载前核对官方显示的大小与剩余空间，避免选装无关平台模拟器。
2. 在 Xcode 的账号设置中登录本人 Apple 账户，确认显示 Personal Team。仅首次新增账号或协议需要本人处理；不购买会员、不自动同意付费条款。
3. 用该团队的证书管理入口创建一张供本机开发使用的 Apple Development 证书。若该选项不可用、要求付费或需要撤销已有证书，保存提示并停止，不自动改走其他方案。
4. agent 核对签发者、有效期、证书链、团队标识和本机私钥是否可签名。私钥保留系统钥匙串中，不导出、不改变系统信任、不更换默认开发工具路径。

## 证书取得后的最小对照

冻结实际证书指纹和链、系统版本及源码摘要后，沿用[原生诊断](DIAGNOSIS.md)的同路径两版模型，仅将实验自签名身份换为新开发身份。使用独立的新虚构项目，不操作旧实验項或用户密钥；账号／服务名必须在运行前固定。旧版创建并读回，新版禁止授权交互后读取，再由旧版清理并确认不存在。

同时检查普通指定要求及项目分区，不能只看 `TeamIdentifier` 或“签名成功”。不手工扩大 ACL 或预先加入新版指纹。首次允许开发工具使用新签名私钥与更新后的凭据授权分开记录；后者一旦需要人工参与，这个更新样本就是失败。

此阶段上限：一份 Xcode 下载与一次安装、一张免费开发证书；两次原生编译、两次签名、四次原生运行、一个虚构项目及其清理；证书就绪后的自动对照最多 15 分钟。下载与本人登录等待单独记录耗时，不能用超时重启多轮。Electron 构建、安装、启动、自动更新、模型调用和远程业务写入均为零。旧实验额度不挪用；出现新失败就保留证据和累计次数。

仅当同一原值在代码变化后无需新系统授权即可读回，且清理可确认时，才将这项诊断标记为通过。失败保留原始状态、日志与精确错误，不通过交互授权重做同一失败样本。

## 通过后仍须完成的工作

另行冻结同一实际签名身份、Electron 版本、固定安装路径与可信 HTTPS 更新来源，以真实闲时更新入口验证连续两个版本跃迁；确保原模型凭据和未过期网站会话延续，任务和停止意图保留。还须明确证书续期／更换、签名校验失败、下载后系统评估和凭据拒绝的处理。不能用手动替换安装包或同版本重开替代。
