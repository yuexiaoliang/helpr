# 第二后台流程对照

一次性技术实验，范围与预算见 [计划](PLAN.md)，对应[取得第二后台的流程对照证据](../../issues/11-second-backend-comparison.md)。

本轮已结束：七步完整路径、换输入校准和两份保留样本通过；原样程序失败及通用修订均保留。结果与边界见 [REPORT.md](REPORT.md)，离线复核用 `node verify.mjs --check`。下列真实执行命令只说明已用入口，不应重新消耗已结束的登记。

`runtime.mjs`、`protocol.mjs`、`upload-permit.mjs` 和 `run.mjs` 来自已完成的分阶段流程实验，原始摘要及初始配置改动见 [来源记录](source-origin.json)。初始执行器调整登录态路径、URL 敏感查询参数脱敏和每轮写请求预算；夹具、独立断言和执行次数限制单独接入。不修改历史实验源码。

`setup-site.php` 仅在独立 Drupal 测试容器中创建原生内容结构、栏目、附件字段及测试编辑账号，不创建实验文章，不属于网页学习程序。`fixtures.mjs` 提供虚构委托和独立的公开页面、栏目与下载字节断言；其中的页面定位不传给模型或执行器。

## 入口

在本目录中运行。真实模型、上传与发布均消耗 [固定预算](PLAN.md)，不可通过新目录或删除登记重置。

```sh
node run.mjs learn
node run.mjs calibrate
node run.mjs evaluate
```

第一次校准的结果定位失败后，使用 `node calibrate-result-position.mjs` 只读核对原发布结果并取得模型位置提议，再执行第二次校准。助手没有手填结果选择器。

学习失败后，仅当已保存的动作前缀可解释且预算允许时，可把该轮 `results.json` 作为 `learn` 的第三个参数；此前的失败继续保留。已执行但结果不明的提交不重复发送。

网页登录态保存为被 Git 忽略的 `private/auth.json`，也可由 `HELPR_TEST_AUTH_STATE` 指定。模型配置与凭据沿用 `../model-api/` 的现有配置。实验元数据、模型记录、版本源码、网页观察和结果保存在 `artifacts/drupal/`；敏感查询参数在送入模型前脱敏。

## 原有保证的边界

本实验继续采用原有输入、文件选择、上传完成、动作前就绪与公开结果的分阶段检查。它不因此取得所有网络副作用与动作均可完整关联的保证。新后台出现的请求关联事实需交给已有的专门事项，不能仅凭最终文章正确宣布副作用授权成立。
