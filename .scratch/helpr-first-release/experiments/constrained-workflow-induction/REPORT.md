# 受限提议下的流程归纳：完整路径未通过

2026-10-10。对应 [验证受限提议下的完整流程归纳](../../issues/16-constrained-workflow-induction.md)。这是一次有预算上限的决策实验，不是产品实现或首版验收。

## 结论

**完整自动归纳仍未成立。** 受限提议取得了新的局部证据：同一协议下的 10 步已执行前缀可换标题、正文和素材路径重放；真实发布动作即使故意标成 `read`，其 POST 仍被程序拦截。但上传本身也被拦截，没有形成完整候选，没有发布、独立下载或完整保留集结果。

当前明确被证伪的是实验执行器的上传放行假设：把 Playwright 暴露的请求正文当成包含完整原文件的字节流。真实校准中源文件为 **3755 字节**，multipart 请求通过 `postDataBuffer()` 暴露的内容只有 **353 字节**。程序要求这个 buffer 包含整个源文件，因此授权上传无法通过。这个失败应归于当前执行约定与浏览器观测能力不匹配；它没有证明受限模型提议无法完成后半段任务。

下一步应先验证上传凭据与完成检查的分工：在通用文件输入动作处验证授权文件及浏览器实际选择的文件，把请求观察用于关联，把网页结果和独立下载用于判断上传完成及字节一致；最终提交仍需单独的任务条件检查。具体能提供哪些保证，必须取得真实证据，不能直接按此建议宣称可靠。

## 模型与程序各自做了什么

| 阶段 | 模型提议 | 程序持有的语义与约束 |
| --- | --- | --- |
| 委托解析 | 输入 key、原文 value/quote、素材 id、任务类别与相容性 | 验证 quote 来源、素材真实存在、输入类型与模板一致；冻结任务和素材摘要。语义理解本身仍依赖模型。 |
| 动作选择 | 当前观察中的控件编号、通用动作、输入来源、字面常量、名称绑定、效果判断 | 所有编号由真实页面唯一匹配产生；未知字段、非法类型、非法控件、混合输入与字面量、错误名称绑定均拒绝。 |
| 输入核对 | 不提出期望值 | `fill` 固定比较原输入，`check` 固定比较原布尔值；可访问名称改变时用同一 DOM 节点找到观察位置，不重复写入。 |
| 条件归纳 | 不编写完整条件 JSON | 已明确为相等比较、且观察名称恰好等于该输入时，名称绑定到同一输入引用。其它字面量保持原值。点击阶段条件来自后续实际可用的控件，不能代替业务成功条件。 |
| 上传及提交约束 | 效果标签只作建议 | 上传路径和本地哈希不可变；同源非安全请求独立检查。模型说 `read` 不能关闭请求检查。当前上传字节例外存在已证伪假设。 |
| 公开结果 | 已实现但未运行：选择每个输入对应的实际观察位置 | 已实现但未运行：固定原输入或原文件哈希，在独立页面核对，并执行独立测试断言。不能把这段代码当作结果规则已自动生成的证据。 |

这是 [codebase-design](../../../../.agents/skills/codebase-design/SKILL.md) 所要求的小 Interface 尝试：调用方提交封闭的小提议，Implementation 隐藏定位、绑定、守卫和检查。当前仍是实验 Module；没有第二个 Adapter，也没有据此确定产品架构。

## 复用来源和人工介入边界

第一次与第二次探索从自然语言、实际素材、已登录页面开始。网站控件和动作由模型从真实观察中选择，维护者没有提供网站路径、选择器、栏目绑定或发布成功文案。

第三、第四次探索复用了第二次的前七步，来源及 hash 在 `reusedSource` 中。程序在遇到缺少动态名称绑定的动作前截断前缀，没有沿用后面的过早发布动作。第三次暴露正文定位的样本依赖；第四次使用通用的相等观察名称绑定规则归一，并记录归一前后内容。归一依据是已执行动作的输入引用和原样本值，不是维护者指定正文选择器。

诊断校准使用第四次成功的 10 步，重新解析新委托后执行。标题、正文、文件路径和名称不同；Excel 内容字节与第四次相同，且上传未完成，**不能称为新素材的完整复用**。栏目仍相同，未验证换栏目。最后的错误效果提议来自第二次真实发布控件，只由测试夹具把首次执行时的标签改为 `read`；没有利用已封存候选的篡改检查。

测试网站和业务断言只存在于此前的 `fixtures.mjs` / `verify.mjs` 及运行时数据。模型客户端、登录态、浏览器依赖沿用已有实验；本次未读取或修改旧版 flowpolit。维护者对通用协议的三次修订均有记录，不能描述成实验程序从一开始就无需调试。

## 上传为何失败

[诊断记录](artifacts/run/diagnostic-calibration/results.json)保存了请求类型、可见正文长度和摘要，没有保存请求正文或凭据。实际 multipart 已发生，不是没有找到文件输入；`setInputFiles` 已返回。程序在网络处拒绝它，所以等待“已获授权的上传被暂停”的逻辑超时为 `upload-not-observed`。这个错误名称不能被解释成浏览器没有发起上传。

本机安装的 Playwright 1.64.0 在 Chromium 路径中将 `postDataEntries` 中存在的 `bytes` 拼接成 `postDataBuffer`，并不补齐没有暴露的文件内容（`playwright-core/lib/coreBundle.js` 37841 行附近）。Chrome DevTools 的 `Network.getRequestPostData` 文档也明确说明 multipart 文件内容会被省略；这是另一个相关读取接口的限制，不能把它混称为 Playwright 当前实际调用的方法。实际失败判断以本次 **353 < 3755** 的记录为依据。[Chrome DevTools 协议定义](https://github.com/ChromeDevTools/devtools-protocol/blob/master/pdl/domains/Network.pdl)

因此，当前规则同时做到了拒绝未满足条件的 POST，也误拒了正常授权上传。还记录到界面操作引发的后台 POST 被拦截；不能把“所有非安全 HTTP 请求”等同于“最终发布”，也不能把按钮标签或 `effect` 标签当成副作用分类的完整证明。

## 防护证据及其限制

- [错误效果探针](artifacts/run/evidence-index.json)只统计 `wrong-effect-s9` 开始之后的请求：实际发布确认按钮被点击，提议为 `read`，POST 因附件条件未覆盖而被阻止。该证据独立于候选封存规则。诊断原始列表还含前缀中的其它后台请求，不能把它们算成多个发布反例。
- 包裹对象、额外授权字段、错误布尔类型三个刻意构造的非法提议均被 schema 拒绝。这是局部协议负例，不是完整业务保留集。
- [最终截图](artifacts/run/diagnostic-calibration/page.png)显示发布失败提示和仍等待上传的 File 块，与事件记录一致。没有把可见的 Publish 按钮或 File 块当作成功。
- 请求拦截不是通用副作用识别器。有副作用的 GET、其它传输通道、后台异步行为及服务器内部操作不在本次保证之内。新建页的 GET 本身可创建测试草稿，因此不能声称“拦截 POST 即没有写入”。
- 动作超时的保守停止、未知状态处理只有本次有限场景的证据；未验证所有取消、恢复或迟到结果情形。
