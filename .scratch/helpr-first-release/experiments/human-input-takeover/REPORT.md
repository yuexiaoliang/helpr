# 人工接管输入实验记录

2026-10-11 开始，2026-10-12 更新（本机时区；原始记录使用 UTC）。事项：[验证人工接管的输入识别与让出操作](../../issues/12-human-input-takeover.md)。

## 当前结论

**本轮受控机制验证完成：查看与对话不接管网页，真人点击、中文输入和 ⌘V 分别让 A 让出而 B 继续；明确继续后先核对页面，续做三步仍保留两处文字。** 用户已确认最终“都保留了”。最新组合 20 项自动断言通过，三轮真人证据合计 14 项断言通过，最终界面与反馈一致；[完成记录](artifacts/run-1791783746833/completion.json)和[核对记录](artifacts/run-1791783746833/validation-review.json)关联原始证据。事项按此范围标为 `resolved`，答案见[事项结论](../../issues/12-human-input-takeover.md#answer)。

真人样本分别来自第 9 次查看／聊天及鼠标、第 13 次中文、第 14 次粘贴及最终继续。最后一轮在准备阶段恢复已核对的中文值，未将恢复写成新真人输入，未宣称四步在同一窗口不中断地连做；第 12 次[工具自测](#授权后工具自测)也不计为真人。页面刷新附近出现过未知归属，实际休眠恢复仍未验证；[页面变化后的输入归属与继续](../../issues/19-page-lifecycle-input-ownership.md)将补齐影响选型的事实，不因本次受控通过而省略。

本轮只验证应用自己的 NSWindow 中四个已登记的原生视图（A、B、chat、shell）。鼠标按下按实际 NSView 命中归属，键盘按下按实际 firstResponder 归属；不使用 DOM `isTrusted`、动作计数、当前标签页或固定忽略时间窗。所属网页收到原生事件时，在 Electron 主进程的同一同步回调内先使旧执行失效，再异步等待浏览器调用结束并读取当前页面。

## 来源依据与适用范围

[Apple 应用内事件观察文档](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/EventOverview/MonitoringEvents/MonitoringEvents.html)说明 local monitor 位于本应用的事件分发路径，处理函数在主线程运行。[Electron 原生窗口句柄文档](https://www.electronjs.org/docs/latest/api/browser-window#wingetnativewindowhandle)说明 macOS 句柄为 `NSView*`。这些文档支持候选路径，具体分流和归属以下面的实测为依据。

来源保证限定于本轮允许的自动路径：Playwright / CDP 对指定页面执行输入。分别采样了 Playwright click、fill、pressSequentially、CDP Input.insertText，以及 Electron sendInputEvent 的单个键盘反例；不能将最后一个键盘样本推广为任意 Electron 输入组合。采用额外系统级鼠标/键盘自动化时，它可能经过原生通道，因此不属于本实验保证的自动路径。

原生事件不构成“物理真人”的身份证明。自动组合中的 NSApp.sendEvent 夹具同样触发接管，全部标为 `testInjection: true`；本轮真人结论结合用户实际操作、原始事件与独立反馈。computer use 的系统输入也会触发原生通道，必须单独标注来源。本地 monitor 本轮没有要求新增系统权限；没有使用全局键盘观察或事件 tap。

环境：macOS 14.8.3 / arm64，Electron 44.7.0、Chromium 152.0.7977.130、Electron Node 24.21.0、Playwright 1.64.0。编译条件和源文件哈希分别保存在每轮 `source/build/metadata.json` 与 `source/hashes.json`。

## 查看按钮故障与修复

实际窗口的最小复现命令为 `node .scratch/helpr-first-release/experiments/human-input-takeover/debug/view-switch.mjs --only-a`。点击“只看 A”后，网页宽度仍为 640 而不是 1280，并产生 `command is not a function`；三个按钮的完整复现也产生同样错误。

排查了三个可区分原因：按钮属性遮蔽同名函数、preload 通信入口缺失、宿主收到指令但未更新布局。[运行时诊断](artifacts/run-1791764485322/command-resolution-diagnosis.json)确认按钮的 `command` 是空字符串，页面词法作用域中的 `command` 与 `window.takeoverLab.command` 均为函数，宿主切换指令计数为 0。故障发生于内联事件处理器的名称解析，尚未进入宿主。

修复将内联 `onclick="command(...)"` 改为 `addEventListener`，显式调用 `window.takeoverLab.command`；按钮选择态由宿主返回的 `viewMode` 更新。旧组合从内部直接设置布局，未经过故障入口，因此旧“切换查看”断言不代表按钮有效。修复后的组合改为实际点击按钮后核对原生 View 的可见性和宽度；三项新检查已在最新完整运行中通过，真人阶段会清空自动检查产生的查看记录。

为了区分代码故障与桌面首次绘制问题，另用真实 `shell.html` 和明确的宿主通信夹具进行独立按钮事件回归。命令为 `node .scratch/helpr-first-release/experiments/human-input-takeover/debug/button-command.mjs <shell.html 路径>`：旧版 HTML 三个按钮均失败（[红色结果](artifacts/run-1791764485322/button-command-red.json)），修复版三个按钮均发送正确的 `view` 指令且无异常（[绿色结果](artifacts/run-1791764485322/button-command-green.json)）。此测试使用本机缓存的无头 Chromium 156.0.8078.4，只证明按钮事件与通信调用，不能替代 Electron 的原生布局和真人核对。

原始运行源码保留不变；诊断期间热加载的页面、最终修复版本和回归脚本保存在该运行的 `diagnostic-source/` 并注明用途。新增诊断程序保存在明确标记的 `debug/`，没有向实验主体加入临时调试日志。修改后的四个 JavaScript 文件语法检查和 `git diff --check` 均通过。

## 仍未覆盖

- 任意页面刷新、导航或原生视图替换后的归属与继续，以及真实休眠唤醒后的控制恢复。实验主动重载及主动断连回归已通过，但第 13 次仍出现非受控刷新附近的未知归属；这些边界由[后续验证](../../issues/19-page-lifecycle-input-ownership.md)继续核对。
- 普通 Chromium 候选，以及 Windows / Linux。没有对等比较证据。
- 新窗口、弹窗、WebContents 重建、跨进程框架变更、原生菜单粘贴、拖放、语音或辅助输入、应用隐藏/最小化与更广泛输入法组合。当前实验只登记这一个窗口；未登记的新原生视图不应被默认为已有可靠任务归属。
- 检测本身不回滚已派发的输入或已接受的请求。逐原语取消与旧执行隔离不等于远端副作用撤销。
- 使用假页面和本地延迟请求，没有真实模型回复；迟到回调为明确标记的夹具。此前真实模型双页实验的证据不冒充本轮真人来源证据。

后续承载选择必须按此范围使用事实，并为支持的输入通道和原生视图生命周期补齐工程约束。

## 真人引导反馈与归属问题

用户反馈“我没太明白要怎么测试、测试 i 什么，说详细点。” 已把 [操作说明](README.md#真人操作) 改为明确的测试目的、窗口区域、逐步动作、预期现象和进入下一步的标志；后续由 agent 每次只引导一个步骤，不再一次索取四步总反馈。测试里的消息发送到实验窗口右下角，最终观察反馈发送回 Codex。

这次尝试不是单纯的说明不足：在第 7 次运行中，查看按钮产生了对应宿主指令，对话测试时两项任务仍有效；随后事件 3499 的网页鼠标输入归属为 `unknown`，事件 3501、3503 分别停止 A、B。后续网页输入也有多次 `unknown`，所以流程停在 observe，不能将“继续”没有推进归为用户操作错误。原始事件摘录和反馈见 [human-guidance-feedback.json](artifacts/run-1791771939936/human-guidance-feedback.json)，关闭前的页面保留在 [before-guidance-restart.json](artifacts/run-1791771939936/before-guidance-restart.json)。

最优先核对的假设是真人准备阶段重载页面后仍沿用旧 NSView 登记，其次是隐藏／显示更换视图，或命中其它未登记视图。第 9 次在真实 Electron 中复现了“旧登记重载后”的失配，重新登记后四项检查通过，支持自有页面重载是本次归属故障的触发条件。实现中仅在任务均已停止、两页处于已知双页布局时重载，然后重新取得原生视图身份、登记并恢复派发。它覆盖本实验的准备路径，仍不涵盖任意网站导航、新窗口或 WebContents 重建。

启动方面，本机锁定的 Playwright `lib/server/electron/loader.js` 会设置 `disable-backgrounding-occluded-windows`，本次仅采用该遮挡开关，没有套用它的全部启动开关。查阅的 [Electron 类似空白视图修复](https://releases.electronjs.org/pr/52863) 已在本机版本之前发布，故不能据此断言本机命中同一缺陷或将升级当成已验证修复。前八次启动事实保留，最新通过仅代表本次可运行。
