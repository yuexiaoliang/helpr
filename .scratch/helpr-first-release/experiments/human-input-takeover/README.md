# 人工接管输入实验

服务于[验证人工接管的输入识别与让出操作](../../issues/12-human-input-takeover.md)。这是 macOS / Electron 的一次性机制实验，尚不是产品实现。当前事实和待补样本见 [REPORT.md](REPORT.md)。

## 运行

需要 macOS、Xcode Command Line Tools、Node 24 的头文件，以及相邻 `visible-page-control` 实验锁定的 Electron 44.7.0 / Playwright 1.64.0 依赖。编译使用 N-API 8，不链接到特定 Electron 的 Node ABI。

```bash
node .scratch/helpr-first-release/experiments/human-input-takeover/build.mjs
node .scratch/helpr-first-release/experiments/human-input-takeover/run.mjs
```

`NODE_HEADERS` 可指定包含 `node_api.h` 的目录。启动先检查 [原定额度](PLAN.md)与已保存的 `artifacts/registration.json`，再运行自动反例及组合核对；不删除或重置登记以绕开限额。加 `--automatic-only` 只运行自动核对并退出，不产生真人结论。真人阶段暂停准备时钟，等待本身不算准备耗时。

用户要求 computer use 自测时，加 `--computer-use`，并可同时使用下述续跑参数。`operator-session.json` 和新交互事件的 `operatorSource: computer-use` 明确标注工具来源；遗留的 `mode: human` 仅表示交互阶段，不再单独作为真人证据。即使工具完成全部输入检查，也只写 `computer-use-summary.json`。续跑读取旧断言时排除工具来源，不能把系统输入工具经过原生通道误记为真人。

实验只在随机回环端口提供虚构页面。两个网页和独立对话属于同一个实验窗口；原生监听仅观察这个窗口，不观察其它应用。没有模型调用、真实后台、上传或发布。

查看按钮的独立回归入口位于 `debug/button-command.mjs`（真实 HTML、宿主通信夹具）和 `debug/view-switch.mjs`（连接运行中的完整实验窗口）。它们只做诊断，不把工具点击计为真人样本；完整窗口探针的 `--reload-shell` 只用于已标记失败的诊断实例，不能热改正在验收的实例。

## 真人操作

测试目的：确认你查看或聊天时自动任务照常运行；你直接操作网页 A 时，A 让出操作，B 继续；明确继续以后，A 先核对当前页面再续做，并保留手工文字。这些页面只使用本机虚构数据。

窗口里有三处区域：顶部是切换查看和当前步骤；中间是 A、B 两个独立任务的网页；右下角是“任务 A 的对话”。“自动进度”数字持续增加，表示程序还在做事；“已让出操作”表示程序停下来把操作权交给你。**下面所有“对话测试”和“继续”，都发送到实验窗口右下角。** 观察反馈再发回 Codex。

只有出现“1 / 4 · 查看与对话”，且 A、B 都显示自动运行时才开始。自动准备过程中请勿点击实验网页。每次只核对当前一步，确认顶部换成下一步后再做下一项。

1. **查看和聊天。** 先看 A、B 的“自动进度”是否都在增加。点击顶部“只看 A”，再点“只看 B”，最后点“同时查看”，确认又出现两页且两个数字仍增加；此时不点击网页里的蓝色按钮或输入框。在右下角输入“对话测试”并点“发送”，应出现对话没有接管网页的绿色回复；再输入“继续”并发送。顶部应变为“2 / 4 · 点击”。
2. **网页点击。** 点一次左侧 A 的蓝色按钮“点这里，接管任务 A”。预期 A 的“人工点击”加 1、状态变成“已让出操作”、自动进度停住；观察两三秒，B 的自动进度应继续增加。然后在右下角发送“继续”，顶部应变为“3 / 4 · 中文输入”。按钮只是虚构网页中的计数操作，接管机制对整个所属网页生效，不依赖此按钮的 ID 或业务事件。
3. **中文输入法。** 程序已把光标放到 A 的“中文输入法核对”框内。不要先点击网页；切到中文输入法，亲手输入并确认“手动接管测试”。这一阶段 A 有一个等待网页可操作的自动点击，因此进度数字不增加；应观察右上角从“自动执行中（等待网页）”变成“已让出操作”，B 继续，文字能完整输入。完成后点击右下角的“复制粘贴样本文字”，为下一步准备固定文本；再发送“继续”。顶部应变为“4 / 4 · 粘贴”。
4. **快捷键粘贴和继续。** 程序已把光标放到 A 的“粘贴核对”框内。不要先点击网页；直接按 `⌘V`，应出现“网页粘贴测试 2026”，A 让出、B 继续。然后在右下角发送“继续”。程序会读取当前页面，让 A 再执行几步并检查两处手工文字仍在；最后顶部显示“操作完成”。回到 Codex 反馈切换、让出、B 是否继续，以及恢复后的文字是否保留。

中文与粘贴步骤要求各自从自动运行开始、以键盘输入独立触发接管；先点击网页会使本步只能证明鼠标接管。脚本检查完整中文 composition 序列和 paste 事件，工具输入不能替代这些真人样本。若顶部没有进入预期步骤，停止尝试后续按钮，回到 Codex 说明当前步骤和实际现象；不把引导卡住归咎于用户，也不凭计数判断通过。

若在中文或粘贴步骤先点了输入框，可在右下角发送“重试本步”。程序先保存当前页面和本次触发记录，再重新准备同一步，并选中已有文字；直接用键盘输入即可。新样本只使用本次重新准备之后的事件，前次鼠标接管不会被改写成键盘接管。

实验引导修订需要重开窗口时，可使用 `--resume-ime-from=<前一运行的绝对路径>` 保留已经完成的查看／聊天和点击证据，只重做中文与粘贴。入口检查前一运行的五项真人断言及点击观察反馈，将出处保存到新运行的 `human-resume.json`；不重放人工事件，不将新窗口写成四步在同一窗口连续完成。新窗口会等待用户在右下角发送“继续”后才准备中文输入。

中文已通过、只需重做粘贴时，使用 `--resume-paste-from=<已完成中文的运行绝对路径>`。入口要求该运行明确为真人来源，具备中文四项断言、用户反馈与已核对的完整文字，并保留前两步的原始证据链。新窗口在准备阶段恢复这段已保存中文，等待用户复制样本并发送“继续”后才聚焦粘贴框。恢复文字不是新真人输入，也不说明四步在一个窗口内完成；最终保留检查基于本次恢复的中文和新粘贴内容。两个续跑参数不能同时使用。

## 实现与证据

- `native/input-monitor.mm`：AppKit 应用内原生事件观察、NSView 归属登记；测试注入是单独标记的夹具入口。
- `electron.cjs`：同一主进程内复用 [ExecutionControl](../independent-stop/control.mjs)，同步使旧执行失效，再取消与核对结果；网页、对话、服务端夹具及引导流程。
- `run.mjs`：准备额度、独立数据目录、运行前源码快照与哈希。
- 每轮 `events.jsonl` 按统一序号记录原生输入、DOM 事件、派发、停止、取消、服务端接收/完成和恢复前观察。`testInjection` 只用于标注证据，不参与输入分类。
- `source/` 保留实际运行源码与编译元数据；`checks.json` 记录断言。`human-stops.json` 是交互停止记录的旧文件名，须结合 `operator-session.json` 与原生事件的 `operatorSource` 判断来源。完整输入流程按来源分别写 `human-summary.json` 或 `computer-use-summary.json`；没有这些文件不代表通过。工具部分自测记录在 `computer-use-result.json`，不能当作完整流程通过。
- 程序生成 `human-summary.json` 时仍等待用户独立反馈。反馈回到 Codex 后另存 `human-final-feedback.json`，与原始摘要、来源链及检查核对后才写 `completion.json`；保留摘要生成时的事实，不篡改其等待反馈标记。
- Electron `BrowserWindow.capturePage()` 的图片只含宿主网页，不能当作多个 WebContentsView 的合成截图。实际窗口布局已另外通过原生窗口截图观察；最终视觉表现仍须真人反馈。

窗口关闭时停止本次演示，并记录未完成状态。输入记录是固定实验页面的测试文本；原生记录不保存按键字符。`profiles/` 与即时连接信息不提交。
