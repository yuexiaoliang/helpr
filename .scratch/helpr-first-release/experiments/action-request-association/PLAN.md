# 网页动作与请求关联实验计划

一次性 AFK 探路实验，回答“验证网页动作、上传数据与写请求的关联边界”。实验代码不作为产品实现；负例和无法建立的保证也是结果。

## 固定范围与预算

- 只访问本机临时 HTTP 夹具及其代理，不访问真实业务网站。虚构收件记录和上传文件保存在本实验目录；已有 WordPress / Drupal 证据只读引用。
- 模型调用 0 次，真实后台准备、上传、发布各 0 次。最多 40 个浏览器场景尝试、5 次浏览器启动、本机夹具写请求 64 次、文件接收 8 次；失败、重跑均累计，不换目录清零。
- 首次浏览器运行起 60 分钟；首次实现后最多两次修订。计数和源码快照先落盘，再启动浏览器或派发场景。额度耗尽后仅整理已有事实。
- 不引入逐步骤人工批准，不替用户决定产品范围，不增加站点专用产品白名单。

## 方法

对照三个位置：浏览器事件 / 请求接口、HTTP 代理实际收到的实体字节、服务器独立收件及下载产出。浏览器记录不能替代服务器事实；代理放行也不能替代业务结果核对。

基线只提取已有执行器的相关规则：普通写请求在当前点击窗口且同源时放行，GET / HEAD / OPTIONS 直接放行；上传核对所选文件和请求文件名。不会冒充重新跑过完整旧执行器。核对同一点击的额外请求、迟到请求误落入下一动作窗口、GET 产生写入、相同文件名但替换字节。

候选 Module 在本机 HTTP 代理前完整缓冲请求，以执行代次、可撤销的一次性许可、精确目标、正文摘要或严格 multipart 字段与文件摘要决定是否转发。其 Interface 为运行时提供的请求约定、arm、revoke 和收件记录。约定由夹具注入，明确不是本轮 AI 自动学得的业务语义。未知内容拒绝；已转发后再停止保留不确定。

即使候选请求约定全部匹配，也要用“上一动作安排的后台请求先到，内容恰好相同”反例检查：字节匹配、当前许可及 initiator 是否足以证明它来自获准动作。不得把本轮候选说成完整授权解法。

## 场景与判据

1. fetch / XHR 同一次点击发出合法与无关请求，核对服务端各收到哪些。
2. 动作结束后及下一动作期间的迟到请求；相同内容的后台请求抢先消费许可。
3. 磁盘 File 上传与同名同大小替换文件；分别记录 FileList、Playwright、CDP 和完整实体字节，再从服务器下载核对。
4. 原生表单、框架内提交、重定向、GET 写入、dedicated worker、service worker、sendBeacon 的有限受控样本。比较 page.route 与 context.route 的实际覆盖，不由接口存在推定已覆盖。
5. 代理已收到但尚未转发时撤销许可；请求转发后再停止；两者必须有不同的结果记录。

每个场景保存独立服务器收件和代理决策，检查目标文件字节及预期收件数。记录 CDP initiator 与 DOM 事件只用于分析相关性，不能把脚本栈或可信点击当作副作用语义证明。至少保留一项完整合法上传与提交的正例。

## 边界

本轮不验证 TLS 解密、任意 HTTPS 网站、QUIC、WebSocket / WebTransport、浏览器扩展、任意跨域 / popup / 下载通道、任意复杂 multipart 编码、服务端内部副作用。HTTP 代理是观测和约束装置，不是浏览器宿主选型。未覆盖通道和首次探索时缺少请求约定的情形必须进入最终选择，不能按“未观察到”算安全。
