# 流程可靠性的候选约定

这是 [验证流程适用性、步骤条件与修复边界](../../issues/14-workflow-reliability-contract.md) 的实验设计，不是产品规格或已确定架构。运行证据与结论另见报告。

## 要检验的主张

已有运行记录可以成为候选流程的依据，但单条成功路径不能证明流程完整。候选需要显式输入引用、可观察条件和结果核对；这些条件本身也要经过正反样本检验。候选的格式正确、可以执行和实际结果正确，是三项不同的检查。

## 外部 Interface

`runWorkflow` 接收固定的任务输入与授权、候选流程、绑定的真实页面以及停止信号，返回完成、阻塞、结果不确定、需要参与或已停止，以及对应证据。可选修复提议经同一执行 Module 校验和执行。调用者不绕过该 Interface 直接完成业务步骤。

本实验从先前真实 AI 探路的记录归纳候选，再验证候选与修复；并未重新实现任意自然语言委托的解析或完整的逐步探索循环。测试驱动提供已解析任务及明确标记的实验授权，不能算真实用户预览确认。兼容性中的任务类型也由测试提供，不能用此实验声称已经解决语义相似任务的自动分类。

## 约定与职责

- **匹配与授权分别检查**：候选具有站点与任务类型条件，任务输入具有类型。输入摘要与本次授权必须一致，文件在开始与提交前再次核对内容摘要。错误候选、改变后的输入或素材不能直接进入后续写入。
- **引用与常量分别表达**：只有结构化引用才绑定任务输入，普通字符串始终是常量。标题恰好叫 `File` 时，编辑器的固定搜索词 `File` 不能被替换成下一篇标题。
- **期望值来自任务，观察位置来自候选**：实际提议曾把样本文件名抄进检查规则。最终实验把期望值固定为任务输入引用；模型提议网页观察位置，不能自行决定本次结果应该是什么。候选目标类型及输入槽位目前仍由测试驱动提供，其自动归纳尚待验证。
- **观察到状态才推进**：定位唯一性与可操作性之外，每个写入步骤有结果条件。提交前再次核对目标、内容与附件状态。通过对照真实“上传进行中”及“上传完成”页面，检验候选上传条件能否区分二者。
- **业务知识留在运行时数据中**：特定网站的定位、字段映射和条件属于模型输出的候选。通用执行程序只解释有限的浏览器动作、类型和检查原语。独立测试断言用于发现候选验证器的误判，不充当产品的运行时判断能力。

- **修复不能改成功标准**：本次最小修复仅允许替换一条动作的定位。输入、动作种类、效果分类、步骤条件、提交检查及结果规则保持固定。超出该范围的提议被拒绝，后续应重新学习或请求必要参与；本实验不自动修复提交动作。
- **结果不确定时保留不确定**：一旦进入可能提交的动作，后续失败不直接宣告“未发布”，也不整段重放。实际状态核对和恢复由已有提交中断事项继续验证。本实验不会声称实现网站侧恰好执行一次。
- **修复版本需要结果证据**：只有运行时检查完成后才返回可保存的新版本，保留父版本与本次证据。测试驱动另行核对真实公开文章与文件，并对照运行时判断是否正确。持久化原子性、并发修复及版本兼容仍归后续事项。

整份流程生成与整体修订的错误保留在原始模型输出中。最后的实验候选采用较小的模型提议，并由测试驱动组合、绑定期望值和展开定位格式。该组合步骤是本次验证的明确限制；它支持评估约定，却不能当作完全自动学习已经成立的证据。

## 检验限度

程序可以检查明确表达的约束，但无法单靠 JSON 格式证明网页字段的含义、提交效果分类或结果规则正确。模型提出的条件需要实际证据；同一个模型反复自查不能代替结果核对。DOM 看起来相同而服务器含义改变、未知副作用及观察后的状态竞态，不能据本实验宣称全部消除。

初始定位、每个浏览器调用前、异步提议返回后都检查执行状态；已经进入浏览器内部的操作如何即时取消，仍须与独立停止和实际 AI 双页归属实验结合，不能由此候选 Interface 自动推定。

本次选择小范围条件表达来检验保证。复杂分支、循环、业务规则语言和具体工程文件结构都不提前冻结。
