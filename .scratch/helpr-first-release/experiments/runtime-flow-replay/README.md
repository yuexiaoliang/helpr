# 参数化流程冷启动与修复实验

此目录是 [验证参数化流程的冷启动重放与修复更新](../../issues/05-runtime-flow-replay.md) 的一次性实验，不是 helpr 产品实现或最终执行器选型。

## 分工

- `engine.mjs` 只提供页面观察、参数绑定、唯一目标定位和通用动作。没有 WordPress 业务步骤，没有网站专用上传／发布函数。
- `worker.mjs` 提供这次测试的自然语言目标和虚构素材，每个阶段启动新的 Chromium 和页面。首次步骤由 DeepSeek 根据实际快照逐项选择。
- `prepare.mjs` 只准备测试账号登录态，不计入流程学习，也不替代产品的首次手动登录要求。远端口令只进内存；登录态保存在被忽略的 `private/`。
- `verify.mjs` 是测试用例的结果断言，在未登录的新浏览器上下文里核对标题、正文、分类以及实际下载文件的字节。
- `materials/` 保存四份不同内容的虚构 Excel、生成脚本及渲染核对图。它们是输入样本，不是 Excel 业务适配器。

## 运行

需要 Node.js、已有的 DeepSeek 本机配置、`ssh essh-home` 和运行中的独立验证后台。模型配置复用相邻 `model-api/config.example.json` 与被忽略的 `.env.local`，不把 Key 写入命令。

```bash
npm install --ignore-scripts
npm run prepare
npm run run
```

`run.mjs` 依次启动四个**不同 Node 进程**。任何一项失败立即结束，不把失败当作可用流程：

1. `learn`：无预置流程，由实际模型探索、上传和发布。成功核对后保存 `workflow-v1.json`。
2. `replay`：更换标题、正文和文件，加载已保存流程。这个进程不读取模型 Key，禁止回退到模型。
3. `repair`：在当前测试页面对已学标题控件的可访问名称做受控变更。原步骤失败后才调用模型，保持原意图替换步骤。核对最终公开结果后才写出 `workflow-v2.json`，保留原版本。
4. `updated`：另一个新进程、新素材，加载新版流程，在同样的变更页面上运行，同样禁止模型调用。

也可以复用已经验证成功的学习记录：`node run.mjs artifacts/<新目录> artifacts/<学习目录>/workflow-v1.json`。脚本保留来源指针、原文件和摘要，另起三个进程执行重放、修复及新版重放；不会再调用模型生成第一次的步骤。

模型配置、调用用途与用量、每次观察和动作、失败、进程身份、流程版本、公开链接、下载文件及截图都保存在 `artifacts/<时间>/`。失败目录也保留，不能只根据最后一次成功推断首次探索可靠性。

已完成的结果及失败样本见 [REPORT.md](REPORT.md)。`npm test` 只检查这轮实际暴露的通用定位与结果归属问题，不调用模型或发布文章。

单独复现某阶段时，可运行 `node worker.mjs <阶段> artifacts/<时间>`；这会重新产生真实测试文章，不是从中断处恢复。需要保留旧证据时使用新目录，复制所需流程文件后再执行。

## 边界

这是独立 Chromium + Playwright + DeepSeek 的组合。没有验证 Electron 中的模型执行器、Stagehand 的模型适配、并行调度、停止／接管、断点恢复、重复提交防护、Excel 内容理解或第二个后台。

这条委托使用已经给定的内容。理解委托与内容生成没有单独调用模型，不可据此宣称整个产品的任务均能零模型运行。

受控变化只覆盖当前页面标题控件属性，未修改站点服务代码。修复结果不代表任意页面变化都可自动处理。整个实验通过真实网页上传和发布；没有用 REST API、WP-CLI 或写数据库代替任务执行。
