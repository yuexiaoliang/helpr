# 上传授权与完整流程的分阶段检查

2026-10-10，本地隔离实验。对应 [验证上传授权与完整流程的分阶段检查](../../issues/17-upload-authorization-and-workflow-checks.md)。这是技术决策证据，不是产品实现或正式验收。

## 结果与适用范围

在既有自动探索前缀上，补全了 14 步发布流程、输入绑定、步骤条件及公开结果规则。模型校准过一次结果链接位置后，新执行完整通过；随后冻结候选，再生成保留集。两组新文字及不同字节附件均完成发布，三个不适用委托被拒绝，控件变更时正确停止。完整校准与两个发布保留样本的浏览器重放均为 **0 次模型调用**，每份新委托仍需要一次模型输入理解。

分开检查文件选择、请求关联、上传完成、动作前就绪与公开产出，足以推进这条真实路径。它不构成任意网站的副作用授权保证：本轮确实观察到一个目的未核实的写请求在点击等待窗口中获准，上传请求也只有元数据关联，不能据此证明传输层文件字节或所有同期请求都在委托范围内。

汇总与原始记录见 [证据索引](evidence-index.json)、[冻结候选](artifacts/staged/frozen-candidate.json)、[预算及调用记录](artifacts/staged/meta.json)。

## 关键观察与职责划分

旧执行器把完整源文件是否出现在 `postDataBuffer()` 中当作上传许可。本轮只读观察再次得到反例：本地源文件和浏览器 `FileList` 中的文件均为 3755 字节且哈希一致，请求暴露正文只有 351 字节。实际控件在编辑器子框架，请求来自其主页面。选择事件之后，原文件控件还会被正常替换；不能要求该旧 DOM 节点一直附着。

| 阶段 | 本轮使用的事实 | 不足以证明什么 |
| --- | --- | --- |
| 输入授权 | 原委托摘录、任务摘要、文件路径与 SHA-256；程序重核素材 | 模型已理解任意自然语言约束 |
| 文件选择 | 当前执行中实际文件控件的选择事件、文件名、长度和字节哈希 | 服务端已经收到文件 |
| 请求关联 | 一次性凭据、任务与执行身份、同源、控件所在框架或其祖先、唯一相符 multipart 文件名 | 请求中的完整文件字节，也不能排除同名伪造请求 |
| 上传完成 | 模型从真实页面选择文件链接，程序读取实际文件并核对 SHA-256 | 后续公开页面已发布成功 |
| 动作前就绪 | 标题、正文、分类、排除默认分类及附件条件；素材和任务仍匹配 | 点击窗口内每个请求都是该动作直接引发的 |
| 公开结果 | 新的未登录上下文，按学习到的规则核对文字，并实际下载比较原始字节；另用独立断言复核 | 网站不存在其它隐含副作用 |

上传凭据在任务、素材或页面位置变化时失效，且只能消费一次，执行结束后不能复用。正常控件重绘允许保留事件时的选择证据；本轮没有把“任意 DOM 改变”都等同于失效。现有文档导航失效检查不等于已覆盖全部导航、弹窗、worker 或跨进程情形。

第二次上传执行真实暂停了请求。此时已选中的文件有界面占位，但完成条件失败；放行之后，同一条件读取到正确文件字节。证据见 [原始观察](artifacts/staged/observation-probe/results.json)、[上传位置学习](artifacts/staged/upload-probe-learn-2/results.json)、[新执行暂停与完成](artifacts/staged/upload-probe-replay/results.json)。

## 完整归纳、失败与校准

前十步来自上一轮 [真实自动探索记录](../constrained-workflow-induction/artifacts/run/learn-4/results.json)。上传目标也来自该记录中的真实提议；本轮重新验证执行，并由模型选择实际文件链接，程序固定字节核验方式。随后由模型选择发布、确认发布和结果链接，另从未登录页面选择标题、正文、分类及附件的结果位置。

程序只组装已有通用原语、显式输入引用和观察条件，没有补写网站选择器、字段映射或成功文案。测试夹具和独立断言含有网站及任务知识，它们不进入执行器的操作规则。文件名或正文的相等观察可以显式绑定输入；普通网站文字保持常量，不按样本值全局替换。

| 尝试 | 观察到的问题 | 处理与证据 |
| --- | --- | --- |
| 首次上传探针 | 旧控件正常脱离 DOM，导致误拒上传 | 改为保留真实选择事件，核对文档、任务和素材；[原始失败](artifacts/staged/upload-probe-learn/results.json) 保留 |
| 完整学习第一次 | 模型重复提议分类检查但漏掉动态名称绑定 | 发布前停止；补充条件只处理尚无检查的同一 DOM 控件；[记录](artifacts/staged/learn/results.json) |
| 完整学习第二次 | 模型把暂停上传的预期失败当作最终上传失败，连续提议错误上传目标 | 三次均在派发前拒绝；正常历史只呈现已验证完成状态，负例留在诊断中；[记录](artifacts/staged/learn-2/results.json) |
| 完整学习第三次 | 一次 finish 提议选中非链接，被类型检查拒绝，随后选到真实结果链接 | 完成真实发布和独立结果核验；[记录](artifacts/staged/learn-3/results.json) |
| 首次完整校准 | 结果链接名称包含旧标题，发布后检查失败 | 状态为 `uncertain`，没有重复发布该委托；[记录](artifacts/staged/calibration/results.json) |
| 结果位置校准 | 原定位过度依赖学习样本 | 用既有位置提议 schema，让模型从两次真实观察中选择稳定、且训练时指向已核验结果的链接；只读核实本次实际产出；[模型校准记录](artifacts/staged/result-position-calibration.json) |
| 第二次完整校准 | 新委托、不同文件字节 | 14 步完成，浏览器重放无模型调用，独立核验通过后冻结；[记录](artifacts/staged/calibration-2/results.json) |

结果位置校准没有修改执行原语、权限判断或结果规则。它使用已有 `positionSchema` 和 `actionFrom` 产生新的 finish 位置，同时更新原来从该位置推导的前一步完成条件。维护者没有指定某个网站控件名称；新候选仍必须通过下一次完整执行才可冻结。

## 错误提议、请求边界与保留的未知

上传暂停后更改素材、改变页面位置、尝试用同一凭据发送普通请求，分别取得拒绝证据；普通请求被拦时，原授权上传仍可完成。见 [反例汇总](artifacts/staged/guard-probes/results.json)。

最终协议还通过了 [任务变更与已完成凭据复用](artifacts/staged/permit-invalidations/results.json) 两个反例；[错误首次效果提议](artifacts/staged/guard-probes-final/results.json) 也在最终协议上重新验证，真实发布请求仍被拒绝。

对真实发布控件注入错误的首次 `effect: read` 提议，附件未就绪时，请求仍因缺少输入条件被拒绝。这与 [封存版本摘要不匹配](artifacts/staged/sealed-tamper.json) 是不同实验；后者只是版本一致性检查，不是恶意篡改防护。完整校准还验证：已就绪任务的标题被改坏后，误标为 read 的发布提议在派发前停止。

普通写请求的门禁目前要求有当前 click/press 动作及就绪证据。**“当前动作”仍是时间窗口关联。** [首次校准日志](artifacts/staged/calibration/events.jsonl) 的 `2026-10-11T01:57:58.788Z` 记录显示：等待发布后条件时，`POST /wp-admin/admin-ajax.php` 被标成当前点击并获准。本轮没有核实其业务目的或副作用，不能把该请求认定为授权发布的一部分。最终结果正确也不能消除这个未知。

另外，当前实现直接放行 GET/HEAD/OPTIONS；它没有证明这些请求无副作用，也没有覆盖所有弹窗、service worker、WebSocket 或分块上传。文件选择哈希、相符请求文件名与最终下载哈希提供了这条路径的对应证据，但不是对任意前端脚本的传输内容证明。未知上传形式应停止；不能为了适配新网站而扩大无条件放行范围。

## 预算、源码与复核

预算在首次请求前固定：70 分钟、60 次请求、260,000 token；观察 8/40,000，学习 26/120,000，校准 12/50,000，保留集 14/50,000。格式修订最多 6 次，程序协议修订最多 4 次；失败不清零、不挪用阶段额度。

精确用量按接口返回 usage 累计，见 [证据索引](evidence-index.json)。它包含失败轮次与位置校准调用，区分输入理解和浏览器重放。早期失败上传探针的原始 `modelCallsDuringBrowserReplay` 是驱动预估值；索引按真实 `probe-artifact` 请求记录校正，该失败探针实际没有调用文件位置模型。

实际实验用时约 34.2 分钟，33 次模型请求、134,617 token，格式修订 0 次、程序协议修订 4 次。观察阶段 8 次 / 13,945 token，学习 16 次 / 105,344 token，校准 3 次 / 4,593 token，保留集 6 次 / 10,735 token。各阶段均在原预算内。结果位置校准是一次已有提议约定下的模型调用，没有新增执行协议；最终四个协议文件与学习前保存的最终快照逐字节一致。

后续把 [网页动作、上传数据与写请求的关联边界](../../issues/18-action-request-association.md) 作为独立问题验证。已有发布闭环可用于并行与跨后台实验，最终执行组合仍须吸收该关联边界的证据。

最终执行协议源码保存在 [source-final-protocol](artifacts/staged/source-final-protocol/)；前两个版本快照与原始失败都留在实验目录。第二次校准驱动只改变夹具目录及证据路径，保留第一次校准记录。位置校准脚本、凭据失效探针及最终错误提议探针属于实验驱动，使用相同执行原语。

复核应同时检查候选、请求/派发日志、模型原始提议、未登录结果与实际下载文件。不能只查看 `completed` 字段、截图、文件名或 HTTP 成功码。重跑应使用新的独立实验记录，不能清空本轮预算或覆盖失败样本继续累计成功。
