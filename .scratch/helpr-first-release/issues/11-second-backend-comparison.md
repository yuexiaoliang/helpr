## Question

前提：[第二套开源验证后台调查](04-second-backend-research.md)、[参数化流程的冷启动重放与修复更新](05-runtime-flow-replay.md)和 [流程适用性、步骤条件与修复边界](14-workflow-reliability-contract.md)。

将已有流程实验换到资料调查支持的第二套后台后，哪些差异能由新的运行时流程吸收，哪些暴露了执行原语、参数或结果核对方式的缺口？取得足以排除 WordPress 专用设计的对照证据。

依据调查首选与实际可用性，在已获授权的 `home` 测试环境独立准备实例、账号和虚构素材，核对其真实网页发布路径。按需使用 `essh` 与浏览器技能，凭据留在安全配置中，不改动已有服务。

使用相同通用实验程序，通过真实 AI 在新网页形成流程并执行一条明确的发布任务，记录改变的运行时数据与保持不变的产品能力；以真实网页和产出核对结果。测试样本与后台结构可准备，站点专用业务代码不能用来补齐执行路径。

沿用已验证的候选流程约定，核对参数绑定、步骤条件和结果规则怎样从第二后台的运行时事实形成；独立测试断言只用于评价，不替代产品能力。记录候选约定是否需要修改及其原因，避免仅把同一录制器换站运行就宣告通用性成立。

[上传授权与完整流程的分阶段检查](17-upload-authorization-and-workflow-checks.md) 已补全单后台真实路径与冻结后保留集，可以据其最终协议进行跨后台对照。记录其前缀来源、模型位置校准与适用范围；维护者若仍需补写选择器、字段映射或成功规则，须计为通用性缺口，不作为自动学习成功。

同时保留该实验暴露的请求关联未知，并将新后台的相关事实交给 [网页动作、上传数据与写请求的关联边界](18-action-request-association.md)。跨后台产出正确不能代替对所有副作用的范围核验。

输出对照证据与暴露的新决策问题。此实验只回答技术通用性问题，不代替正式产品在第二套后台上的完整验收。

## Answer

2026-10-11 完成。[实验报告](../experiments/second-backend-comparison/REPORT.md)与[离线核对结果](../experiments/second-backend-comparison/verification.json)保存完整过程，独立实例与账号配置位置见 [Drupal 后台记录](../../../docs/testing/second-validation-backend.md)。

**取得了排除 WordPress 专用步骤设计的对照证据，但原有程序原样换站未通过。** Drupal 的原生字段表单、栏目下拉框、文件字段和结果页均由真实模型重新探索，最终形成七步运行时流程。没有把人工环境核对的选择器或 Drupal 专用发布逻辑写入执行器；站点初始化和独立结果断言使用的 Drupal 知识不作为产品能力。

过程需要两次通用程序修订：补齐带单引号包装的 ARIA 行、可填写控件类型和 `selected-label` 条件；随后修订上传响应结束等待、后置错误的已执行标志、文件选择次数与失败前缀边界。一次换输入校准又暴露结果定位遗留旧标题，模型使用既有绑定机制改为动态输入位置；维护者启动该校准，未手填网站定位。第一次校准的已发布内容经只读核对成功，没有重发。

修订后的完整学习、第二次校准和两份冻结后样本均通过真实网页及独立下载哈希检查。校准后的网页重放无模型调用，新委托理解各调用一次；草稿、更新旧记录、读取 Excel 生成摘要均拒绝套用附件发布流程，控件改名在写入前停止。共 34 次模型请求、82,783 token、约 9.2 分钟。六篇公开内容包括一篇环境核对样本；七个文件中一个是失败学习留下的临时附件，未为美化结果清理。

前两次学习失败、第一次校准的不确定结果及学习二的多余文件选择全部保留。学习二有两次文件选择但仅一次上传请求，暴露出初始请求预算未约束仅选文件动作；不能宣称所有早期动作都满足次数限制。冻结后的保留样本没有修改程序或候选。素材仅覆盖小型单附件，栏目只验证“Excel 验证”；新网站无需修改通用代码、所有副作用均被授权和完整产品自主修复仍未获得保证。

新暴露的问题进入已有决定，不另建重复事项：

- [确定浏览器承载与流程执行组合](07-browser-runtime-decision.md)：条件语义应区分文字值与选项标签，结果位置须绑定动态输入；有限提议还需要在没有合格节点时明确表达未知。协议经过通用修订才通过的事实必须进入选型。
- [确定执行记录、流程更新与定时恢复的约定](10-durable-execution-contract.md)：动作已经执行、后条件未满足和结果经只读核实是不同事实，上传后核对失败不得退回“尚未执行”并盲目重做。
- [验证网页动作、上传数据与写请求的关联边界](18-action-request-association.md)：学习上传样本的请求暴露元数据为 2,642 字节，而文件为 3,754 字节，仍不是传输字节证明；普通写请求的时间窗口关联限制继续保留。

检查：新增六项原语正反检查通过；保存证据的 324 个文件摘要、阶段预算、源码版本、候选封存、下载字节和服务端内容核对通过；仓库 `npm run check` 的 85 个源码语法检查与 25 项测试通过，既有双页证据核对仍通过。此事项解决的是技术对照证据，正式第二后台产品验收仍待实现阶段完成。
