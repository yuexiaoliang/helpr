## Question

现有实验使用没有客户端认证的回环 CDP 端口，且实际允许第二个客户端操作页面。怎样在保留 Electron、外部 Playwright 控制及按任务独立停止的同时，避免远程网页或未获资格的本机客户端直接控制浏览器、读取宿主能力？

依据[确定浏览器承载与流程执行组合](07-browser-runtime-decision.md#answer)和[确定本机交付、权限与更新约定](20-local-delivery-and-updates.md#answer)。

先验证更接近已选路线的候选：由长期存活的 helpr 控制进程持有 Electron 私有调试 pipe，通过受认证、按当前任务／页面／执行资格限制的转接供执行进程连接。必须消除可绕过转接的裸调试端口。Electron 对应版本在 pipe 断开时会请求退出应用，因此停止单个任务不能关闭共享 pipe。若此候选不成立，再比较宿主 `webContents.debugger` 与私有进程通信方案，并明确它是否需要调整 Playwright 路线；不能把候选偷偷换成已定实现。

使用独立的本机页面和虚构数据，通过实际 Playwright 操作与独立客户端核对：

- 正确身份可以连接；缺少、伪造、撤销和过期资格均被拒绝；没有可直接连接的旁路端口。随机端口和回环地址不当作认证。
- A 的资格不能操作 B；页面、iframe、popup、新 target、重连和旧 session 不能绕过归属检查。不要只检查转接入口的一次登录。
- 两项页面实际重叠运行；停止 A 只结束 A 的派发与资格，B 和宿主继续；控制进程意外退出时不得产生失管执行。
- 远程网页及其子 frame 不能借 IPC、导航、新窗口、外部协议或下载获得宿主文件、凭据或任意命令能力；必要的网站导航与任务 popup 仍可在已登记归属下工作。
- 控制凭据仅经受管进程通信传递，不出现在网页、URL、普通诊断或可分享文件中；记录取消前已发出效果与之后拒绝的新动作。

固定 Electron、Playwright 与候选源码，记录完整启动参数、监听面、断开行为、负例和能力覆盖。预算在运行前确定；本轮模型调用与远程上传／发布均为零。不扫描无关应用或网络，不使用真实登录或模型凭据。

输出支持的控制路径、与原有停止/页面归属证据的差异和剩余限制。不能把一个未经授权连接被拒绝当作全部 CDP 协议已隔离，也不承诺抵御已控制同一用户账号或操作系统的攻击者。只做到足以选择交付控制机制，不构建完整产品。
