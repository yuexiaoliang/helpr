## Question

[上传授权与完整流程的分阶段检查](17-upload-authorization-and-workflow-checks.md)取得了完整流程与保留集证据，也暴露两个不能由结果成功消除的未知：上传许可依赖实际文件选择及请求文件名关联，尚未证明请求实际携带的完整字节；普通写请求依赖当前动作时间窗口，一次目的未核实的 `admin-ajax.php` 写请求在等待发布后条件时被放行。

通用执行器能否取得足够证据，将写请求及上传数据关联到已授权的实际动作，并在证据不足时明确停止或标记不确定，而不把时间相邻、HTTP 方法、URL 字符串或模型效果标签当作授权证明？若某类关联无法由现有浏览器能力可靠建立，首版必须明确的能力边界是什么？

先验证关键观测机制，再投入模型探索。可复用已有真实动作记录与最终执行协议，但不能补写 WordPress 业务白名单。用受控反例区分同一点击期间的无关写请求、动作完成后的迟到请求、同名但字节不同的上传，以及合法上传或提交。测试注入属于独立夹具，产品判断仍须来自通用机制与运行时证据；同时核对是否真正派发以及服务器或可下载产出，不能只读本地拒绝日志。

对 DOM 事件、fetch/XHR、表单、框架、导航、worker 或其它通道，只报告实际验证过的范围。不能因为某通道无法核验就默认其无副作用，也不能承诺识别任意网页的全部隐含行为。必要时给出可实施的能力声明、停止条件和未知结果，而不是扩大无条件放行。

沿用现有虚构新建记录及附件实验授权，不新增逐步骤人工批准的产品流程；不改动已有业务记录或设置。开始前固定预算，保留失败与不确定样本。本事项为执行组合选择提供事实，不提前代替用户作出产品范围取舍。
