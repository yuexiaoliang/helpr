## Question

[上传授权与完整流程的分阶段检查](17-upload-authorization-and-workflow-checks.md)取得了完整流程与保留集证据，也暴露两个不能由结果成功消除的未知：上传许可依赖实际文件选择及请求文件名关联，尚未证明请求实际携带的完整字节；普通写请求依赖当前动作时间窗口，一次目的未核实的 `admin-ajax.php` 写请求在等待发布后条件时被放行。

通用执行器能否取得足够证据，将写请求及上传数据关联到已授权的实际动作，并在证据不足时明确停止或标记不确定，而不把时间相邻、HTTP 方法、URL 字符串或模型效果标签当作授权证明？若某类关联无法由现有浏览器能力可靠建立，首版必须明确的能力边界是什么？

先验证关键观测机制，再投入模型探索。可复用已有真实动作记录与最终执行协议，但不能补写 WordPress 业务白名单。用受控反例区分同一点击期间的无关写请求、动作完成后的迟到请求、同名但字节不同的上传，以及合法上传或提交。测试注入属于独立夹具，产品判断仍须来自通用机制与运行时证据；同时核对是否真正派发以及服务器或可下载产出，不能只读本地拒绝日志。

对 DOM 事件、fetch/XHR、表单、框架、导航、worker 或其它通道，只报告实际验证过的范围。不能因为某通道无法核验就默认其无副作用，也不能承诺识别任意网页的全部隐含行为。必要时给出可实施的能力声明、停止条件和未知结果，而不是扩大无条件放行。

沿用现有虚构新建记录及附件实验授权，不新增逐步骤人工批准的产品流程；不改动已有业务记录或设置。开始前固定预算，保留失败与不确定样本。本事项为执行组合选择提供事实，不提前代替用户作出产品范围取舍。

## Answer

2026-10-12，已完成受控本机浏览器对照及独立原始实体核对，见[实验报告](../experiments/action-request-association/REPORT.md)、[证据索引](../experiments/action-request-association/evidence-index.json)和[固定预算](../experiments/action-request-association/PLAN.md)。25 个场景、2 次浏览器启动、1 次范围内修订，没有重跑；模型调用与真实后台准备、上传、发布均为 0。服务器 17 个请求与候选代理的 12 次拒绝逐项核对，165 项独立记录 / 字节检查通过。场景“符合预期”包含复现不安全关联，不能称为通用授权机制通过。

- **原有证据不足已成实测反例**：同一点击、同一目标和同一同步调用栈的两次写请求都被基线放行；旧计时器请求可落入下一动作窗口；FileList 正确且文件名、大小均相同，网站脚本仍能换掉实际上传字节。GET 也可以在夹具中产生记录。
- **完整实体检查可提供有限保证**：8,192 字节磁盘文件在一次路由观测中只暴露 306 字节正文，完整实体却为 8,498 字节。独立 HTTP 代理能够在转发前核对完整正文、multipart 字段和文件摘要；正确上传 / 提交通过，替换文件及先到的错误正文被拒绝。约定均由夹具提供，没有证明首次探索可自动学习正确请求约定，也没有加入 WordPress 白名单。
- **请求匹配仍非动作归属**：旧计时器发来的请求与新动作约定完全相同时，能在新点击前消费一次性许可；真正的新点击被当作重复请求拒绝。代理候选不能声称已证明请求来自获准动作。CDP 调用栈可供诊断，未验证通用异步因果追踪；即使因果成立，也不自动证明业务语义在授权范围内。
- **通道和停止事实必须保留**：page.route 漏掉本例 service worker 写入，context.route 能拦截但其 frame 不存在；重定向没有第二次页面 route 回调。代理能观察本轮两跳、worker、beacon 和原生框架表单，但没有任意 HTTPS / 跨域 / popup / socket 的覆盖证明。撤销未转发请求可阻止收件；转发后停止仍可能产生结果，不能重发或报作已阻止。

本事项完成的是能力边界调查，现有通用执行器**尚未取得“所有隐含副作用均属授权”保证**。可进入规格讨论的有限能力是：明确受支持通道、完整内容检查、可撤销派发、独立结果核对；不足时保持未知并停止进一步自动派发，已经送出的转入结果核对。首次学习如何取得请求约定、未知通道如何满足用户体验，以及是否采用这些限制，交给[确定浏览器承载与流程执行组合](07-browser-runtime-decision.md)决定。本轮不自行收缩产品范围，不要求逐请求人工批准，也不把 HTTP 代理确定为产品架构。

## Comments

2026-10-11，[取得第二后台的流程对照证据](11-second-backend-comparison.md)补充了 Drupal 样本。学习上传中，所选文件为 3,754 字节，请求暴露的 body 元数据为 2,642 字节；实际下载及服务端文件哈希一致，但仍不是传输完整字节的证明。普通发布继续使用当前动作窗口与就绪检查，没有据最终成功扩大授权保证。学习二还出现“第一次上传后位置核对失败，又选了一次隐藏文件控件”，只有一个上传请求；动作次数、派发次数与服务端产出须分开核对。原始事件和只读服务端审计见该事项链接的实验报告。
