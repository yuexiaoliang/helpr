## Question

在首版 macOS、[Electron 真实网页工作区与受控 Playwright 执行组合](07-browser-runtime-decision.md#answer)及[执行记录、流程更新与定时恢复约定](10-durable-execution-contract.md)下，怎样交付一个用户可以安装、登录、配置模型、持续使用并更新的本机应用，同时保持已确认的任务、素材、登录和停止约定？

明确足以编写规格的交付要求及相应技术路线：

- 首版支持的 macOS 版本、处理器范围和安装分发方式；签名、公证及更新渠道如何适合首位实际用户。不从一台 arm64 测试机器直接推定所有 Mac 均已支持。
- 浏览器与执行进程由谁启动、退出和清理，关闭应用窗口与退出 helpr 如何区分，电脑休眠唤醒及应用重启怎样进入既有恢复约定。不得默认改变“电脑开机且 helpr 运行”的前提，也不把 CDP 断开试验当作真实休眠证据。
- 文件夹素材访问、模型凭据和网站登录状态放在哪里；本机访问权限、日志和备份应保留什么，撤销或清理如何影响定时计划。区分 helpr 自身需求和测试工具的屏幕录制／辅助功能权限，不能把后者误写成产品必须申请的权限。
- 本机控制连接如何只供 helpr 使用，远程网页如何与宿主、对话和本地文件能力隔离；需要哪些运行条件才允许自动执行。
- 应用、Electron、原生输入识别和浏览器控制能力升级前检查什么，检查不通过时如何维持可理解的状态；数据与流程版本兼容由相应持久化约定约束，不能用程序降级推定数据也能安全回退。

推荐具体方案并讨论影响用户体验、维护成本与数据保留的真实取舍。日常文件路径、构建脚本细节和最终 UI 排版留给实现；不得在本事项擅自改动系统权限、电源设置、凭据或发布安装包。若有会改变交付路线的未知，形成单独的有界调查或实验事项。

## Answer

2026-10-12，确定首版在当前 Mac 上交付本人自用应用，支持自动检测更新、默认手动安装与可选空闲自动更新；关闭主窗口保持运行，尊重系统休眠，资料默认本机保留并提供本机备份。以下是交付要求及待验证路线，不表示已有可安装产品或更新能力。

### 交付对象与应用身份

首批目标是用户当前 Apple Silicon / arm64、macOS 14.8.3（23J220）的 Mac。交付可独立打开的应用，不要求用户运行开发命令；这个范围不推定所有 macOS 14、Intel Mac 或其它系统版本已经支持。正式向其他人分发的签名、公证安装包及其它环境取得条件和证据后再安排。

现有[真人接管](12-human-input-takeover.md#answer)和[页面变化](19-page-lifecycle-input-ownership.md#answer)的证据来自开发环境：Electron 44.7.0、Playwright 1.64.0 及本机原生输入扩展。开发目录中的 Electron 可启动不等于打包、安装或跨版本更新可用。[Electron 分发说明](https://www.electronjs.org/docs/latest/tutorial/application-distribution)支持独立应用封装，实际交付须固定 Bundle 身份、架构、签名身份及原生扩展构建方式，并在目标 Mac 上验证。

签名身份连续性是更新与凭据延续的前提之一；面向他人的常规分发还须符合相应 Developer ID、签名和公证要求，见 [Apple 公证说明](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)。本轮只查询可用身份的数量，当前默认钥匙串未检出有效 `Developer ID Application` 身份，没有读取或导出私钥；这不表示用户没有开发者会员或其它身份。稳定本机签名仍只是自用候选，不能凭此宣称更新器、系统安装检查或 Keychain 已通过，也不因此删除自动更新要求。

### 运行、关闭与恢复

helpr 统一拥有工作区、浏览器控制连接及其执行进程，复用[持久记录协议](10-durable-execution-contract.md#answer)管理派发资格。单项任务停止只撤销该项资格，不结束承载另一项任务的宿主；主程序退出则停止所有新派发并清理自有工作者，不能留下继续操作网页的孤立执行进程。

- 主窗口红色关闭按钮只收起应用；页面、任务和计划继续保留，菜单栏入口可重新打开工作区。单个任务标签页仍使用既有收起／停止规则。
- 明确退出或 ⌘Q 才结束程序。退出先阻止新派发、保存记录，已经送出的动作仍按实际效果记录；无法确认的效果保留未知，不能假装取消成功。退出不把所有任务改为用户明确停止。
- 再次打开，先核对原意图、记录、页面与实际结果；原先自动执行的任务满足条件后恢复，待参与、人工接管和明确停止保持原有要求。旧进程回调不能恢复控制，重复打开应用不能取得第二份有效派发资格。
- 遵循 Mac 原有休眠设置，不自动阻止休眠；休眠期间不承诺按时执行。唤醒先重新核对，再按每项计划已有的补做、跳过或询问约定处理。锁屏／解锁与休眠／唤醒分别验证，不能以控制连接断开代替真实系统事件。

运行条件应向用户明确显示。现有输入和页面实验没有证明打包后的退出、重启、真实休眠或升级恢复，不能把事件通知当作可靠保存或恢复完成的证据。

### 文件、凭据与网站现场

| 数据或能力 | 首版要求与边界 |
| --- | --- |
| 任务、确认、计划、流程及结果 | 统一关联记录放在本机应用数据区，按既定协议保存；不混入安装包，也不因替换应用丢失 |
| 素材与必要证据 | 按记录关联保存固定版本，保留来源与用途；定时取材只按已约定范围使用，不能因文件后来变化替换已确认版本 |
| 模型凭据 | 通过 macOS Keychain 支持的受保护路径保存；不可用时说明并暂停依赖它的请求，不降级为明文。普通日志、流程、导出和备份不含密钥或认证头 |
| 网站登录 | 由持久浏览器会话保留，用户在真实网页登录；不同任务页面不自动等于不同账号会话，共享登录变动仍核对受影响任务 |
| 文件访问 | 用户选定的素材范围由 helpr 的执行入口检查；系统拒绝或用户撤销范围后，暂停受影响工作并说明。目录选择不是整个应用的操作系统沙箱 |
| 缓存与清理 | 将可重建缓存与登录、现场、业务记录和证据分别管理，不能把整个浏览器数据目录当作缓存删除 |

模型凭据候选采用 Electron `safeStorage`，它只保护显式交给它加密的数据，不会自动加密 SQLite、素材或整个浏览器目录。[safeStorage 文档](https://www.electronjs.org/docs/latest/api/safe-storage)说明 macOS 使用 Keychain 相关保护；升级后的读取、授权提示和失败行为须用虚构密钥验证，不能声称永远不会再次请求系统授权。

网站 Cookie 应显式启用并验证所选 Electron 版本的 `cookieEncryption`，其默认关闭且迁移不能当作可随意反向切换；这不等于 `localStorage` 或整个 profile 已加密，见 [Electron 44.7.0 fuses](https://github.com/electron/electron/blob/v44.7.0/docs/tutorial/fuses.md#cookieencryption)。持久会话和共享范围依据 [Session Interface](https://www.electronjs.org/docs/latest/api/session#sessionfrompartitionpartition-options)管理。非 Mac App Store 路线不把 MAS 专用的 [security-scoped bookmarks](https://www.electronjs.org/docs/latest/api/dialog) 当作已具备的文件授权机制。

现有原生接管使用 helpr 自己窗口的本地事件监视，实验未为此申请全局输入权限；此前 computer use 的屏幕录制／辅助功能设置属于测试工具，不能直接成为 helpr 的权限清单。打包后按实际所需能力核对最小系统授权，拒绝时明确哪些能力不可用，不要求关闭系统安全设置。

### 浏览器控制与宿主隔离

现有裸回环 CDP 端口没有客户端认证，且[可见网页控制实验](../experiments/visible-page-control/run.mjs)实际允许第二个客户端修改页面。`127.0.0.1`、随机端口或知道 target ID 都不证明调用方有资格。已选外部 Playwright 路线不能将这个实验入口直接作为交付接口。

首个验证候选由长期存活的 helpr 控制进程持有 Electron 私有调试 pipe，通过受认证、受当前任务／页面／执行资格限制的转接供工作者连接，消除能绕过检查的裸调试端口。所用 [Electron 源码](https://github.com/electron/electron/blob/v44.7.0/shell/browser/electron_browser_main_parts.cc)在 pipe 断开时请求应用退出，而 [Playwright `connectOverCDP`](https://playwright.dev/docs/api/class-browsertype#browser-type-connect-over-cdp)接收 HTTP／WebSocket 地址；不能把 pipe 直接交给可随单项停止的工作者，也不能假设 Playwright 已原生支持这条组合。候选不成立时再比较宿主调试 Interface 与私有进程通信，明确是否需要修订原路线。

远程网页启用 renderer sandbox 与 context isolation，禁用 Node integration，保留 web security；网页不持有模型密钥、本机文件能力或任意宿主 IPC。对话使用独立宿主页面，IPC 校验发送 frame、角色和具体允许操作；导航、新窗口、外部协议、下载及网页权限请求经宿主管理，并保留合法任务页面的归属。依据 [Electron 安全指南](https://www.electronjs.org/docs/latest/tutorial/security)，这些是交付前须检验的宿主边界，不是任意网站隐含写入已被隔离的证明，也不承诺抵御已控制用户账号或操作系统的攻击者。

### 保留、清理和本机备份

默认保留任务历史、素材版本和必要证据，由用户主动清理已结束任务；清理前说明会失去哪部分回看与恢复能力。正在执行、待参与、停止后可继续或结果不明的工作所需数据先保留，共享文件还须核对其它任务和计划的引用。空间不足时提示并暂停依赖保存的自动工作，不静默淘汰旧资料；自动到期清理策略不纳入首版默认行为。

清理历史也不能无声删除定时取材所需的完成事实，再把已发布素材当作从未处理。若用户确实清除这些最小记录，依赖它的自动判断须暂停或重新约定，不能凭“查不到”重新发布。

本机备份包含关联记录、流程、素材版本与必要证据，排除模型密钥及浏览器登录／会话目录，不自动上传云端。备份由持久记录拥有者协调取得一致的记录及引用文件，校验完整性与版本，不盲目复制正在写入的单个数据库文件。用户选择的本机备份位置仍可能包含敏感业务内容，不宣称它自动具备整盘或端到端加密。

恢复旧备份前保存当前资料，暂停自动工作并核对实际网站结果，由用户决定继续哪些任务或计划；模型设置和网站登录可能需要补充。备份不能回退网站，也不包含备份之后的新发布、停止或约定变化；不得自动按旧状态补发。应用降级同样不意味着业务资料能安全降级，不相容时保留资料并说明原因。

### 更新检测与安装

自动检测并提醒，默认由用户手动安装，提供“空闲时自动更新”开关。检测只获取版本、平台、架构与兼容信息；不下载安装包或向系统更新器登记待安装版本。Electron 的 [`autoUpdater.checkForUpdates()`](https://www.electronjs.org/docs/latest/api/auto-updater)会在发现更新后下载，成功下载的更新会在下次启动时应用，因此不能将它直接当作无副作用的版本查询。

开启空闲自动更新后，须同时满足：没有正在执行或已到期待派发的工作；没有待确认、待登录或人工接管现场；没有尚未核对的提交结果、未保存或无法重建的网页现场；距离下次计划足以完成当前更新与检查。等待用户不是空闲。停止任务所需的现场同样保留，历史中无需现场的停止记录也不能因更新重新获得执行资格。所需间隔依实际更新耗时和恢复检查确定，本轮不臆定固定分钟数；长期没有时机时提醒用户手动安排。

用户手动安装也需先解释和处理不能关闭的现场，不能把“安装”解释成已经确认发布内容或放弃页面文字。更新准备通过统一派发入口阻止新动作，重新核对空闲条件和下一轮计划，可靠保存并形成本机备份后，才允许下载、登记待安装及替换。条件在交给更新器前变化就推迟；进入安装后的阶段也要留下记录，防止缓存包在下次启动绕过检查。`quitAndInstall` 的窗口关闭次序意味着不能只依赖普通退出回调来做这些准备。

更新包必须来自确定的可信来源，核对签名身份、架构和数据兼容性；正式网络源使用 HTTPS，检测只发送所需版本信息，不上传任务、素材或凭据。可以使用自用更新源，不要求公开 GitHub 发布；可用分发方式见 [Electron 更新指南](https://www.electronjs.org/docs/latest/tutorial/updates)。当前还没有确定并验证正式更新地址、维护方式与签名发布链，这些是交付前提，必须在封装实验中给出具体可行路线，不能悄悄改回只支持手动替换文件。

更新后先检查记录与素材完整性、原生输入识别及网页控制能力，再按原意图核对恢复。检查、备份或兼容性失败时保留可用资料并停止依赖它的自动工作；旧版是否可继续运行取决于数据兼容，不强制回滚数据或盲目恢复网页操作。更新包替换、数据迁移和网站副作用是不同事实，须分别留证。

### 后续证据与本轮边界

新增[验证浏览器控制连接与宿主隔离](24-private-browser-control.md)，核对实际 Playwright 连接、无资格客户端、跨任务控制和断开行为；新增[验证 macOS 自用应用的封装、更新与运行恢复](25-macos-packaged-lifecycle.md)，在当前 Mac 上核对独立应用、签名、两个版本的真实更新、凭据延续、退出、休眠和备份恢复。两项均在取得决策证据后结束，不提前建设完整产品。

[恢复核对依据的自动形成](23-autonomous-recovery-evidence.md)改为等待控制连接验证；[首版组合验证与验收安排](21-integrated-validation-and-acceptance.md)同时等待上述证据及已有持久一致性、自动恢复验证。签名或控制方案不成立时应带着事实修订路线，不能降低已确认的自动更新、两项并行、直接接管或五项业务验收范围。

本轮只调查事实、记录用户选择及调整文档和依赖，没有安装应用、运行新实验、调用任务模型、操作业务后台、改动系统设置或发布安装包。
