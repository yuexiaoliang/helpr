## Question

在已选[浏览器和执行组合](07-browser-runtime-decision.md#answer)、[持久化与恢复约定](10-durable-execution-contract.md)、[本机交付要求](20-local-delivery-and-updates.md)之上，怎样安排实现中的验证与用户验收，才能知道首版整体真的可用，而不是把不同实验各自通过拼成完整产品已经通过？

以已确认的 [首版验收范围](../../../docs/product/acceptance-outline.md)为前提，区分实现前必须消除、可能改变架构的未知，稳定的自动行为检查，以及必须在目标环境完成的真实网页或真人核对。不要在规划地图中提前实现整套产品。

需要明确：

- 自动检查经过哪些公开的 Module Interface，如何核对实际动作、素材、结果、停止意图和无重复派发，哪些观察需要独立于候选实现；不为每个内部函数重复造测试。
- 选定的 Electron、Playwright、原生输入识别、流程学习／重放／修复和结果核对，如何在同一完整产品组合中验证。两项真实任务须有实际推进重叠，并覆盖其中一项接管、停止或等待参与时另一项继续。
- 五项已确认业务验收如何逐步完成：首次附件发布、换输入复用、重启复用、读取 Excel 生成内容并确认发布、换另一套结构不同的后台。维护者手填网站选择器、修补流程或启动校准不能替代产品自行组织学习与修复。
- 共享登录、同一目标、素材版本、并发流程修复、参与请求和结果不明如何纳入反例；未知输入时暂停两项的异常提示需让用户理解，正常路径仍独立处理。
- 目标 Mac 上的真实点击、中文输入、粘贴、窗口／页面变化和休眠唤醒怎样取得证据；若需要真人动作，先完成可自动核对的部分，再给最小而明确的操作说明。工具输入不得计作真人样本。
- 每轮验证的预算、重复与失败记录、成果保存、停止条件和发布前通过条件；明确实验授权与正式任务授权的区别。接受网站隐含写入没有通用隔离保证，不等于可把已观察到的越界或无法确认结果忽略。

输出可交给实现规格的检查与验收安排，不重新缩小既有五项场景、两项并行或直接接管要求。若证据缺口确实需要改变这些要求，单独带着具体事实与用户讨论；不能直接删掉验收条目。

## Answer

2026-10-13，用户确认以下组合验证与验收安排，同日按最新选择将自动安装移出首版。它是后续规格的输入，不是已执行的验收结果或新实验的运行授权。五项业务场景各至少两次独立通过；更新范围为自动检查新版、提醒及手动下载、安装，仍须保留原受保护凭据、有效登录与任务资料。

### 实现前需要解决什么

沿用 Electron、Playwright、原生输入识别、统一执行入口、SQLite 记录与不可变素材文件的既定路线。此前不同实验各自通过的事实继续作为设计依据，不相加推定完整产品通过。

[验证自动更新后无需再次系统授权的凭据延续](26-unattended-update-credential-continuity.md#answer)因用户缩小首版范围而关闭，不是验证通过，也不再阻塞实现规格。已有自签名换版拒绝读取、系统授权及跨升级登录的证据缺口保留。Xcode／Personal Team 准备方案搁置，不为首版继续取得无人参与更新的签名条件。手动升级中的实际系统交互、原密钥读取及未过期登录保留在产品初期贯通并在交付时复验；不靠重填原密钥、重新建立仍有效的登录或降低保护获得通过。

其余缺口先安排在产品实现初期贯通，在交付候选上再复验：它们依赖完整任务、学习、持久记录和工作区，不再各造一个长期维护的演示产品。若贯通出现足以否定既定保证的反例，停止依赖该结论的扩展并回到具体技术决定。

### 三组自动行为检查

自动检查沿用调用方使用的公开 Module Interface；名称表示职责，具体函数、文件和表结构留给规格与实现。每组聚合用户可观察的行为，不为每个内部辅助函数重复造测试。

| 组 | 经过的公开入口 | 独立核对与主要反例 |
| --- | --- | --- |
| 意图、记录与派发 | 当前事实读取、接受委托与参与回复、领取执行／素材／计划、动作预留及结果登记、采用流程候选 | 另一个进程重开真实记录；独立接收端记录实际收到与完成的动作，不读取候选数据库、也不替候选去重。核对重复回复、停止与继续、迟到回调、并发领取、保存失败、旧备份、新素材和并发流程修复；同时核对素材字节。 |
| 网页工作区、执行与流程 | 工作区、网页执行、流程的公开入口；首次探索、重放、修复都走同一资格检查和控制路径 | 从实际网页、目标站点记录和下载内容核对结果，另行计数请求与副作用；验证越权、跨任务、过期执行和远程网页访问宿主被拒绝。产品不能读取独立核验答案，网站专用核验知识不得回灌为业务执行代码或手填流程。 |
| 应用运行、版本检查与资料恢复 | 与 UI 共用的收起／退出、版本检查、手动升级准备、备份、恢复入口 | 用实际两个版本安装包、系统进程树、只读版本请求、备份内容及升级后网页效果核对；事件回放检查保存与派发的顺序和竞争，真实包检验退出完成。不能只看到退出通知就判断所有自有进程已退出。 |

模型请求的取消、用量上限与并发限制纳入第一组，页面工具和恢复判定纳入第二组；确定性检查使用受控回应，不用它评价真实模型理解质量。现有实验检查继续保留，正式产品检查必须走正式入口，并接入仓库日常检查。

### 在同一产品中逐步贯通

1. **最早可运行的产品阶段。** 同一安装包串起真实网页、独立对话、私有控制、原生输入、可靠保存和核对恢复；两项可独立推进的任务从这里进入。先通过停止／接管不串任务、冷重开不重复派发、真实活动状态下的退出与恢复，再扩展业务覆盖。固定应用身份与数据位置，及早核对实际安装、手动换版后的原凭据和有效登录保留，不等最后打包时再验证。
2. **附件与复用阶段。** 通过首次附件发布、更换输入复用和冷启动复用；在这些完整路径中加入计划取材、素材版本、确认归属及变化修复。重放仍允许理解新委托的模型调用，但稳定网页动作的重放须能直接执行并分别记账。
3. **内容与跨站阶段。** 加入读取 Excel、预览确认后发布，以及 Drupal；同一产品代码从实际网页自主形成流程。三种并行组合——探索与探索、复用与复用、探索与复用——都必须有真实推进交叠。
4. **交付候选阶段。** 固定应用、依赖、原生组件及配置版本，在目标 Mac 上完成完整矩阵、两次业务样本和最后真人核对。早期贯通证明实施方向可行，只有交付候选证据能支持交付通过。

### 五项业务样本

每项至少两次独立成功，合计至少十个业务样本；样本内容或输入不同，同一成功输出不重复抵算其它场景的次数。首次探索使用未预置相应业务流程的独立验收数据区；复用案例沿用产品实际学得并保存的流程。产品不得取得测试用预期答案、维护者选择器或人工补写的流程。并行、恢复等专项可附着这些样本取证，不为同一个断言额外重复发布。

| 场景 | 必须保存的通过依据 |
| --- | --- |
| 首次附件发布 | 自然语言委托、产品探索与保存的流程、正确目标／栏目、真实结果位置；下载附件与所选素材版本逐字节一致。 |
| 换输入复用 | 新素材与标题，用户明确要求时改变栏目；输入绑定正确，网页动作重放与其它模型调用分别记录，没有沿用旧文件或旧确认。 |
| 冷启动复用 | 应用完整退出后重开，再使用新输入；不依赖上次仍打开的编辑页、未保存的流程或进程内状态。 |
| Excel 生成内容 | 两份内容不同的表格，事实及数字逐项对照；预览、确认、实际提交保持版本和任务归属，内容改动后旧确认不能继续使用。 |
| 不同结构后台 | Drupal 使用相同通用产品代码完成两次任务；站点知识与具体步骤来自运行时观察和流程，不由维护者补写业务实现。 |

两个站点的模型调用、上传、创建草稿、保存和最终发布分项计数。独立核验既查看最终结果，也查看多余结果与已观察到的异常；成功页面不掩盖多发、串素材或越出委托的已知效果。

### 组合检查矩阵

| 主题 | 在完整产品中必须覆盖 |
| --- | --- |
| 并行与查看 | 三种探索／复用组合真实重叠；A 接管、停止或待确认时 B 继续；第三项合格任务在容量已满时排队，容量释放后依条件推进。只看、切页、移动鼠标和对话输入不误接管。隐藏主窗口时两项合格任务仍推进，恢复窗口不丢现场。 |

| 页面与输入归属 | 点击、独立中文输入、独立粘贴分别触发对应任务让出；刷新、导航、新窗口、视图重建后重新核对。归属未知时说明原因并暂停窗口内两项，只恢复被明确继续的那项，不抹掉另一项的停止。 |
| 共享条件 | 同一登录过期、恢复及切换账号只影响相关工作；同一目标的冲突得到协调，无关工作继续。不得以两个独立页面推定账号和目标没有共享影响。 |

| 发布约定 | 自然语言复述素材范围、目标和内容规则；符合有效约定的新内容可自动发布，不每次重新索要确认。修改目标或处理规则时重新确认，撤销约定后不能继续沿用；不同平台任务不共用一次内容确认。 |
| 修复与流程采用 | 真实网页变化触发产品自身重新观察，在原约定内核对后保存新做法并告知；之后冷启动再复用修复版。同一流程并发修复不互相覆盖正在使用的版本，未经核对的候选不被采用。 |

强杀进程、受控存储故障、休眠和实际断电分别记录。现有证据没有证明物理断电后的保证；不得把进程强杀改称断电验收，也不在用户的日常 Mac 上擅自断电。具体持久化规格须写明承诺与证据边界，若要求增加实际断电验证，另给隔离条件与具体方案，不自动计作已通过或删除已有恢复要求。

### 真人操作安排

预计集中为两轮：最早产品贯通时一轮、交付候选时一轮；每轮按 10–15 分钟主动操作安排，实际超时或系统阻塞就保存现场并另行安排，不反复要求用户盲试。这不是当前预约或新一轮实验授权。实际安装及手动升级所需系统交互另记，与接管、锁屏和休眠的真人证据区分。

每轮先由 agent 检查实际安装包、窗口可见、页面完成绘制、任务确实推进、输入焦点、记录采集及预期状态。截图失败或窗口不就绪先处理测试装置，不发过期步骤给用户。

给用户一次一个简短动作，说明要操作哪个窗口、预期看到什么，以及何时停下。独立键盘／粘贴案例不先点击网页输入框；点击接管单独测试。步骤后由 agent 读取记录、页面文字和另一任务进度判定，无需用户报数字或理解内部调度。真正的中文输入法、⌘V、锁屏和休眠不能用自动化事件代替。最终还需由本人确认实际使用流程可理解；自动计数通过不代替这项体验核对。

### 预算、失败与证据

- 本事项的模型请求、远程业务写入、应用构建／安装／启动和故障注入均为零。旧封装实验已经停止，原预算不重置，也不借用残留清理额度开新实验。
- 每批实际验证先固定候选版本、样本与账号／目标范围、要跑的案例，以及模型请求和费用、网页动作、草稿／上传／发布、构建／安装／启动、故障和运行时长的具体数字上限；真人等待另记。数字依届时可运行路径形成可审阅方案，不能在没有产品时用随意的统一次数充当已获授权预算。
- “每场景两次通过”是完成门槛，不是可以一直试到成功的额度。每批只运行预列的案例和恢复动作；失败、启动失败、准备工作、修复后的重跑都计入累计用量。重启进程或换目录不清零，超出当前授权前先准备具体增量方案；已有授权内的本地修正与自动检查继续完成。
- 最终提交结果不明、已观察到越界或串任务、停止失效、关键保存失败、凭据保护失效、异常弹窗或自有进程残留时，停止受影响的自动验证。先保留原始事实、时间、版本、进程和必要现场，再做明确限于测试资源的清理；未知结果不能通过删数据、换样本或补点按钮改成成功。
- 确定性反例在修正前应能失败、修正后通过；真实模型或环境偶发失败保留原样，再区分候选问题、环境问题与观察装置问题。修订后重跑受影响的检查及其组合，涉及控制、记录、签名或原生组件时不能只跑局部单测；无关已固定证据不重复消耗。
- 证据包含源码／安装包与依赖版本、输入素材版本、原始事件、独立核验、失败和修复差异、累计用量及真人参与。人工关闭错误弹窗等协助必须写进结论，不能计作自动通过。私钥、凭据、浏览器资料、运行时数据库及构建包遵循 ignore，仅保存脱敏且足以复核的材料。
- 验证只使用明确范围的测试素材和后台；批准验收安排不等于委托生产发布、购买签名服务、公开分发或永久更改系统设置。届时已有授权适用时不重复询问，出现具体新增外部责任才给用户看实际方案。
