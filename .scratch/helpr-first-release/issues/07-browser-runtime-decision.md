## Question

前提：[参数化流程的冷启动重放与修复更新](05-runtime-flow-replay.md)、[可见工作区中的 AI 双页操作归属](06-ai-parallel-binding.md)、[人工接管的输入识别与让出操作](12-human-input-takeover.md)和 [流程适用性、步骤条件与修复边界](14-workflow-reliability-contract.md)。页面与输入对照已经取得事实；人工接管已取得 macOS / Electron 固定已登记视图中的真实证据，[页面变化后的输入归属与继续](19-page-lifecycle-input-ownership.md#answer)已补充受控生命周期证据和未知出口，具体限制须一并进入本次选择，不能由 AI 页面绑定或停止实验代替。

基于实际页面、输入来源、独立停止、AI 并行与流程重放证据，首版采用哪一套浏览器承载和执行组合，关键 Module 的 Interface 需要提供哪些保证？

[AI 双页实验](../experiments/ai-parallel-binding/REPORT.md) 已在两种宿主取得真实模型、显式 target、独立执行进程及逐原语停止的组合证据；验证对象是小型封闭动作执行器。它没有证明 Stagehand 或其它 SDK 的内部动作可取消，也尚未与完整发布流程合成。选择时需明确实际采用的执行器及未覆盖原语的处理，不能仅凭宿主相同把两组独立实验当作完整组合已验收。

比较已取得证据的方案，给出明确推荐和影响用户体验、维护成本及后续扩展的取舍。用已确认产品行为判断方案；需要范围变化时明确说明，不把未通过实验的能力默认为可用。

流程表示与执行机制的选择必须能承载已验证的适用条件、参数绑定、步骤条件、结果判定与修复限制；不能仅凭可以录制和重放动作就确定方案。提交恢复、内容版本和第二后台事项各自补充的证据仍须进入最终规格，不能由宿主选型替代。

[上传授权与完整流程的分阶段检查](17-upload-authorization-and-workflow-checks.md) 已在既有自动探索前缀上补全真实发布、模型位置校准及冻结后保留集，解除此前只有局部复用证据的缺口。这仍是单后台、单附件及有限任务形态的证据，不能直接推广为完整产品能力。

该实验还观察到目的未核实的写请求在点击等待窗口中被放行；上传文件选择与请求元数据的对应也不是传输字节证明。须结合 [网页动作、上传数据与写请求的关联边界](18-action-request-association.md) 的事实，确定执行 Interface 能提供的保证、必须停止或保持不确定的范围；不能把结果正确当作所有副作用均在授权范围内。

形成足以写规格的选型结论、必要的能力约定与仍需在实现中检查的限制。只有符合难逆转、需要背景解释且存在真实取舍的决定才写 ADR；文件结构和日常实现细节留给后续工程工作。

## Answer

2026-10-12，选定 **macOS 上的 Electron 真实网页工作区、独立任务对话视图、外部 CDP 连接的 Playwright，以及 helpr 自有的统一执行与结构化流程机制**。这是首版实现路线，已有实验为关键机制提供事实；完整组合尚须在实现中验收。首版五项业务场景、最多两项独立任务并行和直接操作网页接管均保持。

### 组合与取舍

| 范围 | 采用的方案与原因 | 保留的代价或限制 |
| --- | --- | --- |
| 用户工作区 | Electron 的 `WebContentsView` 承载任务的真实网页；任务对话使用独立的宿主视图，宿主拥有布局和页面生命周期 | 维护桌面应用与原生输入识别；升级需复验视图结构和输入归属。首版支持 macOS，具体系统版本与硬件范围另定 |
| 网页控制 | 执行端通过外部 CDP / Playwright 连接，按宿主登记的 `webContents` 与 target 身份绑定任务，不按 URL、页面顺序或当前焦点选页 | CDP 并不提供所有 Playwright 功能的同等兼容；每种采用的动作和观察能力都需声明及验证，不把实验中 `_electron.windows()` 的枚举缺口当作已修复 |
| 执行隔离 | 宿主保留用户网页；每项活跃执行使用独立派发进程，分别控制取消、旧执行失效与迟到结果。首次探索、重放和修复经过同一个执行 Interface | 进程隔离不隔离网站账号和服务端对象；共享登录、页面或目标仍由任务协调处理，规则和持久状态进入后续约定 |
| AI 与流程 | 模型提出当前观察支持的结构化动作和修复；通用程序检查后派发。网站定位、字段映射和任务规则保存在可版本化的运行时流程中 | helpr 需要实现学习与修复的自动组织，实验中维护者启动校准或修改通用协议不能成为日常使用步骤 |
| 稳定复用 | 固定所用流程版本并绑定本次输入；已学网页步骤由程序执行，理解新委托和组织新素材仍可按需调用模型 | 不承诺整次任务零模型调用；流程适用性与本次发布授权分别核对 |

普通 Chromium 加扩展也取得了页面身份、真实双页重叠和独立停止证据，并未被证明不可用。但其直接真人接管缺少同等证据，插入网页的对话输入也会进入网站事件观察范围；当前 Electron 路线更贴合独立对话与直接接管的已确认体验，因此首版不同时维护第二种宿主。

Stagehand 没有参与本次完整流程和接管组合的实测，不进入首版关键执行路径，也不新增一轮只为覆盖所有备选库的实验。未来引入任何 SDK 时，都须经过同一执行 Interface，核对其内部动作和取消能力；不能直接把一个会自行重试的多步调用当作可停止的单步动作。该选择不表示所有版本的 Stagehand 都不兼容或不可取消。

已有宿主、AI 并行、真人接管与生命周期事实分别见[页面归属](01-visible-page-control.md#answer)、[独立停止](02-independent-stop.md#answer)、[AI 双页](06-ai-parallel-binding.md#answer)、[真人接管](12-human-input-takeover.md#answer)、[页面变化](19-page-lifecycle-input-ownership.md#answer)。官方契约另说明 [WebContentsView 与所显示 WebContents 的关系](https://www.electronjs.org/docs/latest/api/web-contents-view)，以及 [CDP 连接的兼容范围与 `noDefaults`](https://playwright.dev/docs/api/class-browsertype#browser-type-connect-over-cdp)。文档用于核对接口含义，不替代本仓库运行证据。

### 关键 Module 的 Interface 保证

以下确定调用方能依赖的行为，不冻结文件结构、方法名或全部数据字段。实现与测试经过同一 Interface；复杂的原生登记、控制连接、检查及重试留在相应 Implementation 内。

| Module | 调用方交付或取得什么 | 必须集中保证的行为 |
| --- | --- | --- |
| 工作区 Module | 将任务关联到真实页面和登录上下文；提供带任务归属的观察、输入及页面生命周期通知 | 对话与网站内容分开；同 URL 不混淆；popup 和新页面必须建立归属才可派发；刷新、页面替换、连接失效后旧绑定不能静默继续。仅查看和对话不接管网页 |
| 网页执行 Module | 接收固定任务目标、输入与内容授权、流程版本或探索提议，返回进度、参与需求和带证据的结果；承接停止与新的继续意图 | 校验任务与执行身份、当前页面、本次参数、内容授权及动作能力。所有自动动作、重试和模型提议统一经过派发前检查；停止后不再新派发，迟到结果不创建后续动作；已经发出的效果仍独立核对 |
| 流程 Module | 依据任务与页面提出可复用候选、形成学习／修复候选，并提供固定版本与验证来源 | 适用性不代替本次授权；条件和参数有实际来源；验证后才采用新版本，失败候选不覆盖旧流程。并发更新与保存原子性由持久化约定落实 |

模型请求沿用已有按服务配置、任务归属和取消约定，模型不直接持有宿主或浏览器的任意操作入口。素材和确认记录沿用[版本关联证据](13-material-preview-binding.md#answer)，网页执行不能把一个孤立的“已确认”标志当作本次内容授权。

不同执行的任务、输入、观察和结果不得串用。是否共享登录与目标对象不能只依据“分属不同标签页”判断；不能证明互不影响时由系统协调等待，涉及目标取舍才请求用户参与。两个任务同属一个任务组不构成一起停止、重试或发布的理由。

### 流程采用什么形式

采用带来源和验证记录的结构化运行时数据，至少表达：适用条件、输入的类型／来源／约束、参数引用、步骤的前条件／动作／后条件、结果核对规则、必要的重新观察入口及版本关系。步骤条件依赖实际观察，不能只凭模型将某个动作标为“发布”或“只读”就赋予效果保证。

模型提议需落入已实现并验证的通用动作与检查能力。已有实验覆盖点击、填写、选择、上传等有限原语和相等、真实选项标签、实际文件摘要等检查，可以作为实现起点；当前实验 JSON、附件任务模板和 `testAuthorization` 不是产品语言或任务授权入口。首版不把模型生成的任意脚本直接当作流程执行；缺少所需能力时明确说明当前不能继续，新增能力须是通用能力并经过验证。

学习或修复先形成候选版本，核对实际结果后按用户既有约定自动记住，并简短告知；不要求用户编辑流程。修复不得改目标、替换已确认内容或削弱成功条件来制造成功。已经派发且结果不明时先核对，不能通过重复发布来试探进度。一次成功只支持实际验证的路径，未出现的分支不能凭模型补写就标为可复用。

这些选择来自[流程约定](14-workflow-reliability-contract.md#answer)、[分阶段完整路径](17-upload-authorization-and-workflow-checks.md#answer)和[第二后台对照](11-second-backend-comparison.md#answer)。后两项证明有限流程可形成并换输入复用，也记录了工程修订与位置校准；尚未证明任意新网站原样自主成功。产品仍须在五项首版场景中自行组织学习、核对与修复，不能靠维护者补填网站选择器通过验收。

### 人工接管、继续及网页写入范围

正常情况下，人工操作只让对应任务让出，不受影响的任务继续。无法确认窗口内输入归属时，保留未知并说明原因，暂停窗口中两项自动执行；这不是把两项都认定为人工接管，也不是宣布任务失败。用户在相应任务明确继续后，先核对当前页面、输入、停止原因和已有结果，再继续剩余工作。另一项已明确停止的任务保持停止，核对期间出现的新停止优先于较早的继续请求。

重新查看、登录恢复、恢复连接或重启都不能清除用户的停止意图。对于原先自动执行而被技术故障中断的工作，按既有产品约定核对后恢复；无法确定时请求参与。网页刷新已丢失的未保存文字不得伪称保留，实际休眠唤醒尚需目标环境验证。

用户接受的首版网页写入保证是：**helpr 自己的操作、素材、目标和结果必须按委托核对；不承诺在发送前识别并阻止网站脚本的所有隐含写入。** 这一区别来自[请求关联的实测反例](18-action-request-association.md#answer)，不因采用 Electron 或 Playwright 自动消失。

- 首次学习可在已确定的任务目标和内容授权范围内自动探索。不把“已经掌握网站每一条请求的精确约定”设为所有探索动作的前提，也不新增逐请求批准或网站专用业务白名单。
- 网络观察可用于识别异常与核对效果，覆盖范围必须如实记录；没有观察到不等于没有发生，通道未覆盖也不能标为已经核验。时间相邻、同一点击、相同正文和文件名均不作为请求授权归属的充分证明。
- 发现输入、内容或目标不符，观察到额外异常改动，或已提交结果仍无法确认时，停止后续自动动作，核对实际结果并在需要时请求参与。“继续”不使旧授权或旧动作重新有效，也不是忽略未解决异常的许可。
- 动作调用完成、网页后条件成立、业务结果核对成功和网络证据范围分别记录；不能合成一个成功标志。只有效果有充分依据时才报告完成；尚不明确的事实保留不确定。
- 本轮不采用“拦截一切请求的 HTTP 代理”作为既定产品架构，也不将实验中的正文匹配当作通用因果或业务授权证明。若以后要求更强的网络隔离保证，应另立目标与证据要求。

已收到的提交或上传可能在停止后完成；结果核对与有限续做沿用[提交中断证据](08-result-recovery-evidence.md#answer)。以上不是对网站隐含副作用的授权，也不降低已确认的内容预览和发布约定要求。

### 后续工作与未获保证

本次没有运行新实验、调用任务模型或改动真实后台。独立实验为当前选择提供依据，不能把真实 AI、真人接管、完整业务发布、共享登录、并发修复与恢复拼成“同一产品组合已验收”。真实休眠、复杂页面／弹窗、渲染崩溃、应用重启及升级兼容仍须按目标组合核对；对没有对应保证的操作不应无声降级为任意浏览器脚本。

架构理由记入 [ADR-0003](../../../docs/adr/0003-electron-controlled-execution.md)，用户范围同步到产品共识与验收要求。具体持久事实、原子变化、流程并发更新和定时恢复交给[确定执行记录、流程更新与定时恢复的约定](10-durable-execution-contract.md)。

选型使原地图中的两片未定范围可具体表述，新增并连接：[确定本机交付、权限与更新约定](20-local-delivery-and-updates.md)和[确定首版组合验证与验收安排](21-integrated-validation-and-acceptance.md)。前者处理安装、登录／凭据、控制连接、目标系统与升级；后者区分会改变路线的前置未知、自动检查和最终真人／真实网页验收。若后续证据否定关键保证，应回到相关决策，而不是将限制悄悄写成已支持。
