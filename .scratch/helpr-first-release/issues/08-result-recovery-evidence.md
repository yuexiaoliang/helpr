## Question

前提：[参数化流程的冷启动重放与修复更新](05-runtime-flow-replay.md)。

在提交前、提交请求已发出但回执丢失、结果已经存在等位置中断执行后，哪些运行时证据足以判定已完成、可继续或仍无法确定，从而避免重复发布？

复用已能运行的流程实验，用独立测试后台控制中断时机，重新打开页面并核对真实产出。记录恢复判断需要哪些执行记录、素材与目标关联，以及如何处理无法确认的情况。

核对两项任务处于不同进度时结果不会串用；已停止、待确认和人工接管的意图不能因进程重启被覆盖。测试环境可控制故障，产品侧核对方法须来自通用能力与运行时流程，不能固定为查询某个 WordPress 结果。

输出事实证据与最小记录要求，供持久化和恢复协议设计；区分页面或结果可重新观察，与运行中执行已经完整恢复这两种结论。

## Answer

2026-10-11 已完成。本次 [真实运行报告](../experiments/result-recovery/REPORT.md)取得提交前、提交成功但回执丢失、结果核对后尚未保存完成判断、派发标记与实际发送之间空隙的 SIGKILL 证据；新进程和新浏览器依靠执行记录、网页和实际下载字节重新判定。两项同名任务处于不同进度时未串用结果，三种用户意图在重启后均保持。累计 10 次新执行准备、6 次上传、2 次发布、0 次模型调用；原 8 次准备失败、额度批准与上传漏计补记全部保留。

### 足以采用的恢复判断

| 事实 | 本次支持的处理 |
| --- | --- |
| 能唯一定位本执行对应记录，且实际产出满足该流程的结果条件 | 确认网站效果已完成，不重复提交；本例核对标题、正文、分类和实际下载的附件 SHA-256 |
| 单一执行者在最终派发前持久保存了草稿检查点，重新定位后内容与素材仍匹配 | 可以继续该记录的剩余提交步骤；本例新进程续跑只发布一次、没有再次上传 |
| 已记录可能派发，但没有足够证据确认实际结果 | 保持无法确定，不自动重新执行；即便现场显示草稿也不足以消除旧请求仍可能生效的歧义 |
| 结果暂时不可读、任务关联不唯一或内容／素材不匹配 | 保持无法确定；可以再次只读核对，不能据此推定未提交 |
| 意图为已停止、待确认或人工接管 | 保持该意图与对应等待，自动动作为空；已经发生的网站效果单独记录 |

标题只能用于缩小查找范围，不能作为结果归属。本轮有四条同名可见记录；将一项任务的公开结果交给另一项检查时，标题相同仍被正文和附件条件否定。本地“最后一个动作没有返回成功”也不能证明网站没有执行。

### 后续协议必须保留的最小事实

这里明确所需信息，不预定数据库或最终字段布局。

| 信息 | 用途与本轮证据 |
| --- | --- |
| 任务、具体执行及其不可变输入摘要 | 区分同名任务和不同执行；正文、分类及素材均绑定到该次输入 |
| 目标站点、使用的登录上下文引用、可重新定位的稳定记录标识 | 在新浏览器里找到同一对象；本例使用网页给出的编辑记录地址，无法唯一对应时不能认领 |
| 素材实际字节摘要、流程版本、恢复入口及结果条件版本 | 重新核对相同任务含义；素材变化、版本不兼容或记录损坏时拒绝沿用进度 |
| 最近已核对检查点与不可逆动作的派发阶段 | 区分确实未派发的草稿和可能已发送的提交；持久标记本身不能关闭本地记录与远端效果之间的空隙 |
| 用户执行意图，及其对应的参与上下文 | 重启后的事实核对不能自行解除停止、确认等待或人工接管；参与请求身份和迟到回复处理仍由后续协议确定 |
| 实际结果地址、核对证据及观察时机；独立的未知／失败信息 | 成功事实可以重新取得，查无结果必须保留歧义；截图失败不能抹掉功能判断 |
| 上传、草稿保存与最终发布的分别记录 | 准备失败仍可能留下文件或草稿，不能只用“发布未完成”推定没有副作用或素材可重新消费 |

稳定目标关联应在取得时及时保留：A4 原准备已经保存草稿，但常规记录还没有保存目标地址，后续复核依赖额外留存的失败页面观察。这是记录窗口的反例，不能当作准备阶段任意中断均可自动恢复的证明。摘要检查也只是发现不一致，不构成防篡改签名。

### 保证边界与交接

恢复行为由通用浏览器能力及独立 JSON 流程约定驱动；WordPress 请求知识只在测试代理中控制故障和计数，未进入恢复判定。恢复入口与记录定位由操作者在真实页面上校准，本次没有模型调用，也没有验证这些恢复约定能够自动归纳。

本次确认的是“新进程可重新观察实际结果，并在一个已确认草稿检查点有限续跑”，不是恢复浏览器内部运行栈或交付完整恢复系统。机器断电落盘、多个恢复者、迟到请求、跨网站与外部编辑、真实人工接管及全部上传副作用仍没有本轮证据。

最小记录、原子变化、版本迁移及未知结果的产品处理交给 [确定执行记录、流程更新与定时恢复的约定](10-durable-execution-contract.md)；动作与实际写请求的关联继续由 [验证网页动作、上传数据与写请求的关联边界](18-action-request-association.md)取得证据。现有事项已经覆盖这些下一步问题，本轮不新增重复事项。

`npm run check`、`npm run test:browser` 以及本实验 `verify.mjs` 均通过；证据核对覆盖 15 次恢复及最终网页列表，运行方法见 [实验入口](../experiments/result-recovery/README.md)。
