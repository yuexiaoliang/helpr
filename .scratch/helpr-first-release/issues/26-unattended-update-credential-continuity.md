# 验证自动更新后无需再次系统授权的凭据延续

Type: task
Label: wayfinder:task
Mode: HITL
Status: resolved
Blocked by: 21, 25
Map: [helpr 首版技术决策地图](../map.md)

## Question

以下保留创建时的验证问题和边界。2026-10-13，用户将自动安装移出首版，本事项因范围变更关闭；它不是已通过的能力，也不再是实现规格的前置条件，见下文 [Answer](#answer)。

在当前目标 Mac 上，能否采用可持续维护的应用签名与凭据访问路线，让已配置的 helpr 经过真实自动更新后，无需用户再次进行系统授权，就能读取原模型凭据、保留仍有效的网站登录，并核对恢复允许继续的工作？

用户在 2026-10-13 明确要求“自动更新必须无需系统授权即可恢复工作”。这比“授权后仍能读回”更严格，属于实现规格前必须解决的交付路线问题。沿用自动检测、默认手动安装与可选空闲自动更新，不以取消自动更新、丢弃加密、重新登录或更新后人工授权替代。

### 起点与已有证据

- [封装与运行恢复验证](25-macos-packaged-lifecycle.md#answer)已完成有界实验。实际升级后读取原虚构密钥成功，但需要用户系统授权；相同 designated requirement 尚不足以解释或排除弹窗。不得推定每种正式签名都会出现同一问题，也不得宣称换成正式签名必然消失。
- 原登录 Cookie 在跨版本核对前已自然过期，因此没有取得跨升级保留登录的有效证据。同版新 Cookie 重开通过不能补上这一缺口。
- 现有身份是实验用自签名，系统评估未作为正式分发接受；正式签名身份、可信 HTTPS 更新来源及维护方式仍未固定。不能把用户曾允许实验授权解释成已选择正式身份、同意购买服务或改变系统信任。
- 旧封装实验已停止，构建、安装和启动额度已用完。此事项必须另有具体有界方案；不得复用旧预算或剩余清理次数继续运行。

### 必须回答与核对

1. 先从冻结源码、签名和应用路径、实际受保护项目、原生组件及原始时间线定位请求授权的条件；事实不足保留未知。核对 Apple 与对应 Electron 版本的一手材料及实际可用配置，不让用户猜技术原因。
2. 给出可用于当前自用交付的具体签名身份、凭据访问与可信更新来源候选，说明维护责任与已知代价。需要新增账号、费用、凭据权限或外部发布时，先将具体候选和必要条件准备可审阅，再请用户决定；可只读取得的事实由 agent 查明。
3. 只搭建回答此问题所需的最小安装包，不扩展成另一套产品。固定身份、路径、加密设置与依赖，在首次正常设置后保留原凭据和未过期会话，通过真正的闲时自动更新入口连续验证两个版本跃迁及重开；模型请求、远程业务上传和发布保持零，以虚构受保护值和受控网页核对实际机制。
4. 更新前后读取的是同一原始凭据和原会话，不能通过重新创建项目、重填值、重新登录或复制测试答案获得通过。记录 Cookie 有效期、服务器会话条件和系统授权观察；窗口未绘制或测试超时不当作“没有弹窗”。首次设置、正常解锁、更新新增的授权提示和网站自身会话到期分别说明。
5. 开启闲时更新后的检测、下载、安装、重开与恢复使用实际候选路径；自动检测不能提前下载，任务／现场与更新的既定资格不放宽。任何人工处理系统授权的升级样本都不能计为无授权通过。
6. 拒绝受保护数据访问、错误身份、来源或更新失败时，资料与停止意图保留，不继续依赖无效凭据的工作；不能将 Keychain 项放开给所有应用、降低为明文、关闭 Cookie 加密或改变系统安全设置作为成功方案。

### 运行边界与输出

先形成冻结候选、独立判定依据、构建／安装／启动／更新／系统设置和用时上限、停止与清理方式。用户实际需要的首次设置尽量集中，agent 先完成自动准备，再给最小明确指引；用户密码不进入对话或日志。新实验的授权与原实验分别记录，已有有效授权范围内不重复请求。

输出实际可用路径、版本与证据、未成立之处及其对首版路线的影响。满足门槛才支持写入实现规格；若候选失败或条件缺失，保存失败与累计消耗，提出下一项具体需要决定的问题，不无限追加尝试，也不代替用户放宽无授权要求。完整产品仍须按[组合验证与验收安排](21-integrated-validation-and-acceptance.md)复验。

## Answer

2026-10-13，用户决定：“如果自动更新一定需要签名的话，那我们可以先不做，以后产品盈利了再做”。本事项按**移出首版范围**关闭，不按实验通过关闭。

- 首版保留自动检查新版和提醒，由用户手动下载、安装；自动下载安装（含空闲自动更新）及零新增系统授权的恢复要求留到产品盈利后，届时另立工作与验证方案。
- [原生诊断](../experiments/unattended-update-credentials/DIAGNOSIS.md)仍为失败：相同自签名规则与路径下，代码换版后禁止授权交互的读取被拒绝。已取得的事实、研究报告、原始证据与累计次数保留；没有完成实际无人参与更新，也没有证明跨升级登录保留。
- [免费开发签名验证方案](../experiments/unattended-update-credentials/PERSONAL-TEAM-PLAN.md)搁置，未下载或安装 Xcode、登录 Apple 账户或签发证书。首版不为此要求会员、证书或新实验；不挪用已结束实验的额度。
- 手动升级仍需在真实安装包中核对数据、原受保护凭据及仍有效的网站登录，并按原意图恢复工作；本次不改为明文、不关闭 Cookie 加密，也不扩大公开分发范围。系统授权提示的已知问题保留并进入[组合验收](21-integrated-validation-and-acceptance.md#answer)，不把资料丢失或反复要求同一授权当作合格。

本事项已不在当前地图的决策路径上，转入地图的 Out of scope。其退出解除无人参与更新的规划阻塞，可按修订的[本机交付约定](20-local-delivery-and-updates.md#answer)进入实现规格；完整产品仍须实现和验收。
