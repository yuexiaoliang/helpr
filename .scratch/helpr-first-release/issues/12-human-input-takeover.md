## Question

前提：[真实网页的页面归属、并行与输入来源证据](01-visible-page-control.md)和 [独立停止与迟到结果的处理](02-independent-stop.md)。

在已取得页面绑定证据的候选中，怎样可靠识别用户直接操作网页，并让对应任务让出操作，同时让另一项独立任务继续？取得可以支撑浏览器承载选择的机制与运行证据，保持已确认的“直接点击或输入接管，说继续后恢复”体验。

已有输入样本否定仅使用 `isTrusted`、宿主鼠标钩子或键盘按下钩子的简单方案：自动点击也会触发 trusted 与宿主鼠标事件；本机真人中文输入法序列中，`compositionend` 记录为 false，`before-input-event` 只记录到抬键。事件计数、页面焦点和固定时间内忽略输入，不能未经验证就充当来源证明。

明确待验证机制允许哪些自动输入通道，取得区分来源的实际证据，并覆盖自动与人工操作交错或同时发生的情况。可以先验证一个有事实支持的候选；另一候选缺失的证据明确保留，不能据此作对等比较。必要时比较不同来源信号，但不预先规定最终技术路径。

使用独立停止实验所得控制机制，核对以下组合：自动操作不会误触发接管；真人点击、中文输入法和粘贴能让对应任务让出操作；查看、移动鼠标和切换标签页不会接管；浮窗输入与网页输入归属明确；接管 A 时 B 继续。记录接管前已派发的动作实际会怎样，检查迟到结果不会恢复 A 的自动派发。用户说“继续”后，先核对当前页面，再按有效目标恢复。

真人样本不能用 agent 的系统输入模拟代替。若需要系统权限或特定输入法条件，记录实际依赖与用户可见影响；无法满足已确认体验时，明确阻碍与取舍，交由后续选型讨论，不私自改成需要用户先点“接管”按钮。

输出可重跑实验、来源判断依据、反例、组合范围及运行证据。此事项验证人工接管机制；完整产品状态模型、业务流程和最终架构仍由相应事项处理。

2026-10-12，完成 macOS / Electron 在已登记任务视图中的人工接管机制验证。**查看和对话不接管网页；真实点击、中文输入法与 ⌘V 可分别让 A 让出，B 继续；明确继续时先核对页面，旧执行不重新生效，续做后文字保留。** 这为浏览器承载选择提供一个候选的受控运行证据，尚不是最终选型或产品验收。

### 机制与来源边界

候选使用应用自身 NSWindow 内的 AppKit local monitor。鼠标按实际原生视图命中判断任务，键盘按实际 firstResponder 判断任务；所属任务在同一主进程同步回调中使旧执行失效，然后等待浏览器原语取消并读取结果。自动路径限定为本轮验证的 Playwright / CDP 输入，并保留 Electron 单键输入反例的具体范围。不用 DOM `isTrusted`、当前标签、计数或固定忽略时间窗代替来源判断。

原生事件本身不证明物理真人，computer use 也会经过该通道。工具自测、自动原生注入和真人输入分别记录来源；真人结论结合原始事件与用户独立反馈。应用内 monitor 没有要求新增系统权限；此前屏幕捕获授权属于 computer use 的窗口读取能力。

### 仍影响选型的限制

页面重载曾使旧原生视图登记失效。实验主动重载后的重新登记已验证，但非受控刷新附近再次出现未知归属并停止 B；不能据此宣称任意导航、弹窗或视图重建可用。已形成[验证页面变化后的输入归属与继续](19-page-lifecycle-input-ownership.md)，作为浏览器承载选择的前置事实补充。本事项的完成不豁免该缺口，也不要求用户重复已经通过的真人步骤。

实际休眠唤醒后的连接恢复尚未验证；公开 IPC 主动断连回归不能代替该保证。普通 Chromium、其它操作系统、更广输入法、原生菜单粘贴和辅助输入也未取得对等证据。检测不能撤回已派发输入或服务端已接受的请求，旧执行隔离不等于回滚副作用。完整业务流程、真实模型与人工接管的最终组合仍须在实现与验收中核对。
