## Question

前提：[确认现有模型 API 的接入条件](03-model-api-access.md)。

一次真实 AI 探索形成的记录，怎样成为能替换素材与输入、跨进程保存并重放的流程？核对网页变化后，经验证的修复能否更新后续做法，取得选择流程表示与执行机制需要的证据。

使用实际模型服务、候选执行原语与独立测试后台，完成一条最小路径；从无预置该业务流程开始。改变文件或标题、结束进程后重新加载流程，在新页面执行并核对结果；通过受控页面变化观察修复与更新。

分别记录理解委托、内容处理、网页探索、网页重放和修复中的模型调用。稳定动作直接执行的证据与整个任务零模型调用不是同一要求。

此实验可先在独立浏览器中进行，无需等待最终工作区选型。记录参数、等待条件、网页身份、流程版本及实际结果之间的必要约定，明确尚未验证的宿主组合。此事项验证重新执行保存的做法，不代表已经解决中断执行恢复。

## Answer

2026-10-10：完成独立 Chromium + Playwright + `deepseek-flash` 的真实后台实验。[实测报告](../experiments/runtime-flow-replay/REPORT.md)、[复现入口](../experiments/runtime-flow-replay/README.md)和[四阶段汇总](../experiments/runtime-flow-replay/artifacts/2026-10-10T10-30-00-complete/summary.json)已保存。

从无业务流程开始，AI 学出 17 个成功步骤并实际发布 Excel 附件。更换标题、正文和文件后，新进程加载原文件完成发布，网页重放调用模型 0 次。把标题控件改名后，原步骤失败，AI 用 1 次调用修复；核对实际公开文章及下载文件后保存新版本，再由另一个新进程以第 4 份素材零模型重放成功。四次正式结果的附件均逐字节一致，四份素材的哈希不同。

这给出了“运行时保存带参数的通用动作，稳定步骤直接执行，发生受控变化再修复并发布新版本”的可行证据。网站步骤和字段对应关系存在于学得的 JSON，测试素材、目标和结果断言属于实验用例，没有放进通用执行器。尚未据此选择最终宿主或工具组合。

后续规格至少需要保持这些关系：

- **参数与素材归属**：执行引用自己的标题、内容和素材，而不是把第一次录到的值直接重放。素材在开始处理后如何固定版本，以及生成内容与用户确认怎样关联，另行验证。
- **页面与等待条件**：动作始终绑定本次 Page、批准的网站 origin 和命名 frame；等待目标就绪。输入会改变可访问名称，核对必须仍指向刚才的元素。动作歧义不能靠随意选第一项消除。当前只有本条路径的证据，复杂上传完成条件仍需按运行时事实形成。
- **流程版本与验证结果**：本次执行固定父版本，修复产生候选版本；只有实际结果核对成功才保存新版本，并保留父版本与验证来源。本次未验证并发修复、原子保存或崩溃恢复。
- **结果独立于动作返回**：公开文章的标题、正文、分类和实际文件是验证依据。实测出现“已发布，但读取结果报错”，因此不能将执行器失败直接等同于未产生结果，也不能据此整段重跑。
- **模型调用按用途记账**：本条委托的理解并入探索、正文直接给定；成功探索 20 次、修复 1 次，两次冷重放均为 0。不能将它解释为完整自然语言任务或内容处理从此无需 AI。

报告保留了两轮失败探索和一次失败结果读取。对照暴露了页面观察信息不足、模型重复失败动作、控件改名和瞬时重复结果提示等问题。4 项针对实际故障的本地浏览器回归检查通过。

本事项不覆盖 Electron／Stagehand 的实际组合、双任务 AI 操作归属、停止与接管、提交中断恢复、第二后台或 Excel 内容生成。后续工作按地图当前优先次序推进。
