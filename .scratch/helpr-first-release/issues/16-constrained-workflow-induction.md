## Question

前提：[验证无需人工修订的流程归纳与条件校准](15-autonomous-workflow-induction.md)取得了否定性结论：宽泛的动作与条件 JSON 提议在真实探索中反复混淆阶段、误判已填写内容，并出现非法输出；完整流程没有形成。原生工具调用也不足以单独保证参数合法。

同一实验中，一个更小的提议已经取得局部证据：动作和输入由此前探索确定，程序固定 `fill` 的相等语义及输入引用，模型只提出实际字段的观察位置。该方式通过了正文填写前后的真实正反状态、未参与校准的文字复用和控件更名时停止。

能否把这种受限提议扩展为完整的探索与归纳闭环，让模型只从实际观察、已确定输入和通用动作中作出小范围选择，由程序持有协议结构、状态、不可变目标和可确定的动作语义，最终形成无需维护者补写网站规则的可复用流程？这不是要求模型一次写出更长的完整流程 JSON，也不预先选定某个执行框架。

## 需要取得的证据

- **提议及程序职责明确**：每个阶段返回什么由固定 Interface 约束；未知字段、包裹对象、非法参数及语义不一致明确拒绝。模型不能决定检查的期望内容、改变授权或把程序错误解释为任务完成。若程序自动组合规则，记录组合依据及其通用性。
- **实际观察决定推进**：区分控件名称、字段值与动作效果；已满足的输入不重复填写。动作成功但定位改变时，只在该阶段校准观察位置，不重做可能有副作用的动作。无进展、未知状态和预算耗尽有可核对的停止结果。
- **完整路径成立**：从明确的自然语言委托、素材和已登录真实页面开始，形成目标输入、适用条件、动作、步骤条件和结果规则，完成上传、发布与独立下载核对。可以重用通用代码和本轮真实记录，但不得由维护者补写选择器、字段绑定、提交条件或成功规则；复用起点和预设事实必须列明。
- **条件有正反证据**：把已有正文条件证据扩展到上传及提交前条件。通过实际上传未完成与完成状态，检查规则是否能够区分；候选或修订必须在新的执行里验证，不能只靠模型自述或 JSON 校验。
- **首次效果判断与篡改防护分开**：封存记录可以阻止把已有提交标成读取，但不能证明最初分类正确。对实际提交动作及至少一个错误效果提议，取得执行侧不会仅凭模型标签绕过约束的证据；未知副作用保留明确限制。
- **完成后再测保留集**：至少另一组未用于归纳或修订的素材与文字、相近但不同的委托、常量碰撞及控件变化。分别记录正确完成、正确拒绝或需要参与、结果不确定和错误宣告成功。真实内容预览与确认版本仍由已有事项负责。

沿用已配置测试模型，先在现有后台完成一条完整路径，再讨论第二后台。开始前设置总调用、时间及修订预算，按阶段预留验证开销；达到上限保留失败，不通过逐轮清零预算增加尝试。前一事项的具体失败不可当作普遍不可能的结论，也不能仅换个输出包装就宣告问题解决。

输出候选职责划分、真实完整路径与保留集证据、失败和未覆盖范围。若仍不足以支持自动学习，给出具体被证伪的假设和下一项需要决定的选择；不以局部通过宣布全流程成立。

## Answer

2026-10-10。本事项以有边界的否定性结论解决：**完整自动归纳未通过**，没有完整候选、成功发布或独立下载核对。具体记录见 [受限提议归纳实验报告](../experiments/constrained-workflow-induction/REPORT.md) 与 [原始证据索引](../experiments/constrained-workflow-induction/artifacts/run/evidence-index.json)。

受限 Interface 取得了局部进展：模型只从当前真实控件编号、通用动作和任务输入中选择；程序固定字段相等语义、名称绑定、不可变输入与执行检查。一次新委托解析后，10 步已执行前缀在新的真实页面上完成，浏览器重放过程没有模型调用。此前还暴露并修正了程序元数据与绑定语法冲突、正文观察名称保留旧样本文字的问题。维护者没有补写网站选择器、栏目映射或成功文案，但通用协议经过三次有记录的修订，不能把调试过程抹去。

完整路径停在上传：浏览器已经对真实隐藏文件输入调用 `setInputFiles`，但 3755 字节素材的 multipart 请求只向 `postDataBuffer()` 暴露 353 字节。程序要求请求 buffer 包含整个原文件，因而误拒正常授权上传。这直接否定了当前上传放行假设；不能将它归结为模型普遍无法完成任务。

首次效果判断取得独立负例：测试夹具将真实发布动作在本次执行中的标签故意设为 `read`，实际 POST 仍被输入覆盖检查阻止。这个检查没有使用候选封存摘要，区别于篡改已有标签的防护。但同一规则也阻断合法上传，尚未兼顾正确推进和提交约束；有副作用的 GET 等未知行为仍不在保证内。

总计 28 次模型请求、150,296 个已返回 token；所有实际提议通过形状校验，没有格式修订，动作语义仍有错误。开始前固定的三次程序协议修订额度已用完，未重置预算。剩余请求额度只用于冻结协议的诊断，没有用于继续改执行规则。

真实上传的未完成/完成条件对照、完整候选校准及完整保留集均未取得。局部校准更换了文字、文件名和路径，但文件内容字节与对应学习样本相同，上传未完成，不能算新素材的完整复用。相近委托、常量碰撞与控件变化的完整路径均未测试。

下一步优先 [验证上传授权与完整流程的分阶段检查](17-upload-authorization-and-workflow-checks.md)：先验证文件动作处的授权证据、请求关联与可下载产出的职责划分，再继续完整归纳。已有测试委托已授权本次新建记录及附件操作，无需为本实验新增逐步骤请用户批准的流程。完整学习缺口继续阻塞浏览器组合选型和第二后台对照。
