# helpr 首版实现规格

Status: ready-for-agent
Map: [首版技术决策地图](map.md)
Updated: 2026-10-14

本文汇总已确认的产品要求、技术决定与验收安排，是[23 项实现事项](../helpr-first-release-implementation/README.md)的共同依据。2026-10-14 已同步用户确认并提交于 `33f6eab` 的[工程技术栈方案](../helpr-first-release-implementation/engineering-stack-proposal.md)及 ADR-0005。`ready-for-agent` 表示规格可以进入实现准备，不表示产品已实现、原型已全部批准或验收通过；本次仅更新文档，代码实现仍按用户要求暂停。

首版先交付当前 Mac 自用版本；首次对外测试或发布前办理正式签名与公证；自动下载安装留到产品盈利后。每项功能遵循[原型确认与实现](../../docs/agents/issue-tracker.md#原型确认与实现)，技术选型的整体确认不扩展原型批准范围。

## Problem Statement

用户需要反复在真实网站处理素材、填写内容和发布结果。不同网站的页面结构、登录状态及操作步骤各异，重复操作消耗时间；单次 AI 操作即使成功，也未必能在更换素材、重启程序或网页变化后正确复用。

用户希望用自然语言说明目标，直接看到网页，必要时亲自操作或停止，再让系统接着完成剩余工作。多个平台的任务应独立推进，不能因为另一项在等确认而全部停下，也不能把某项的素材、回复或停止意图用到另一项。定时执行、意外中断和升级之后，系统尤其不能因本机记录不完整就重复发布。

现有仓库已完成产品访谈、技术选择和有界实验，尚无满足这些要求的完整产品。下一阶段需要把工作区、学习与复用、参与、记录和恢复放进同一个可安装应用，取得整体可用的证据。

## Solution

交付一个在用户当前 Apple Silicon / arm64、macOS 14.8.3 的 Mac 上独立打开的 helpr 应用。用户配置模型服务、在真实网页登录后，用自然语言委托工作。系统选择素材、理解目标，在实际页面执行并核对结果；首次形成可复用流程，后续稳定的网页步骤直接由程序重放，理解新意图和生成内容仍按需调用模型。

网页是主要工作区，每项任务有独立对话浮窗、进度和结果。首版最多两项独立任务同时自动推进。用户直接点击或输入网页就让对应任务让出操作；明确停止立即生效；明确继续时先核对，再处理剩余工作。需要登录、确认或补充信息时，用户可以在所属任务或全局提醒中参与。

任务、确认、流程、素材版本和实际结果可靠保存在本机，定时工作遵守各自的取材和错过时间约定。应用重开、解锁或唤醒后按记录与网页实际结果核对；无法确认的工作保持未知，不盲目重发。

首版包含本机历史、主动清理、备份恢复、自动检查新版及提醒。用户手动下载和安装新版，升级前保存与备份，升级后核对资料、凭据、登录和执行能力。自动下载安装及对外分发分别遵循上述后续安排。

## User Stories

### 委托、素材和复用

1. 作为用户，我希望在设置中配置模型服务地址、模型和凭据，以便正常任务对话不必反复选择模型。
2. 作为用户，我希望模型凭据受保护保存且不进入普通日志和备份，以便持续使用已有服务而不泄露密钥。
3. 作为用户，我希望在真实网页完成首次登录并复用仍有效的登录，以便不为每次任务重复登录。
4. 作为用户，我希望用自然语言描述网页工作，以便无需编写脚本、选择器或流程图。
5. 作为用户，我希望按自己约定的目录和取材规则选择素材，以便系统使用本次工作的正确输入。
6. 作为用户，我希望选中的素材保存为固定版本，以便原文件后来改变也不会偷偷替换已经确认的内容。
7. 作为用户，我希望把 Excel 原文件上传并发布到指定栏目，以便结果中的附件可下载且字节与所选素材一致。
8. 作为用户，我希望首次成功的网页做法能被记住，以便后续减少重复探索。
9. 作为用户，我希望更换文件、标题或明确指定的新栏目后仍能复用适用的步骤，以便本次输入不会沿用旧文件或旧值。
10. 作为用户，我希望彻底退出并重开应用后仍能复用流程，以便工作不依赖上次残留的编辑页或内存。
11. 作为用户，我希望系统读取 Excel 后提出文章建议，以便事实和数字能回溯到源表格。
12. 作为用户，我希望在所属任务预览并确认生成内容后再发布，以便最终提交符合自己的要求。
13. 作为用户，我希望内容、素材或目标改变后重新核对确认是否适用，以便旧确认不会批准新内容。
14. 作为用户，我希望同一产品能在结构不同的后台学习做法，以便不用等待开发者为每个网站编写业务代码。
15. 作为用户，我希望网页变化后系统在原目标内修复、核对并记住新做法，以便后续能复用修复后的流程。
16. 作为用户，我希望能分清哪些网页步骤直接重放、哪些部分使用了 AI，以便理解复用效果和实际消耗。

### 工作区和参与

17. 作为用户，我希望每项任务展示真实网页、独立对话、进度和结果，以便随时了解它正在做什么。
18. 作为用户，我希望多平台委托拆成独立任务并可归组整理，以便各平台分别确认、执行和查看结果。
19. 作为用户，我希望全局参与提醒可以直接输入或操作，以便不必先寻找对应标签页。
20. 作为用户，我希望提醒和任务对话中的回复始终归属原任务，重复回复只处理一次，以便不串任务或重复提交。
21. 作为用户，我希望查看、切换页面、移动鼠标和任务对话输入不打断网页执行，以便边看边交流。
22. 作为用户，我希望直接点击网页立即让对应任务让出操作，以便亲自处理现场。
23. 作为用户，我希望中文输入法和粘贴也能独立触发让出操作，以便不必先点击才能接管。
24. 作为用户，我希望无法确定输入归属时得到明确说明并暂停窗口内相关任务，以便系统不会猜错并抢操作。
25. 作为用户，我希望明确说“继续”后先核对页面和已有结果，以便只续做剩余工作、保留手动输入且不重发已完成内容。
26. 作为用户，我希望明确停止立即生效且无需二次确认，以便迅速阻止后续动作。
27. 作为用户，我希望停止后迟到的回复或已发送动作的结果被如实记录，但不自行恢复执行，以便停止意图和实际结果都可信。
28. 作为用户，我希望能用自然语言修正目标，以便系统重新理解剩余工作而不要求我选择技术上的停止类型。
29. 作为用户，我希望已结束任务关闭标签页后保留历史，以便整理工作区并能回看结果。
30. 作为用户，我希望关闭未完成任务时能就地选择收起或停止，也能按 Esc 返回，以便关闭动作不会含糊地改变执行意图。
31. 作为用户，我希望收起后仍能从活动任务和提醒返回，以便保留网页、待办及原来的执行状态。
32. 作为用户，我希望从历史或活动入口重新打开仅恢复查看，以便不会意外重启已停止的任务。

### 并行、约定和定时

33. 作为用户，我希望最多两项独立任务真正同时推进，探索和复用都适用，以便减少相互等待。
34. 作为用户，我希望容量已满或工作互相影响时由系统安排等待，以便无需管理执行器或锁。
35. 作为用户，我希望 A 接管、停止或等确认时不受影响的 B 继续，以便参与某项工作不拖住全部任务。
36. 作为用户，我希望共享登录失效、账号切换和同一目标冲突只影响相关工作，以便系统既不串用状态也不过度暂停。
37. 作为用户，我希望能够明确约定以后按某套要求自动发布，以便符合约定的内容不必每次重新批准。
38. 作为用户，我希望系统复述并记住发布约定的素材范围、目标及内容规则，以便我知道自己授权了什么。
39. 作为用户，我希望能修改或撤销发布约定，以便未派发工作及时遵守新意图。
40. 作为用户，我希望每项定时计划明确时间、时区、取材和错过时间的处理方式，以便休眠或未运行时不会按未知规则补做。
41. 作为用户，我希望定时任务在后台新建标签页而不切换当前页，以便当前查看和操作不被打断。
42. 作为用户，我希望缺少素材或选取不明确时再请求参与，以便系统不会任取一份文件。
43. 作为用户，我希望未处理素材按约定、目标、版本和日期或期次分别判断，以便改名不重复发布、另一目标又不会被错误跳过。
44. 作为用户，我希望上轮等待、已停止或结果不明的同一工作留在原任务，以便下次定时不会另开一份绕过停止或重复处理。
45. 作为用户，我希望新的合格素材仍按有效约定继续，以便旧工作的局部阻碍不会一律阻止后续工作。
46. 作为用户，我希望明确要求再发布一次时可以形成新的工作意图，以便去重记录不妨碍有意重复。
47. 作为用户，我希望关闭或停止本次任务不取消定时计划，以便本次执行与未来安排分别受控。

### 记录、恢复和资料

48. 作为用户，我希望程序中断后恢复任务、确认和流程记录，以便有效确认不因回执丢失而反复索要。
49. 作为用户，我希望网站可能已经完成时先核对真实结果，以便缺少本机成功记录不会造成重复发布。
50. 作为用户，我希望结果不明时明确显示仍待核对，以便不会把超时或未找到结果当成可以重发的证据。
51. 作为用户，我希望重开、重新登录或解除系统暂停后仍保留停止、待参与和接管意图，以便环境恢复不代替我的继续指令。
52. 作为用户，我希望记录保存失败或空间不足时暂停依赖它的自动动作并说明原因，以便系统不会继续做无法可靠记录的工作。
53. 作为用户，我希望每项完成结果能查看实际位置和必要证据，以便区分完成、待处理与无法确认。
54. 作为用户，我希望历史、素材版本和必要证据默认本机保留，以便回看和恢复；主动清理时能知道影响。
55. 作为用户，我希望清理不误删未完成工作、共享资料和自动取材所需的完成事实，以便不会丢现场或重新发布旧素材。
56. 作为用户，我希望创建不含模型密钥和网站登录的本机备份，以便自行保管任务、流程和素材。
57. 作为用户，我希望恢复旧备份后先暂停并核对，再选择继续哪些任务或计划，以便旧资料不覆盖更新的意图或重复网站上已有的结果。

### 本机运行与交付

58. 作为用户，我希望应用在当前 Mac 上独立打开，以便日常使用无需运行开发命令。
59. 作为用户，我希望关闭主窗口只是收起应用并保留菜单栏入口，以便任务和定时计划继续运行。
60. 作为用户，我希望明确退出或按 ⌘Q 后停止派发、保存资料并结束自有网页进程，以便不会留下继续操作的后台进程。
61. 作为用户，我希望 helpr 遵循系统休眠设置，解锁或唤醒后先核对，以便电脑休眠和任务恢复符合预期。
62. 作为用户，我希望自动获知新版及可信下载入口，以便自己决定何时下载和安装。
63. 作为用户，我希望手动升级前妥善处理现场并保存备份，升级后保留任务、原密钥和有效登录，以便持续使用而不重新建立全部状态。
64. 作为用户，我希望系统权限、凭据或兼容检查失败时保留资料并说明受影响能力，以便能处理问题而不被要求关闭系统安全设置。
65. 作为用户，我希望网站无法获得任意本机文件、模型密钥或宿主命令，以便真实网页与应用能力保持明确边界。
66. 作为用户，我希望交付前在同一产品中通过真实业务、并行、恢复和真人操作核对，以便获得可持续使用的应用。

## Implementation Decisions

### 1. 已选路线与实现边界

- 采用 Electron 承载真实网页和独立宿主对话视图，Playwright 操作网页，helpr 自己组织任务、逐步检查、学习、复用和恢复。Stagehand 不进入首版关键执行路径。
- 采用本机执行。电脑和应用需保持运行；测试服务器只承载测试网站，不承接产品调度或代用户执行。
- 产品源码提供通用网页原语、素材读取与内容处理能力。网站步骤、字段映射、结果识别和业务规则是运行时形成的流程数据，不能用网站专用源码、维护者选择器或预填流程代替自主学习。
- 既有实验代码作为证据与可审查的实现参考。正式产品需要清晰的 Module Interface、稳定的数据约定及打包入口，不直接把多个实验启动器拼成应用。
- Electron、Playwright、原生输入组件和存储绑定在首个可运行产品中固定版本；已有实验版本只作兼容基线。更换这些依赖须重验受影响的能力，不能默认升级兼容。

工程取舍按“由 AI 维护、人类实测验收；维护与验证优先；成熟工具优先、必要处自研”执行。以下是已确认的组合，具体兼容版本在恢复实现时核对后精确锁定；发布元数据或单库支持声明不能充抵实际组合通过。

| 部分 | 已选工具与实现要求 |
| --- | --- |
| 语言与契约 | 正式应用采用 TypeScript 严格检查与 Zod。外部、模型及跨进程输入做运行时校验；结构正确不代表归属或权限正确。旧独立实验可以保留 JavaScript。 |
| 宿主界面 | React、CSS Modules，按需使用 React Aria 无样式交互组件；落实已确认的布局和视觉，界面订阅有版本的业务投影，局部交互使用 React。 |
| 业务状态 | XState 稳定 5.x 在唯一记录拥有者内计算任务生命周期的合法转换，各任务分别建模；首版不叠加第二个全局状态库。网站步骤仍为运行时流程数据。 |
| 数据与迁移 | 独立受管记录进程中的 better-sqlite3、Drizzle ORM／Kit 稳定发布版本；SQLite 短事务与独立不可变文件共同保存关联事实。 |
| 编译与打包 | electron-vite 稳定发布、electron-builder 稳定 v26 与 node-gyp；显式多入口及独立 CJS preload，采用普通构建路径，原生组件和生产资源在实际包中验证。 |
| 通信 | Electron 原生通信加 Zod 固定业务契约；按真实通道核对发送方角色、任务、执行、请求身份和版本，不增设通用 RPC 框架。 |
| 模型 | AI SDK Core 加显式直连 provider；SDK 处理协议与流式解析，helpr 控制资格、每次发送、预算、取消与未知用量。 |
| 诊断 | Pino 加 pino-roll，本机结构化诊断、限定字段、脱敏及有界轮转；业务历史和恢复证据独立保留。 |
| 包管理 | pnpm，一个正式应用、一个产品锁文件及必要的本地原生包；采用默认隔离依赖布局，显式管理依赖构建许可，旧实验保持独立。 |
| 日常检查 | Vitest、React Testing Library、独立类型检查、类型化 ESLint、React Hooks 规则、现成模块边界规则与 Prettier。旧实验检查保留，不替代正式产品检查。 |

Node、pnpm、直接依赖及锁文件固定为共同验证过的组合，本机与 CI 使用同一版本来源。依赖升级单独进行并复验受影响能力，不批量自动升最新版或自动修复依赖。依赖及许可证清单依据实际 pnpm 依赖图和包内容；不通过全量依赖提升掩盖未声明引用。通用表格与时间工具的具体选择随对应功能原型确定，见下文素材及定时约定。

### 2. Module 与 Interface

公开 Interface 以调用方需要的完整行为划分。UI、后台协调和测试使用同一入口；模块内部的数据表、消息转接和辅助函数不另设给调用方的操作通道。

| Module | Interface 接受和返回什么 | 隐藏的 Implementation 与约束 |
| --- | --- | --- |
| 委托与协调 | 接受自然语言委托、目标修正、停止、继续、参与回复和计划修改；读取任务事实、进度、参与请求和结果 | 理解并拆分任务、确认适用性、素材选取与内容版本、执行容量及共享资源协调。所有输入绑定任务和当前版本，模型不能自行扩大委托。 |
| 持久记录 | 读取当前事实；按预期版本接受意图／回复；领取执行、素材工作与计划触发；预留动作、登记观察、保存和采用流程候选 | 独立受管进程中的单一记录拥有者，XState 纯转换、better-sqlite3／Drizzle、SQLite 事务、不可变文件关联、幂等及并发与跨重开一致性。不向工作者暴露任意表写入。 |
| 工作区 | 为任务提供有归属的真实页面、当前观察和页面生命周期事件；显示任务对话；报告人工输入、登录和现场可恢复性 | Electron 页面、会话共享、焦点和原生输入绑定、导航与新窗口管理、受限宿主通信。页面引用失效后不可继续沿用。 |
| 网页执行 | 接受任务当前执行资格、固定输入／授权／流程版本或探索提议；逐步执行并返回进度、参与需求、检查点与结果证据；响应资格撤销 | Playwright 与私有控制转接、逐动作检查、取消和迟到处理、动作事实与业务结果的区分。首次探索、重放、修复和恢复续做共用同一路径。 |
| 流程 | 查找适用版本；根据真实执行形成候选；验证并申请采用；提供重放和恢复所需的结构化规则 | 参数与来源绑定、适用条件、前后条件、版本和验证证据、并发修复。不授予任务权限，不把模型自称成功当验证。 |
| 应用运行 | 与 UI 共用的收起、返回、退出、版本检查、手动升级准备、资料清理、备份和恢复；接收系统生命周期事件 | 拥有者与工作者生存期、锁屏与休眠暂停、版本来源、迁移与文件完整性。跨模块操作由持久记录和统一派发条件协调。 |

模型服务、时钟、受控网页连接、原生输入、存储和版本来源是适合替换的 Adapter。业务判定留在对应 Module；不为每个 Adapter 或内部对象建立独立测试 Seam。主要行为检查保持已确认的三组公开入口。

上述 Module 是行为边界，不要求与进程逐一对应。进程职责按 [ADR-0005](../../docs/adr/0005-record-process-and-state-transitions.md)落实：

| 位置 | 职责与边界 |
| --- | --- |
| 受信宿主界面与独立对话 | 展示投影、保留所属任务的局部交互，通过受限命令表达意图；不另建业务记录权威或自行授予执行资格。 |
| 长期控制拥有者 | 协调任务、持有即时内存资格和独占私有 pipe，在派发前核对最新条件；收到停止先阻断及撤销旧资格，再请求保存。 |
| 独立记录进程 | 唯一持久记录拥有者，按预期版本计算状态转换、校验并提交事实，提供提交回执和有版本的投影；承担查询、迁移及一致备份。慢查询或磁盘同步不阻塞控制进程的事件循环。 |
| 独立网页宿主 | 承载真实页面及可信页面归属，原生输入组件保留在宿主的 AppKit 所属线程；远程网页不取得宿主桥、密钥或任意本机文件能力。 |
| 每项执行的工作者 | 使用经任务资格限制的能力，网页操作经控制拥有者转接；不直接持有裸 CDP 或任意数据库写入权限，单项退出不结束另一项任务。 |

XState 的转换不直接产生网页、模型或计时副作用。允许的业务命令及可序列化参数经 Zod 校验后与相关事实提交，不把原始 actions、函数或 actor 引用当持久协议。提交失败时，内存投影不能冒充已保存事实；即时停止及其尚未保存的状态仍须如实显示。已提交回执也不是永久许可，控制拥有者仍检查后来发生的停止、接管和页面变化。

通信区分请求、提交回执与实际效果，核对可信通道角色和当前版本，处理超时、断线、重复及迟到；消息内自报的任务编号不能证明身份。记录进程不可用时阻断依赖它的自动工作，恢复连接本身不解除原停止或未知。控制拥有者退出时核对全部自有进程的清理；独立记录进程没有增加第二个持久权威。

### 3. 任务事实和用户意图分别保存

任务有稳定身份、目标版本、来源与可选任务组；每次执行有新的身份及前序关联。任务组只作整理，不持有组级对话或审批。一个任务可以多次执行；流程复用不是复用上次任务或执行身份。

以下维度不能压成一个含糊的“进行中／已完成”字段：

| 事实 | 必须表达的内容 |
| --- | --- |
| 用户意图 | 当前委托、目标修改、明确停止、接管及明确继续的次序；未知输入暂停与明确停止分别保存 |
| 执行条件 | 当前执行身份、记录版本、容量与资源资格、确认／约定、素材及流程版本、页面绑定、系统暂停、保存和凭据状态 |
| 参与请求 | 所属任务、执行和请求版本，问题与内容版本，有效／已回复／失效事实及已接受回复 |
| 派发与效果 | 动作预留、是否可能送出、返回、观察到的后置条件和实际业务产出；未知保留未知 |
| 展示状态 | 当前页面是否显示或收起、活动入口与历史位置；不作为自动执行许可 |

例如，“用户已停止”可以与“先前送出的发布后来完成”同时成立。后者更新实际结果，不抹掉停止或批准下一步。展示文案要让用户理解这两件事，无需暴露内部执行编号。

| 触发 | 行为 |
| --- | --- |
| 明确停止 | 立即阻断该任务新的模型动作与网页派发、撤销旧资格，再可靠记录；直接反馈，不二次确认。已发送的请求继续按实际结果登记。 |
| 直接网页输入 | 先让对应任务让出操作，再交付用户输入；保留文字与现场，另一独立任务继续。 |
| 输入归属未知 | 记录未知并暂停同窗口内两项，说明原因；不伪造两项均被用户接管或停止。 |
| 明确继续 | 建立新的执行资格，先核对当前目标、页面、结果、确认与条件；已完成就返回结果，剩余部分合格才继续，未知不重发。旧回调不会因继续变有效。 |
| 目标或内容改变 | 重新评估流程和确认／约定的适用性，失效请求不可再接受；保留仍有效的确认及已产生结果。 |
| 仅查看、重新打开、登录恢复、重启或唤醒 | 这些事件本身不撤销停止或接管，也不替代参与回复；原先获准自动执行的任务须核对后才可继续。 |

待参与、接管、停止及未知输入暂停跨重开保留。恢复核对正在等待时再次发生停止或输入，新的事实优先；旧核对完成不得解除更新的暂停。

### 4. 工作区、接管与参与交互

- 宿主界面采用已选 React 组合。创建任务只输入目标，缺少或写错网站地址由 AI 在任务中分析、补问或纠正；01 先交付基础工作区，真实理解能力由 02／03 接入。任务标签并入 header，恢复成功等短暂提示悬浮显示，为网页保留空间；沿用已确认的第 4 款无竖线标签栏与悬停卡片。
- 真实网页由独立 WebContentsView 承载，任务对话由受信宿主视图承载；对话输入不落入网页接管路径。每项任务有自己的会话、预览、参与请求和结果。
- 原生输入识别覆盖本应用窗口中已登记的网页视图，分别验证点击、中文输入法、粘贴。看页面、切页、移动鼠标和聊天不算接管，自动化输入不能伪装成真人输入。
- 页面、frame、弹窗和任务映射由宿主建立并随生命周期更新。刷新、导航、新窗口、视图重建、控制连接失效或焦点关系变化使旧绑定失效；重新观察并确认归属前不能使用旧资格。
- 全局提醒可以提供输入和操作，携带稳定任务与参与请求身份，不按当前活动标签页路由。与任务对话重复回答通过同一接受入口去重；已失效回复明确告知用户。提醒能引导返回对应真实页面。
- 全局可操作提醒属于首版，具体承载与焦点表现须在目标安装包验证；不得因为某个系统通知方案尚不可用而静默删掉此能力，也不把未经验证的系统功能设为必备依赖。
- 定时任务后台开页，不抢用户查看页或焦点。收起任务保留网页和对话现场，固定活动入口与提醒仍可到达；无法重建的现场不能靠销毁页面来模拟保存。

React 与交互组件的选择不改变已确认行为。任务切换后的草稿、中文输入中的提交、焦点返回及订阅清理须通过实际用户入口检查；不能由局部 UI 状态恢复业务执行。原生输入与资格撤销的跨进程顺序仍须另取组合证据，不能以状态文字最终变为“已让出”作为顺序证明。

任务标签页的“×”按最新事实处理：已完成、已停止或以失败结果结束时直接关闭并保留历史；执行、排队、待参与或接管时，在标签页旁给出“收起任务／停止任务”，说明收起后的行为。点击外侧或 Esc 仅收起提示，不改变任务；停止不作默认焦点或 Enter 的隐式选择。提示期间任务完成时按新状态处理。

在提示中选停止即停止本次执行并关闭标签页。重新打开只查看；明确继续后仍有合格剩余工作时恢复活动入口。关闭或停止本次执行不取消计划。

### 5. 两项并行与共享条件

系统最多授予两项可独立推进的任务自动执行容量，首次探索和流程复用均适用；第三项合格任务等待。等待用户参与或已让出操作的任务不长期占用自动推进容量，但页面、待办和本身的限制保留。额度释放只影响调度，不给等待任务补出缺失的确认或授权。

登录上下文和网站目标是实际共享资源。两个标签页不能证明账号、登录和服务端对象彼此独立；同一任务组也不必共享。工作区报告会话归属与变化，协调模块只暂停依赖该条件的工作，对可能互相覆盖的目标串行协调。登录恢复仅解除登录阻碍，不能恢复明确停止或略过内容确认。

共享阻碍解除后的积压工作按当前任务、素材处理事实、计划及用户既有约定判断；新的取舍才请求参与，不使用“一律补发所有积压”之类隐含规则。用户不需要配置工作者、锁或并发模式。

### 6. 素材、内容与发布约定

选定素材时取得固定字节及来源、选择规则和工作含义，验证完整性后保存为不可变素材版本。文件路径和名称不是版本身份；已确认文件后来变化不替换原版本。读取表格得到的事实保留来源位置及解析版本，文章建议、预览、附件和实际提交参数都关联相应素材与内容版本。

表格解析采用成熟库，具体库及版本在事项 18 的原型中用代表性文件核对后确定。原型明确实际支持的格式、公式缓存与重算能力、日期及缺失值等输入边界；不能把缓存读取等同于重新计算，无法确定的内容不得伪造成可靠事实。该选择时机不减少首版 Excel 内容处理范围，也不要求自研通用解析器。

生成内容默认在所属任务建议、预览、确认。确认至少绑定任务、适用目标、内容和素材版本；任一相关内容或目标变化都重新判断适用性。不同平台分别确认，不能把 A 的确认用到 B。已经可靠接受且仍有效的确认不因回执丢失或重启重新索要。

发布约定用自然语言复述并保存素材范围、目标、内容处理规则和有效版本。符合当前约定时可直接发布；改变平台、栏目或内容规则超出原约定时重新确认。撤销立即使尚未派发的相关动作不合格；已送出的效果如实核对。流程只说明做法，不能提供发布权限。

发布核对分阶段进行：执行前核对意图、参数与权限；准备过程中及时保存目标关联、草稿和上传事实；提交前核对当前内容、附件、目标及确认；提交后核对实际产出。已观察到串素材、内容不符、异常写入或最终结果不明时，停止受影响的后续自动动作并核对。

上述约束作用于 helpr 的行为与已观察到的结果。网站脚本可能产生额外请求，首版不承诺发送前隔离所有隐含写入；正确发布也不证明没有其它改动。不要以时间窗口、请求文件名或模型标为“只读”推定全部效果已获授权，也不引入逐网络请求审批。

### 7. 流程学习、重放、修复与模型

流程是可版本化的结构化运行时数据，包含适用条件、参数与来源约束、各步骤前置条件／动作／后置条件、结果识别、恢复观察入口，以及版本、父版本和来源证据。动作仅使用通用受控能力。模型提出做法，不能提交任意宿主脚本或借多步 SDK 绕过逐动作检查。

首次委托由产品根据实际页面形成候选、组织执行并核对，不依赖维护者填写网站步骤、任务参数位置或正确结果。只有真实观察和验证支持的部分才记为可复用；模型生成但未走到的分支不能标为已验证。

复用前核对任务与流程适用性，绑定本次输入，固定本次使用的流程版本。稳定网页动作可以不调用模型直接执行；理解委托、选取或生成内容等模型调用分别记录，不把“有模型调用”误算为网页步骤未复用，也不把总用量降低单独当成功标准。

页面变化触发重新观察与受限修复；目标、授权和成功条件不因修复放宽。核对成功后自动采用新做法并简短告知用户。未知的提交结果不能通过再发一次来验证修复。

并发修复保留各自候选、父版本和证据。采用时检查当前版本，过期候选不能覆盖另一项已采用成果或改变正在执行的固定版本；需要合并时形成新候选重新核对，不要求用户选择技术分支。

模型 Adapter 支持已验证的可配置服务协议，服务地址、模型与凭据由设置管理，不把测试提供方写成唯一选项。请求有任务与执行归属、取消、并发限制、超时和用量记录；模型提议经当前资格检查后才能变成动作。服务端尚未返回用量的取消或中断请求保留未知消耗，不能假记为零。配置、认证、能力或连接不满足时给出可理解的对应原因，普通错误和记录不含凭据或认证头。

模型 Adapter 采用 AI SDK Core 与显式配置的直连 provider，不以模型字符串隐式选择 Gateway，不启用内容遥测或 SDK 自主网页工具循环。按冻结版本关闭全部隐式重试；每次重新发送都重新核对资格并记账。实际发送前有控制检查，不能只依靠通知回调抛错阻止请求。用原始用量判断字段是否完整，不把适配器补出的零当作服务端真实零；取消也不能证明服务端没有计费。先用可计数的本机模拟服务验证协议、重试和取消，再按既有有界安排核对真实服务能力。

### 8. 持久记录与派发协议

单一持久记录拥有者串行协调写入，SQLite 使用短事务；网页和模型等待不占有长事务。素材与证据存为独立不可变文件，写入、同步及完整性核对完成后，记录才能引用。事务、同步、文件发布顺序和存储版本由产品存储 Adapter 明确实现，并以故障用例检验；数据库事务不能把远程网站效果一起原子提交。

记录拥有者位于独立受管进程，通过 better-sqlite3 和 Drizzle 访问数据，状态转换、事实与允许命令按预期版本提交。Drizzle 生成的迁移经审查后冻结，运行时不对用户库执行开发期结构同步。升级保留旧数据备份并检查迁移失败或中断后的可恢复性；数据格式、状态模型及引用文件共同管理版本。SQLite 备份 API 不自动取得外部素材的一致快照，仍由记录拥有者协调。

| 必须可靠关联的记录 | 主要关系 |
| --- | --- |
| 任务与执行 | 任务、目标版本、来源、任务组、执行身份、前序执行、控制拥有者及当前资格 |
| 意图与参与 | 意图次序、暂停原因、参与请求及版本、已接受回复、有效确认、发布约定及撤销 |
| 输入与内容 | 选择规则和范围、来源、素材版本、工作日期／期次、解析事实、预览、确认与实际提交参数 |
| 流程 | 不可变版本、父版本、适用条件、候选与验证证据、当前采用引用、本次固定版本 |
| 网页动作与结果 | 页面／会话归属、稳定目标、动作身份、预留与可能派发事实、检查点、返回、观察及业务结果 |
| 定时与素材处理 | 计划版本、时间／时区／错过策略、触发领取、工作身份及未完成／未知／核实完成事实 |

公开修改请求携带请求身份、预期版本及相应任务归属。同一请求身份和同一内容返回已接受结果；同身份不同内容拒绝。并发版本冲突返回当前事实供重新判断，不盲目重试过时操作。状态查询和只读计划不领取工作、不重置计数、不触发派发。

以下关系必须在同一次数据库提交中成立，不能分成几次成功状态各自暴露给调用方：

| 原子变化 | 不可拆开的事实 |
| --- | --- |
| 接受意图或参与回复 | 接受记录、当前意图／确认依据，以及受影响的旧资格和请求失效 |
| 领取执行 | 唯一有效执行身份、共享资源和自动推进容量的检查与分配 |
| 预留动作 | 当前归属、输入、授权、流程及资源资格检查，与一次性动作预留 |
| 记录核实结果 | 已核实业务结果、相应素材处理事实和本次工作进度 |
| 领取定时触发 | 本轮领取、取材或等待决定、本轮任务及素材工作的关联 |
| 采用流程 | 完整候选与证据引用，以及按预期父版本更新当前采用引用 |

同一公开操作跨事务重试仍遵守请求幂等和预期版本约定；浏览器观察、模型请求和文件准备在相应事务外完成。

每次动作按以下顺序执行：

1. 确认控制拥有者和工作者仍有效，核对任务／执行／页面／会话、素材／内容／授权／流程版本、共享资源、容量和系统状态。
2. 可靠保存本次动作预留及必要恢复事实；保存失败不发送。
3. 临近派发再次核对停止、输入和资格变化，消费一次性预留后送出动作。相同预留不能因通信重试被消费两次。
4. 及时登记返回与实际观察；分开记录动作返回、步骤条件、最终业务结果及观察覆盖范围。辅助截图失败不覆盖已核实结果或导致重做；缺少关键证据时保留未知。

停止在内存中立即阻断新动作，再保存停止事实。保存失败时当前进程仍保持阻断并告知“停止尚未可靠保存”，不能声称未落盘意图必然跨崩溃保留。关键记录不可写时所有依赖该记录库的自动派发保持暂停。

新启动先取得唯一拥有者身份并使旧工作者和控制连接失效，不能仅凭超时或 PID 推断旧动作已经结束。已经送到网站的请求可能在进程退出后产生效果；旧执行返回只可作为历史观察归档，不可推进当前执行。

### 9. 结果核对与恢复

恢复使用正常执行形成并及时保存的目标身份、来源和版本、已知上传、结果入口和检查点。产品自己从实际页面形成这些依据，不能使用测试答案、网站专用后台脚本或人工补写恢复规则代替。

XState 快照只提供记录中的状态依据，不能在恢复后直接启动会再次产生网页或模型动作的 invocation。先检查记录及模型版本，再核对实际效果和当前资格；状态迁移成功也不等于可以继续派发。停止须保留后续明确继续的合法路径，不能以终结整个任务状态机代替产品的停止含义。

| 现场与记录 | 恢复行为 |
| --- | --- |
| 能唯一关联本次目标，实际结果与内容／附件符合要求 | 记录核实完成并告知结果；即使缺少本机成功回执也不再次提交 |
| 有可信的未派发检查点，旧控制已撤销，现场和当前条件匹配 | 仅执行剩余工作，经过相同确认与派发入口；不能因找到草稿就直接推定属于此行 |
| 已预留或可能派发，但最终结果、身份或内容无法确认 | 保持未知，仅做可独立确认的只读核对并按需请求参与；不把查不到、超时或没有成功记录当未发生 |
| 已停止、接管、待参与或未知输入暂停 | 保留意图；可登记已到达结果，后续执行仍需相应条件，不自动续做 |
| 缺少记录、记录损坏、版本不兼容或素材不匹配 | 保留原资料，暂停依赖它的执行并说明；不从空记录重建一份可发布任务 |

核对阶段不重新发送原写入动作。找到同名对象、多处冲突结果、错误版本或被替换的正文不能认定完成。若核对本身需要超出原约定的操作，进入相应参与流程。

恢复协议覆盖进程中断与实际系统生命周期，并明确存储失败的行为。已有强杀、同步和休眠证据不等于物理断电证明；不承诺未验证的硬件故障保证，也不削弱已确认的中断恢复要求。

### 10. 定时与素材工作身份

每项计划保存时间、时区、取材范围与规则、有效发布约定及错过时间策略。补最近一次、跳过或先询问由各计划约定，不偷偷选全局默认。计划修改保存新版本与生效范围，取消后阻止尚未派发的触发；已经产生的结果不回滚。

创建或修改时用具体时间复述，包含时区及重复／不存在等歧义时刻的处理；无法唯一确定就澄清，机器时区改变不偷偷改变已有约定。已经开始的旧工作与根本未启动的错过轮次分别处理，补最近一次不删除旧任务或清除其等待条件。

时间计算使用成熟库，具体库及版本在事项 20 的原型中用时间表达、时区及夏令时例子确定，区分“每天某时刻”和“每隔固定时长”。库提供候选时刻，计划意图、生效版本、触发领取、去重及错过后的恢复仍由 helpr 管理；不能以库的默认歧义处理或内存定时器代替已确认约定。

计划的一次触发领取与一份素材工作的领取分别去重：前者避免同一个到点事件重复建任务，后者关联约定、目标、素材版本和日期／期次等工作含义。流程版本或计划版本变化本身不使相同工作变成未处理，文件改名或移动也不改变相同字节的已完成事实。

同一素材发往 A、B 分别记录；A 完成不跳过 B。运行、等待、停止或未知的旧工作保留原任务，新触发不能复制它；新合格素材按当前条件安排。用户明确再发一次形成新的意图和工作身份，仍受同样的目标、内容和执行检查。

源文件字节变化产生新素材版本，但是否纳入下一轮、更新旧记录或另发，由取材和发布约定决定，不能由文件变化自行批准。确实失败且能确认未产生效果的重试也关联原工作，仍核对授权、故障和恢复条件，不重新把素材当从未处理。

电脑或应用未运行时不承诺定点执行。恢复后先核对旧工作和实际效果，再按计划的错过时间约定处理；定时触发不能绕过已停止工作或通过换执行身份清除未知。

### 11. 控制通道、宿主与登录隔离

长期存活的 helpr 控制拥有者持有 Electron 私有调试 pipe，Playwright 工作者通过受管进程通信和能力转接使用它，不暴露可绕过检查的裸回环 CDP 端口。单项停止撤销其资格，不关闭两项共享的宿主；拥有者退出时关闭全部自有页面和工作者。

转接检查调用者、任务、执行、目标页面、session 和允许能力，归属由受信宿主建立，不信任模型或网页自己申报。未支持协议能力拒绝并取得具体兼容证据后再增加；页面／frame owner 查询也不得成为跨任务通道。旧执行、外部客户端和远程页面均不能取得其它任务或任意宿主能力。

远程网页启用 sandbox 与 context isolation，禁用 Node integration，保留 web security；无模型密钥、任意文件或通用宿主 IPC。对话等宿主页面的 IPC 校验发送 frame、角色和允许操作。导航、新窗口、外部协议、下载和网页权限由宿主管理并保持任务归属；上传只开放当前获准的固定素材。

网站登录使用持久浏览器会话，用户在真实网页登录；共享范围显式记录。凭据候选采用 macOS Keychain 支持的 Electron safeStorage；不可读时保留受保护数据、暂停依赖请求，不降级为明文。显式启用并验证 Cookie 加密，不把它称为整个浏览器资料或 localStorage 已加密。

当前原生输入路线只监视本应用窗口的本地事件；权限需求以实际安装包为准。测试工具的屏幕录制／辅助功能权限不自动成为 helpr 的权限清单。目录选择限定应用的素材用途，不宣称构成操作系统级沙箱。首版不要求用户关闭系统安全设置。

原生输入组件沿用宿主 AppKit 线程中的 Objective-C++／Node-API 路线，用 node-gyp 构建，固定源码、SDK、目标架构及部署条件。electron-vite 显式编译控制、网页宿主、记录、工作者和受限 preload；electron-builder 收集实际生产依赖和迁移等资源，fuses 配置后再签名。不得以绕过 sandbox、放宽 preload 或打开裸调试端口解决包内路径与依赖问题。

### 12. 本机运行、资料与手动更新

主窗口红色关闭按钮仅收起，保留菜单栏入口和真实页面，任务及计划继续依条件推进。明确退出或 ⌘Q 先阻止新派发、保存记录，再关闭自有视图、工作者与控制进程。退出不批量改成“用户停止”；观察到退出通知也不等于进程树已经清理。

锁屏与休眠分别持有暂停原因。唤醒但仍锁屏时继续阻断；两者都解除后重新核对，原先合格任务才续做。新的锁屏或停止使正在进行的旧核对失效；重复系统事件不启动并发恢复。遵循原系统休眠设置，不自动阻止休眠。

任务历史、素材和必要证据默认保留。用户主动清理前显示影响，保护未完成、待参与、停止后可继续、结果不明及被其它工作引用的数据。必要的素材完成事实不能随历史无声删除；若其确被用户清除，依赖它的自动判断须暂停或重新约定。空间不足不静默删除旧资料。

备份由记录拥有者协调一致快照和引用文件，核对清单、完整性及版本；包含任务、流程、素材和必要证据，排除模型密钥、网站登录及会话目录，不自动上传云端。备份可能有敏感业务内容，不宣称自动整包加密。恢复前保留当前资料；恢复后暂停自动工作，结合新旧记录与网站实际结果核对，由用户选择继续哪些任务／计划。备份后的停止、约定变化或发布不能被旧快照无声覆盖；当前记录不可得时也不能默认旧意图仍有效。

固定应用身份和数据位置，业务资料与安装包分离。首次可安装版本就验证打开条件、受保护凭据和有效登录保留；需要从自用身份迁移到正式签名时单独核对，不能靠重填原密钥或重新登录取得升级通过。

自动版本检测只向已确定的可信 HTTPS 来源查询所需版本、平台、架构和兼容信息，显示提醒及可信下载入口；不上传业务资料或凭据，不下载包、不登记待安装版本、不运行自动替换。用户手动下载和安装。不能将会触发下载的更新 API 当作只读检查。

手动升级准备与派发共用协调入口：先处理不能安全关闭或重建的现场，阻止新动作，保存任务、计划和参与状态，形成可核验备份，再退出供用户替换应用。安装意图不等于批准发布、放弃手动文字或允许重发；准备中到点的计划不得越过暂停。用户从外部强行替换或终止应用仍按中断恢复处理。

新版启动检查数据、素材、原受保护凭据、未过期登录、原生输入和网页控制能力，再按原意图核对恢复。来源、架构、备份、迁移、兼容或凭据失败时保留资料，暂停依赖工作并说明。允许必要的手动系统交互，但重复要求同一授权、丢失原密钥或有效登录不能算稳定通过；程序降级不代表资料可安全回退。

先完成当前 Mac 自用。首次对外测试或发布前办理 Apple Developer Program、Developer ID 签名和公证，验证实际安装、系统功能与身份迁移；本规格不立即购买会员、安装 Xcode 或恢复免费签名实验。自动下载安装及无人参与更新路线在盈利后另行规划。

### 13. 本机诊断与维护

采用 Pino 与 pino-roll 保存可关联任务、执行及进程的本机诊断。只记录限定事件、关联 ID、错误码和耗时等字段，各进程独占文件并按容量和数量轮转；不直接序列化完整消息、网页、模型内容或任意异常字符串。分享由用户主动导出脱敏资料，默认不接云端错误收集、内容遥测或自动崩溃转储。

诊断日志不承担事务事实或恢复依据，异常退出可能丢失日志尾部；诊断写入与关键业务保存失败分别处理，不能因日志存在就认定动作已可靠保存。日志轮转不得删除任务历史、素材或必要证据，这些资料继续遵循用户主动清理和引用保留规则。

## Testing Decisions

### 1. 使用已确认的三组 Seam

检查从真实调用方使用的 Module Interface 进入，断言可观察行为与独立事实。正式产品测试不能只调用实验候选或比较内部函数调用次数；不为每个辅助函数增加重复检查。只有时间、模型、故障等必要外部条件使用受控 Adapter，持久化和组合行为尽量使用实际组件。

| 组 | 公开入口及被测 Module | 独立依据与关键反例 |
| --- | --- | --- |
| 意图、记录与派发 | 委托与协调、持久记录；委托／参与回复、停止／继续、执行／素材／触发领取、动作预留与结果登记、候选采用 | 另一进程重开真实记录；独立接收端只记实际收到与完成，不读取候选数据库或替它去重。覆盖重复请求、相同身份不同内容、竞争领取、预算与取消、迟到结果、保存失败、旧备份和并发修复。 |
| 网页工作区、执行与流程 | 工作区、网页执行、流程；首次探索、重放、修复和恢复使用相同控制与派发路径 | 实际网页、目标站点记录、下载字节及额外请求／效果计数。覆盖归属、变化、确认、稳定身份缺失、错误版本、共享登录和目标冲突，以及无资格／跨任务／过期控制。 |
| 应用运行、版本检查与资料恢复 | 应用运行及其与记录、工作区、执行的组合；使用 UI 相同的关闭／退出、只读检测、升级准备、清理、备份和恢复入口 | 两个真实版本安装包、实际进程树、网络请求、备份内容、原凭据和升级后网页效果。事件次序检查与真实安装包检查互补；不能用退出通知代替所有自有进程结束。 |

模型请求的取消、预算、重启计数和并发限制纳入第一组，页面动作和恢复判定纳入第二组。受控模型回应只验证协议，不评价真实理解能力。网页核验用的独立答案和网站知识不能提供给产品来生成流程或判定完成。

本次技术选型沿用以上已确认入口。新增进程、状态库和测试工具不产生新的业务测试边界；其故障、版本及组合检查分别从相应公开入口进入，断言实际保存、派发、网页收件和用户可见结果。

### 2. 同一产品的贯通顺序

1. 从事项 01 的已确认工作区开始，固定兼容工具链，在同一实际安装包贯通两项真实页面、独立对话、私有观察能力及独立记录进程，先验证手动登录与冷重开。随后按 02–06 的原型批准范围接入模型、双任务执行、原生接管及恢复，尽早形成组合并核对停止／接管不串任务、冷重开不重复和正常／异常退出；及早在 09 检查手动换版的原凭据和有效登录。01 的观察范围不提前开放自主执行。
2. 打通首次附件发布、换输入复用和冷启动复用，在完整路径中加入计划取材、素材版本、确认归属和网页变化修复。
3. 加入 Excel 内容处理、预览确认和 Drupal；探索＋探索、复用＋复用、探索＋复用均取得真实推进交叠。
4. 固定交付候选的应用、依赖、原生组件和配置版本，执行完整矩阵、五项业务各两次及最后真人核对。早期实验和贯通记录不自动算交付候选通过。

这也是已发布事项的贯通依据。每项纵向形成可验收行为，所需工程能力随路径接入，不先完成全部底层模块再首次连接真实工作区。选型确认不替代各功能的原型确认，也不新增实际运行额度。

### 3. 五项真实业务，各至少两次

至少十个独立成功样本，使用不同素材或输入；同一输出不重复抵算不同场景次数。首次探索使用没有预置该业务流程的独立验收资料区；后续复用实际学得的流程。账号、栏目和测试文件可以准备，产品不得取得维护者步骤、选择器或预期答案。

| 场景 | 通过依据 |
| --- | --- |
| WordPress 首次附件发布 | 自然语言委托、实际探索及保存的流程、正确栏目和真实结果；下载附件与固定素材逐字节相同 |
| 更换输入复用 | 新素材、标题及明确要求的新栏目正确绑定；稳定动作直接重放，理解和内容处理的模型调用单记，无旧文件／旧确认 |
| 冷启动复用 | 完整退出、重开后用新输入完成；不依赖上次页面、进程内状态或未保存的流程 |
| Excel 生成文章 | 两份不同表格的事实和数字逐项核对，建议、预览、确认和提交版本一致；修改内容使旧确认失效 |
| Drupal 不同后台 | 相同通用产品代码完成两次任务，流程来自运行时观察；不新增站点专用执行代码 |

独立核验也检查多余结果、错误素材和已观察到的越界效果，成功页面不能掩盖这些失败。分别记录模型、上传、草稿、保存和发布次数。专项检查可附着业务样本取证，不为同一断言额外重复发布。

### 4. 交付组合矩阵

| 主题 | 必测行为 |

### 5. 真人核对、运行预算和失败

真人核对预计两轮：最早产品贯通与交付候选，各安排约 10–15 分钟主动操作。开始前 agent 检查正确安装包、窗口可见、页面已绘制、任务推进、焦点与记录采集；一次只给一个明确动作、预期结果和停止位置，由 agent 读取记录核对，无需用户报计数。点击、中文输入法、⌘V、锁屏及真正休眠分别取得真人证据，自动输入不能替代。实际安装和系统授权另记；不要求用户反复盲试。最后由用户核对流程是否可理解。

本规格不是新实验、模型调用、远程发布、购买会员或改系统设置的授权。每批实际验证按已有授权，事先固定候选、测试账号／目标、案例、具体消耗上限和停止条件；模型及费用、网页动作、上传／草稿／发布、构建／安装／启动、故障和时长分别记账。两次成功是门槛，不是无限重试额度；失败、准备失败和修后重跑均累计，重启或换目录不清零。已有额度内的必要修正继续完成，新增消耗超出已授权范围时再形成可审阅增量方案。

遇到结果不明、串任务、已观察到的越界、停止失效、关键保存或凭据保护失败、异常弹窗、自有进程残留时，停止受影响的自动验证，先保存现场和失败，再做限定测试资源的必要清理。不能删失败、换样本、人工关闭弹窗后计作自动通过。修复重验受影响行为及组合，无关已固定证据不重复消耗。

保存候选与依赖版本、素材版本、原始事件、独立核验、累计消耗、失败与修正、真人操作及结论。私钥、凭据、浏览器资料、运行时数据库和构建包按 ignore 管理，提交脱敏且足以核对的材料。

### 8. 交付判定

五项业务各两次、完整组合矩阵、工程组合与已冻结性能门槛、目标 Mac 真人核对、只读版本检测和实际手动升级全部满足，才能交付。未解决的重复发布、串任务、停止或恢复失效、资料丢失、凭据或控制边界问题，以及范围内其它未通过项均阻止交付。演示可用、无报错或实验结束均不能代替。

交付说明列出实际支持环境、版本、运行条件、安装与必要使用步骤、已验证范围和证据入口。十个成功样本不证明长期稳定性；其它 Mac、平台和网站以另行取得的证据为准。

## Out of Scope

- 当前首版同时交付 Windows、Linux、Intel Mac、其它未验证 macOS 环境，或由远程机器／云端代执行；超过两项自动并行。
- 本轮正式向其他用户分发、注册或购买开发者会员。正式签名、公证和对应验证在首次对外测试或发布前完成，不延至盈利后。
- 自动下载、自动安装、空闲安装开关、无人参与更新及更新后零新增系统授权保证；这些留到产品盈利后，不取消首版只读检查、提醒及手动升级的数据保留要求。
- 为 WordPress、Drupal、栏目或 Excel 业务编写产品专用执行代码；把旧版项目架构、模拟界面或实验夹具直接当产品实现。
- 承诺任意网站均可自动化，或宣称微信公众号、小红书等尚未验收平台已受支持；按表格批量新增／更新后台记录仍属扩展场景。
- 任务组会话、组级集中审批、用户手工编排流程或配置执行器；逐网站请求审批，以及发送前隔离所有网站隐含写入的通用保证。
- 自动到期删除历史、云端备份、把登录和模型密钥装入业务备份；整份资料自动加密或应对已控制操作系统攻击者的保证。
- 将所有逻辑拆成内部函数测试，或继续扩张已结束实验来替代同一产品的贯通和验收。
